# 主页规格 · 按功能组织（用户 2026-09-20 拍板）

> **用户原话**：「就把这个当亮点一页就行，然后总体还是去这个，根据功能去做这个项目的主页」
>
> 即：
> - **亮点页** = RhineLab 三维档案终端（`/lab/` 形态），只做**一页**，不承担全站
> - **主页** = 按**功能**组织（不是按架构、不是按技术分层）
>
> 本文只定**结构与内容**。美术在内容定稿后再动。

---

## 一、为什么要重构（现状的问题）

`site/index.html` 现行 8 节按**架构**切分：

```
01 总览 · 02 数据流 · 03 记忆结构 · 04 能力清单
05 档案终端 · 06 界面速览 · 07 已知边界 · 08 安装
```

问题：**读者要的是「它能帮我干什么」，页面给的是「它是怎么搭的」。**
`数据流`（观察→检索→注入→固化）与 `记忆结构`（注入面 × 记忆库）是**实现视角**，
对第一次来的人没有意义——他们还没决定要不要用。

改法：**主线改为功能，架构降级为「怎么做到的」的补充说明。**

## 二、新结构（主页）

```
┌ 顶栏    品牌 · 功能 · 亮点 · 安装 · 边界 · [中/EN] · GitHub
│
├ §01 HERO        一句话主张 + 安装命令 + 事实芯片
│
├ §02 她做六件事    ← 功能总览，全站骨架（6 张卡）
│
├ §03 ① 自动记忆      不用你说，她自己记
├ §04 ② 可查可改      每条都能看见、能改、能删
├ §05 ③ 三层结构      规则 / 笔记 / 日志，各管各的
├ §06 ④ 主动提醒      该记得的事，她替你记着
├ §07 ⑤ 继承与隔离    别人的记忆能搬过来，不同项目互不打扰
├ §08 ⑥ 卫生与开关    乱码进不来，每个功能单独可关
│
├ §09 亮点页入口       大卡片 → 三维档案终端
├ §10 安装            三步
└ §11 已知边界        4 条（保留，这是信任凭证）
  页脚                法务层
```

## 三、六个功能的归属（12 项能力 → 6 个功能组）

| 功能组 | 吸收的原能力 | 一句话（读者视角） |
|---|---|---|
| **① 自动记忆** | 1 无问自忆 · 3 记忆自己写自己 | 不用你说「记得记一下」，她自己记 |
| **② 可查可改** | 4 唤起可审计 · 12 记忆可携带 | 每条都在你自己盘上，能查能改能删 |
| **③ 三层结构** | 2 三层记忆 | 硬规矩、项目笔记、每日流水，分三层放 |
| **④ 主动提醒** | 5 主动提醒 | 截止日期和承诺，她替你记进日历 |
| **⑤ 继承与隔离** | 7 外部记忆继承 · 10 工作区隔离 | 别家 AI 的记忆能搬；多个项目互不串味 |
| **⑥ 卫生与开关** | 6 一切皆开关 · 8 生产级卫生 · 11 模型无关 | 脏东西进不来；不想要的一键关掉 |
| （补充）| 9 上下文管理 | 并入 ① 作为「写满了怎么办」的小节 |

**为什么是 6 组而不是 12 条平铺**：12 条并列没有主次，读者记不住。
6 组每组 2–3 件事，刚好在「一屏能读完」和「信息不丢」之间。

## 四、每节写什么（逐节内容规格）

### §01 HERO
- **H1**：无问自忆，记忆不断线。
- **副文案**：记忆放在上下文窗口之外；该想起的自己浮现，每次唤起都有据可查。
  上下文写满时，她不再把自己压缩成摘要——合上一本写满批注的笔记，翻开新的一页。
- **安装命令**：`pnpm add @a9i5k4/dsh-auto-memory@latest` + 复制按钮
- **事实芯片**：`v3.0.0` · `BSD-3-Clause` · `runtime deps 0` · `Win/macOS/Linux` · `中英双语`
- **右栏**：**待定** —— 用产品界面截图，不用角色定妆稿（角色定妆稿移去亮点页）

### §02 她做六件事
6 张卡，每张：编号 + 标题 + 一句话 + 锚点链接到对应详述节。
这节是**导航页**，不展开细节。

### §03–§08 六个功能详述（每节统一四段式）

```
【标题】      ① 自动记忆 —— 不用你说，她自己记
【正文】      2–3 句人话，说清「发生什么 / 对你意味着什么」
【示意】      一张小图或内联 SVG（不追求华丽，讲清机制即可）
【证据行】    1 行小字：可验证的事实（数字 / 命令 / 面板位置）
```

**每条都要有「证据行」** —— 这是本插件「唤起可审计」调性的自证。

### §09 亮点页入口
- 一句：「想看它长什么样？进档案终端。」
- 大卡片 → 三维档案终端（RhineLab `/lab/` 形态，DeepSeek 配色）
- 明确标注：**需要 WebGL**；低配设备自动降级

### §10 安装
沿用现行三步 + 补 npm 命令 + 「30 秒验证装好了」动作。

### §11 已知边界
沿用现行 4 条 CAUTION（实验特性 / 语义档可选 / 仅回环 / 序列帧未交付），补第 5 条：亮点页需 WebGL。

### 页脚（法务层，三层分列）
1. **上游署名**：RhineLabUI / rhinelab-blog-theme · `Copyright (c) 2026 LBEILC` · MIT
2. **本插件许可**：BSD-3-Clause
3. **角色署名**：鲸鱼娘设定 · CC BY-NC-SA 4.0（**注意与非商业条款的冲突，必须分列**）
4. **素材排除声明**：未包含上游 GLB 模型 / Blender 工程 / 原片素材 / 游戏品牌
5. **免责声明**：与 DeepSeek 官方无隶属关系

## 五、亮点页规格（三维档案终端）

**目标**：把 RhineLab `/lab/` 抽出来，换成 DeepSeek 配色，内容换成本插件的 40 项。

### 抽取范围（只取三维终端，不取博客）
```
lab/index.html          → 入口
src/*.ts  (~40 个)      → 三维场景 + 开场 + 过渡
src/*.css               → 样式
public/assets/*.glb     → ⚠️ 不能用（MIT 不覆盖），需替换或自建
public/fonts/           → 字体（沿用 MiSans 或换）
public/audio/           → ⚠️ 授权待核
```

### 内容映射（40 槽 = 5 主题 × 8）

| 主题（原） | 主题（新） | 8 槽内容来源 |
|---|---|---|
| 工程研究 | **核心机制** | 观察 / 检索 / 注入 / 固化 / 水位 / 锚点 / 索引 / 缓存 |
| 生命科学 | **记忆库** | 事实库 / 情节库 / 技能库 / 规则 / 笔记 / 日志 / 归档 / 索引 |
| 机构档案 | **能力** | 12 项能力选 8 项 |
| 能量研究 | **界面** | 概览 / 唤起回顾 / 设置 / 工作区图 / 向导 / 审批 / 语义档 / 导出 |
| 特别项目 | **工程** | 体积 / 依赖 / 性能 / 许可 / 测试 / 兼容 / 隔离 / 卫生 |

### 配色改造（三档，待用户选深度）
- **(a) 只改 CSS 层** —— 覆盖层 + 排版，约 1 天
- **(b) CSS + 材质反相** —— 照 `theme-material.ts` 的方法论走一遍，3–5 天
- **(c) 连灯光/雾/AO 重标定** —— 1–2 周

### 阻塞项（必须先解决）
1. **GLB 模型不能直接用** —— MIT 不覆盖。选项：① 自建低模 ② 用程序化几何（Three.js 内置）③ 联系原作者要授权
2. **音频授权未核** —— `public/audio/README.md` 要读
3. **角色层** —— 三维里放鲸鱼娘需要**模型**，线描 PNG 进不去；要么叠 2D 图层，要么不做
