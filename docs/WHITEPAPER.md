## 0. 一句话

> **同一份记忆字节，同时喂给三个消费者。任何一处写入，都要同时满足三套约束。**

这是本插件全部工程复杂度的来源，也是历史上绝大多数 bug 的来源。

## 1. 核心不变量

### 1.1 三个消费者

记忆在磁盘上是纯 Markdown 明文。但同一份字节被三个**语义不同**的消费方读取：

| # | 消费者 | 怎么读 | 对字节的要求 |
|---|---|---|---|
| ① | **注入面** | 每轮自动注入进上下文 | 必须**干净、短、有结构**；乱码与超长行会污染上下文 |
| ② | **检索面** | 词法 + 语义双路召回 | 必须有**可切分的锚点结构**；锚点被破坏则召回精度下降 |
| ③ | **语义面** | digest 供语义模型编码 | 必须**可重复生成**；同一输入必须产出同一 digest |

### 1.2 约束

> **一处写入，三处生效。** 写入方必须同时保证：
> 1. 注入面拿到的字节在**预算内且无污染**；
> 2. 检索面能按锚点**正确切条**；
> 3. 语义面的 digest 能**正确失效并重建**。

### 1.3 为什么这条不变量危险

因为它**大多是静默降级**：

- 注入进了一段乱码 → 模型读到噪音，**不报错**；
- 锚点被写坏 → 召回少了几条，**不报错**；
- digest 没失效 → 语义召回用了旧向量，**不报错**。

**不爆的时候，完全看不出来。** 这就是为什么必须有一条显式约束 + 一批针对性断言。

## 2. 一次真实事故（本不变量的代价）

这是本项目最典型的一类 bug，值得完整记录。

### 2.1 现象

用户在面板「日志」页签看到**乱码**；同时记忆文件侧也出现异常内容。

### 2.2 根因

**两条写入通路，只修了一条。**

- 该插件有**两条互不相干**的写入通路：`procedure`（技能）线与 `fact`（事实）线；
- 早先的清洗器只接进了 `procedure` 线；
- `fact` 线的三个入口（`crossFeed` 的 fact 分支 / `factCandidateFromRow` / `hubFlushTick` 的回写）**从来没有过清洗器**；
- 于是脏数据既进了 `facts.json`，又经回写污染了 `MEMORY.md`。

> **教训**：「修了一条通路」不等于「另一条受保护」。
> 只修**具名入口**是治标；把清洗**下沉到写原语**才是治本。

### 2.3 处置

- **当时**：在三个已知入口设防，补清洗器 + 新增判据族；
- **根治（在途）**：把 `sanitizeForWrite` 下沉到写原语（`appendText` / `writeFull`），
  使**全部写入路径自动受保护**——不再依赖「记得给新通路接上清洗器」；
- 存量脏数据按**用户拍板**采用 `skip` 并留痕，**不做「清洗后照写」**。

> **为什么不做清洗后照写**：那等于悄悄改数据，并丢失「曾出现脏 fact」这一诊断事实。
> 本项目纪律是 **fail-soft 必须留痕、不得静默改写**。

### 3.3 三条时间轴（判据互不相同，勿混）

系统里同时存在三条**周期不同、判据不同**的时间轴。它们极易被混为一谈，是本项目
新增功能时最容易踩的坑：

| # | 轴线 | 周期 | 判据（唯一权威） | 触发者 |
|---|---|---|---|---|
| ① | **工作台轮换** | **跟随 ②**（3.1.8 起合并，不再独立可调） | `epoch` 变化 = `'B' + floor(本地日历日天数 / periodDays)` | `_wbRotateTick`（15s 心跳） |
| ② | **会话自动归档** | **2 天**（`autoArchiveDays`，唯一入口） | 会话最后活动时间超过阈值 | `sessionArchiveSweep`（`checkIntervalMin`，下限 15 min） |
| ③ | **归档后自动删除** | **7 天**（`autoDeleteDays`） | `archivedAt` 已知且超过阈值 | 同上 |

> **★ ① 必须 ≤ ②，这不是可调参数，是硬约束。**
> 挂在工作台会话下的子代理会**持续刷新**该会话的活动时间。若轮换周期 > 归档天数，
> 旧工作台**永不静默** ⇒ 永远进不了归档 ⇒ ②③ 整条链断裂。**轮换的存在意义即为此。**

> **★ 3.1.8 二合一（用户指令）**：原先 ① 与 ② 各有一个独立数字（都默认 2），
> 用户指出「两个 2 是不是得二合一，不然还会耦合」——**判断正确**。
> 两个数字本质是同一段生命周期的两个阶段，各配一个数必然失配：
> ① > ② 则归档链断裂；① < ② 则白建会话。**故 ① 已降级为 ② 的派生值**：
> `_workbenchPeriodDays()` 只读 `autoArchiveDays`，设置页只留「归档阈值」一个旋钮，
> 「工作台轮换周期」改为**只读显示**（跟随上一项）。老配置由 `_unifyPeriodPre()`
> 在配置加载唯一汇聚点一次性收敛（`workbenchPeriodDays` 跟随 `autoArchiveDays`）。
> **`workbenchPeriodDays` 键仍存在但不再是独立输入** —— 运行时不读它，
> 仅作老配置兼容；把它当第二个旋钮使用即为回退（守卫 ⑬ 有反向断言钉死）。
> **判据**：凡有两个可独立影响同一行为的输入，即未真正合并。

## 6. 子代理归属与轮换门（3.1.x 新增）

### 6.1 问题

子代理会话是 **durable** 的（宿主持久化），**删不掉**。旧设计让每个子代理都新建一个会话，
于是持久会话无限增长——这就是历史上「会话爆炸」的根源。

### 6.2 设计：一个工作台会话 + 定期轮换

- **全部子代理挂到同 1 个工作台会话**（`记忆中枢 #<epoch>`）之下；
- 该工作台**每 2 天轮换一次**：旧期让位、新期接管，旧会话**保留不删**
  （删除会让 catalog 指向不存在的目录，反而重新制造要根治的幽灵条目）；
- 子代理按母会话给定的 `childId` 复用，不再无限新建。

### 6.3 归属判据（唯一，不得散落）

```js
function wbOwnerOf(sessionId, st) {
  if (st.current  && st.current.sessionId  === sessionId) return 'current'
  if (st.previous && st.previous.sessionId === sessionId) return 'sealed'
  return 'orphan'
}
```

- **`current` 放行；`sealed` / `orphan` 一律拒绝并记 diag**；
- 六个写路径（`greet` / `fold` / `summarize` / `consolidate` / `consolidate-logs` / `distill`）
  **必须先过它**；
- **期牌 `epochToken = sha256(epoch + '|' + sessionId).slice(0,16)`** ——
  一个字段同时编码「期号 + 会话」，故归属比对只需一次；
- **`_wbTokenOf` 只读落盘值、不做派生兜底**：若允许「字段缺失就现场算一个」，
  这个门将**永不失配**（恒真），等于没装。

### 6.4 ★ 一次真实缺陷的完整取证（3.1.7 修复）

> 这是本项目**最值得记录的一次缺陷**，因为它的形态极隐蔽，且**只在真实翻期那一刻才暴露**。

**现象**：工作台状态文件卡在 `phase="sealing"`，`epoch` 停留在旧期号；
诊断日志每 60 秒重复一行 `wb-rotate: sealing -> create ... ok=true reason=ok`，
**连续 8 分钟不停**。

**根因链（三段，缺一不可）**：

1. `_verifyWorkbench` 在「相位 ∈ {draining, sealing} 且落盘期号 ≠ 当前期」时返回 `ok:true`
   —— 这个分支**本意**是「轮换窗口内旧期仍权威 ⇒ 不停记忆功能」（服务于**门控可用性**）；
2. `ensureWorkbench` 见 `v.ok` 就**走复用分支直接 return**，从不把落盘 `epoch` 收敛到新期；
3. 心跳的 sealing 分支每 60 秒重试一次 ⇒ **永远 `ok=true`、期号永不推进** ⇒ 死循环。

**根因性质**：**同一条判据被两种语义共用。**
「旧期仍权威」（保记忆不停摆）与「轮换已完成」（需要期号真的变了）
是**两件不同的事**，却被 `ok:true` 一个布尔值同时承担。

**后果（功能性，不只是日志噪音）**：
落盘期牌恒为旧期 ⇒ 与当前期不符 ⇒ **E2 归属门把全部受门控记忆任务判为不匹配而拒绝**；
同时旧工作台被持续刷新、永不静默 ⇒ **§3.3 的 ②③ 两条链断裂**。

**修复（4 处，全部 fail-closed）**：

| # | 位置 | 改动 |
|---|---|---|
| ① | `ensureWorkbench` 复用分支 | 增加 `opts.rotate` 旁路：轮换时**跳过**复用分支 |
| ② | sealing 同意门 | 改为**三态**：`true`=已获批 / `undefined`+有当前会话=**迁移态放行** / `false`=**明确拒绝** |
| ③ | sealing 建期调用 | 改为 `ensureWorkbench({ consent: true, rotate: true })` |
| ④ | sealing 成功后 | 由相位唯一写者 `_wbSetPhase` 把 `epoch`/`epochToken` **收敛到当前期**并复位 `active` |

> **② 为什么要三态**：`consentGranted` 是后加的字段，而本机工作台**早于**该字段存在
> （旧版本直接建立、从不弹窗 ⇒ 用户**当时没有任何拒绝的机会**）。
> 若把「字段缺失」与「用户拒绝」同判，同意门会被架空；若一律放行，同意门同样形同虚设。
> **必须区分「缺失」与「显式 false」。**

**★ 真机验收（2026-09-26 用户重启后，一次通过）**：

| 判据 | 修复前（现场） | 重启后（实测） |
|---|---|---|
| `phase` | `sealing`（滞留 8 分钟+） | **`active`** |
| `epoch` | `B10358`（跨零点未推进） | **`B10359`** |
| `epochToken` | `5993a42678d9dfc1`（旧期） | **`431bb8de4da62580`** = `sha256('B10359\|session-cd00ac3b-…')` |
| `drainStartedAt` / `sealTriedAt` | 1790352010052 / 每 60s 重写 | **`0` / 字段消失** |
| `current` / `previous` | 无 previous | 新会话 `session-cd00ac3b…` / 旧会话 `session-81fa8b3b…` 进 `previous`（**未删除**） |
| 诊断日志 | 每 60s 重复 `sealing -> create granted=false ok=true` | `consent raw=undefined migrated=true refused=false` → `workbench ready … epoch=B10359` → `sealing -> create granted=true` |

> **一条与首版记载相反的事实**：rotate **会建新会话**（规格 §9.3 即如此设计），
> 旧会话转入 `previous` 并被守卫 ⑰ 保护、**不删除**。首版演练断言写的
> 「current 不换」是 **mock 造成的假绿**，已按真机语义改写（见下）。
> 另：日志中**没有** `wb-rotate: converged` 一行 —— 因为 `ensureWorkbench` 自身
> 已经完成了期号落盘，第 ④ 步的「重读并收敛」是**幂等兜底**（`r.reused=false` 时不触发）。
> 该行只在「建期成功但落盘期号仍未变」时出现，属异常路径的正常出口。

**验收方式（★ 方法论，值得复用）**：取**自造的「卡死态」夹具**当输入，
分别喂给**旧代码**与**新代码**，各自用**自身真源码**抽出的函数在隔离目录真跑一次 tick：

| 组 | 结果 |
|---|---|
| A 旧代码 | 5/5 **复现卡死**（`opts=[null]` 不带 rotate ⇒ 期号不动、相位不变、期牌仍旧） |
| B 新代码 | 10/10 **闭环**（`{consent:true, rotate:true}` ⇒ 期号收敛、相位复位、旧会话进 `previous`、期牌键到新会话） |
| C 幂等 | 3/3（已收敛态再 tick **不再空转**） |
| D 真机 | 3/3（真机文件**逐字节未动** + 状态自洽 + 未处卡死态） |

> **★ 三处「假绿」教训（同一根因：判据不如实反映真机）**：
> 1. **夹具不得依赖真机故障态**：首版直接读真机 `workbench.json` 当输入，用户重启后真机自愈
>    ⇒ 「复现卡死」前提消失、13 条断言集体转红。**受控演练的输入必须自造**，
>    否则演练只在故障窗口内可重放。已改为自造 `phase=sealing` + 人为旧期 + 过期 `sealTriedAt`。
> 2. **mock 必须复刻真机的可观测行为**：首版 mock 恒返回 `reused:true` 且不建会话，
>    于是断言「current 未换」在 mock 的假设里成立 —— **真机其实换了会话**
>    （日志实证：`workbench session created ... <新 id>` + `previous={sessionId:<旧 id>}`）。
>    这类断言是**mock 决定的假绿**，比没有断言更危险（它给出虚假信心）。已按真机语义改写为
>    「旧会话进 `previous` + 期牌键到**新**会话」。
> 3. **别把现场快照写成不变量**：首版 D 组断言「真机仍为 sealing/旧期（宿主未重启）」
>    —— 那是**当时**的现场，用户一重启必然转红。已改为形状不变量：`phase` 合法
>    **且** 期牌 = `sha256(落盘期|当前会话)`。
>
> **方法论要点**：`_wbRotateTick` 内部用的是 **`Date.now()`** 而非入参 ⇒
> 必须注入 FakeDate 才能越过 60 秒节流；期号算法含**基准日 `Date.UTC(1970,0,5)`**
> （不是 01-01）且用**本地日历日**，复刻时必须逐字照抄，否则会得出错误的「期望期号」而假红。

### 6.5 轮换门的相位机

```text
active --期号变--> draining --族静默--> sealing --新期就绪--> active(新期)
```

- **主判据 = 全部子代理静止**（`_subagentInflight === 0` + 子代理目录 mtime 静默 2 分钟）；
- **空 catalog / 全幽灵一律判静止**（否则永不轮换）；
- **异常判「不静止」**（保守，不 fail-open 架空这道门）；
- **30 分钟超时是纯防御**：只记 diag，**绝不强切**——强切会造出「半轮换」
  （旧的还有人在写、新的已开始）；
- **相位迁移只有一个写者**：`_wbRotateTick`（15 秒心跳）。

## 7. 归档与删除自持（3.1.x 新增）

### 7.1 为什么不依赖外部插件

归档/删除曾由第三方插件 `dsh-session-archive` 承担。**客户机不保证装了它** ⇒
本插件改为**自持**：配置入口在本插件设置页，生命周期自己管，`lib/session-archive.js` 是独立模块
（纯函数边界，便于单测；不读 `workbench.json`、不认识「工作台会话」）。

### 7.2 生命周期（三段）

| 阶段 | 默认 | 键 |
|---|---|---|
| 子代理结束后**保留** | — | `subagentGcEnabled=false`（回收系统已判废） |
| **自动归档** | 2 天 | `autoArchiveEnabled` / `autoArchiveDays` |
| **归档后自动删除** | 7 天 | `autoDeleteEnabled` / `autoDeleteDays` |

### 7.3 ★ 安全边界（不得放宽）

三条**默认安全**，任何改动都必须先证明不破坏它们：

1. **归档时刻未知的会话永不自动删除**（拿不到 `archivedAt` ⇒ 不进删除种子）；
2. **与 sweep 同一 tick 内刚归档的会话不删除**（避免「刚归档就被删」）；
3. **家族内只要有一个受保护成员，整个家族跳过**（`family-protected`）；
4. **工作台会话（`current` / `previous`）必须被归档与删除入口拒绝**
   （守卫以**行为断言**钉死，不是文本断言）。

> **为什么「回收系统」整体判废**：删除会话目录**并不减轻前端渲染负担**——
> 宿主 `handleSessionRemoved` 对 `origin==='subagent'` 只降级 status、不删投影 store。
> 于是「删掉 ⇒ 界面少渲染」这个原始诉求**不成立**，回收系统遂失去存在理由。
> 这是**先取证、再判废**的样本：不是「觉得没用」，而是**证明它做不到它声称的事**。
