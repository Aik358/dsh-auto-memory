# 引航者计划 · dsh-auto-memory

> **状态**：已立项 · 2026-10-18（第 1 期试运行）
> **性质**：社区计划章程 —— 本文件是额度发放、贡献认定与社区报告上站的唯一判据。
> **落点**：`docs/CREATOR-CREDIT-PROGRAM.md`；面向社区的公开版见 `docs/landing/program/index.html`。
> **验收**：本文件与 `docs/FRONTEND-CO-CREATION.md`（前端共创）、`docs/CONTRIBUTORS.html`（贡献者页）三处口径一致。

## 摘要

> **命名**：「引航者」取自航海——以实证为舵，在语义记忆与模型调参的未知海域里为社区拨迷寻路。三档阶梯沿用同一意象：**启航**（第一次下水）、**远航**（一次完整交付）、**领航**（长期在航线上）。

这个插件有两端可以被真正参与：**前端**是一套零构建、单文件、可换肤的界面；**后端**是一个有参数可调的语义模型（BGE-M3 嵌入 + 激活策略），它的每一个门限都能实测。

第 1 期额度由独家 API 赞助方 **DSHAPI（api.dshapi.icu）** 划给社区，用于两类工作：插件前后端的 debug 与优化升级，以及围绕这套记忆系统的前沿研究（模型选型、评分标定、合成数据、蒸馏实验）。

额度按**证据**发放，不按**承诺**发放。每条贡献都必须带可复核的凭据：PR 链接、复现步骤、复现脚本与其输出、或一篇可公开复核的报告。

## 一、为什么有这笔额度

三个事实决定了这件事值得做：

1. **前端是短板，而改前端不需要门槛。** 记忆面板 12 页签 + 设置页 8 分组，信息密度高、布局拥挤；前端零构建、单文件、纯 ESM，clone 下来就能跑着改。
2. **后端有真实的调参空间。** 语义侧车（Python）负责「像不像」，JS 核心负责「该不该」；检索、融合权重、激活阈值、注入预算都是可测量的旋钮，每一个都对应一篇已发表的技术报告。
3. **已经有人验证过这条路可行。** 一位社区成员用 54.2 万条真实群聊消息对《检索选型》报告做了一次**第三方独立复核**，得出一个可冻结结论、两个可用数字、两个空结果，并留痕了四类方法判定错误。这类工作此前无处申领资源——本计划就是把它接上。

### 轨道 B · 研究（调参、评测、复现）

| 方向 | 例子 |
|---|---|
| 复现 | 用别的语料/硬件重跑某篇报告的实验，看结论是否成立 |
| 反驳 | 找到某条结论的适用边界，或用更强判据推翻它 |
| 补实验 | 报告里明确写「本轮没测」的部分（见 §八） |

| 合成数据 | 构造难负例、覆盖对、跨库镜像等对抗结构 |

### 轨道 C · 观察（写报告）

| 方向 | 例子 |
|---|---|
| 工程调查 | 缓存、注入成本、性能、内存占用的一线测量 |
| 生态对照 | 与其他记忆系统的横向比较 |
| 第三方复核 | 对本站任一报告的独立复算（公开报告形态见 §七） |

## 三、证据等级与额度档位

档位按**证据强度**划分，不按贡献者的身份或资历划分。

| 档位 | 证据 | 周期 | 说明 |
|---|---|---|---|
| 🟢 **启航档** | 一条被确认 / 已复现的 issue（含复现步骤与版本） | 周额度 | 够跑通环境、复现问题、验证一个假设 |
| 🟡 **远航档** | 已合并的 PR；或前端共创计划 A 档方向被采纳的改动；或文档/本地化/落点地图类贡献 | 月额度 | 够做一轮完整的对照实验 |
| 🔴 **领航档** | 持续贡献：多条 PR、长期 review、维护某个模块、长期跟进某条研究线；或一篇被收录的社区报告 | 季额度 + 优先续期 | 够支撑一条完整的实验线 |

**三条认定规则**：

1. **同一份贡献不重复计档**：一个 PR 已计远航档，它的 issue 不再单独计启航档。
2. **issue 必须可复现**才计入；纯建议类 issue 不计档，但仍是有效贡献（见贡献者页）。
3. **研究类贡献按证据完整度计档**：只给结论不计档；给出复现脚本 + 结果文件 + 效度威胁，按远航档起计；若结论被采纳进决策台账或上站为社区报告，按领航档计。

## 四、额度是什么、不是什么

**是**：模型推理额度。用来跑测评、跑复现、跑标定、做合成数据与蒸馏实验、以及在开发中调用模型。

**不是**：算力。这笔额度**不能**用来训练或微调模型权重——它不是 GPU 时间。凡涉及权重训练的需要，走 issue 单独讨论，不占本计划额度。

额度只用于本项目相关的开发与研究，不得转售、共享、二次分发或用于对外商业服务。

## 五、申领流程

1. **准备三行**：GitHub 用户名 / issue 或 PR 链接（有几条贴几条）/ 用途一句话 + 打算用的模型。
2. **私信作者**（QQ 群内私信或 issue 里 @）。
3. **核验**：按 §三 的证据规则核定档位，回执里写明档位、周期与额度。
4. **发放**：以**可限额、可停用的独立 key** 发放，并附接入说明（base_url / 可用模型 / 额度周期）。key 只发给申领者本人。

**集中处理**：每期固定一个批次处理窗口，避免私信堆积导致漏办。

## 六、复核、续期与停用

| 环节 | 判据 |
|---|---|
| 续期 | 上一周期内**有拿得出的产出**（PR / 报告 / 实验记录），不看承诺 |
| 降档 | 额度已用但无对应产出；或产出与申报用途不符 |
| 停用 | 转售、共享、外泄 key；大规模爬取；违规内容；用途与申报严重不符 |
| 退出 | 贡献者主动退出，剩余额度作废，已发表内容与署名不受影响 |

复核只看一件事：**给了额度之后有没有跑出东西**。没有产出的解释成本远高于直接降档，因此不做听证。

## 七、社区报告：怎么上站

社区成员产出的研究不需要经过本站改写就能公开，但上站需要满足四条：

1. **独立性明示**：页面标注为第三方独立复核 / 社区报告，与官方技术报告分开陈列，不混排进官方列表。
2. **可复核**：全文数字须由随附复现物（脚本 + 结果文件 + 语料统计口径）可重算；不可复算的数字不采信。
3. **匿名化**：涉及个人与机构的信息须机械脱敏，方法与数字不得因脱敏改动。
4. **留痕**：方法修正过程与效度威胁必须保留。删掉失败与修正的报告不予收录。

**署名**：报告作者署名并链到其 GitHub / 主页；贡献计入贡献者页。
**版面**：社区报告使用站内既有版式语言以保持可读性，但页脚必须声明「非本项目官方发布物」，结论由作者负责。
**不修改内容**：除机械脱敏与链接修正外，本站不改写社区报告的正文、结论与数字。

## 九、边界与红线

## 十、FAQ

**Q：不申领额度就不能贡献吗？**
不能这么说反而更准确：不能。提交 issue、PR、报告都不需要额度，贡献者也都会进贡献者页。额度只是把「想做但没资源跑」的那部分接上。

**Q：只提了 issue 没有代码，能领吗？**
能，走启航档：一条可复现的 issue 就够。但要能复现——带上版本、步骤、预期 vs 实际。

**Q：额度到期没用完会怎样？**
作废，不结转。周期按档位走（周/月/季）。

**Q：可以要求指定模型吗？**
接入说明里会列可用模型。需要计划外的模型，在申领时说明用途，单独评估。

**Q：研究结论归谁？**
归作者。本站只是收录与署名，不改写内容。
