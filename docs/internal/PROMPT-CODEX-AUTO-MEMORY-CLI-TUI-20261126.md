## 1. 目标与交付边界

实现可安装、可交互、可自动化的 Auto Memory CLI/TUI。先启动 DeepSeek Harness（DSH）并加载 Auto Memory 插件，然后从终端连接该运行实例。默认 DSH 模式要把 DSH WebUI「记忆」页签和旁边独立的「白板看板」页签的全部业务内容、状态和可用操作带到终端。每项都走真实插件 API 或由现有后端处理器提供的正式接口。

CLI 是同一个插件包的第二个用户入口。DSH 插件拥有记忆引擎、授权、存储、索引、任务和写入。CLI/TUI 处理调用、数据投影、终端交互与机器输出。首版随 @a9i5k4/dsh-auto-memory 同包发行，复用一份安装、运行实例、模型资产与数据。保留稳定的、与分发方式无关的客户端调用契约，将来可以独立发布轻客户端，或者让独立运行时实现同一契约。数据迁移与运行时拆分另有明确触发条件。

每个 Harness 在自己的模块内适配。DSH 是默认且完整的模式。ZCode 与 Codex 各交付真实适配和各自的能力状态，按可用扩展点接入注入、事件、会话归属、工具调用和权限。对 Cloud Code、gcode、Kimi Code 等此前提到的宿主确认产品与版本，依据公开扩展点和实测决定可交付的能力，逐个接入。记录每个适配的授权与功能缺口。CLI/TUI 与上游记忆服务使用同一份业务契约。

这是一项完整实施任务。实现过程可以按里程碑推进，范围、测试与验收以本任务书及实测得到的覆盖矩阵为准。用户明确允许充分使用时间和模型额度。先测绘，接着施工、回归、打包和实际宿主验收。如果会话支持原生 Goal，以本任务书的完整验收目标启动 Goal。每个里程碑在工作树内记录改动、验证命令、结果及下一步，上下文压缩或会话恢复时回读施工记录继续。需要真实登录、宿主授权或存在外部阻塞的分支单独记录，同期推进可执行分支。验收完成由真实证据决定。

## 4. 架构、调用契约与 live 状态

建议模块边界为 CLI 命令层、TUI 展示层、版本化客户端、插件内公开操作注册层，以及分开的 Harness 适配器。Node/ESM 与当前同包安装优先；技术选型以真实可维护性、终端可用性、依赖体积及跨平台结果佐证。导出一份可供后续独立发行或适配使用的客户端契约。已有插件功能接同一业务执行器，兼容旧 WebUI 和工具入口。以小范围接线组织 lib/index.js，把新契约、传输和投影放独立模块。

- 同一个操作描述驱动发现和分发。描述包括稳定 operation ID、请求与结果 schema、作用域、读写与审批属性、支持状态、契约版本、弃用信息。只公布显式开放且调用方获授权的能力。对已有插件工具验证实际 JSON Schema，完整处理嵌套对象、数组、条件必填和枚举。补充必要的薄接口时复用业务校验、事务与现有状态机，避免通过 HTML、DOM 抓取或读取用户 Markdown 重做后端。
- 运行中的插件报告实际加载版本、构建身份、实例代次与能力清单版本，可和磁盘已安装版本区分。每次命令读取当前状态或按需验证修订号。CLI 通过通用 list/describe/call 发现和运行兼容的新操作，并提供常用友好的别名。加载新版后探测新能力，实例、工作区或契约变化时刷新。未知版本与不受支持的能力有明确原因和下一步。权限、目标路径、CAS 与幂等仍由服务端根据本次身份校验。
- 默认同一台机器已运行的、身份明确的 DSH/插件实例。优先复用 DSH 官方连接和受授权调用机制。给出 profile、workspace/ref 和受验证的 session ID 的选择与失败诊断。多实例选择后保持目标稳定。项目写入需明确目标，拒绝模糊工作区、过期目的地或修订。确认失败或网络超时的写入先核对回执，防止重复提交。只读与写入参数携带最小作用域。
- 单次命令直接请求 live 数据。TUI 先获取快照，再按修订号订阅或按需增量刷新。实现一致性所需的断线/切区/加载旧实例处理。续传支持时正确补齐，版本失效时重取快照。轻量 watch 不调用全量调试、模型、索引重建、注入或其他有副作用动作。将实际状态、策略预览、最近一次投递和最后读到的快照分别标记来源、目标与时效。设置变更对下一次 CLI 请求可见。插件更新沿用宿主支持的加载方式，不要求额外执行一遍 CLI 手工同步。
- 配置、身份或审批只使用官方能力和当前账户授权，本机传输默认保持本机。读取和输出采用最小数据量，配置、诊断和能力清单使用经过审查的字段投影。敏感凭据、会话内容与工作区数据按作用域约束，业务传输和诊断不附带遥测。终端渲染过滤不可信控制序列并保留正文语义。CLI 退出后后端已受理的任务与记忆仍由插件管理。

建议入口示意，最终经测试后统一名称与帮助：

~~~text
 dam                       在 TTY 打开工作台
 dam status [--watch]      快速读取当前工作区的真实状态
 dam doctor [--json]       检查实例、插件、契约、授权范围和依赖
 dam api list|describe|call
 dam memory …             读取、检索、编辑和回读来源
 dam board …              浏览白板与事件并执行授权操作
 dam jobs …               发起、查看和处理受控后台任务
 dam --harness dsh|zcode|codex …
~~~

非交互命令具备一致的 --help、--json 或流式 JSON 输出、退出码和 stderr 诊断。所有示例和 bash/PowerShell 安装命令应在打包后的命令上复验。支持使用终端的普通安全权限调用，异主机接入仍以部署授权为准。

## 5. Harness 适配层

- 定义一个统一适配协议及契约测试，显式约定宿主能力探测、当前 workspace/thread 或 session、事件、可用注入面、工具注册/调用、审批、整理任务执行器、版本与降级。统一业务层依赖该协议。宿主差异仅由各自适配器承担。用一个可测试的适配注册入口支持后续加新 Harness。
- DSH 适配使用原生上下文和工具挂点、正式 HTTP 或等效宿主服务以及真实运行实例，为 CLI 默认提供完整能力。在不引入其他宿主配置的情况下可独立安装和验收。保持现有注入语义，按真实模型请求判档，区分真人输入、工具后续、压缩与恢复事件。诊断预览、实际投递回执和观察缺失分别可见。
- ZCode 适配复核已有 hooks/MCP 与 CLI 模式，选择实际允许的预加载、提交、回合结束时机。证明插件握手、事件触发、挂载工具以及模型确实收到预期上文。把模型侧蒸馏的可执行方式与材料预览区分。如果目标宿主未提供工具内执行器，标注原因并给出支持范围内的执行路径。
- Codex 适配用目标版本实测 MCP stdio 的能力和 Hooks/原生扩展点。覆盖会话开始/恢复、真实输入、结束及压缩事件在该版本的实际支持，保证工作区绑定、工具可见/执行、所支持时机的注入、同轮去重和回执。只有确实接管 Codex 客户端会话或原生后台任务时才采用 App Server，按其公开协议与目标版本验证。保持调用者的审批与 sandbox 边界。
- 不同宿主回调里的会话标识、工作区、功能声明和读写权限要隔离。CLI 切换模式时明确显示当前后端、支持的功能以及降级原因。对缺宿主、未授权、只读安装、MCP 断链、重复或乱序 hook 和工作区切换有可复现负路径。适配状态分清实现、在隔离宿主验证、在真实宿主验证。宿主无实际接入证据时保留缺口与可执行补验步骤。

## 6. 终端设计与使用体验

按需求研究 Codex CLI、Cloud Code CLI、CoCC、switch 和 dsh-tui。先确认名字对应的产品、可用仓库或已安装版本，注明参考内容与许可证。提炼清晰的当前上下文、键盘导航、阅读密度和状态反馈，形成 Auto Memory 自有的终端界面。

- 首屏直接呈现连接状态、工作区、最近事件和可执行入口。主区域有清楚区别的「记忆」和「白板看板」，允许项目切换、搜索和打开详情。宽终端使用列表与详情分栏。窄端允许详情纵向或单屏切换。状态栏只保留有用的实时信息与按键提示。
- 白板提供可浏览的流、泳道、工作流与事件详情视图，依据能力矩阵支持过滤、来源、正文和查验。规则、项目记忆、检查点等长文本支持 Markdown 的标题层级、换行和分页。终端无法承载的复杂画布用等效导航保留数据、关系、筛选及精确操作。危险动作沿用原有预演/审批，显示目标和预期回执。
- 支持快捷键提示、命令搜索、焦点、返回、长任务与取消，支持中文宽字符、emoji 及长 Windows 路径。测试亮暗主题、16 色和真彩、NO_COLOR/非 TTY、有无 Unicode 或 alt-screen 的回退。提示和可访问性交互可用文字独立辨识。高频键盘操作即时更新。用实测终端画面核对文字截断、布局跳动、权限/断线/空态和大数据流畅性。
- 使用 PTY/终端截图验证至少一个窄窗口和一个宽窗口，含超长正文、中文、大量事件以及无色输出。交付可读截图或录屏，写出真实可复现的键盘路径和视觉验收，避免只凭快照宣称可用。

## 7. 施工顺序与验收

1. 核对仓库、可写基线、宿主版本和目标授权。在可见的工作笔记建立完整能力矩阵，记录基线用例和真实连接方式。以隔离数据跑三条竖切链路：状态/设置回读，检索/来源回读，白板事件/检查点。确认开始、失败、停机和重连表现。
2. 建立版本化操作注册与调用契约，交付非交互 CLI 和可实测的工作区、鉴权、错误、读写回执。按矩阵接齐 DSH 功能并实现同包安装。调用注册、TUI 设计、适配器调研可在契约明确后分不同写域并行。业务入口调整与联合回归由统一集成点处理。
3. 完成两页的 TUI 投影和交互，持续用真实后端及干净宿主验证。设置回读与状态刷新验证零重启。可先在隔离 profile 联验后端、CLI、TUI，再合并安排产品宿主一次重载以验证实际加载的版本；按实测报告需要的重载次数，宿主停机与变更另按实际授权执行。
4. 完成 ZCode/Codex 两条适配的版本/能力验收。先按照官方真实契约和可用安装环境走完整调用，遇到不支持的面列明行为和复验点。不能把命令占位、假接口或测试桩当作迁移完成。并行执行宿主互不依赖的验收，归档各线结果。
5. 用实际注册表和公开契约的自动比对护住后续版本。检查新增/删除/变更逐项都有声明，公开接口可定位到真实处理器，权限变化或不兼容参数/返回变更有版本迁移策略。根源是运行时注册与契约。保留原 Web 路径守卫、文档校验，再从干净候选打包实际安装。CI 输出具体操作差异，模型或开发者审核变更。正常发版沿用仓库预检。预演和 npm pack 在隔离目标路径进行，公开提交、推送、发版及覆盖生产 profile 由项目维护者另行执行。

用正常入口真 import、真启动、真调用、回读真实结果。覆盖测试至少钉住这些现象：

- Web 保存状态 → CLI 下一次查询和 watch 可见。CLI 写 → Web/引擎读回相同工作区及版本。未知/过期/并发以及超时后的重试保持真源一致。至少使用两个隔离项目比较串话、跨工作区范围和拒绝不改变内容的指纹。
- 冷暖索引、旧宿主和正在更新的索引分别有真实对照。读到已提交旧快照时标明时效。验证会话授权在派发前和返回前受检查，取消后保留应有的占用语义。蒸馏覆盖正常摘要、重入拒绝、超时归档、归档失败保留活跃原文，以及关闭失败时延后回收。
- 新增一个有实际处理器的公开操作，保持旧 CLI 通用客户端不变即可看到并调用。破坏契约或制造缺项差异时，守卫拿到具体操作名并失败。隔离变异副本需跑到真实调用和结果断言。
- 以合成和隔离记录演示两页所有交互，实际 GUI 与 CLI 对摘要、明细、来源、分页及事件/账本修订一致。核对白板视图从同一事件/维护文档投影，数据来源完整，不偷偷放弃长正文或只保留一条示例路径。
- 只运行一份插件、引擎和写者，CLI 无第二个工作区库或 worker。DSH 未运行、插件缺失、未授权、载入旧构建、多个实例和宿主版本不匹配时能独立诊断。好路径和失败路径给出可复算的测试数、退出码、产物指纹和实机记录。
- 安装产物中有可用的 bin 与契约/运行时依赖，在隔离的 Windows 与可用的其他支持平台验证 PATH/包管理器和启动；校验旧客户端、旧存量记忆、原 WebUI/工单基线。基线已有的失败记录来源，同时列出本次引入的任何回归。日常跑影响集，里程碑跑相关完整回归与真实宿主对照。

## 8. 收口交付

提交可用的实现、覆盖矩阵、安装和命令手册、适配协议与新增宿主指南、打包验证、TUI 画面、运行证据和一份可继续执行的工程记录。按后端/契约、CLI/TUI、DSH/Codex/ZCode 适配分线核验，分别附基线与运行证据。每个已宣布支持的能力必须能从构建产物进入、在正确实例执行、验证结果。尚待宿主或用户许可的验收项标明精确原因、已完成边界和可执行的复验入口。达到完整覆盖与验收后再结束任务。
