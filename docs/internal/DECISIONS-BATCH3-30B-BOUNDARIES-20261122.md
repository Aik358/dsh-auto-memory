## 1. 预算组（D30B-1…4）

### D30B-1 · full / 压缩重建不豁免整帧预算

- 裁定：`injectBudgetChars` 是**整帧总额**，`human_full`、`post_compact`、压缩重建帧同样受它约束，不设豁免通道。
- 依据：A2 裁定「budget = 整帧总额、S8（锁段）优先」；若 full 豁免，`budget` 就不再是可复算的总约束，A2 的计量等式失效。
- 影响：超长 full 帧会被降级/省略，回执必须记录降级项；**不得**为 full 另开预算键。
- 留痕点：整帧预算计算处、full 帧组装入口。

### D30B-2 · 静态纪律并入全局预算；M6 唤回尾独立

- 裁定：静态纪律段（静态注册面）**计入**整帧预算；M6 唤回尾的 **4096 UTF-8 字节**预算**独立**，不进动态快照的总账。
- 依据：静态纪律是注入正文的一部分，进账才使总额可信；M6 尾部有自己的 4096B 上限且现状不进动态账本，为它重算一套预算的改动面与本批无关。
- 影响：回执的「总额」必须写明「静态已计入 / M6 未计入」，避免两个口径混用。
- 留痕点：整帧预算计算处、M6 尾部组装处（标注「独立预算，不计入整帧」）。

### D30B-3 · must 段超额：保留 must + 回执标 overcommit

- 裁定：`user-memory` / `project-notes` 两个 must（锁定）段**永不截断**；超出可用额度时，先压缩/省略其他非锁段，并在回执记 `budgetOvercommit`。
- 依据：R-E 已定「锁段不得截断，超限整帧显式失败」；本项把「失败」细化为「优先挤非锁段 + 显式标 overcommit」，避免一个 must 段就把整帧打死。
- 影响：极端配置下非锁段可能被挤空——这是**已接受**的代价，但必须可见（overcommit 回执）。
- 留痕点：锁段识别处、超额分支、回执字段。

### D30B-4 · 旧 `8000` 不主动迁移

- 裁定：旧散键（含本机显式 `injectBudgetChars=8000`）保留为**只读影子**；只有用户在新「投递策略」模块里**显式保存**后，才写 `deliveryPolicy`。不启动一次性迁移把 8000 改写成新默认。
- 依据：R7 已定「新键 `deliveryPolicy` 为唯一写入源、旧键本批只读影子」；主动迁移会**改变用户当前实际注入量**，属产品行为变更，不在本批授权内。
- 影响：本机行为零变化；设置页需显示「兼容（只读）」而非可编辑双写。
- 留痕点：策略读取处的兼容分支、迁移函数入口（标注「不做一次性迁移」）。

## 2. MEMORY 投递（D30B-5）

### D30B-5 · 两份 MEMORY 继续尾部窗口（不是全量）

- 裁定：`user-memory`（用户级 MEMORY）与 `project-notes`（项目笔记）**继续现有尾部窗口投递**；本批**不改全量**，也不另造第二份来源。
- 依据：改全量会使两份 24K 上限的文件直接把整帧预算吃满，与 D30B-1/D30B-3 叠加后其他内容段长期被挤空；且属产品行为变更，需独立评估，不在本批。
- 影响：`~11.8K 合约`与「尾部窗口 ≠ 全量」的既有描述继续成立；不得在文档/UI 里写「全量」。
- 留痕点：两份记忆的读取与截断处（标注「tail window, not full text — D30B-5」）。

## 7. 追加裁定 · D30B-13（2026-11-22 16:05 Asia/Hong_Kong）

**触发**：执行者按 §8 停手回报 —— 新事件模块缺少旧 `T1` 一行摘要的等价接口；生产精简投递「`[当前事件]`」与「`[最近事件]`（≤3 条）」都依赖它，直接替换会丢内容。

**裁定**：**选 B —— 先补齐等价 T1 API，再与卡片/目录一起迁移。** 不接受「保留旧 T1、只迁卡片与目录」的部分迁移。

**等价定义（写死，实现者不得重新设计）**：语义 = 「`summary` 去掉换行、折叠首尾空白后取首句，限长 `RENDER_LIMITS.T1`(140)；首句为空则用 `name` 截断到 140 兜底」，与旧 `renderT1Pre`（`lib/event-render.js:139`）**逐字节相同**。判据以差分对比为准，不许用文字近似。

**三条理由**：① 等价是机械可证的（只需复用已导出的 `firstSentencePre` 与常量 `T1=140`，`cutPre` 加导出即可），不是产品决策；② 部分迁移会留下两套渲染栈，U3b 接管时要同时养两条路径，正是本批要清的债；③ 卡片与 T1 行同源于 `summary`，若两者归一化不同，同一帧内会出现用户可见的分裂。

**实施与验收**：三个生产调用点（`index.js:10453 / 10988 / 12551` 附近）全覆盖；整体受同一 `useEventView` 开关约束，不允许「一半新一半旧」的运行时状态；验收见任务书 A7（差分逐例相等，含 `T1-SUMMARY-10.` 夹具与四类边界）、A8（限长/兜底变异必须变红）、A9（三处调用点 grep 覆盖）；**做不到逐字节等价即停手回报**。

**代码留痕**：所有相关落点标 `// [DECISION D30B-13 | 2026-11-22 | user ruling] …`。

## 8. 追加裁定 · D30B-14 开关统一（2026-11-22 16:45 Asia/Hong_Kong）

**触发**：批次 A 复核发现 `lib/index.js:10422` 是 `const useEventView = true` —— 源码硬编码，生产无法在设置里关闭；而批次 B 计划用运行期键。两种「off」语义并存会让回滚不可控。用户裁定：**选甲（统一成一个运行期开关）**。

**裁定**：新增嵌套字段 `deliveryPolicy.deliveryMode`，三态：

| 值 | 事件投影（卡片/目录/T1） | 组装 | 等价于 |
|---|---|---|---|
| `legacy` | 旧 `event-render.js` | 旧字符预算 | `decdeccf` 之前 |
| `eventView`（**缺省**） | 新 `event-view.js` | 旧字符预算 | 批次 A HEAD（`c6c32c21`） |
| `units` | 新 `event-view.js` | **按单位组装** | U3b 目标 |

**规则**：

1. **唯一开关**：`useEventView` 必须由该策略派生（`deliveryMode !== 'legacy'`），删除硬编码常量；不允许任何第二处「开关」。
2. **承载位置**：`lib/injection/policy-v2.js` 的严格白名单与枚举（`validatePolicy` 对未知字段抛 `DeliveryPolicyError`）；**不要**改 `resolvePolicy()`（它是逐帧 tier 解析）。保存入口 `lib/index.js:4425`，加载入口 `lib/injection/policy-runtime.js:10`。
3. **非法值**：保存时拒绝；已存储的非法值加载时回落 `eventView` 并留 degradation，不抛未捕获异常。
4. **不新增顶层配置键**（`deliveryPolicy` 已存在，顶层仍 182）。
5. **缺省 = `eventView`**：不改变当前生产行为；`units` 必须由显式配置开启，不在本批默认翻转。

**验收（并入任务书 C0/C0b/C1）**：三态帧 digest 逐字节对照 —— `legacy` == `decdeccf` 基线、`eventView` == 批次 A 基线（3 组场景）、`units` != `eventView`；非法值保存被拒、手写非法值加载回落 `eventView` 且可见 degradation。

**代码留痕**：所有落点标 `// [DECISION D30B-14 | 2026-11-22 | user ruling] …`。
