## 8 · 发版后必做：alpha.5 → alpha.6 差异核对（用户指令 2026-11-05）

> 用户原话：「在发 alpha6 之后，diff 一下 alpha6 和 alpha5 的区别，列出一些需要让社区开发者进行核实的高风险变动点」

### 触发时机

**alpha.6 正式发布之后**（不是发布前）。此时 tag 已存在，diff 基准明确。

### 做法

1. 取基准：`git diff v3.4.0-alpha.5..v3.4.0-alpha.6`（以实际 tag 名为准，发布后回填）
2. **按风险分类**，不是按文件罗列。分类维度见下
3. 产出 `docs/internal/ALPHA6-RISK-REVIEW-<date>.md`，**面向社区开发者**（能被外部理解、不自带内部黑话）
4. 在 GitHub 发一条讨论/issue 邀请社区核实（**本机 token 实测有 admin 权限，可直接发**）

### 高风险变动点的识别维度（本次已知会命中的）

| 维度 | 本次候选项 | 为什么高风险 |
|---|---|---|
| **默认值/行为变更** | 范围选择从「实际整理全部区」变成「只整理当前区」 | 老用户观感变化，可能以为坏了 |
| **用户可感范围缩小** | 同上 | 同上 |
| **新增语义字段但无消费者** | 若 #522 进 alpha.7 则不涉及 | 误导调用方 |
| **弹窗/界面互斥逻辑改动** | 团队优先 + 双版互切（P6） | 两组件可见性裁决，回归风险高 |
| **写入口径变动** | 发布门前置校验（范围不含当前区 ⇒ 拒绝上传） | 会拦住原本能上传的操作 |
| **生成器/构建产物** | `client.js` 生成区若变动 | 换皮肤/自定义构建者受影响 |
| **测试运行器行为** | #536 若改了 run-smoke 边界 | 影响所有下游 fork 的 CI |
| **协议/兼容** | #471 Python worker reload | 影响激活模式用户 |

### 输出格式要求（对社区友好）

每个高风险点写四项：
1. **改了什么**（一句话，无内部黑话）
2. **谁会受影响**（什么配置/什么场景下的用户）
3. **怎么自检**（给出可复算的命令或操作步骤，社区能自己验）
4. **如果觉得不对怎么办**（提 issue / 回滚到 alpha.5 的方法）

### 明确不作为高风险列的

- 纯文档改动、纯注释、纯测试新增
- 内部重构但对外行为完全等价（需给出「等价」的证明，不能只声称）
