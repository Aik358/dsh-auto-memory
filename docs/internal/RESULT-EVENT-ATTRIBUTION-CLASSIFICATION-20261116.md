## 1. 两个必须先说的构造缺陷（都是我自己犯的，一修一识别）

### 1.1 缺陷一：候选截断把 gold 挤出可见集【已修】

首版证据包把候选截断到 **30** 个，而候选池中位数是 **59**。实测后果：

| 项 | v1（截断 30） | v2（全量给） |
|---|---|---|
| attach 类的 gold 在可见候选中 | **91 / 333** | **333 / 333** |
| 被判 create-new 的 attach 类中，gold 根本不可见 | **64 / 81** | 0 |

**v1 的低分基本是假的**：模型被要求从看不见 gold 的候选里选，只能答新建。

同一模型、同一协议，只改候选可见性：

| 指标 | v1（有缺陷） | v2（已修） |
|---|---|---|
| 总体 vs 结构真值 | 0.5595 | **0.8348** |
| mixed-open-closed | 0.2593 | **0.8851** |
| attach-plain | 1.0000 | 1.0000 |

**教训（写进交付）**：把候选截断到 N 个当成工程优化，实际是在**改变任务定义** —— 从「在候选集里找」退化成「在没有答案的集合里猜」。任何 top-K 截断都必须在报告里写明 gold 覆盖率。

### 1.2 缺陷二：closed-boundary 场景是循环论证【已识别，不可修】

场景分类写成「上轮模型标签为 not-applicable ⇒ closed-boundary」，然后拿**结构真值**去评这组。这构成循环：

- 这 27 例中 **27/27 的候选池都有 open 候选**（openRatio > 0）；
- 即：上一轮模型说所有候选都关了、无处可放，但**结构事实是当时有 open 候选**；
- 新一轮模型判 attach-existing（25/27）—— 从结构看**这是对的**，上一轮才是错的；
- 而我用上一轮的错标签当场景定义，再宣布新一轮错。

**处置**：该场景**保留在数据里但在主指标中单列**，并在 §0 同时给出排除该场景的口径。**没有删除任何坏例**。

## 2. 实验设计

| 项 | 做法 |
|---|---|
| 输入 | 记录（at / kind / 正文≤1000字）+ 候选（eventId / 标题 / createdAt / closedAt / **statusAtRecord** / 摘要≤120字） |
| **不提供** | cov12 覆盖率、特征分数、任何排序结果 |
| 候选顺序 | **按 eventId 字典序**，杜绝「排第一即答案」 |
| 模型不可见 | gold 标签、场景标签、split 归属 |
| 候选完整性 | **全量给出**（中位 59 个），已验证 gold 覆盖 333/333 |
| 协议约束 | 记录时刻之后才存在的候选不可选；时间近≠同一件事；主题相似≠同一件事 |
| 模型 | glm-5.3-flash，独立上下文，temperature=0，JSON 强制 |

**证据分层**：L1 时间（原始值，不做「越近越优」暗示）· L2 生命周期（statusAtRecord）· L3 来源（同仓库）· L4 身份（eventId/标题）· L5 文本。

### 3.2 场景分解

### 3.3 时间假设检验

| gold 与记录时间差 | n | vs 结构真值 |
|---|---|---|
| sameDay(0) | 72 | 0.9028 |
| 1-7d | 45 | 0.8444 |
| 8-30d | 20 | 0.9000 |

**结论比 v1 温和**：v1 曾观察到时间越近越差（sameDay 0.43 vs >30d 0.61），v2 修正后差距缩小（0.9028 vs 0.9767）。

## 7. 结论与建议

**能准确归类吗？—— 能。attach 方向 0.8863、create 方向 0.9406、事件定位 0.9665。**

**建议**：

1. **模型可用于归属判定的主体环节**，尤其是判断该不该新建（0.9406）。
2. **不要直接用整体 0.8348 这个数** —— 含一个自相矛盾场景。对外用 **0.8719（排除矛盾场景）** 或直接分类型报。
3. **时间权重仍应放弃**：修正装置后 sameDay 仍非最高，方向与 v1 一致。
4. **本轮最强可迁移经验不是模型分数，而是那个装置缺陷**：任何「从候选中选」的任务，必须报告 gold 覆盖率。v1→v2 的 0.5595→0.8348 全部来自这一个修复。
5. **ambiguous 类仍弱（0.5946）** —— 真正未解的部分，也是下一步唯一值得投入的方向。
6. **不要把 model-reviewed 当 human-reviewed 金标**；本轮进一步证明：closed-boundary 那 27 例就是上轮模型标错、被我当场景定义的证据。
