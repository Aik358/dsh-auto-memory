#### #431 —— 撤回/被取代记忆经 Tier-0 原文目录重新标为 current 注入

- **实测**：`lib/tier0-catalog.js:315` `return { layer, status: 'current', ... }` —— **硬编码 current**，从不解析条目正文里的状态行。`lib/index.js:7670-7673` 把 `s.notesText / s.planText / s.userText / s.logText` 原样喂进去。
- **契约冲突**：`docs/internal/THREE-LAYER-CONTRACT.md:53` 明写「被 `superseded`/`retracted` 的**不出现在目录**（I5）」；而 `tier0-catalog.js:9` 的注释自称「status 一律 current（判定属写入侧，指引层不臆断）」—— 注释与契约直接矛盾，**契约优先**。
- **改点**（3 处，全部在纯函数层）：
  ```
  lib/tier0-catalog.js:304-316  buildRecordPre
    现状：return { layer, status: 'current', date, title, oneLine }
    → 改为：unitLines 先拼原文 → statusOfBodyPre(...) 取状态（最后一个状态行胜出）
            保留 status 与 supersededBy/reason 到记录上；非 current 的**不返回记录**
            （与 I5 同口径：宁可少一条，不注过时结论）
  lib/tier0-catalog.js:339-343  extractSourcePre 的循环
    现状：for (const unitLines of groups) { const rec = buildRecordPre(...) ; if (rec) items.push(rec) else dropped++ }
    → 改为：非 current 单独计数为 statusDropped（不混进 dropped），并在返回体透出
            { items, units, dropped, statusDropped }，供 I7 显式标注
  lib/tier-layer-inject.js:516-520  catalog 构建
    现状：buildTier0CatalogFromTextPre(o.sources, {...})
    → 改为：把 statusDropped 汇总进 degradations（新 code 'tier0-status-filtered'，
            文案：'[降级] 目录层已挡下 N 条非 current 记忆（审计视图仍可见，不进注入）'）
  ```
- **依赖方向**：`tier0-catalog.js` 目前只 import `node:fs`（零内部依赖）。要复用状态解析有两个选择 ——
  - **(a) 直接 import `./note-status.js`**：该模块零 import、纯函数，不存在循环（`wb-sidecar` 那条反向依赖限制不涉及）。**推荐**：与 `tier-layer-inject.js` import `l0-extract.js` 的既有做法同构。
  - (b) 内联复制一份解析（`rules-layer.js` 的既有先例）：多一个漂移源，**不推荐**。
- **波及面**：`buildRecordPre` 仅 `extractSourcePre` 一个调用点；`extractSourcePre` 仅 `buildTier0CatalogFromTextPre` / `buildTier0CatalogPre` 两个出口；后者全仓**零生产调用**（只有测试）。消费方 `composeTieredInjectionPre` 一处。`renderCatalogLinePre` 不改（它已经支持 status 参数）。
- **既有测试影响**：`smoke-test-tier0-catalog.mjs:99/105/111/117` 断言 `status:'current'` —— 全部是**无状态行**的夹具，仍绿。`smoke-test-i5-status-filter.mjs` 全绿（它测的是 hits 侧）。
- **前后端同步**：**无**。`state.tier0Meta` 无前端消费者（`lib/client.js` 对 `tier0Meta` 零命中），只是诊断面。`snapshotTier0Title` 文案不用改。

  - 正路径：带 `<!-- dsh-status: retracted -->` 的单元不出现在 `items`、正文不出现在 `catalog.text`
  - 负路径：①无状态行 ⇒ 仍为 current（向后兼容）；②未知状态值 ⇒ fail closed（挡下）；③`[[current]]` 夹具必须仍全绿（防过度收紧）；④`statusDropped` 计数 == 被挡单元数；⑤降级行文案不含被挡条目正文

#### #422 · 健康缓存过期后显式召回无法发布新探测结果

- **实测**：`lib/index.js:16056` `if (Date.now() - engine._pyRtCacheAt >= 60000) return null` —— **只 return null，不动 `_pyRtCache` 也不动 `_pyRtCacheAt`** ⇒ 过期对象永久占位。`:16036` 的守卫再拒绝 `interpreterOnly` 产出的无-worker 结果发布 ⇒ `preparePythonRecallPre` 的 `current === runtime`（`:16088`）永不成立 ⇒ **每次显式召回都探测、每次都失败，且不会自愈**。
- **改点**：
  ```
  lib/index.js:16053-16065  pythonRuntimeCached
    现状：TTL 到期 → return null（缓存对象留在原地）
    → 改为：到期即摘除引用 + 归零时间戳，再走 identity 校验
            if (Date.now() - engine._pyRtCacheAt >= 60000) { engine._pyRtCache = null; engine._pyRtCacheAt = 0; return null }
  lib/index.js:16035-16039  发布守卫
    现状：if (!(_pyRtCache && identity匹配 && _pyRtCache.worker && !out.worker)) { _pyRtCache = out; _pyRtCacheAt = now }
    → 改为：守卫从「拒绝整条发布」降级为「只保留旧的 worker 字段」，并**无条件刷新 TTL**
            const staleWorker = engine._pyRtCache && engine._pyRtCache.identity === identity
              && engine._pyRtCache.worker && !out.worker
              && engine._pyWorkerVerdict && Date.now() - engine._pyWorkerVerdict.at < 600000
            engine._pyRtCache = staleWorker ? { ...out, worker: engine._pyRtCache.worker } : out
            engine._pyRtCacheAt = Date.now()
  ```
  关键：**过期的 worker 结论不得再挡新结果**（这正是 issue 原话）；但新鲜的 worker 结论（<10min）仍优先，避免弱档探测把刚拿到的 `verified-ok` 抹掉。
- **波及面**：`_pyRtCache` 在 index.js 共 6 处（15927/15934/15959/15961/16036-16037/16054），读方 6 处（15641 `resolveSemanticTier`、16069 `resolvedPythonCommand`、16081/16087 `preparePythonRecallPre`、17485 `python-setup` 路由、17614/17619 `semantic-status` 路由）。**响应体形状不变**。
