## 2. 真实事件汇适配

- `EventStoreLedgerSink(workspaceRoot, storePath)` 以 `fileWithinRoots` 校验真实 storePath 位于当前工作区 `artifacts/`；工作区外、相对路径均拒绝，且不把非法路径的 mkdir 错误当成业务结果。
- `append` 真实调用 `eventStorePre.append(storePath,eventId,{checkpoint,opId:storageOpId})`，写入隔离 store，并从真实事件读回。
- 同一业务 opId 分别使用 `:prepared`、`:committed`、`:failed` 存储键；检查点保留业务 opId、phase、operationDigest 与协议载荷。
- 显式 R4 载荷由真实事件存储生成并持久化 `checkpointId=ckpt_<16hex>`，写前校验唯一性；旧 append 不生成或回填 ID，返回字段保持原样。
- appliedOps 对 R4 保存 `{at,operationDigest,payloadDigest}`；同键同载荷去重，异载荷拒绝；旧数字台账拒绝 `op-payload-unverifiable`。
- 台账淘汰后，从带业务 opId+phase+digest 的检查点恢复；阶段 idemKey 用于在已保留的真实检查点上确认同载荷身份。
- `listCheckpoints` 支持事件 ID 或业务 opId 查询，读取真实事件；旧记录给 `checkpointId:null`、`legacyCheckpointKey`、`identityMode:'legacy-derived'`，不伪造持久化 ID。
- prepared/committed/failed 载荷只保留 changeSet、revision、引用与错误信息，不新增未变全文拷贝。
