## 二、为什么不能直接 apply（实测）

`git apply --check --verbose --exclude="*.png"`（对本分支）逐文件结果：

```
Checking patch lib/client.js...                 → error: patch does not apply
Checking patch skins/iter5/legacy-native-overlays.css... → OK
Checking patch skins/iter5/native-map.js...      → OK
Checking patch skins/iter5/native-operations.css... → OK
Checking patch skins/legacy/iter5-325.js.frozen...  → OK
Checking patch tests/smoke/smoke-test-iter5-skin.mjs → error: patch does not apply
```

**读法（关键）**：`client.js` 不适用**不是障碍**——它正是**生成区产物**（现树生成区边界：`ITER5-GENERATED:BEGIN` L10392 → `:END` L12778；legacy 段 L10386–L10383）。
按生成器自身纪律（`build-iter5-skin.mjs` L938 原文）：「**是修复就先搬进生成源（skins/legacy/iter5-325.js.frozen 或 skins/iter5/*）再重跑**」。
⇒ 正解 = **移植生成源 + 重跑生成器**，`client.js` 由生成器产出，**不手改生成区**。

## 四、执行顺序（每步含闸门）

```
0. 前置基线（已实测绿）
   node tools/build-iter5-skin.mjs --check --strict   → SYNC-OK
   node tools/run-smoke.mjs ...                       → 331 PASS / 0 FAIL / 0 TIMEOUT

1. 备份：copy lib/client.js + skins/iter5/* + skins/legacy/*.frozen 到 artifacts/backup/

2. 逐块移植 B1–B3（生成源；仅替换函数体，禁止整块替换式重构）
   ★红线判据：只动 native-map.js 的布局/图组件函数与两个 CSS 的对应选择器；
     不触碰生成区、不触碰无关函数。

3. 移植 B4（冻结源；注意 .frozen 是 **LF**，不是 CRLF）

4. 移植 B7 测试（并把其内部断言接到本仓夹具口径）

5. 重跑生成器（唯一合法序列：--check 绿 → 无 flag 实跑）
   node tools/build-iter5-skin.mjs --check --strict   → 必须 SYNC-OK
   node tools/build-iter5-skin.mjs                    → 写盘（生成 client.js 生成区）

6. 运行时守卫（硬性规则：静态守卫不足以证明「能加载」）
   node --check lib/client.js
   node tests/smoke/<真执行 __ModuleLoader__.load({factory}) 的守卫套件>

7. 重钉 iter5 基线（用户裁定 2026-10-10：重钉以**套件打印的 actual** 为准）
   node tests/smoke/smoke-test-iter5-skin.mjs  → 取 actual → 填回

8. 全量回归 → 必须回到 0 FAIL（基线 331；新套件 +1 ⇒ 332）

9. 收尾：EOL 检查（lib 树纯 CRLF / .frozen 纯 LF）、账本、白板
```

## 五、本方案不做的事（防越界）

- ❌ 不 `git merge` / 不整块 apply PR；不引入上游 commit 历史。
- ❌ 不手改 `lib/client.js` 生成区（会被下次生成覆盖，且 `--check` 判 stale）。
- ❌ 不照抄上游基线锁值（R89 是**上游**的；本机基线号与值须自行推进）。
- ❌ 不移植 PNG/README；不引入任何第三方依赖。
