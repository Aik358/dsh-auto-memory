# R4 P4-1 读侧接线结果 · 2026-11-11

## 结论与边界

后端选择器与任务书要求的六个读侧已接线，**默认关闭**，保留 legacy 双读；本报告表示源码与隔离测试完成，等待 Lead 复核与提交。

- 开关：`ledgerDocEnabled:false`；启用还要求 handoff 开启。默认配置下不构造新读侧。
- `LedgerDocReadSide` 按 documentId/eventIds/current manifest 选择；没有显式绑定的多文档返回 `document-selection-required`，不按最近事件、mtime 或 active 事件猜测。
- 每次读取从实际文档全文重算 revision；chunk 身份为 `documentId + sectionId + revision`。
- 失败通过 `readErrors`、检索中的“维护文档读取失败”及选择状态报告，不以空文档伪装成功。
- 只修改 `lib/index.js` 与 `lib/ledger-doc/`，以及本批测试、契约和共享基线；未修改 `lib/event-store.js`、`lib/event-write.js`、`lib/client.js`、`skins/`。
- 未执行真实记忆迁移/删除、未启用生产读侧、未启动或重启宿主、未跑全仓。

## 实现

| 路径 | 接线 |
|---|---|
| 动态注入 | `_doRefresh` 读取当前维护文档，保存 id/revision；同进程 committed readback 更新当前文本。 |
| 跨工作区接续 | `buildContinueCarry` 使用源会话的 `resolvePathsForSession` 路径，返回 maintenanceDocument 的 id/revision/path/relativePath。 |
| `scope=all/handoff` | 维护文档 chunk 进入 corpus 与 L0，按查询词过滤；`ledger-doc:` 身份支持展开。 |
| 语义检索 | chunk 进入语义来源及 rank snapshot，revision 改变会改变身份；真实 recall 的语义路径已执行。 |
| 事件下钻 | 通过事件 members 与 checkpoint 显式绑定读当前关联文档；无绑定明确报告；同一文档不重复输出。 |
| 指纹 | `handoffMaterialStamp` 启用时调用 `HandoffMaterialStamp.readStamp()`，内容 revision 参与指纹。 |

`LedgerDocSystem` 新增 `readDocuments`、`readSide`、`lastCommittedDocument` 与 `readOnly` 生命周期支持。只读启动不预热 stamp、不创建写入目录；真实装配显式传入隔离 `storePath`。
统一导出新增 `LedgerDocReadSide` 和 `ledgerDocumentChunks`；`lib/ledger-doc/index.js` 实测 43 个导出（含 P4-0 的 `EventStoreLedgerSink`）。契约文档已补读侧 API。
