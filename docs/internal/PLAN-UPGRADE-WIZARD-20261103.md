## 2 · 触发时机

```text
会话挂载 → 3s 延迟（避开首屏抖动）
  → 闸①该工作区 legacy === true
  → 闸②本会话未点「本次不再提示」
  → 闸③距上次 snooze ≥ 24h 或 snooze 次数 < 3
  → 渲染第 1 页
```

**为什么延迟 3s**：改成「打开就弹」打断的是正经干活；延迟 + 仅在空闲时弹，兼顾发现率与打扰。

## 3.6 · 草案信道：为什么必须「写文件」而不是「返回 JSON 文本」

**你的建议可行，且是防污染的正解**，但信道选法有讲究：

| 方案 | 可行性 | 问题 |
|---|---|---|
| A. 子代理**把草案 JSON 写进指定文件**（`<runId>/draft/<wsKey>.json`），引擎校验后落盘 | ✅ **选定** | 需要允许 bash 写**草案目录**（非记忆库），边界清晰 |
| B. 子代理在最终消息里返回 JSON，引擎解析 | 🟡 回退通道 | 长草案会被截断；常裹 ```json 围栏或加解释，解析脆弱 |
| C. 继续用 `memory_event` 当结构化通道 | ❌ | 被 `resolvePaths` 绑死在中枢（#520 实证） |

**选定 A + B 回退**：
1. 引擎在 `~/.dsh/memory/upgrade-runs/<runId>/draft/` 建目录，写 `MANIFEST.json`（清单+白名单）；
2. 提示词要求：**只允许写该目录**，禁止写任何记忆库文件（`event-store.json` / `MEMORY.md` / `PLAN.md`）；
3. 引擎读草案 → **校验（§3.7）** → 校验通过才落盘 → 渲染白板 → 回执；
4. 草案文件即断点续传依据：已 `validated` 的区不重跑。

**边界纪律（与 P6 不冲突）**：`win_bash` 从「严禁写」细化成「**只许写 upgrade-runs 草案目录**」，越界即判失败。这样既不放弃结构化输出的好处，也不给"直写记忆库"留口子。

## 3.7 · 门控：十道闸，挡「烂模型污染白板」

草案先过闸，**任何一闸不过 ⇒ 该区不落盘、整区回滚**（fail closed），并把具体错误回给子代理重试（上限 2 次）。

**失败策略（已裁定）**：某区连续 2 次不过 ⇒ 标 `failed` 并**跳过该区继续下一区**，不中断整批；全部结束后给**汇总报警**（失败区列表 + 每区最后一次拒因 + 「单区重试」入口）。理由：一个坏区不得卡死整批；但必须让用户看见，不能静默跳过。

| # | 闸 | 判据 | 不过的处置 |
|---|---|---|---|
| 1 | **Schema** | 严格字段白名单；未知字段、类型错、超长 ⇒ 拒 | 回错误 + 重试 |
| 2 | **必填** | `name≤80`、`summary≤400`、`sections{goal,doing,deadend,next}` 四段非空、`members≥1`、`rationale` 非空 | 拒 |
| 3 | **溯源真实性**（最狠的一道） | 每个 `rel` 必须是 manifest 内真实存在的文件；`quoteRef` 必须能在该文件中**子串命中** | 拒（专挡幻觉引用） |
| 4 | **守恒** | 草案 `selfCheck{events,checkpoints,coveredLogs}` 与引擎**重算值**一致；`coveredLogs` ≥ 日志数的 80% | 拒 |
| 5 | **形态** | 单检查点事件占比 ≤ 30%；平均 members ≥ 1；事件数在 `[1, 日志数×1.5+5]` | 拒 |
| 6 | **去重** | 事件名重复、`idemKey` 重复、与既有事件重名 ⇒ 拒或标跳过 | 拒/跳过 |
| 7 | **卫生** | 复用 `sanitizeForWrite`：乱码/复读/重复行/base64/HTML 注入；单条 ≤ 2000 字 | 拒 |
| 8 | **渲染门** | 白板渲染必须非空、含预期节、锚点集合不丢（M1 保护门） | 该区回滚到备份 |
| 9 | **写盘门** | 落盘走 `writeStorePre`（原子）+ 库锁 `withEventStoreLockPre`；schema 版本不符 ⇒ 拒 | 回滚 |
| 10 | **一致性（默认关闭 · 高级选项）** | 同一区跑两次草案，事件名集合 Jaccard ≥ 0.6 才落盘 | 标 `needs-review` |

**关于闸 10**：默认**关闭**（额度敏感型用户占多数，双跑=费用×2）。设置页提供「高质量模式（费用约 ×2）」开关；开启后闸 10 生效，且 UI 明示费用翻倍。

**打分印象**：闸 3（溯源）+ 闸 4（自检重算）能把"模型编造引用"和"模型瞎报数字"同时挡掉，是本方案的核心防线——**不依赖闸 10 也能挡住绝大部分污染**。
**低成本兜底**：闸 1–7 全部是纯函数、零 LLM，可在 P1 先落地并单测。

## 3.8 · 只检测不整理（Dry-run）模式

在第 1 页给「先只看体量」入口，行为：

1. 只读扫描（`upgrade-workspaces` + `upgrade-status`），**零 LLM、零写盘**；
2. 展示：每区 PLAN/日志字符数、预计 token、按三渠道的费用区间、预计耗时、检测到的缺项；
3. 附「只读检测报告」可导出（Markdown），供用户决定是否真跑；
4. **不产生** `upgrade-state` 的 running 记录，不触发写闸。

价值：降低劝退率；也让"先评估再付钱"成为默认路径。

## 5 · 迁移期间的 memory 渠道

| 通道 | 迁移中行为 | 理由 |
|---|---|---|
| 用户侧写工具（`memory_log/memory_note/memory_event`） | **拒绝** + 「正在运行升级程序，请稍后补写」 | 避免写进正在被重渲染/合并的文件 |
| 迁移自身受控通道 | 不受影响 | 否则自锁 |
| 只读（`memory_recall/read/status`） | 正常可用 | 查历史不该被挡 |

**补写队列（不得静默丢）**：被拒条目落 `pending-writes/<runId>/<ts>.json`，迁移结束或下次启动自动 replay，完成回执写「补写 N 条」。
依据：项目规约「不得静默永久丢弃已写入数据」（#489 同族教训）。
