## 一、进版本主题的判据（本次确立）

**进 3.3 主题** ⇔ 满足「**需要一次用户可感知的一次性迁移**」。

理由：这类改动**单独发布要用户迁一次**，若拆成多个小版本，用户要**反复经历迁移窗口**（每次都是功能短暂不可用 / 数据看似消失）。
**捆绑到一个版本 ⇒ 用户只经历一次**。

**不进主题** ⇔ 无功能收益的重构、纯守卫强度、纯维护性建议 —— 它们不产生「迁移事件」，可以随时零散做，不该占用版本主题的迁移预算。

## 二、3.3 版本主题候选（需一次性迁移）

### C-01 · #201 语义向量策略 v2（Python 侧）

**现状（代码证据）**：

```python
# python/worker_semantic_v1.py
L305: real = hasattr(self.embedder, 'encode_ids')  # tokenizer-id path
L311: # tokenizer directly (chunk_record_token_ids -> build_doc_ids
L336: encode_items.append(self.embedder.build_doc_ids(ids))
L359: vectors = self.embedder.encode_ids(encode_items)
```

**缺陷（两条叠加）**：

| # | 问题 | 后果 |
|---|---|---|
| ① | `build_doc_ids` 先加特殊 token，`encode_ids` 内部再次包装 | **双重 `[CLS]/[SEP]` 包装** ⇒ 向量语义偏移（模型见到的形态与索引时不一致） |
| ② | 512 正文分块先被裁短，下一块仍从**原边界**继续 | 满块正文**尾部 token 永久丢失**，且未移入下一块 |

**收益**：
- 语义检索**准确率实质提升**（这是插件核心功能之一）
- 满块文档**不再丢内容**

**代价 / 迁移窗口**：
- 需把 `CHUNK_POLICY_VERSION` 升 v2 ⇒ **既有全部向量判 stale**
- 触发**全量重嵌入**；BGE-M3 在 CPU 上为**分钟级**
- 重嵌入期间**语义检索拒服务**
- **JS 档（lexical）零影响** —— 影响面仅限启用 Python 语义的用户

**前置条件**：
1. 决定「重嵌入是阻塞式还是后台渐进式」——**渐进式可把窗口从「分钟级不可用」降到「降级服务」**，强烈建议先定这个；
2. 给出用户可见的进度/告知（避免被误判为"语义检索坏了"）；
3. 明确回滚路径（保留旧向量 or 可重建）。

**工程量**：中等（worker 两处 + 分块预算 + 版本迁移 + 回归）。

### C-02 · #179 工作区目录键物理身份化

**现状（代码证据）**：

```js
// lib/index.js L3131-3134
wsKey(ws) {
  if (!ws) return 'default'
  return '--' + String(ws).replace(/[\\/:*?"<>|]/g, '-') + '--'
}
```

**缺陷**：分隔符与连字符被折叠为同值 ⇒ `C:\work\a-b` 与 `C:\work\a\b` 生成**同一个目录键**，两个工作区共用一份记忆/白板/卡片身份。

**收益（要说实话）**：
- 消除**碰撞**。
- ⚠️ **无任何新增功能**；只对「同时存在 `a-b` 与 `a/b` 两个工作区」的用户有实际收益（概率低）。

**代价 / 迁移窗口**：
- 改键 = **换目录名**。现有记忆位于 `--D--dsh-auto-memory--/`，换算法后变 `a3f2…/`
- ⇒ **旧目录不会自动认领，用户会看到「记忆全没了」**
- ⇒ 必须做**旧键迁移 + 碰撞提示**，不能只换算法

**前置条件（必须先定的产品决策）**：
1. **升级时机**（随 3.3 一次性做）；
2. **迁移交互**：静默搬迁 / 提示确认 / 碰撞时如何提示。

**工程量**：中等（键算法 + 迁移 + 回归），但**风险在于迁移本身**（fail-closed 会表现为数据消失，需 fail-soft + 明确告知）。

### 为什么 C-01 与 C-02 捆绑

两者的共同点**不是技术**，而是**都会造成一次「用户可感知的数据/服务短暂异常」**：

| | 用户看到什么 | 若分开发布 |
|---|---|---|
| C-01 #201 | 语义检索短暂不可用（重嵌入中） | 迁 2 次 |
| C-02 #179 | 记忆目录更换（看似"消失"再回来） | 各自一次 |

⇒ **合并到一个 3.3，用户只经历一次**。这也是本文件「进主题判据」的直接应用。
