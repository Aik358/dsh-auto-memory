## §4 ★ 诚实标注规则（**本轮最重要的一条**）

**背景**：v1 对**未实现的「团队」能力**用了完成态展示（「当前会话已登录」「actor 不可伪造」），而 `lib/client.js` 中 `团队`/`登录`/`不可伪造`/`防篡改` **全部 = 0 次**，且 `docs/proposal/index.html` 自己把「团队共享记忆」列为**里程碑 3**。这会被甲方当成虚假承诺。

### 硬规则

1. **「团队」L1 整体标注**：进入该 L1 时，**首屏顶部必须有醒目声明**：当前版本未实现、属规划中方向；不得出现「已登录」「已启用」等完成态措辞
2. **两级标注视觉可分**：已实现 = 正常样式；规划中 = 统一徽标（建议 `规划中` 胶囊）+ 降饱和 + 顶部条
3. **禁止清单**（出现即判失败）：
   - 完成态措辞用于未实现能力（如「已登录」「保证」「不可伪造」）
   - 全文件 `规划` / `里程碑` / `未实现` 计数为 0（v1 的问题）
4. **必须有「已实现 vs 规划中」总览**：在设置或在团队页，用一张对照表让客户一眼看清边界
5. **保留 v1 已有的正确做法**：v1 对「不做端到端加密」「审计是追溯级不是防篡改级」的诚信披露是对的，**照搬不丢**

### 5.2 工程硬约束
- **单文件 HTML**，内联 CSS/JS，**零外部依赖**（不得有任何 `http(s)://` 资源引用）

- `lang="zh-CN"`；深色默认、可切浅色；响应式（主视口 ≥1280）

- **无网络请求**；交互全部内置假数据
- 交互必须**真实可点**（导航切换、抽屉开合、模态、开关翻面、筛选）
