⇒ 结论：**不是需要再重构，而是第一轮验收口径错**——只验了结构与标签，没验真实输入下的行为。

因此不需要"第二次重构"。需要的是：**同一批模块的验收升级 + 剩余接线**。

## 二、分工原则

| 角色 | 承担 | 不承担 |
|---|---|---|
| GPT（外部） | 方案设计、缺陷定位、逐阶段 diff 复审、测试用例设计 | 直接改本仓文件、真实宿主验证、全量回归、发版 |
| Lead（本机） | 按方案施工、逐条复现缺陷、本地跑回归、真实 HOST、提交 | 把契约级裁定推给外部 |

理由（必须成立，不是保守）：

1. **真实 HOST / 全量回归 / 修复后副作用只能在有运行环境的机器上完成**；外部无法执行，也无法自证。
2. **契约级变更（FM 预算、NT 定稿协议、PJ 模式语义）属于裁定**，需用户拍板，不能代做。
3. **每次改动都要过 41 导出锁 / CRLF / 抽取式测试兼容**，这些是本地约束，外部不可见。
4. 但 GPT 的方案与复审质量已被本次验证（三条核心缺陷全部属实），**应继续用于设计与复审**。

## 三、验收口径升级（本批核心变更）

旧口径：结构/标签/计数。
新口径：**必须真实输入 + 真实执行 + 可量化差异**，每条至少一条负路径。

1. 断言对象不得是"源码是否含某字符串"；只能作为额外守卫，不能作为 PASS 依据。
2. 每个公共模块必须有一条"真实输入 → 真实输出 → 量化比对"的验收（如 F14：cap=1 时 `text.length<=1` 或显式失败）。
3. 每条验收必须含负路径，且负路径要能真正失败（变异验证：去掉修复必红）。
4. 涉及预算/上限的验收，必须同时给出**字符数与 UTF-8 字节数**。
5. 涉及档位/身份的验收，必须覆盖**全部生产档位 × 边界输入**，不能抽样代替全量。
