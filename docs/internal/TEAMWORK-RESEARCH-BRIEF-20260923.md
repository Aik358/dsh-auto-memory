3. **待解疑问**：「同步问题对于语义库的向量编排也值得去考虑。」

## 三·B、向量层实机取证（主线程实测，**直接决定"实时同步难不难"的答案形态**）

> 这几条是本轮**新取到的一手事实**，A/B 报告必须以此为前提，不得凭空假设"向量在云端某处"。

| 事实 | 证据 |
|---|---|
| **向量确实落盘**，为 JSON 工件：`~/.dsh/memory/semantic/vectors-<16hex>.json`（当前 5 个，最大 2.29 MB） | 实机 `Get-ChildItem` 列出 5 个 `vectors-*.json` |
| 工件结构：`{schemaVersion, namespace, policyVersion, identity{11键}, workspaceRef, scope:'Workspace', memoryIndexVersion, chunks[104], vectors[104]}` | 直接解析 `vectors-c6eef0495385c669.json` |
| **`identity` 就是"向量空间身份"**：`provider='bge-m3-onnx-int8-pre-v1'`、`model='bge-m3-int8'`、`modelRevision`、**`dimension=1024`**、`normalization='l2_normalize'`、`dtype='int8-dynamic-onnx'`、`chunkPolicyVersion='m7_chunk_pre_v1'`、`configHash` | 同上 |
| **向量复用已是内容寻址**：`sha256Hex(it.l0)` → 命中则直接复用，**跨 id 复用**（`via:'hash'`）且**批内同 hash 只嵌入一次** | `lib/l0-index.js:154-166`（`vecByHash` / `resolveReuse`）、`:168-177`（`needEmbed` 去重）、`:178`（注释「不变更新的真实输入数 = 0」） |
| 索引文件名按 **workspaceKey** 的 sha256[:12] 生成 | `lib/l0-index-sync.js:46-59`（`L0_INDEX_WS_HASH_CHARS=12`、`l0IndexFileNamePre`） |
| 嵌入模型为 **bge-m3 int8 ONNX，1024 维**；另有 e5-small 清单与 q8 manifest | `lib/semantic-js.js:430-435`、identity 字段 |
| 语义向量文件**按 workspace 分**（`scope:'Workspace'` + `workspaceRef`） | 同上 |

**对用户疑问的直接含义（待 A/B 验证）**：
- 「向量编码难」这一担忧，在本仓**已有两道现成防线**：① 内容寻址 hash 复用（同文本永不重算）② 向量空间身份（换模型/换维度/换 chunk 策略会造成身份不匹配 ⇒ 天然隔离，不会静默混用）。
- 因此真正待答的**不是**"如何避免重复编码"，而是：**跨成员共享时，向量工件该共享还是各端本地重算？** 这正好是 B 报告 Q4 的核心。

## 四、必须回答的问题清单（供 A/B 报告覆盖）

**A（竞品与差异化）**
- A1 大厂/竞品在「团队共享 AI 记忆」上到底做了哪些？（Claude / ChatGPT / Cursor / Copilot / Notion / Glean / Rovo / Mem0 / Zep / Letta / Cognee …）
- A2 它们**是否已支持团队共享**？多用户身份、权限、冲突、向量同步各自怎么处理？
- A3 commit / 工作流 / RAG 三类，**对标的最小可用形态**各是什么？（不做成卖点，但必须有）
- A4 本仓哪些能力**找不到等价物**？（这是「人无我有」的唯一判据：**没找到等价物**，而非「我觉得很特别」）
- A5 每条亮点必须回答：**为什么大厂做不了/没做**（要有真实技术或产品原因，不接受「他们没想到」）

**B（同步 × 向量）**
- B1 实时同步对向量编码难在哪？**逐条量化**（增量 embedding 成本公式、模型版本漂移、chunking 变更、写入放大、端侧算力）
- B2 真正的瓶颈是「嵌入计算」还是「冲突一致性」？
- B3 业界增量/近实时向量同步怎么做？（脏标记、micro-batch、语义去重、向量库 upsert 一致性）
- B4 **「写立即可见（词法兜底）+ 秒~分钟级向量补齐」是否已是业界事实标准？** 若是，则「实时同步」的真实含义要重新定义
- B5 记忆条目的同步：CRDT / OT / 服务端权威，哪个合适？为什么？
- B6 本仓「只标状态不删」+「两阶段迁移」能否直接当同步原语？代价是什么？
- B7 冲突场景表：同条并发改 / 一人删一人改 / 离线重连
- B8 阿里云为主、多云端兼容：2–3 个候选架构 + 分阶段路线 + **「实时同步」对应到哪个具体指标**
