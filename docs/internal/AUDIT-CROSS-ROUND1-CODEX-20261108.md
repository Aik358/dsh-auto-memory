### B6-3 为什么是致命的

**原 S0 方案（只把摘要换成一行指针）会制造一个比现状更糟的结果**：

- 现状：摘要 13,997 字符，项目层 58 条**内容在场**（虽然混在「用户级硬性约束」标题下）
- S0 后：43 字符指针，模型按指针去 `memory_rules op=list` 取全文 ⇒ **只拿到 user 层 65 条，project 层 58 条彻底拿不到**

**修法**：`op=list` 必须加 `layer` 参数（`all` / `user` / `project`，默认 `all`），并在指针文案里写明两层都有。**这是 S0 的前置条件。**

### 4.1 唯一要纠的一条（B4 的 token 算术）

Codex 写：

> 沿用任务书「44K 字符约为 22K token」的假设，每百万投递 2–3 次应是 **44–66K token，即 4.4%–6.6%**

- **乘数它算对了**（我原文「66–132K」是错的，22K×2=44K）
- **但它沿用了「44K 字符 ≈ 22K token」（2:1）这个比例** —— 对中文是错的。中文混排约 1 字符 ≈ 0.6–1 token，
  44K 字符约 **26–44K token** ⇒ 真实占比 **5.2–13.2%**，不是 4.4–6.6%

> 结论：**双方都把「字符→token」的换算当成了已知量，实际它没有 tokenizer 实测支撑。这一项应标记为「待实测」。**
