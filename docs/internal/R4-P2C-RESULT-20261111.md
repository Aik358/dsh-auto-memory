## 新指纹实现

lib/ledger-doc/material-stamp.js 导出 HandoffMaterialStamp、MATERIAL_STAMP_SCHEMA、MATERIAL_INVALIDATION_SCHEMA、MaterialInvalidationBus、publishCommittedDocument。

- 构造默认 enabled:false；只有 enabled:true 才读盘。关闭时 read() 返回 r4-material-stamp-disabled，readStamp() 返回空串。
- 只接受工作区 artifacts 内的绝对隔离 handoff 根；planPath、eventsPath 也必须在该 handoff 根内。默认路径分别是 PLAN.md 与 event-store.json。
- 使用既有 fileWithinRoots/lstat/realpath 做物理边界检查，不跟随越界文件/目录链接；没有 os.tmpdir()。
- 每次 read() 从真源读取，不使用内容缓存。结构化对象含 schema、plan、legacyLatest、documents、events、readErrors，并补充 rootState 与 documentsState 使缺失/空目录/错误可区分。
- 最终 stamp 是 SHA-256(canonicalize(material))，字符串格式 sha256:<64hex>。未改变任何现有 handoffMaterialStamp 返回值。
- PLAN 与最新旧账本均计算内容 revision；旧账本沿用 latestLedgerNamePre 的正则和 mtime 最大、平手字典序靠后的选择口径。
- documents/ 中全部合法 .md 文件名按 documentId 排序，逐份读取当前正文，校验固定协议结构并重算 revision。manifest 不参与身份判定；文档头 revision 与正文摘要不一致时进 readErrors。
- 事件按 id 稳定排序；每项投影恰好包含 id/name/summary/status/sections/updatedAt/checkpointCount/outcome，checkpointCount 可从实际 checkpoints 长度得出。损坏 JSON、缺失文件和空数组各自可区分。
- readErrors 含 source、稳定错误 code 及 documentId/name 身份（如有），不写入正文、绝对路径或密钥。ok:true 表示完成了一次带状态的扫描；complete:false 表示扫描含读取错误，不把错误静默伪装成稳定旧指纹。

## 失效协议

失效信号为独立、同步、进程内提示，不是新的文档真源，也不跨进程共享：

1. 写者完成文档原子写并成功读回后，调用 publishCommittedDocument(bus, handoffDir, writeResult)。helper 只接受 ok:true 且 noop:false 的实际提交结果。
2. 信号包含 schema=r4-material-invalidation-v1、进程 epoch、递增 sequence、每工作区 handoffVersion、规范化 handoffKey、documentId、已读回 revision、可选 opId 和 committed:true。
3. 订阅用 subscribe(handoffDir, listener)，仅接收相同规范化 handoff 根的通知；返回幂等退订函数。非法 documentId/revision 在发布前拒绝。
4. 某个 listener 抛错时继续通知其余 listener，并在返回值 listenerErrors 中暴露异常消息；这不是门控成功信号，不用空 catch 隐藏。
5. 读侧收到通知后应重取 HandoffMaterialStamp.read()。read() 总是从磁盘重算 revision，故其他进程写入即使没有本进程信号也可被下一次读取发现；stamp 本身不纳入进程内版本号。
6. 现有 P1 document-store.js 没有失效回调。本批次只提供独立 helper 和测试，不声称 store 已自动发信号。未来 P3 应在文档 committed 且读回后调用；事件 committed 完成通知属于 P3 的另一阶段，不得混作文档已落盘证明。

## 调试中修正的夹具问题

- 初版夹具把事件库放在 handoff 根外，构造器正确拒绝 → 改为每个合成工作区自己的 handoff/event-store.json。
- 直接改文档正文而未更新文档头 revision，读侧正确返回 MATERIAL_DOCUMENT_REVISION_MISMATCH → 正常写入夹具同步重算元数据；revision 损坏仍保留为负路径。
- 失败测试曾留下旧夹具 → 只对本套件两个专属目录做重建，验证重复执行同计数。
- 纯改名不更新内部 documentId 属于损坏，不是合法重命名 → 补充身份与 revision 同步后验证合法重命名。
