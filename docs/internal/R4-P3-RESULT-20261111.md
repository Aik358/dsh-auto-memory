## 2. 实现

### Phase 0 → 3

- Phase 0 通过 locked-store 读取并校验 documentId、eventIds、opId、expectedRevision、完整 changeSet 与标题/固定结构。可预期错误不追加事件；noop 不产生 WAL。
- 候选 revision 由完整规范化候选计算。operationDigest 绑定协议规定的 documentId、expectedRevision、eventIds、candidateRevision 与 changeSetDigest。
- Phase 1 逐事件追加 prepared；持久化业务 opId、完整区域变更、基线/目标 revision、updatedAt 与摘要，不复制未变整篇文档。
- 存储键分别为 `opId:prepared`、`opId:committed`、`opId:failed`；业务 opId 在检查点中保持共享。
- Phase 2 重新取文档锁、重读、复核 CAS，用 P1 原子写并复核 candidateRevision/读回正文。
- Phase 3 文档成功则逐事件 committed；意外写失败则 failed，引用实际 preparedCheckpointId，记录实际 revision、错误码与 changeSet。
- 多事件不声称原子事务；prepared/committed 部分成功逐事件返回。committed 失败不回滚正文；索引/缓存失败分别标 `indexStale` / `cacheStale`。

### 合成事件汇与恢复

- 事件汇在独立 JSON 中原子持久化检查点与 appliedOps，支持按 eventId/phase 故障注入、真实 checkpointId 和跨实例读取。
- appliedOps 项含时间戳、operationDigest 与阶段载荷摘要；容量淘汰后从检查点恢复证据；旧数字台账明确返回 `op-payload-unverifiable`。
- 同 opId/phase/载荷重放去重；不同载荷或摘要不一致拒绝 `op-payload-mismatch`。
- 磁盘仍为基线时，prepared 可恢复并逐字节构造目标；磁盘已是目标时仅补缺失 committed，不重写正文。
- 有 failed 终态的操作不自动重试覆盖；缺 prepared、缺关联事件、缺变更区域和摘要不一致均拒绝。

## 3. 真执行结果

命令：`node tests/smoke/smoke-test-r4-wal.mjs`。

**最终连续三次：每次 PASS 25 / FAIL 0；变异 CAUGHT 4 / MISSED 0；RESTORED GREEN。**

| 分组 | 实测覆盖 |
|---|---|
| 正常路径 | 单事件完整 Phase 0→1→2→3；两事件同一 opId、各 prepared+committed、文档写恰 1 次；noop 零新增 WAL |
| Phase 0 | 非法 ID、重复区域/非法结构、可预期 CAS 均文档不变、事件 +0，并有合法正向对照 |
| Phase 1 | 首个 prepared 失败 abort；第二个 prepared 失败保留部分状态，文档不变 |
| Phase 2 | 另一写者先提交后返回 document-version-conflict，不覆盖赢家 |
| 原子写异常 | rename 前失败残留旧 revision；rename 后读回失败残留目标 revision；均追加 failed 并保留 changeSet |
| committed | 第二事件 committed 失败时目标版已存在，返回 documentCommitted:true、eventComplete:false，部分 committed 可见 |
| 索引/缓存 | 失败分别 indexStale/cacheStale，正文与 committed 不变 |
| 进程被杀 | prepared 持久化后真实 kill 子进程；初始文档无半文件，replay 后恰 prepared+committed 各一 |
| 恢复 | prepared 重建目标逐字节一致；缺终态且磁盘为目标时 reconcile 补 committed；重复重放不增加检查点 |
| 重放证据 | 台账清空后从检查点恢复；旧数字台账拒绝；同 opId 异载荷拒绝，同载荷正向去重 |

## 4. 变异验证

所有变异只在 `artifacts/_r4-p3-mutation/` 的完整依赖副本中真 import、构造、执行。

| 变异 | 实测结果 |
|---|---|
| 去掉 prepared | 恢复返回 wal-prepared-missing，恢复用例红 |
| 去掉 committed | committed 计数 0 !== 1，对账用例红 |

| 去掉 operationDigest/载荷校验 | 同 opId 异载荷被错误 deduped，判据红 |

每个变异执行后恢复该隔离副本；最后干净 WAL+sink 正向执行与 replay 复绿。
