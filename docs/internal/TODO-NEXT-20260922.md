   - 判据门对 plan **刻意最弱**（`lib/wb-contract-pre.js:647-681`）：P-H1 只需 ≥1 个 ≥N 字符的非空 `## ` 顶层节；P-H2 是 200000 上限。正常白板文本必然通过。

4. **真因：三处指令只写"重写"，没有一处写"创建"** ——
   - `lib/index.js:160`（GUIDANCE 白板纪律）：「维护时机（**条件触发，不是每轮**）：完成阶段性工作、或**发现白板/账本所述与现状不符**、或方向有实质变化时——**写记忆的同时顺手维护白板**」。两个主触发都**以"已有白板"为前提**（"白板所述不符"要求白板存在）。
   - `lib/index.js:5815`（每轮尾部提醒）：「对项目全貌的理解发生实质变化时，用 `memory_note(kind=plan)` **重写**白板 PLAN.md」——动词是**重写**。
   - `lib/index.js:10255`（工具描述）：「kind=plan:**整体重写**白板 PLAN.md……对项目全貌的理解发生实质变化时用，**旧版自动归档**」——"整体重写"＋"旧版自动归档"两处都预设已有版本。
   - `lib/index.js:629`（注入快照标题）：「**内容过时**/理解有实质变化时，用 `memory_note(kind=plan)` 重写」——同样预设内容已存在。

5. **放大器：没有白板时模型连"提示"都看不到** —— `lib/index.js:5457` / `:5661` 的注入条件都是 `cfg.handoffEnabled !== false && (s.planText || s.latestHandoffText)`：`planText` 为空时**整段白板快照不注入**（`:629` 的标题 `snapshotPlanTitle` 也就不会出现）。于是"新建后的第一句话"自始至终不存在。

6. **前端承诺与后端事实相反（用户看到的那句）** —— `lib/client.js:208` 空态文案写的是「(白板还是空的——**模型理解项目全貌后会自动写**；也可在对话中让它用 `memory_note(kind=plan)` 写)」。后端没有任何指令要求这件事 ⇒ 用户看到的是"永远空着的白板"，符合报障描述。

**唯一会触发创建的通路**：`lib/index.js:3848` 的**接续前刷新仪式** prompt（`'1. 调用 memory_note(kind=plan, content=…)'`）——但它只在**接续**（handoff/continue）被触发时才注入，常规会话里到不了。

**判定**：这是**提示词/指令层的覆盖缺口**（prompt-coverage bug），**不是**路由 bug、不是权限 bug、不是门控 bug。与 `writeTextAtomicPre` 的并发缺陷**无关**（白板写盘走 `writeFullRaw` = `node:fs/promises.writeFile`，见 `lib/index.js:6006-6009`，**不经过** `config-io-pre.js`；后者只服务 `config.json`，调用点仅 `lib/index.js:2035 / 2055 / 10882`）。
