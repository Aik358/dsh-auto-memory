# 2.3 归属判据：时间权重与可用信号分层

> 日期：2026-11-16
> 性质：基于当前训练/跨域结果的只读分析，不修改生产、不启动训练。

## 1. 先回答：时间权重应不应该加？

**应该，但不能简单按“越近越好”。** 时间更适合作为：
- 记录时刻的硬约束；
- 事件生命周期与阶段关系；
- 相同工作窗口的弱证据；
- 任务持续/中断/恢复的线索。

它不能单独证明归属，否则会把并行工作误并。

## 2. 可用于区分“子信息属于哪个事件”的信号

### A. 硬约束与身份（优先级最高）

- 显式 eventId / issue / task / PR / commit；
- 事件是否 active / paused / closed；
- 记录时刻是否早于候选创建；
- 记录是否属于候选允许的窗口/工作区；
- 候选 ID 是否合法、是否真实存在。

这些可以排除候选，但不能把匹配标识直接当作语义归属。

### B. 内容与来源证据

- 真实来源文件、路径、行号、文档 ID；
- 原始/规范化指纹与可信指针；
- 检查点正文中的具体目标、动作、结果、失败原因；
- 引用同一文件/同一提交/同一任务节点的关系。

要区分“真实来源相同”与“同文复制”：前者是证据，后者可能只是存储重复或自引用。

### C. 生命周期与阶段

- 规划 → 实施 → 验证 → 交付；
- 失败 → 修复 → 复验；
- 同一任务的阶段延续，还是另一件事的开题；
- 批次伞事件 vs 专属修复事件；
- 记录是 founding、阶段检查点还是交接账本。

这比“标题相似”更能区分主线与子任务。

### D. 时间结构（可作为权重，但不是单独判据）

- 与候选最近检查点的时间差；
- 与候选创建/最近更新时间的距离；
- 是否落在同一连续工作窗口；
- 候选是否已 long-gap / closed；
- 同一批次、同一阶段的时间局部性；
- 中断后恢复是否仍有相同目标/来源/动作。

可考虑 `exp(-Δt/τ)` 或分桶，但只能作为辅助信号，且必须在真实留出上证明有效。

### E. 上下文与关系链

- 显式父子任务、批次伞、关联 PR/issue；
- 共享目标/来源/动作，而非只有同关键词；
- 记录是否引用了候选事件的结果或失败；
- 是否为同一工作流的下一步。

## 3. 不能当作归属证据的东西

- 只有标题/主题相似；
- 只有同仓库、同文件后缀或同模板；
- 候选含当前记录全文（self-leak）；
- 当前 open/closed 覆盖历史状态；
- 同时间发生但没有任务关系；
- 模型投票或置信度本身。

## 4. 当前证据支持的方向

- cov12+pairwise 精排在冻结留出上优于 cov12，但召回@5仅0.70；
- 语义召回0.25、融合0.5125，说明主题相似不能代替归属；
- 本地19事件/单类split与外部模型标签都不能提供完整真值。

因此，下一步应先做**时间/生命周期/来源关系的消融实验**，而不是继续扩大同类四态训练或只加语义召回。

## 5. 建议的可验证实验

1. 保留 cov12+pairwise 为基线；
2. 分别加入时间差、生命周期、来源/标识关系，逐项测量误 attach/误新建/closed/新建；
3. 严格 LOO，候选池含 open/closed 混合，保留真实留出；
4. 重点测试：并行工作、跨日恢复、同文异事、同事件不同阶段、closed/新建边界；
5. 不直接生产，不把模型标签冒充人工金标。
