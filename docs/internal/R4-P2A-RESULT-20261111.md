## 2. 实现结果

- `LockedLedgerDocumentStore` 显式包装 `LedgerDocumentStore`，默认构造即启用锁；既有 store 自身没有行为变化。
- `createDocument` / `updateDocument` / `readDocument` 的真实调用均由 `withSharedStateLock` 包裹；更新覆盖 P1 的整个「读→校验→CAS→原子写→读回」临界区。
- 锁名兼容：包装器传入 `documentPath + '.lock'`，共享锁实现再追加 `.lock`，最终为 `<document>.md.lock.lock`。这与 `lib/memory-writer.js:521` 的既有调用完全一致，不是另造 `.md.lock` 锁名。
- 锁获取失败返回 `{ok:false,error:'lock-unavailable',cause}`，job 不执行；锁内业务异常原样上抛，不伪装成取锁失败或成功。
- 使用 `AsyncLocalStorage` 按异步调用链禁止文档/索引锁嵌套；独立文档在不同调用链仍可并行。
- `runOperation` 是隔离编排口：D-read 后释放 D，再 E-prepared；D-CAS/write 后释放 D，再 E-committed；最后 I-reindex。事件回调自行拥有其既有锁，本包装器不外加事件锁。
- 部分失败逐资源可见：索引失败返回 `indexStale:true` 与已成功的 document；committed 失败保留 `resources.events='prepared'`、`prepared` 与 document winner；异常 cause 不吞。

## 4. 有区分力的变异

仅在 `artifacts/_r4-p2a-mutation/` 复制 protocol、document-store、shared-state-lock 与 locked-store；生产文件不就位修改。

- 将文档锁调用替换为直接 `return job()`。
- 两个子进程在 rename 前经文件屏障同步：双方均已完成对同一旧版本的内部 CAS，再各自 rename。
- 变异结果：**两个进程都返回 ok:true**，判据「恰一成功、恰一 conflict」实际以 `2 !== 1` 报红，证明真实后写覆盖/丢更新，而非靠屏障超时偶然报红。
- 还原副本源码且不启用双写屏障，同一跨进程判据恢复为一成功一 conflict，**GREEN**。

## 6. 诚实限制

- 仅验证本机同主机文件锁，不声明网络文件系统/跨主机互斥。
- prepared/committed/reindex 由合成回调验证顺序、状态保留与失败语义；本批没有生产 WAL、真实事件提交或真实索引接线。
- 锁不是通用回滚机制；已直接写入目标后的异常不会自动恢复，该边界已实测。
- 未做真实存量迁移、物理删除或生产端到端；未跑全仓回归。
