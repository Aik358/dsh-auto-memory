## 2. 五判据落地

### 2.1 身份映射

- 候选来自精确 sourceRef、规范化全文、声明 eventId；旧检查点使用 identityMode:'legacy-derived' 与确定性 legacyCheckpointKey，不伪造持久化 checkpointId。
- 无 sourceRef 时要求全局唯一规范化全文匹配；重复候选、声明冲突、检查点缺失、多事件缺一方均 fail-closed。
- sourceRef 与全文冲突时不得用全文覆盖指针；声明多事件逐个选取并核对。

### 2.2 规范等价

- 严格 UTF-8 解码；CRLF/CR→LF；仅去生成的交接 H1、eventId 与协议元数据整行；去行尾空白和首尾空行。
- 保留普通注释、正文、额外节、标题层级与行内空白；比较完整规范化 SHA-256，不以四段或摘要代替全文。
- 旧 inventory 规范器只用于 normalization-candidate 分类，不能令 v1 等价判据通过。

### 2.3 四段语义

- 统一解析 goal/state/dead/next，逐字段输出 presence、empty、explicitNone、双向 SHA 与差异原因。
- 缺字段、空字符串、显式「无已确认失败」分别记录；dead 空值按语义不明失败。
- 额外节如果已经包含在全文相等证据中不自动失败；未被候选正文覆盖则失败。

### 2.4 绑定与时间线

- 每候选记录 filenameTimestamp、birthtime、mtime、cp.at 及三类差值；指针存在时核对同源 rel/bytes/sha256（字段存在才参与对应校验）。
- 文件创建窗口使用 filename/birthtime/mtime 与 1 秒时间精度容差、5 秒写后检查点界限；时间倒挂、窗口不明、越界、源审计期间变化均失败。
- 冻结副本可通过 SHA 校验后的 snapshot manifest 恢复原始 birthtime/mtime 证据，报告标 statSource:'snapshot-manifest'；元数据与复制字节不符即失败。

### 2.5 报告持久化

- 每篇源文件读取后再次读取并比较 SHA-256；报告用同目录临时文件 + fsync + rename 原子写。
- reportSha256 对移除摘要字段后的 canonical JSON 计算；写后重新读取并复算核对。
- 汇总 total=inputFileCount，同时单列实际 reportCount；缺篇、事件库快照变化、报告读回异常均使批次 ok:false。
- 报告只保存区域 ID、哈希和判据，不保存整篇旧正文。真实 687 份报告递归检查 text/normalized 正文属性数为 0。
- 非法 relPath 在审计入口拒绝，原子写层再次要求目标仍位于报告目录，防止错误报告路径越界。
