# 二、复核的六个方向（**按优先级排序，前两个是用户点名的**）

## 方向 A · ⭐ 缓存与状态耦合面（**最重要，前几轮几乎没查**）

R4 要把账本从「每次新建」改成「就地编辑同一份文档」。**就地编辑最大的风险不是文件写坏，是各处的缓存与内存状态不再同步。**

必须逐个查清（每个都要给 文件:行号 + 是否被 R4 影响）：

1. **`state.latestHandoffText`**
   - 在哪写入（写账本时）、在哪读取（注入时）、在哪失效？
   - R4 就地编辑后，这个缓存**会不会变成旧内容**？谁在什么时候刷新它？
   - 规划 `PLAN-LEDGER-R4 §2.2` 只说「工具读回成功后才更新 state.latestHandoffText」——**这句话够吗**？
     追问：如果另一个进程/会话改了文档，本会话的 state 怎么知道？有没有失效机制？

2. **`index.json`（sidecar 派生索引）**
   - 账本变更时它怎么更新？是全量重写还是增量？
   - R4 改成「就地编辑 + 稳定文件名」后，sidecar 的 `sourceRevision` 怎么算？（现行按文件名/内容 sha）
   - **稳定文件名意味着 sourceRef 不再变化**，那 sidecar 怎么知道内容变了？
   - 仓内有 prototypes/sidecar-store（journal + expectedState CAS），它的协议能不能直接用于这个场景？

3. **事件库 `event-store.json`**
   - 检查点 append-only，但 R4 的文档是**可变的**——检查点里的 `sourceRef` 指向一个会变的文件，**历史检查点的语义会不会漂移**？
   - 规划说「检查点存规范四段 + 指针 + 指纹」，那么**指纹**能不能解决漂移？给机制分析。?

4. **注入面缓存**（`state.loadedAt`、节流指纹、档位状态）
   - 现行有「骨架快照 vs 完整版」节流：指纹相同就不重复注入。R4 文档就地编辑后，**指纹怎么算**？
   - 如果文档变了但指纹没更新，注入面会**一直认为没变**——这个风险排查了吗？

5. **面板/前端缓存**
   - `handoffPanelData`、事件卡片、白板视图有没有各自缓存？
   - R4 引入新目录 `handoff/documents/` 后，旧面板会不会**读不到**或**读成两份**？

6. **多会话/多进程**
   - 同一工作区可能被多个 DSH 会话同时打开。R4 的锁/CAS 能否覆盖**跨进程**？
   - `withSharedStateLock` 的作用域是什么？（读 lib/shared-state-lock.js 源码回答）
