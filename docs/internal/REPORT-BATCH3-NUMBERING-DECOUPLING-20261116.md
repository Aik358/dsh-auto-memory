## 2. 解耦方案：语义代号

### 2.1 命名规则

代号格式 `B3-XX`：`B3` = Batch 3；`XX` = 两字母语义缩写，取**职责英文首字母**，**不取数字**。
理由：数字会再次被误当作顺序或可映射关系；语义缩写强制每次引用都写出职责。

### 2.2 映射表（**新口径**）

| 代号 | 名称 | 职责 | 溯源（仅供追溯） |
|---|---|---|---|
| **B3-RC** | Rules Complete | 规则**完整只读聚合**（user+project 双层、多行正文） | 细则 3.0.1；进度报告 3.0.1 |
| **B3-RP** | Rules Pointer | 摘要档**一行指针** / `human_full` 给完整正文 | 细则 3.0.1+3.0.2；进度报告 3.0.1+3.0.2 |
| **B3-FM** | Final Metering | 最终段组装后再计量，账实一致、每请求一次 | 细则 3.0.4；进度报告 3.0.4 |
| **B3-NT** | Notification | prepare 不消费、只提交最终保留、幂等 | 细则 3.0.5；进度报告 3.0.2+3.0.3 |
| **B3-BD** | Board & Docs | 去 2000 预截断、按节选择、保尾部 | 细则 3.0.6；进度报告 3.0.5 |
| **B3-CB** | Callback | 修恒真断言、真执行工厂、真 apply 回调 | 细则 3.0.7；进度报告 3.0.6 |
| **B3-EV** | Event Views | 四段消费、检查点截断、事件展开（旧 3.1–3.4） | 总表 3.1–3.4 |

**注意映射的「多对一」与「一对多」**：

- 一个 B3 代号可能溯源到**两条不同旧编号**（如 B3-NT ← 细则 3.0.5 + 进度报告 3.0.2/3.0.3）——这正是重合内容被融合的结果。
- 一条旧编号可能**拆到两个** B3 代号（如细则 3.0.1 同时喂给 B3-RC 与 B3-RP）——因为「能读到完整内容」与「在哪个档位呈现什么」是两个验收单位。

### 2.3 消歧规则（施工时强制）

1. **禁止**在任何新文档、任务书、代码注释里用 `3.0.x` 指代施工对象。
2. 引用旧编号时**必须**带来源前缀：`细则-3.0.2` / `进度-3.0.2`，且**只能出现在「溯源」栏**。
3. 若发现新文档仍用裸 `3.0.x`，视为**编号事故未修复**。
4. `noticeRemoteEnabled` 不得被任何 B3 代号吸收。
