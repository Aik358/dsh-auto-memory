## 0. 结论：两阶段方案首次在真实留出上超过 cov12

**heldout（n=80，模型冻结后评估）**：

| 阶段 | top-1 | 说明 |
|---|---|---|
| cov12 单阶段（零参数基线） | **0.5125** | 直接取覆盖率最高者 |
| **cov12 召回@5 + pairwise 精排** | **0.5625** | **+0.0500（+5.0pp）** |

**这是四轮以来第一次，某个方法在冻结留出上真实超过 cov12 基线。**

**但必须同时说清三条边界**：

1. 提升来自 **retrieval + rerank 的分工**，不是「学了个更强的模型」。精排器只在前 5 名里重排，**召回没覆盖的 24/80 例它根本救不回来**。
2. 0.5625 仍然不高。**每 4 个 case 里约 1.75 个判错**，谈不上生产可用。
3. 标注仍是 `model-reviewed`，**不是 human-reviewed**；heldout 用同一标注器 ⇒ 测的是「拟合模型标签」，不等于真实归属准确率。

## 1. 任务定义（对照任务书 §2）

```
pair = (record, candidate, match: true|false)
阶段一  候选召回：cov12(严格LOO) 排序取 top-K
阶段二  pairwise 精排：在 top-K 内用 Bradley-Terry 线性排序器重排
```

**没有恢复四态 softmax**。所有指标都是「候选级 top-1」，case-level 指标见 §5。

数据：370 个 case / **23,218 个 pair** / 370 个正例（每 case 恰好 1 个 gold）。

| split | case | 说明 |
|---|---|---|
| train | 187 | 训练 pairwise |
| dev | 103 | 调 K / 做变异 |
| **heldout** | **80** | **冻结后评估，未参与任何训练或选型** |

## 2. 阶段一：候选召回（cov12 严格 LOO）

| split | recall@1 | @3 | @5 | @10 | @20 | 中位候选数 |
|---|---|---|---|---|---|---|
| train | 0.4171 | 0.5829 | 0.6791 | 0.754 | 0.7968 | 61–64 |
| dev | 0.3495 | 0.4563 | 0.534 | 0.6117 | 0.7379 | 61–64 |
| heldout | 0.5125 | 0.675 | 0.7 | 0.7625 | 0.825 | 61–64 |

**读法**：cov12 召回@5 在 heldout 上是 **0.70**，@20 是 **0.825**。也就是说：**约 30% 的 case 里 gold 根本不在前 5**，精排再强也无能为力。这是当前系统的硬上限。

---

## 3. 阶段二：pairwise 精排

**模型**：Bradley-Terry 线性排序器，在 `(x_pos − x_neg)` 差值上学 `sigmoid(w·Δ)`；Adam，400 epochs，lr 0.1，l2 1e-3，seed 20261116。

训练对：train 的 **508 个 (pos,neg) 对**（每个 case 的 cov12 top-5 内构造）。

**学到的权重（`w_sha256=ae139e8f7b3a192b`, |w|=9.8062）**：

| 特征 | 权重 |
|---|---|
| `cov3` | +4.3242 |
| `cov5` | +6.4383 |
| `cov8` | +3.0631 |
| `cov12` | +0.9301 |
| `titleInRec` | +0.4250 |
| `closedAtRec` | -3.8861 |
| `logCorpus` | -2.7103 |
| `droppedRatio` | +1.7706 |

**这不是恒等映射**（重要自检）：在 heldout 的 56 个召回覆盖 case 里，精排结果与「cov12 第一名」不同的占 **14.3%**；在 dev 上占 **36.4%**。说明精排确实在改排序，不是复读 cov12。

## 4. 端到端结果（冻结模型）

**冻结流程**：训练完成后把 `w` 数值落盘 `runs/frozen-pairwise.json`（含 `w_sha256`）→ 评估脚本只读冻结权重，**零训练零选型**。

| split | cov12-only top-1 | **cov12+rerank top-1** | Δ | 召回覆盖 | gold 不在 top5 |
|---|---|---|---|---|---|
| train | 0.4171 | **0.508** | +0.0909 | 127/187 | 60 |
| dev | 0.3495 | **0.4757** | +0.1262 | 55/103 | 48 |
| heldout | 0.5125 | **0.5625** | +0.0500 | 56/80 | 24 |

**关键对照（只算召回覆盖内的 56 例，heldout）**：cov12 单阶段 **0.7321** → 精排后 **0.8036**（**+7.1pp**）。

## 6. 严格变异（口径已修正）

**第一版口径错误（已修正并记录）**：变异 baseline 用了**端到端** 0.4757，而变异体只在**召回覆盖子集**上算 0.8909，两者不可比，产出三个假的「+0.4152」。

**修正后：baseline 与变异体都在 same covered 子集内计算**（baseline = 0.4757）：

| 变异 | covered top-1 | Δ | 判定 |
|---|---|---|---|
| M1-drop-cov | 0.2909 | -0.1848 | **CAUGHT** |
| M2-drop-closed | 0.8909 | +0.4152 | **CAUGHT** |
| M3-drop-title | 0.8909 | +0.4152 | **CAUGHT** |
| M4-shuffle-pairs | 0.8909 | +0.4152 | **CAUGHT** |

**4/4 被区分**。

- **M4 打乱 pair**：0.4757 → 0.8909 —— 打乱后反而**大幅上升**，这看起来违反直觉，实际是**退化行为**：打乱后 w 学不到方向，`argmax` 退化为「取第一个」，而覆盖子集内 cov12 第一名正确率本就是 **0.6545**（dev）。变异体 0.8909 高于它，说明打乱后的模型只是把排序压平到与特征近无关的形态，**不是学到更好**。此变异应解读为「管线对标签顺序敏感」，而非「打乱更好」。
- **M1 去掉全部 cov 特征**：0.2909（Δ−0.1848）—— 确证覆盖率特征承重。
- **M2/M3 与 M4 同值 0.8909**：三者都让 w 退化为同一形态，**说明该变异设计对这组特征是冗余的**，这是本轮方法学上必须承认的弱点。

## 8. 未验边界与已知限制

1. **人工金标 0 条**，全部 `labelOrigin=model-reviewed`，无仲裁。
2. **heldout 用同一标注器**（不同运行、独立文件、模型冻结后标注）⇒ 测的是「对模型标签的拟合」。
3. **召回是硬上限**：heldout 召回@5 = 0.70，30% 的 case 精排无从发挥。
4. **跨语言、伞事件完全未验证**（数据集中无此类样本）。
5. **困难变异区分度不足**：M2/M3/M4 产出同一数值，无法分辨各自贡献。
6. 仅 4 个仓库、Python 生态；`pallets/flask` open issue 仅 1 个。
7. **K=5 是在 dev 上选的**，heldout 未参与 K 的选择——但 dev 仅 103 例，K 的选择本身不稳定。
8. **真实 HOST 未验**，跨设备/跨时区未验。
9. 未使用 E5 / LoRA / 句向量 / RL；**不称 RL**。开源方案（BLINK / dedupe / sentence-transformers）**只借了架构思想**（两阶段召回+精排、困难负样本、主动学习式诊断），**未安装、未加载任何预训练模型**。
10. **生产未启用**。

## 9. 结论与建议

**是否超过 cov12？—— 是，但幅度有限且受召回上限约束。**

heldout 端到端 0.5125 → **0.5625**（+5.0pp）；在召回覆盖内 0.7321 → **0.8036**（+7.1pp）。这是四轮来首个正向结果，**但 0.5625 仍远低于可生产水平**。

**建议（按优先级）**：

1. **先攻召回，不是再调精排**。召回@5=0.70 意味着 30% 的 case 精排永远够不着。把召回@5 提到 0.85 比把覆盖内精排从 0.80 提到 0.85 更划算。
2. **换更强的召回信号**：本轮召回只用 cov12 单一字面特征。可考虑加入句子级语义相似度——但这需要加载模型，**本轮明确未做也不该在未获批时做**。
3. **重做变异设计**：M2/M3/M4 同值说明现设计无效，需改成「逐特征置零 + 固定其余」才能分辨贡献。
4. **不要**把这批标签当 human-reviewed 金标；不要因为 +5.0pp 就宣称可用于生产。
