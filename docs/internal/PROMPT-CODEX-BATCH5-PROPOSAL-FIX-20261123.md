### M2 · 恢复「宁拆勿并」，不要与「宁建勿挂」合并

**这是语义反转，最严重的一条。**

| | 位置 | 原文含义 | 你的新版 |
|---|---|---|---|
| ⑦ | 归属判据 15 条之⑦ | **宁拆勿并**：证据不足时**优先把同一件事拆开**，别硬并成一件 | 被改写成「证据不足**宁建勿挂**」 |

两条是**不同维度**的判据：

- **宁拆勿并** = 事件**粒度**问题：该拆成两个事件就拆，别为了省事并成一个。
- **宁建勿挂** = **归属选择**问题：没有匹配事件时宁可新建，别错挂到别人身上。

合并后「优先拆分」这条规则**消失了**，模型遇到模糊粒度时会倾向建新事件而不是拆分既有事件 —— 行为与批次3/4 的归属纪律相反。

**要求**：两条**并列保留**，各自成立。参考写法（可自行优化，但两条语义都不能丢）：

```
· …同标识异线不挂。无匹配才 memory_event(action=create,name)。粒度不明宁拆勿并，归属不明宁建勿挂。
```

**验收**：新全文必须同时出现「宁拆勿并」与「宁建勿挂」两个短句，且各自修饰不同对象（粒度 / 归属）。
