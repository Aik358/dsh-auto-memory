## D4-1 · 4.3 = **A：回读全局时段总结**

### 裁定

- **采纳 4.3-A**。`memory_read({kind:"summary"})` 读取**最新一条已生成的全局时段总结**，响应明确标注 `scope:"global"`。
- 任务书中「该工作区最新一条」**作废**。原因：`summarizePeriod()` 自 2026-09-01 起就是全局统揽（源码注释原话：「时段总结不再绑定单一工作区——聚合所有工作区的日志，源文件列表与缓存都走用户级目录」），记录只有 `summary` / `works` / `generatedAt` / `cached`，**没有工作区身份**。要求按工作区读等于要求新建存储维度 —— 那是新功能，不是「回读」。
- **不得**为迁就本项而改动 `summarizePeriod` 的生成逻辑或存储布局。4.3 是**纯读**。

### 排序（采纳提问方建议，加两条约束）

1. 主键：`generatedAt` **降序**；
2. `generatedAt` 缺失 / 非有限数 / `<= 0` 时，用**文件 mtime** 兜底；
3. 两者都相同 ⇒ 按**文件名降序**稳定排序（文件名含日期+时段，字典序即时间序）；
4. **排序结果必须与返回值一致**：返回的那条就是排序第一的那条，验收要构造「mtime 与 generatedAt 顺序相反」的夹具证明主键优先、兜底只在必要时生效。

### 响应契约（硬约束）

- 必须含：`scope:"global"`、来源**绝对路径**、`generatedAt`（或 `generatedAt:null` 并标注用了 mtime 兜底）、正文字节长度、正文全文。
- 返回正文必须与磁盘该文件**逐字节相等**（验收给 sha256 对照，不许用「包含」断言）。
- **空态与读失败必须可区分**（沿用既有纪律，不得伪装为空成功）：
  - 目录不存在 / 目录内无候选 ⇒ 明确空态（含「为什么空」的 code）；
  - 文件存在但读失败 / JSON 解码失败 ⇒ 明确 `unreadable` 并指出坏文件，**不得**静默跳过当成空。
- 非法 `kind` 行为不变；错误文案要能让调用者看出合法集合已含 `summary`。

### 验收补充

- 隔离变异 ≥2：①改排序主键（把 `generatedAt` 换成 mtime）⇒ 相反顺序夹具必须变红；②把「读失败」分支并入空态 ⇒ `unreadable` 用例必须变红。
- 文档：`docs/USER-GUIDE.zh-CN.md` / `.en.md` 的 `kind` 列表补 `summary`，并写明**这是全局总结、不是工作区总结**（避免用户误解）。

## D4-2 · 4.5 = **A：本轮只接 `units`**

### 裁定

- **采纳 4.5-A**。去重只接 `units`（按单位组装）路径。`legacy` 与 `eventView` **保持现状**，本轮不改变其输出。
- 理由（决定性）：D30B-14 把缺省定为 `eventView`，其价值是「缺省行为零变化 + 可原样回滚」。在兼容档上做去重等于让**默认行为漂移**，必须重新裁定 D30B-14 的字节等价约束 —— 那不在本批授权范围内。`units` 是用户显式开启的新能力，在那里修才是对的。
- **`eventView` 的重复必须作为已知项显式列出**：写进回执「未解决」组，并在 CHANGELOG 草稿的「仍在问题中 / 未验证」组留一条。**不许隐藏、不许用「已修复」概括。**

### 保留判据（确认提问方草案，原文采纳）

1. 账本入选且保留**完整正文** ⇒ 优先保留**账本原段位**，只省去检查点中的同文字段；
2. 账本关闭 / 只投指针 / 正文未入选 ⇒ **保留检查点正文**；
3. 内容**差一个字符** ⇒ 两份都保留。
4. 去重后留下的那一份**必须仍在它原本的段位**（不得把账本内容挪到事件段）。

### 追加约束（四条）

1. **去重键 = 规范化后逐字节相等**的内容指纹（统一 `\r\n`→`\n`、去首尾空白后比较）；**禁止**前缀相似度 / 编辑距离 / 长度相同等模糊匹配。
2. **去重与预算计量的顺序**：去重必须发生在 `measureFrame` **之前或同步**，不得先计量后去重导致帧体积虚高、`budgetOvercommit` 误判。
3. **无同文场景的 `units` 输出必须不变**：既有三场景（空库/常规/满额）的 `units` digest 在去重实现后要与实现前逐字节相同 —— 这是防止「去重顺手改了别的东西」的回归锚，必须先取实现前 digest 再改。
4. `pushPart` 计数口径按提问方实测：**31 处文本命中 = 28 处具名直调 + 1 处通用转发 + 2 条注释**。我独立实测得 31 命中 / 1 条 `//` 行首注释，差异在注释形态，**按提问方的分层接受**（它区分了具名直调与通用转发，比我的粗计数更可用于判断覆盖面）。此处再次印证：验收判据要写**功能覆盖**，不能写 grep 命中数。

### 验收补充

- 隔离变异 ≥2：①指纹改成「长度相同即视为重复」⇒「差一字符」负路径必须变红；②去重后不重算预算 ⇒ 预算账断言必须变红。
- 必须给出去重前后的帧字符数与 `unitReceipt` 的 `selectedCount` / `rejectedCount` 对照。
