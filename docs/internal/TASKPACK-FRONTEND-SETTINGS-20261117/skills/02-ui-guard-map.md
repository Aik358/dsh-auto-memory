## 何时适用

- 仓库有 tests/smoke/ 这类「读源码字符串」的静态守卫套件（非浏览器端到端测试）
- 守卫以 indexOf/includes/正则 断言源码文本，而非运行行为
- 目标 UI 文件是单写者的大文件（改一行可能被多处锚点引用）

## 步骤

1. 用 glob 列出 tests/smoke/*.mjs，再用 grep pattern="client\.js|CLI_SRC|lib/client" 筛出读浏览器文件的套件（实测 43/177 个读 client.js）
2. 对筛出的套件按关键词二次 grep：section\(|sectionLabels|MEMORY_TABS|panelTab|data-dam-|--dam-|KANBAN_|jumpToSection —— 这些是结构断言的高发区
3. 逐条读命中行，把断言分成三类并记录「文件:行号 + 锁的内容」：(a) 计数锁（如 eq(tabsReuse,2) 锁 MEMORY_TABS() 调用次数）；(b) 精确正则锁（如 panelTab 三条逐字正则）；(c) 结构不变量锁（如触发点↔渲染点同分区、块行数区间、行号邻接差=1）
4. 对每个待做的 UI 改动，逐条判定它是「会撞锁」还是「不撞锁」——判据：断言检查的是「函数调用形态」还是「块内容」。只看调用形态的锁（如 G1a 只看 section('key', sectionLabels.key, [ 这一串）在只改块内容时不会红
5. 对「会撞锁」的项，规划为独立批次，并同批做三件事：改代码、改守卫的期望值、更新守卫头部注释说明为何演进（保留它原本防的那类事故的不变量本体，只改写判据）
6. 优先寻找「不撞锁的收敛路径」：把被计数锁盯住的函数改成派生函数（函数名/签名/调用次数不变，只改返回值），可在回归全绿前提下完成结构收敛
7. 读守卫文件头部注释——本仓守卫头部记录了真实事故的复现形态（如设置页面板搬到别的分区后因滚动式导航落在视口外，用户报障"弹不出来"），改该区域前必读
8. 每批收尾跑：node --check lib/client.js + node tools/run-smoke.mjs --filter=<本批关键词>；并核对改后文件无裸 LF（本仓 client.js 为纯 CRLF）

## 检查点

- [ ] 确认套件总数与其中读 client.js 的数量（本轮实测 177 总数 / 43 读 client.js）
- [ ] 确认每个锁是「计数」还是「形态」还是「内容」——决定该批要不要改守卫
- [ ] 确认守卫头部是否记录了历史事故形态，以及本批改动是否会复现它
- [ ] 确认改动后 EOL 性质不变（纯 CRLF 文件不得出现裸 LF；注意不要用「CRLF 计数不变」当判据）

## 成功判据

- 产出一张「文件:行号 → 锁的内容 → 本批是否撞锁 → 对策」四列表，覆盖所有与本次改动区域相关的守卫
- 每个被判「不撞锁」的结论都有判据（断言只看调用形态，不看块内容），非凭感觉
- 被改动的守卫：其原本防的事故不变量仍存在（判据被改写而非删除），且头部注释已同步说明演进原因
- 每批收尾 node --check 通过 + 对应子集回归全绿；无裸 LF
- 若存在「派生函数」式不撞锁路径，已优先采用而非直接改守卫

## 回滚

- 改守卫前先备份该 .mjs（Copy-Item 带时间戳后缀）；若改动后回归红且无法判断是代码错还是契约变更，回滚守卫与代码到本批起点，重新拆批
- 若已改守卫期望值但发现守卫原本防的事故被复现，立即恢复守卫原文并回退对应代码改动
