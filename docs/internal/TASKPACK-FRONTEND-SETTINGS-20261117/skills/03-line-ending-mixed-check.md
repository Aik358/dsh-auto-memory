## 何时适用

- 已知该文件原本的行尾风格（用 git show HEAD:<file> 或编辑前的检测结果确定）

## 步骤

1. 改完任何源码/测试文件后，立刻对该文件跑混用检测：统计 CRLF 出现次数与「裸 LF」次数（裸 LF = 前面不是 \r 的 \n）
2. 判据：crlf > 0 且 loneLF > 0 ⇒ 行尾已损坏（混用），必须修复；只满足其一即为健康的纯 CRLF 或纯 LF
3. ★反例（禁止）：用「行尾总数」或「与 HEAD 的数量是否相等」当判据 —— 文件因新增行变长时数量必然改变，会误报/漏报
4. 修复：按该文件原本的风格统一。纯 LF 文件把 \r\n 全部替换为 \n；纯 CRLF 文件把裸 \n 补成 \r\n
5. 修复后复核：git diff --numstat 的行数应回落到「实质逻辑改动量」（若仍显示全文件行数，说明还没归一）
6. 再用 git diff --ignore-cr-at-eol --numstat 交叉验证，确认真实改动量

## 检查点

- [ ] 编辑工具写整文件时最容易翻面（如整体重写、格式化成 CRLF），逐行 anchor 替换通常安全

## 成功判据

- 目标文件检测结果为「纯 CRLF」或「纯 LF」之一，不存在混用
- git diff --numstat 显示的行数与实质改动量一致（不是全文件行数）
- 修复后该文件对应的测试套件仍通过
