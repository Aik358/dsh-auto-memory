## 2. 实现内容

### 编解码与身份

- `lib/team-baseline.js` 新增 `decodeBaselineDocumentPre`，纯函数、零 IO、异常返回 `{ok:false,reason}`。
- 校验 documentId 协议格式、文件名大小写、绝对路径、`..`、斜杠混用、重复文档、文档头、eventIds、createdAt/updatedAt 和正文重算 revision。
- 可选 `documents` 清单与实际入包文件双向核对；checksum 覆盖所有实际入包文件的名称与原始字节内容。
- 保留既有 brotli、编码前大小闸门和解压 `maxOutputLength` 闸门。
- 上传返回 `documents:N`（无文档时为 0）；旧基线 pack/unpack/apply 的无 documents 形状不变。

### 上传与物理边界

- `lib/ledger-doc/baseline-documents.js` 使用 `LedgerDocReadSide` 只读当前 `handoff/documents/`，不扫描 `handoff-*.md` 旧快照。
- 非法 documentId、内容、revision、关联字段、读取错误、符号链接文件、junction/越界物理路径均 fail-closed，上传不入队。
- `lib/index.js` 的 `uploadBaselinePre` 改为 async；全仓真实调用点核对后，生产路由已使用 `await`。其余命中为注释、文档或本批测试。

### 应用、冲突与回滚

- 应用前逐文档读取本地 revision；同 revision 同内容幂等，不产生重复 `-b/-c` 文件。
- 不同 revision 默认返回 `document-conflict`，不写文件；`force` 不等于覆盖授权。
- 仅接受显式 `documentResolutions: { [documentId]: 'local'|'remote' }`，分别产生 `keep-local` 或 `overwrite-remote` 审计；基线路由已透传该字段。
- 文档进入同一写计划；备份支持嵌套 `documents/` 目录；写中失败返回 `applied`、`failedItems`、`rolledBack`、`rollbackFailed` 和 `documentsAudit`，只回滚实际成功写入的文件。
- 缺少目标或源文档不构成删除授权。
