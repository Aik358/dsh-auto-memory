## §2 变更清单

### 2.1 宿主 0.1.6-alpha.2 → 0.1.7-alpha.1（权威来源）

来源：GitHub Releases API
`https://api.github.com/repos/deepseek-ai/deepseek-harness/releases`（HTTP 200）
对应 release：`tag_name = dsh-v0.1.7-alpha.1`，`name = v0.1.7-alpha.1`，`prerelease = true`，`published_at = 2026-09-22T06:16:27Z`，`target_commitish = c36a83ff6bb95e3f82cf79f9be7c724270a8aa61`。
人类可读页：<https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.1>

**官方在 release notes 中**显式点名「插件需适配」**的条目共 3 条**（英文原文摘引，逐字）：

1. > "Attachments stored only in custom events are no longer read or exported automatically; **plugins must adapt**."
   > 中文原文：「仅保存在自定义事件中的附件不再自动读取或导出，**插件需适配**。」

2. > "Unify workspace file reads under readBytes; **plugins must migrate from the old APIs**."
   > 中文原文：「工作区文件读取统一为 readBytes，**插件需迁移旧接口**。」

3. > "Save settings in the current Profile's plugin configuration, supporting fields declared for live updates. Import from the legacy settings.yaml is attempted only once; **custom settings plugins must adapt**."
   > 中文原文：「设置改由当前 Profile 的插件配置保存，支持声明过的实时更新字段；旧 settings.yaml 仅尝试导入一次，**自定义设置插件需适配**。」

其余与插件生态相关的条目（原文摘引）：

4. > "Continue Profile loading past unreadable optional bundles and retain diagnostics and disable/remove controls in Plugin Manager."
   > 「无法读取的可选插件包不再直接中止 Profile 加载，并在插件管理页保留错误信息和禁用、移除操作。」

5. > "Fix source-launch initialization failures caused by runtime module resolution, and **support linking plugins under local development**."
   > 「修复源码启动时受模块运行时解析行为影响导致的初始化失败，并**支持 link 到本地开发中的插件**。」

6. > "Preserve special JSON keys in plugin projection caches when reopening sessions."
   > 「修复会话重新打开时，插件投影缓存中部分特殊 JSON 字段丢失的问题。」

7. > "Support bidirectional Remote streams and binary transfer for ordinary call results and Office previews, reducing large-file encoding overhead."

8. > "Allow plugins to declare localized titles and descriptions through the locale data structure and icons in package.json, and use them in the Plugin Manager display."
   > 「插件可通过 locale 数据结构声明多语言标题和描述，通过 package.json 声明图标。」

9. > "Support ordered patch-file lists in plugin bundles while retaining single-file declarations. Plugins can declare configuration fields that update without reloading, retaining running instances when only those fields change."

10. > "Add Work Details, Performance and Usage, and Developer Tools settings. ... **Developer Tools is enabled by default and keeps third-party session tabs visible when disabled.**"
    > 「新增「工作过程展示」「性能与用量」「开发者工具」设置；…开发者工具默认开启，**关闭时仍显示第三方会话标签页**。」

11. > "Session logs upgraded to V4 and add a batch migration tool for developers, including support for some V3 histories with missing turn-end records."
    > 「Session 日志升级为 V4，新增面向开发者的批量迁移工具…」

12. > "Reserve model output capacity and additional context headroom for proactive compaction, reducing overflow after long outputs."
    > 「主动压缩会预留模型输出预算和额外上下文空间…」

13. > "Add `--dump-config-schema` to export JSON Schema for Cordis configuration and patches."

14. > "Fix Web access when deployed under a reverse-proxy subpath."

15. > "Fix Messages API request failures when resuming sessions containing historical subagent notifications."

补充来源（第三方解读，非权威，仅作交叉参考）：
- 0.1.2-rc.1 release notes 中提到社区插件升级 skill：`https://github.com/oh-my-dsh/dsh-plugin-upgrade-skill`（官方声明「与 DeepSeek AI 没有隶属关系」）。

## §4 必须改项逐条方案

> 前提：**尚未执行任何改动**。以下为方案，需用户拍板后另行实施。
> 纪律提醒（用户既有硬性规则）：改 `lib/index.js` 后**必须由用户手动重启 dsh web**，agent 不得自行重启宿主。

### 4.1 M1 —— Session 日志 V4 兼容（最高优先级）

**风险**：本插件两大核心功能建立在解析会话 JSONL 之上 ——
① 转写/接续材料（`foldSessionLogEvents`，`lib/index.js:9346`）；
② 水位感知的模型与窗口解析（`:3258` 读 sessionFile、`:9358-9372` 读 `request/header` / `request/context`）。
官方 0.1.7 明确「Session 日志升级为 V4…兼容部分 V3 会话缺少轮次结束记录的情况」。
**若 V4 改变了事件 `type` 名或 `data` 形状，上述两处会静默产出空结果**（不报错、不抛异常 —— `foldSessionLogEvents` 整体包在 try/catch 内，`:9349-9352` 与 `:9356` 逐行 `catch` 后 `continue`）。

**方案（分四步）**：
1. **先取证，不改码**：升级前先抽样 1–2 个真实会话 JSONL，记录当前 V3 的事件 type 集合与 `request/context` 字段形状，落盘为基线快照。
2. **升级后立即复跑同一批样本**，对比 `foldSessionLogEvents()` 的输出（`msgs.length`、`provider`、`model`、`attachments` 计数）。
3. **若 V4 改了形状**：在 `foldSessionLogEvents` 内做**双版本兼容**（V4 分支优先、V3 分支回退），而不是直接替换 —— 与 v3.1.2 目录选择器「双路径兼容」同一手法，保持旧会话仍可读。
4. **补一条守卫**：把「给定样本 JSONL → 期望 `msgs.length` / `model`」做成 smoke 断言，V4 变更时**必须变红**而不是静默退化。
   ⚠️ 这正是仓库既有纪律要求的形态：「字符串枚举/联合类型字面量写错时编译器不报错，会被静默忽略；此类常量集合必须配测试断言兜底。」

### 4.2 M2 —— 附件不再从自定义事件自动读取

**风险**：`lib/index.js:9466-9521` 的 L3.5 附件清单功能（把「用户投过这张图/这个文件」在接续材料里还原成可读路径）**完全依赖**从消息事件的 `content` 里读 `{type:'image'|'file', attachment:{attachmentId,...}}`。
官方 0.1.7：「仅保存在自定义事件中的附件不再自动读取或导出，**插件需适配**」。

**方案**：
1. **确认命中面**：本插件读取的是 `user/message` / `assistant/message`（`:9373`，属**标准事件**）里的附件描述符，**未必**属于官方所指「仅保存在**自定义事件**中的附件」。
   ⇒ **推断（中置信）**：本插件可能**不受影响**，但措辞「不再自动读取或导出」范围未在 release notes 中限定死，**必须实测确认**。
2. **实测方法**：升级后打开一个历史会话，跑 `/continue`（接续），检查接续材料里 `【第2.5层 · 旧会话附件清单】`（`lib/index.js:4401-4403`）是否仍出现。
3. **若确实丢失**：改为在会话导出/落盘阶段**主动**记录附件描述符（而非事后从事件回读），把附件清单的取材从「读事件」改为「读本插件自己的旁路索引」。
4. **保持 fail-soft**：`attachmentBlobPathsPre` 现有「未知/异常 id ⇒ 两值均为 ''（fail-soft，绝不抛）」（`:9507`）必须保留。

### 4.3 M4 —— `settings.yaml` 读取路径降级

**风险**：0.1.7 起设置改由 Profile 插件配置保存，「旧 settings.yaml **仅尝试导入一次**」⇒ 该文件不再随用户改设置而更新。
本插件三处读它推导模型 `contextWindow`：
- `lib/index.js:3163` `readTextSafe(path.join(dshHome(), 'settings.yaml'))`
- `lib/index.js:8018` `readFile(path.join(dshHome(), 'settings.yaml'), 'utf8')`
- `lib/water-window-pre.js:14`（纯函数，解析 settings.yaml 文本 → 模型窗口映射）

**后果**：水位卡的「窗口来源」会永远停在导入时的快照，新模型/改窗口后查不到 ⇒ 退化到 fallback `131072`。UI 上会显示「回退默认值」（`lib/client.js:429` 的 `waterFallbackSrc`）。

**方案（按优先级）**：
1. **首选**：把窗口解析的**权威源**改为官方路由容量（本插件已有该路径，`:3283` 注释「优先官方 request/context 容量」）。`settings.yaml` 降为**末位兜底**，并在设置页文案里如实标注来源 —— 现有文案 `waterAutoSrc/waterManualSrc/waterOfficialSrc/waterFallbackSrc` 四档已具备表达能力，只需确保 `settings.yaml` 命中时不再冒充「自动检测」。
2. **次选**：改从 Profile 的插件配置读取当前模型列表（需先摸清 0.1.7 的存储位置与形状）。
3. **不改**也可以接受为**优雅降级**（有 fallback、不报错），但应在 `docs/` 记录该已知边界。

### 4.4 附带发现（非 0.1.7 引入，但建议同批处理）

**`package.json:30` 声明注入 `@deepseek-ai/dsh-client-runtime`，该包本机不存在。**
- 实测：宿主 `node_modules/@deepseek-ai/` 下无 `dsh-client-runtime`（仅 `dsh-ptc-runtime` / `dsh-ptc-runtime-node`），profile 层亦无。
- **推断（中置信）**：该声明来自更早的宿主版本，包名后已被上游改名或合并；当前是**惰性无害**的（0.1.6-alpha.2 下 Profile 未因此报错）。
- **与 0.1.7 的交互**：release notes「无法读取的可选插件包不再直接中止 Profile 加载」说明 0.1.7 正在**加固**这一场景 ⇒ 升级后**更**安全，但也有可能开始**显式报错**提示该包不可解析。
