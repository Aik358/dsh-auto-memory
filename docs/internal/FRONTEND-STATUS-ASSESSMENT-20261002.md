## §1 一页总评

**结论：前端已走出 3.2.5→3.2.6 的混乱期，处于"带结构性负债的稳定态"。**

### 4-2 三大历史事故的病根与对症修复（均有注释存档）

1. **病根 2**（产物块每轮 +1，2.10M→2.68M，幂等失效）→ stripBlocks 循环摘净（:87-111）+ seam 写出标记对。

### 4-3 残留风险（按优先级）

1. **默认模式告警后仍写盘**——破坏性覆盖的门没焊死，只从"静默"降为"需人主动走对流程"。防线=纪律+告警，无进程级硬闸。**建议：执行 agent 侧把"无 --check/--strict 跑生成器"视为违规操作。**
2. **幂等验收 fixture 仍处"移除待恢复"**（iter5-skin :396-407，恢复判据已写明且现已满足——本次 --check 实跑即证明）——当前没有任何自动化测试验证生成器幂等，生成器再吞块只有下游行为测试偶发能接住。
3. **静默 no-op replace 群约 25 处**（:289/:303/:307/:311/:372-375×8/:386/:395/:401/:417-435/:439/:443-445/:484）——includes 守卫成立但目标串因源结构变化不在时 replace 静默跳过，生成"成功"但补丁缺失。**`skins/iter5/README.md:16` 宣称"每个变换点要求唯一匹配"与实现不符**，是真实的文档-实现裂缝。
4. **无 -1 检查的锚 4 处**：frozen 切片（:54-55）、saveStart/fieldStart（:161-162）、modeStart/modeEnd（:199-200）——锚被改坏时静默产出坏片段。
5. **本地 debris**：`tools/build-iter5-skin.mjs.stage1`（58KB 旧副本，无 --check 时代防线，可执行位）+ skins/tools 侧约 18 个 .bak（~2.3MB）。被 .gitignore 忽略不进发布物，但**误跑 .stage1 风险真实存在**。这正是 issue #166（npm 7 份 client.js 残留）的同款碎片堆积习惯。

### 4-4 生成器安全等级结论

**中高。"让执行 agent 用是可放心的，前提是它只被允许以 --check / --strict 两种形态运行。"** 三大事故病根都有对症修复且有注释存档；`--check` 的"定点性质"一张网兜住所有源↔产物漂移（唯一骗过方式是产物与"源×生成器"分毫不差——那等于正确落源）。

### 4-5 修改前端的标准 SOP（建议固化为纪律）

1. **改源不改产物**：动皮肤/设置/存储/技能/统计 → 改 `skins/iter5/*` 或 `.frozen`；动 H3-1 定义、D2 订阅、legacyKnob、F6/H1 头部这类"生成器注入到手写区的片段" → 改生成器本身。**"会被覆盖区"大于 BEGIN/END 标记对**——这是最易被误解的一点（build 注释 :447-449 明确记载过"手插后 --check 报 stale、clean 生成会丢"）。
2. client.js 里试错可以，试完**必须把改动搬进源**再固化。
3. 唯一合法序列：`--check`（确认同步）→ 需重建时先 `--strict` 干跑看"将丢弃哪些行"（不写盘）→ 确认无 orphan 后才允许不带 flag 实跑 → 立刻 `node --check lib/client.js` + `node tests/smoke/smoke-test-iter5-skin.mjs`。
4. **永远禁止**：不带 --check/--strict 直接跑；运行 `.stage1`。
