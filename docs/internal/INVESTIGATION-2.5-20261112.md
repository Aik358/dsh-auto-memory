# 2.5 白板随事件重绘：当前完成度与剩余缺口（只读调查 · 2026-11-12）

> 只读核对当前源码与文档，不修改生产代码、测试或真实记忆。当前工作树有既有 R4/A1 未提交改动，本报告不改变其归属。

## 结论

2.5 仍有实质缺口。已有「手动 fromEvents 渲染 + 稳定定序 + 旧卡归档留痕」；缺「事件写入成功后的自动重绘触发链」及完整保护验收。

## 已有部分

| 能力 | 当前事实 |
|---|---|
| 手动入口 | memory_note(kind=plan, fromEvents=true) 读取当前工作区事件库并渲染；空库明确拒绝。 |
| 渲染器 | plan-render.js 输出当前状态/近期进展/关键约束/待办；含状态、四段、来源与版本指针，事件 id 稳定定序。 |
| 白板写保护 | writePlanSnapshot 保留 CAS、锁、M1、用户区保护、设置迁移协调、sidecar，不应替换。 |
| 旧卡留痕 | fromEvents 调用把旧白板卡号并入 archivedIds，归档留痕而非物理删除。 |
| 升级路径 | upgrade-apply 使用同一渲染器做整理/预览，不是事件写入后的通用自动重绘。 |

## 剩余缺口

### A. 自动触发链

memory_event 的 create/set/append/close 分支未调用渲染器；renderPlanFromEventsPre 没有事件写成功后的自动调用点。未核实到专用配置键，handoffEnabled/boardMode 不能当该能力开关。面板「改事件→白板自动重画」的文案与当前行为不一致。

建议：在工具调用层增加默认关闭的显式开关，事件事务成功后调度；不改 event-write.js 底层事务。调用走 resolvePaths 与 writePlanSnapshot，不复制保护。

### B. 身份与人工内容

anchoredPlanPre 仍以出现顺序分配 id，事件 id 未直通锚点。手写/旧白板切换到渲染时旧卡通过 archivedIds 归档，需证明无丢卡、无静默覆盖用户内容。用户备注区有保护代码，但自动渲染没有等价合并协议；需明确完全派生投影还是允许人工备注/自有卡。

### C. graph 档与内容覆盖

当前默认 boardMode=graph，sidecar/泳道投影存在；自动重绘不能只验 legacy。需验证 graph 消费、旧卡/人工内容保留与当前实际 PLAN 体积；历史快照数字不是当前证明。

### D. 失败与回滚

失败须可观测，不吞掉「事件已成功、白板未更新」；避免事件锁内嵌套白板/事件写锁；CAS 冲突不覆盖，可重试；off/无 handoff 路径零副作用。R4 documentId/maintenanceTopic 是另一链路，不能把 R4 WAL 当自动重绘完成。

## 建议生产边界

1. 独立、默认关闭的 2.5 自动重绘入口，统一调用现有渲染器与 writePlanSnapshot。
2. 明确人工备注/自有卡承载与合并协议；不靠归档解决。
3. 在 create/set/append/close 既有刷新点后接入，不改事件存储层；index.js 同一时间一个执行者。
4. 验收：off 零副作用；on 事件成功后更新；旧卡/备注/anchors 保留或显式归档；失败可回滚；两进程不覆盖；legacy 与 graph 分别验证。
5. 与 2.6/2.7/2.8 串行；2.4 真实归并继续冻结。
