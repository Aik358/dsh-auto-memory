## 4. 第二关：接线真实性（本批最容易造假的地方）

对 11 个模块逐个回答三问：

1. 公共模块是否导出该能力？
2. `lib/index.js` 是否存在**真实调用点**（给出 file:line）？
3. 调用点传入的是**真实运行数据**，还是被测试夹具/常量替代？

以下情况**一律判为未接线**：

- 只 `import` 不调用；
- 调用点在死分支（如恒假条件、被提前 return 跳过）；
- 调用点只在测试里存在；
- 生产传参是硬编码常量而非真实状态。

## 5. 第三关：内容放大风险（本批最高优先级，必须逐条实测）

**背景**：内容档位与帧节奏是两件事。"帧节奏允许 full"**不等于**"所有内容都投全文"。若实现把内容也一律 full，会造成每轮重复投递大量材料、稀释当前任务、并让通知与版本观测失真。

请逐条核验，并给出证据：

1. **固定档位**：是否存在把 `profile:'full'` / `tier:'human_full'` 写死的调用点？
2. **跨层错用**：是否用规则层的 `_isFullTier` 去决定白板/账本档位？（该集合含 `legacy`、不含 `hang_compensate`，与白板策略不一致，属错用）
3. **截流被绕过**（**严重**）：当 `memLegacy.legacy === true`（存量未迁移）且档位为 `human_full` 时，既有截流（7 节白名单 / 总预算 2400 / 单节上限 800）是否仍然生效？若被绕过，判严重缺陷。
4. **异常回退放大**：公共模块抛错、参数非法、未知档位时，回退路径是否把 slim 放大成全文？**空 catch 静默吞掉档位错误**判不可接受。
5. **档位词表一致性**：生产真实档位（如 `legacy`、`run_full`、`hang_compensate`）是否被公共模块接受？抛 "unknown tier" 即不一致。
6. **重复请求累积**：同输入连续调用两次，输出是否**逐字节相同**？

**必须附量化表**（否则不接受该条结论）：

| 档位 | plan 字符 | plan 字节 | ledger 字符 | ledger 字节 | final 字符 | final 字节 |
|---|---|---|---|---|---|---|

并给出 full / slim 对照，说明差值来自哪一段。

## 6. 第四关：语义等价与边界

逐项给出 是 / 否 + 证据：

- 白板 slim：是否只保留既有核心节？**是否因为白板节没有 `type:` 标签就全部保留**（等于不裁剪）？
- 账本 legacy：是否仍走既有四段加权截断，而不是无限全文？
- 规则 legacy / slim：是否只给指针、不展开正文？
- `human_slim` 是否带维护块，而 `run_slim` 不带？
- 无命中：是否**不回退全文**，并显式记录降级？
- R4：`ledgerDocEnabled` 是否仍默认 `false`？legacy 双读回滚是否保留？
- 2.3（事件归属）：是否仍为 proposal-only，不自动 attach / merge / archive？
- 2.4 与 SidecarStore：是否仍保持冻结，未被本批顺带启用？
- 既有 1.4 行为是否保持（不得以"重构"为由改变对外语义）？

## 7. 第五关：识别"假绿"（本次审核的重点产出之一）

smoke 套件全绿**不等于功能正确**。请抽查 `tests/smoke/smoke-test-batch3-*.mjs`，标出下列恒真型断言：

- 只断言"源码里存在某个字符串/正则命中"——这只能证明文本存在，不能证明行为；
- 只断言"返回值类型是 string/array"，不校验内容；
- 只调用公共模块，**不经过生产入口**——无法证明接线；
- 夹具输入是常量构造，与真实会话数据形状不一致；
- 断言与变异点不在同一层（改生产代码但断言测的是模块自身，变异不会红）。

对每条指出：文件、行号、为什么恒真、应当怎么测（例如从生产代码块抽出到沙箱，注入不同输入真跑并比较输出差异）。
