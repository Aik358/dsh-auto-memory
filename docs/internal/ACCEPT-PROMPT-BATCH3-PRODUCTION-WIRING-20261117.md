## 4. A 部分：已接线模块的功能完整性审核

对每个**你确认已接线**的模块，逐项回答：

### 4.1 接线真实性

1. 生产调用点在哪（file:line）？
2. 传入的是**真实运行数据**还是常量/测试夹具？
3. 是否存在"调用点在死分支"（恒假条件、提前 return、异常必被吞）？

### 4.2 语义等价

- 与改前行为相比，输出是否等价？等价到什么粒度（逐字节 / 语义 / 仅结构）？
- 若不等价，差异是**有意裁定**还是**漂移**？请对照 L1 判断。

### 4.3 内容放大风险（最高优先级）

背景：**内容档位与帧节奏是两件事**。"帧节奏允许 full"不等于"所有内容都投全文"。

逐条核验并给证据：

1. 是否存在写死 `profile:'full'` / `tier:'human_full'` 的调用点？
2. 是否用规则层的 `_isFullTier` 去决定白板/账本档位？（该集合含 `legacy`、不含 `hang_compensate`，与内容选节语义不一致）
3. **截流是否被绕过**：`memLegacy.legacy === true` 且档位为 `human_full` 时，既有截流（7 节白名单 / 总预算 2400 / 单节 800）是否仍生效？
4. **异常回退是否放大**：公共模块抛错、参数非法、未知档位时，回退是否把 slim 放大成全文？
5. **档位词表一致性**：生产真实档位（`legacy`/`run_full`/`hang_compensate`）是否都被公共模块接受？
6. **空白结果**：公共模块返回空串时，生产是接受空白（内容消失）还是回落？
7. **降级留痕**：告警是否真的可被读取，还是"只写不读"（写入后无人消费 = 等于没发生）？
8. **重复请求**：同输入连续两次调用，输出是否逐字节相同？

**必须附量化表**，否则该条不接受：

| 档位 | memLegacy | plan 字符 | ledger 字符 | final 字符 | 是否超预算 |
|---|---|---|---|---|---|

### 4.4 假绿识别

抽查新增 smoke 套件，标出恒真型断言：只匹配源码字符串、只断言返回类型、不经过生产入口、断言与变异点不同层。给出：文件、行号、为什么恒真、应如何改测。

## 5. B 部分：未接线模块的全面研究与方案建议

对每个未接线模块（含你复核后确认零调用的全部符号），产出一份**可执行方案**，包含：

### 5.1 现状

- 公共模块提供了什么能力（导出的 API、入参、返回值、DTO）？
- 它**本应**在生产哪个位置生效？给出你判断的插入点及其上下文（file:line + 周围逻辑）。
- 当前该位置**实际**由什么代码承担同样职责？新旧两套是否并存（并存即双源风险）？

### 5.2 接入方案

请给**至少一个**具体方案，并说明取舍：

- 接入点：改哪个函数、在什么位置插入、前后依赖是什么？
- 参数来源：每个入参从生产哪个真实状态取（变量名 + 行号）？哪些目前**取不到**、需要新增采集？
- 兼容策略：如何保留旧行为作为回滚？是否需要 typeof 兜底（若该函数体被 `new Function` 抽取执行）？
- 顺序依赖：与其它未接线模块的先后关系（例如事件段是否应先于最终帧、最终帧是否必须先统一预算）？

### 5.3 风险与前置条件

- 接入后最可能出现的三类故障（附触发条件）？
- 需要哪些**未决边界**先定案（如整帧预算、事件段额度、full/slim 具体视角）？L1 里哪些属于"未决"，不得擅自定值？
- 是否会影响既有计数锁（工具数 22 / 路由 86 / 配置键 181 / 导出 41）？

### 5.4 验收设计

- 该模块接入后，**怎样才算真的生效**？给出可执行的验证方式（不是"跑 smoke 通过"）。
- 必测的负路径有哪些（至少三条）？
- 如何在不断言源码字符串的前提下验证行为？

### 5.5 建议顺序

把所有未接线模块排一个接入顺序，说明为什么这样排（依赖、风险、可回滚性）。指出哪些可以并行、哪些必须串行。
