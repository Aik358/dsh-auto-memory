## 2. 第一步：**独立复查**（不许只抄前报告）

### 方法 A · 从工具 schema 反推（以 schema 为准，不以铭文为准）

逐条列出 `memory_*` 工具的 **required 参数**，再拿铭文里所有「调用短写」去对：

### 方法 B · 从「铭文要求的行为」反推

## 3. 第二步：**缺失能力盘点**（用户重点，别漏）

列出插件**本来就有、但铭文完全没提**的能力，分三层判断。**注意：判断标准是「不写会不会导致模型做错或想不到」，不是「工具存不存在」。**

### L1 · 每轮必须知道（不写就会做错 / 调失败）

判据：**缺它 ⇒ 模型照铭文做必然失败或必然写错**。典型是必填参数、原子写入特性、去重要求。

### L2 · 需要时应该想到（写不写取决于它值不值那几十个字符）

判据：**缺它 ⇒ 模型不会失败，但会想不到用某个更合适的路径**，导致多轮往返或答非所问。
例如（**候选，需你核实并判断是否值得进铭文**）：

| 能力 | 工具/参数 | 为什么可能值得进铭文 |
|---|---|---|
| 取某事件完整经过 | `memory_recall(expand=evt_xxx, eventId, checkpointIndex 或 idemKey)` | 铭文只说「查全经过用 memory_recall(scope=events)」，但 scope=events 只给摘要，**取全文要 expand** |
| 白板按事件重绘 | `memory_note(kind=plan, fromEvents:true)` | 铭文要求「白板不符就写 plan」，但**手写全文与投影重绘是两条路**，投影那条更省且不会丢卡 |
| 单卡更新白板 | `memory_note(cardId+expectedCardRevision)` | 改一张卡不必重写整篇 |
| 时段总结回读 | `memory_read(kind=summary)` | 批次4 刚做的能力，铭文完全没提 |
| 记忆冲突裁定 | `memory_conflict(action=list/resolve)` | 有冲突时的唯一入口 |
| 技能库查询 | `memory_procedure_list(scope/stage/query/includeNoise)` | 铭文只说「先查技能库」，没说怎么查 |
| 规则增删改 | `memory_rules(op=list/update/remove, expect)` | 铭文只说「规则增删改→memory_rules」，**没说 op 与 expect**（改/删必须带 expect，否则必拒） |
| 外部记忆 | `memory_external(action=list/import)` | 跨工具记忆继承的入口 |

**你要做的**：对每条给出「进 L1 / 进 L2 / 不进」的判断 + 一句话理由（主要是**字符成本 vs 避免的损失**）。**不要全塞进去** —— 铭文塞满工具清单会挤垮规则本身。

### L3 · 明确不建议写进铭文

列出你判断**不该进**的（如 literature_*、calendar_*、memory_fit_*、memory_upgrade 等低频/专用工具），并说明为什么（每轮成本 vs 使用频率）。**这一节同样重要** —— 它证明你想过边界，不是把所有东西堆进去。
