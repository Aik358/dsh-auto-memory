## 2. 本轮实测的四个关键发现（会改变做法）

### 2.1 1.4 的判据有**两份实现，只有内联那份是活的**

| 位置 | 形态 | 是否可达 |
|---|---|---|
| `lib/index.js:24585-24622` | `memory_log` handler 里的**内联 IIFE** | **生产唯一生效路径** |
| `lib/event-write.js:156` `pickActiveEventByTopicPre()` | 模块级导出函数，被 `lib/index.js:37` import | **全仓零调用点**（只有注释提到它） |

⇒ **1.4 只改模块版 = 零效果；只改内联版 = 留下第二份过期实现（下次维护必踩双副本）。** 处置见 **D3**。

### 2.2 1.4 的字面要求与 #543 的用户裁定冲突

总表原文：「…匹配不上再退回「最近 active 事件」」。但 `#543`（2026-11-04 用户裁定 B）正是**取消**「未传 eventId 就挂到最近 active」的行为——它造成正反馈污染（唯一 active 事件吸附一切日志，检查点 append-only 不可逆）。

⇒ 「无标识日志如何处理」是产品取舍，不能由执行者自行定案。见 **D1**（推荐：保留词袋兜底，不回退 #543）。

## 3. 1.4 · 主题门换判据

### 3.1 目标

把「未传 eventId 时挂哪个事件」的判据，从**词袋重合率**升级为**高基数标识匹配**：标识（issue/task/commit/PR/evt id）是强证据，词袋是弱证据。

### 3.2 标识族定义（内联实现，不得引用外部符号）

| 类别 | 正则（草案） | 命中样例 | 必须排除的反例 |
|---|---|---|---|
| GH issue / PR | `#(\d{1,5})` | `#543` `#1234` | Markdown 标题 `# 标题`（数字紧跟 `#`，天然不匹配） |
| issue 词形 | `\bissue[:#\s]*(\d{1,5})` | `issue 543` | — |
| task 号 | `\btask[-_ ]?(\d{1,4})` | `task-38` `task 21` | `taskforce`（有 `\b` + 分隔符要求） |
| PR 号 | `\bPR[:#\s]*(\d{1,5})` | `PR #87` | — |
| commit sha | `\b[0-9a-f]{7,8}\b` **且**含 ≥1 个字母 **且**含 ≥1 个数字 | `551c9b31` `231e67ff` | `20261108`（纯数字=日期）、`deadbeef`（无数字）、`defaced`（无数字） |
| evt id | `\bevt_[0-9a-f]{8}\b` | `evt_23e2976e` | — |

规范化：全部小写；commit sha 取前 8 位；产出 `Set<string>`（形如 `issue:543`、`task:38`、`sha:551c9b31`），避免跨类混淆。

### 3.3 三分支判定

```text
I_log = ids(logText)                    // logText = (gate.clean || note)
候选   = (store0.events || []).filter(status === 'active')   // ★全部 active，不是只看 updatedAt 最大
I_ev(e)= ids(e.name) ∪ ids(e.summary)

① ∃ e : I_ev(e) ∩ I_log ≠ ∅
      → attach（多命中取 updatedAt 最新）
② I_log ≠ ∅ 且 存在 e 使 I_ev(e) ≠ ∅ 且 ∀此类 e 零交集
      → 新建（标识冲突 = 强负证据：明确是另一件事）
③ 其余（I_log 为空；或所有 active 事件 I_ev 均为空）
      → 词袋兜底：现有 0.34 判据，行为逐字节不变（D1=A 时）
```

**为什么分支 ② 只看「有标识的事件」**：无标识事件提供不了负面证据，把它当「零交集」会误拆。

### 9.2 关键实现选择（为什么这么做）

1. **判定仍只走规则**：离线实测 e5 top1−top2 余弦分差中位仅 0.006（最大 0.055），任何阈值都会误并 ⇒ L2 只进回执做候选提示，不参与 attach 决策（套件 J6/J7 钉住「语义可用时仍新建」）。
2. **L2 的触发与成本**：仅 `dryRun` 或「未自动归属 + 引擎已预热（`status().ready`）」时计算；向量按文本 hash 缓存在 `engine._attrVecCache`（≤512 条，事件未变零重复嵌入，套件 J4/J5：首次 `embedPassages=1`、第二轮仍 1）；任何异常降级为「无语义候选」并写进回执，**不阻塞写入**（J8）。

### 10.3 `smoke-test-la5-302` TIMEOUT —— 阈值问题，按重车道处置

实测：单跑 **50 PASS / 0 FAIL / exit=0**，但**自耗 242s**（与干净 HEAD worktree 一致 ⇒ 与本批无关）。
它落在**轻车道**（默认 60s 阈值）⇒ 回归里恒判 TIMEOUT。

**第一版处置（不够）**：按既有口径登记入 `HEAVY_MS` 走重车道（240s）—— 实测仍 TIMEOUT。

**根因**：`runPool(list, width, timeoutMs)` 收的是**车道级单值**，重车道 51 个套件共用 240s；
而 la5 单跑已 242.4s、并发下更慢 ⇒ 车道级阈值对"只有一个套件特别慢"这种形态无能为力。

**最终处置（per-suite 阈值）**：`runPool` 的第三个参数改为接受**函数或数字**——
`resolveTimeout = (n, t) => (typeof t === 'function' ? t(n) : t)`，重车道传入
`(n) => Math.max(heavyTimeoutMs, HEAVY_MS[n] || 0)`。登记值 420000（约 1.7× 余量）。
**为什么不会顺带放宽其余套件**：表内只有 la5 的登记值 > 240000，其余 50 个 max() 结果仍是 240000 ⇒ 逐字不变。

**不抬高全局 `--timeout`**——那会把所有轻套件的挂死发现时间从 1 分钟拖到 4 分钟（该表 105 行已立此判据）。
**验收**：全量回归 **PASS 242 / FAIL 0 / TIMEOUT 0 / FLAKY 0（242.5s）** —— 这是本仓首次全绿。

### 10.7 铭文「压预算」的三次踩坑（教训 · 已固化）

往铭文塞新内容时，第一反应是压缩既有措辞腾空间。本轮连撞三次，每次都被既有断言抓住：

| 轮次 | 压掉了什么 | 谁红 | 结论 |
|---|---|---|---|
| 1 | 「确信可复用就 **action=activate**」→「可复用就 activate」；「**别另写同名新条**」→「别另写同名」 | `smoke-test-i335-procedure-update`（2 条） | 既有断言按**字面**钉这两句 |
| 2 | 「**kind=note 不等于白板/账本**」「**write 直接写 docs/**」 | `smoke-test-t7bcd`（T7d-2/T7d-3） | 同上 |
| 3 | 15 条新行本身 | —— | 正确做法：**只压新增内容**，既有锚一字不动 |

**固化判据**：往铭文加内容前，先 `grep -o '` 出全部对铭文的断言（本轮实测 **4 个套件 + 若干条锚**），
把这些锚当成**不可改动的字面量清单**；腾空间只能压「本次要加的那段」或纯装饰性措辞（如 `**`、`⚠️`、重复括注）。
**不要先压再跑** —— 一次 `grep` 比三次回归便宜。
