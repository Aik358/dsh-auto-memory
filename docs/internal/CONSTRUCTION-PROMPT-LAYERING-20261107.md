## S1 · 规约条目化（治 74.4% 丢失）

**落点**：`lib/rules-layer.js:244-265`（entry → rows 的切分处）与 `:303-325 ruleSummaryPre`、`:348 rowsOf`。

**做法**：
1 对每个 entry 的正文按 `^-\s+` 拆成 bullet 子条目，id = `${entry.id}#${n}`（n 从 1 起），`layer`/`anchorLine`/`at` 继承父条目。
2 每种子条目打 `kind`：命中祈使判据（`禁止|必须|不得|一律|须|不要|改成|要求|只能|应当|不允许`）⇒ `rule`；否则 ⇒ `note`。
3 **不丢弃 note**（用户要求全投），渲染时加中性前缀「（说明）」——保留信息但**不冒充硬约束**。这是本批唯一的语义取舍，必须写进注释。
4 一条 entry 只有 1 个 bullet 时行为与现在逐字一致（不得引入新行）。

**验收（真执行，禁源码断言）**：
- 真跑 `extractRulesLayerPre`（真实两文件：`userFile` 27,392 字符 / `notesPath` 23,747 字符）断言：user **49→93**、project **17→122**；`kind==='rule'` 与 `kind==='note'` 的条数分别打印。
- 抽 3 条此前从未渲染的 bullet（如 `mem_a6f8015d` 的第 2、3 条），断言其文本出现在 `renderRulesSectionPre` 输出里。
- 物理量：输出字符数（预期 8,082 → 约 25,000，实测回填）、条数、sha256。
- **变异**：把拆分开关置 false ⇒ 条数回到 49/17，否则断言无效。
