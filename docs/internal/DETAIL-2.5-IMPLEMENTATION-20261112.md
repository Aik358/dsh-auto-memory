# 2.5 生产实现建议（第二轮 · 2026-11-12）

> 只读方案，未改生产代码。与 2.6–2.8 的第二轮独立调查并行；旧路径共享写入处由 Lead 串行裁决。

## 结论

2.5 不需要新渲染器、第二套事件 WAL 或真实数据迁移。应补一个**默认关闭、事件事务成功后调用、失败可见**的自动重绘入口。

## 1. 正确的触发边界

- 在 memory_event 的 create/append/set/close 对应成功分支接入；rename 改变标题也应覆盖，不能漏。
- 放在 eventStorePre 对应写操作成功返回之后、工具返回之前。
- **不要放在 refreshEventStatePre 之后**：它是刷新链，不是事件提交边界，可能造成重入或额外写入。
- 不改 event-write.js / event-store.js 底层锁；不在事件锁内再次进入白板或事件写入。
- 使用本次 p/resolved paths，不重新猜工作区；未绑定或 handoffEnabled=false 时不重绘。

## 2. 建议 API 与配置

- 单一引擎方法：自动读取当前事件库、renderPlanFromEventsPre、复用 writePlanSnapshot。
- 返回结构化状态：{ok, path, revision, bytes, eventCount, archivedIds, warning/error}，不用布尔吞错。
- 新开关 planAutoRedrawEnabled，默认 false；不改变 boardMode 或 R4 的 ledgerDocEnabled 语义。
- 返回给模型的事件成功文本仍保留；另加重绘成功/失败附注，禁止将事件已成功误报为整体失败。
- 首期只支持同一工作区同步、确定性重绘；不自动迁移、不清理旧账本、不做真实归并。

## 3. 身份与人工内容（写前保护，不能只做归档）

- 稳定 ordinal 只能保证同输入顺序稳定，不等于事件 id 锚点直通；渲染器还会先按 startMs/createdAt 排序，改名/改时间可能改变位置。
- anchoredPlanPre 不会自动继承旧 id；M1 可降级且 archivedIds 是「合法消失」豁免，不是内容保留。
- **自动写前必须先做内容映射**：事件 id → 旧锚点/用户区；无法映射的自有卡原样保留；再进入现有 CAS/M1/迁移锁。
- 默认语义建议：事件派生区可重绘，人工备注/自有卡不应因切换自动重绘被归档。需要保留的人工区域必须有显式承载，而不是把全部旧卡塞进 archivedIds。
- 若决定采用完全派生投影，须另行裁定旧人工内容的保留/迁移协议；本批不自行创造「旧卡全部归档即无损」结论。

## 4. 失败与回滚

- off、未绑定、空事件库：不写 PLAN，返回明确 skipped 状态。
- CAS/M1/用户区拒绝：事件不回滚、不重试覆盖；附真实错误和可重试提示。
- 重绘失败不得回写一条新事件检查点，避免 memory_note 与 memory_event 循环放大。
- 回滚为关闭开关/撤掉触发调用；不删除或修改已有事件、PLAN 归档或用户内容。
- 首次启用仅在隔离工作区；生产19387和真实记忆均不动。

## 5. 并行调查边界

- 2.5 只调查触发、身份、graph消费和隔离验收；不改 lib/index.js。
- 2.6/2.7/2.8 各自独立复审；共享 memory_note 的生产修改由 Lead 串行安排。
- 2.4 真实归并冻结；G-1/G-2与R4/A1不在本批顺手改。

## 6. 必须验收

1. off/未绑定时零副作用；on 后 create/append/set/close/rename 均更新正确 PLAN。
2. 重复事件写入或 idem 去重时，不因刷新链重复重绘。
3. 旧卡归档数、锚点数、用户备注区、PLAN 字节数可复算；无静默丢卡。
4. CAS/M1/保护门拒绝时事件已成功、重绘失败如实分离。
5. graph 与 legacy 分别验证真实读盘/面板消费，不只看源码字符串。
6. 两进程竞争不覆盖；锁内不嵌套；错误恢复可重试。
7. 真 import→真调用→真读写隔离工作区，记录 PASS/FAIL、字节数、sha256；本轮不宣称这些已执行。
