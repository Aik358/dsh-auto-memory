## 1. 为什么必须改（问题定性，非「调比例」）

v2 把 `conversation.view` 会话页做出来之后，用户实测反馈两个问题：

| # | 现象 | 根因（代码证据） |
|---|---|---|
| A | 点页头「切换浮层」后，**上面的东西消失、连按钮一起消失**（共存档下尤甚） | `MemoryPageView` 页头的按钮执行 `controller.setPanelPos('bottom-left')`；而会话页签仅在 `panelPos === 'page' \|\| 'both'` 时注册（`lib/client.js` registerSurfaces 内）。点一下即把当前页签注销 ⇒ **自毁按钮** |
| B | 整体「看着奇怪、有拉伸」 | 把为 **440px 浮层**设计的界面（12 个横向滚动页签 + 单列纵向堆叠 + 小字距）**原样**铺到 1400px+ 整页，**没有任何大屏版式**。这不是比例问题，是版式缺失 |

用户原话：「你把一套通过小窗口表达的资源扔到了大窗口上，但未做任何优化」「我觉你在上方整页的情况之下，要大改这个 UI」。

## 2. 已拍板方向（用户二选一确认）

- **骨架**：**左侧固定侧栏导航 + 右侧多列栅格内容区**（不再用顶部横向滚动页签）。
- **范围**：**全部 12 个 tab 都做大屏版式**（概览 / 日志 / 精修 / 记忆中枢 / 存储 / 笔记 / 白板 / 反思 / 连接 / 日历 / 搜索 / 工作区）。


### 3.1 硬性要求

1. **删掉自毁按钮**：页头不得再有会注销本页的操作。若保留「切到浮层」入口，必须改为
   *先保证页签不消失*（例如改为「打开浮层并保持页签」，或直接移除该按钮，改由设置页切换）。
2. **浮层与小页各用一套版式**：窄容器（浮层）继续用现有紧凑布局；宽容器（会话页）走新的大屏布局。
   两者共享**数据与状态**，**不再共享同一份版式**。
3. **响应式断点**：侧栏在窄窗（< ~900px）应折叠为图标条或顶部横条，避免页签被压扁。
4. **去掉浮层专属控件**：拖拽手柄 / 关闭 / 钉住对大页无意义，不应出现在页头。
5. **动效**：等用户提供的 design skill 到位后统一做（切换分区、卡片入场、栅格重排）。

## 4. 实施前必须先修（本轮审计产出的前置项）
