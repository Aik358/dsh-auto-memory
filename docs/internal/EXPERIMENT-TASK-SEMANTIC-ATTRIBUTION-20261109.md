# 任务书 · 语义归属实验 v3（验证 1.4 的 L2 排序 + L3 模型裁决）

> 2026-11-09 · 关联：施工总表 1.4 / §15 候选排序器 / 批次 5.1 铭文
> 本文件只出实验方案与数据包说明，不含产品代码改动。
> **v1 / v2 数据包已作废**（原因见 §10），现行数据包是 **v3**。

## 0. 为什么做这个实验

1.4 要解决的是「未传 eventId 时这条日志挂哪个事件」。现行判据（词袋重合率 ≥0.34）在 211 条真实日志上实测：

| 事实 | 实测值 |
|---|---|
| 按现行判据（只比「最近更新」事件）通过 | **0 / 211 = 0%** |
| 扫全部 47 个 active 取最高分 | 12 / 211 = 5.7% |
| 理论最高命中率（事件词集 ÷ 日志词数）中位 | 0.351；另有 45.9% 条目数学上不可能过线 |

⇒ 不是「阈值太严」，是**口径错配 + 候选集只有 1 个**，等于每条日志都新建事件。

语义模型（C2 e5-small q8，384 维）实测（金标=独占标识，n=37）：name+summary top-1 48.6%；+四段 32.4%；
**+最近 3 检查点 top-1 54.1% / top-3 75.7%**；全体 top-1 余弦挤在 0.905–0.928、top1−top2 分差中位 0.006–0.012。

⇒ **语义能排序、不能靠阈值判定**。1.4 因此定为四层：L1 标识硬判 → L2 向量排序 → L3 模型裁决 → L4 词法兜底。
本实验只验证 **L3**：给定 L2 候选（及 L1 信号），模型能不能判对。

## 1. 假设与预注册判据（先定死，后看结果）

| 编号 | 假设 | 判据 |
|---|---|---|
| H1 | 纯语义候选 + 模型判断，在「候选里确实有正确答案」的 case 上能判对 | **A 轮 covered 命中 ≥ 25/33（76%）** |
| H2 | 给上 L1 信号后达到可上线水平，且不制造误并 | **B 轮 covered 命中 ≥ 44/53（83%）且 new 组误并 ≤ 1** |
| H3 | 「拿不准」是真实存在的态 | uncertain 率 15%–35%（过高=没判断力，过低=硬猜） |
| H4 | L3 必须优于「纯 L1」基线 | B 轮 covered 命中 **> 26/53（ruleL1 基线）** |

**否决线**：A 轮 covered < 20/33 且 B 轮 covered < 38/53 ⇒ L3 不成立，1.4 退回「L1 规则 + L4 词法」。

### 2.1 案例从哪来、金标怎么定（**这是 v3 与 v1/v2 的关键差别**）

- 案例：2026-11-04 起的真实日志条目 92 条（`WS/*.md` 的 `- HH:MM [kind:…] 正文` 行）。
- **金标 = 检查点溯源（provenance）**，不用规则猜：每条日志都能在事件库里唯一定位到「它当时被写进的那个事件」。
  - `kind=attach`（77 条）：该事件在本条之前已有检查点 ⇒ 决策时它**已存在**，正确动作是挂它。
  - `kind=new`（15 条）：本条就是该事件的**第一个检查点** ⇒ 决策时该事件**尚不存在**，正确动作是新建。
  - 其中 5 条 attach 在遮蔽后「无可辨识材料」⇒ `answerable:false`，**不进准确率分母**（否则不可答）。
- 只取 2026-11-04 起，因为此前的归属由旧逻辑「无脑挂最近更新的事件」决定（#543 之前的缺陷），**其归属不可信**。

### 2.2 遮蔽（防泄漏）—— v1/v2 就是死在这里

因为案例是**已经写进库的历史条目**，事件材料里天然含「本条日志原文」，模型可直接字符串匹配得答案（v1 试点 c001 就是这么「对」的）。v3 做了三件事：

1. 候选事件材料里**剔除与本条日志相同（或为其前缀）的检查点**；
2. 若事件名与本条日志高度重合（事件由该条日志创建），该候选的 `name` 置 `null` + `nameMasked:true`；
3. `kind=new` 的 case，把「由本条创建的那个事件」**从候选池里整体移除**（决策时它不存在）。

体检：v3 cases 里目标日志原文出现次数 = **0**；含 `goldSource` = false。

## 3. 两轮独立判定

| 轮次 | 允许看 | 可挂集合 | 输出 |
|---|---|---|---|
| **A 纯语义** | `log` + `candidates`（忽略 `identifier` / `l1Candidate`） | `candidates`（语义 top-5） | `out/results-A.jsonl` |
| **B 完整链** | 同上 + `identifier`（L1 信号）+ `l1Candidate`（L1 指到的事件的材料） | `candidates ∪ l1Candidate` | `out/results-B.jsonl` |

> 先跑完 A 全部 92 条，再开 B；不得跨轮复用结论。`l1Candidate` 只在该 case `identifier.decision=match` 时存在。

## 4. 指标与基线（评分器实测，可直接复算）

| arm | 覆盖 | attach 命中（覆盖内） | attach 命中（全集 72） | new 正确 | 误并 | uncertain |
|---|---|---|---|---|---|---|
| `baseline:embTop1`（直接取语义第一名） | 33 | 15/33 = 45.5% | 15/72 = 20.8% | 0/15 | **15** | 0% |
| `baseline:ruleL1`（纯规则层） | 53 | 26/53 = 49.1% | 26/72 = 36.1% | 1/15 | 4 | 56.5% |

两个关键读数：
1. **覆盖是硬上限**：语义 top-5 只覆盖 33/72（45.8%）的正确答案；加上 L1 才 53/72（73.6%）。
   ⇒ attach 准确率必须与覆盖一起看，否则分母里混进了「候选里根本没有正确答案」的 case。
2. **纯 L1 会误并**：15 条新事里它判挂 4 条；纯语义第一名更糟，15 条全挂（误并 15/15）。
   ⇒ L3 的价值 = 在 L1 点不中的地方补判 + 在 L1 指错时否决。

## 5. 评分与人工抽查

```bash
node artifacts/_ranker-prototype-v3-20261109/evaluate.mjs \
  --gold  artifacts/_ranker-gold-v3-20261109/gold.jsonl \
  --cases artifacts/_ranker-prototype-v3-20261109/cases.jsonl \
  --a out/results-A.jsonl --b out/results-B.jsonl --out out
```

评分器负路径已自测：少行、重复 caseId、非法 decision、`attach` 缺 eventId、**eventId 越出该轮允许集合** 全部 exit 1。

**人工抽查（必须做）**：
1. B 轮在 `new` 组判 `attach` 的每条（误并嫌疑）；
2. 两轮结论翻转的 case（标识信号的真实贡献）；
3. A 轮「金标在候选内却判 new/uncertain」的 case（判断力问题，不是覆盖问题）。

## 6. 风险与已知局限

| 风险 | 处置 |
|---|---|
| 单一评判者偏差 | 用另一个对话/模型跑；不要用写这份任务书的人当执行者 |
| 金标仍非「人类理想答案」 | provenance 记录的是「当时写进哪个事件」。11-04 后发现归属已由显式 eventId 或新建决定 ⇒ 可信；但仍是**当时的判断**，不是绝对真理 |
| 样本量 92（attach 可答 72） | 结论粒度到 ±3 条，不报小数点后一位 |
| 遮蔽可能过头 | 5 条被标 `answerable:false` 已从分母剔除；若执行者觉得某些 case 不可答，记为 `uncertain`（H3 也看这个） |
| 上下文长度 | 92 条建议分批（每批 30 条），批间不复用结论 |
