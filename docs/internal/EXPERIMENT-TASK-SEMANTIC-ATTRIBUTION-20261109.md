# 任务书 · 语义归属实验（验证 1.4 的 L2 排序 + L3 模型裁决）

> 2026-11-09 产出 · 关联：施工总表 1.4 / §15 候选排序器 / 批次 5.1 铭文
> 本文件只出**实验方案与数据包说明**，不含产品代码改动。数据包已生成本机，路径见 §2。

## 0. 为什么现在做这个实验

1.4 的出发点是「未传 eventId 时挂哪个事件」，现行判据是词袋重合率 ≥0.34。实测（211 条真实日志）：

| 事实 | 实测值 |
|---|---|
| 现行 0.34 判据通过率（只比「最近更新」事件） | **0 / 211 = 0%** |
| 即便扫全部 47 个 active 取最高分 | 12 / 211 = 5.7% |
| 理论最高命中率（事件词集 ÷ 日志词数）中位 | 0.351，另有 45.9% 条目数学上不可能过线 |

⇒ 结论：这不是「阈值太严」，是**口径错配 + 候选集只有 1 个**，等于每条日志都新建事件。

语义模型（C2 e5-small q8，384 维）实测（金标=独占标识，n=37）：

| 事件表示方式 | top-1 | top-3 | top-5 |
|---|---|---|---|
| name + summary | 48.6% | — | — |
| + 四段 | 32.4% | — | — |
| **+ 最近 3 条检查点** | **51.4%** | **75.7%** | **83.8%** |

且全体 top-1 余弦挤在 0.905–0.928、top1−top2 分差中位 0.006–0.012（max 0.055）⇒ **语义可以排序，不能靠阈值判定**。

所以 1.4 定为四层：**L1 标识硬判 → L2 向量排序 → L3 模型裁决 → L4 词法兜底**。
本实验只验证 **L2 给的候选 + L3 的模型判断，能不能真的把归属判对**；L1/L4 都已有明确规则，不需要实验。

## 1. 假设与判据（先注册，后看结果，避免事后解释）

| 编号 | 假设 | 预注册判据（数字先定死） |
|---|---|---|
| H1 | 只看语义候选（不用标识），模型也能判对多数强金标 | **A 轮 exclusive ≥ 30/37（81%）** |
| H2 | 给上标识信号后达到可上线水平 | **B 轮 exclusive ≥ 32/37（86.5%）且 unsafeMerge ≤ 10/100** |
| H3 | 「拿不准」这一态是真实存在的，不是模型偷懒 | uncertain 在 ambiguous 组 ≥ 40%，在 exclusive 组 ≤ 15% |

**否决线**：若 A、B 两轮 exclusive 都 < 27/37（73%），则 L3 不成立 ⇒ 1.4 退回「L1 规则 + L4 词法」，
语义仅作**提示**（在回执里给 1 个候选让模型自己决定，不参与自动判定）。

### 2.1 数据是怎么造的（可复算）

- 来源：本工作区 `2026-10-26` 起的真实日志条目 **211 条**（`WS/*.md` 的 `- HH:MM [kind:...] 正文` 行）＋ 事件库 47 个 active 事件。
- 候选：e5-small q8（C2）对「事件 name+summary+最近 3 检查点」编码取余弦 top-5，`cosine` 原值随 case 给出。
- 标识信号：`#\d{1,5}` / `issue \d+` / `task-\d+` / `PR #\d+` / 7–8 位 hex（须同时含字母与数字）/ `evt_[0-9a-f]{8}`。
- 金标（**只用规则，不做人工标注**，所以每档都带 `goldConfidence`）：

| goldSource | n | kind | 置信度 | 含义 |
|---|---|---|---|---|
| `rule-exclusive-id` | 37 | attach | high | 日志里有**只属于某一个**事件的标识 ⇒ 强金标 |
| `rule-identifier-no-match` | 100 | new | medium | 日志有标识，但没有任何 active 事件含它 ⇒ 应为新事 |
| `rule-ambiguous` | 11 | none | none | 多个事件各自有独占标识 ⇒ 规则判不了 |
| `rule-partial-no-exclusive` | 14 | none | low | 有交集但无独占标识 ⇒ 规则判不了 |
| `no-identifier` | 49 | none | none | 日志无标识 ⇒ 无金标，只观察行为 |

> **诚实披露**：`rule-identifier-no-match` 这一档的「应为新事」是**推论**，不是人工确认——可能是同一件事被拆成了
> 多个都没标识的事件。所以评分时这一档只看「new 正确率 / 误并率」，**不把它的分歧直接判为模型错**；
> 分歧条目要人工抽查（见 §5）。

## 3. 实验设计：两轮独立判定

| 轮次 | 输入 | 要求 | 为什么需要 |
|---|---|---|---|
| **A 纯语义** | `cases.jsonl`，**忽略 `identifier` 字段** | 只看 log + 候选 | 测「语义候选 + 模型判断」本身的上限 |
| **B 完整链** | 同文件，**使用 `identifier` 字段** | match/conflict/none 作硬信号 | 测真实生产形态（L1+L2+L3） |

两轮必须**先跑完 A 再跑 B**，且不得跨轮复用结论（否则 A 被污染，等于没测）。
输出 schema 与约束见 `README.md`（同一份，执行 Agent 只看那个）。

## 4. 指标与已算出的基线

| arm | exclusive 准确率 | wrongAttach | new 正确率 | unsafeMerge |
|---|---|---|---|---|
| `baseline:rule`（直接用 L1 信号） | **100.0%** | 0 | **100.0%** | 0 |
| `baseline:embTop1`（直接取语义第一名） | 51.4% | 18 | 0.0% | **100** |

**这两个基线是本实验最重要的对照**：
- 纯规则在强金标上 100%，但它只能覆盖 37/211（其余 174 条完全没有主意）⇒ 所以需要 L2/L3；
- **纯语义第一名的误并率是 100/100**——它会把每一条「新事」都挂到某个旧事件上。这就是「语义不能做判定」的最直接证据。

因此 L3 的价值不在「把 37 条判对」（规则已经能），而在**处理另外 174 条**：
候选里有没有正确事件、模型能不能在「新事 / 已有事件 / 拿不准」之间做对。

## 5. 评分与人工抽查

```bash
node artifacts/_ranker-prototype-20261109/evaluate.mjs \
  --gold  artifacts/_ranker-gold-20261109/gold.jsonl \
  --cases artifacts/_ranker-prototype-20261109/cases.jsonl \
  --a out/results-A.jsonl --b out/results-B.jsonl --out out
```

评分器自带负路径（自测已验证）：缺行、重复 caseId、`attach` 缺 `eventId`、非法 decision 都会直接报错退出（exit 1）。

**必须人工抽查的两类**：
1. `B 轮` 在 `new` 组判 `attach` 的（误并嫌疑）——逐条看是否其实同一件事；
2. 两轮之间**结论翻转**的 case（A 判 X、B 判 Y）——这是「标识信号到底帮了多少」的直接证据。

## 6. 风险与已知局限

| 风险 | 处置 |
|---|---|
| 单一评判者偏差（同一模型自评） | 建议**用另一个模型/另一个对话**跑；至少保证执行者不是写这份设计的人 |
| 上下文长度 | 211 条一次性喂会超长且质量下降 ⇒ **分批**（建议每批 40 条，批间不复用结论） |
| 金标噪声 | `rule-identifier-no-match` 置信度 medium ⇒ 只看比例 + 抽查，不当绝对真值 |
| 泄漏 | 金标单独存放于 `artifacts/_ranker-gold-20261109/`，README 明示「本目录没有金标」 |
| 样本规模 | 强金标只有 37 条 ⇒ 结论粒度到「±3 条」为止，不要报小数点后一位 |

## 7. 三种结局分别怎么用

| 结局 | 判定 | 后续动作 |
|---|---|---|
| B 达标（H2 成立） | 接入 L2+L3 | 1.4 按四层实现；回执三态 + 候选列表；阈值只用「分差」作提示、不作自动判定 |
