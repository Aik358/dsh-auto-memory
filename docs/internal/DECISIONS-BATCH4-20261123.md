## D4-1 · 2026-11-23 · 4.3 读全局时段总结

**触发**：Codex 实测 `summarizePeriod()` 聚合**多个工作区**并把结果写到用户级 `summaries/`，记录字段只有 `summary` / `works` / `generatedAt` / `cached`，**无工作区身份**；旧文件无法按工作区可靠拆分。任务书「该工作区最新一条」前提不成立。

**裁定**：采纳 A。读最新一条**全局**时段总结，响应标注 `scope:"global"`。不得为迁就本项改动总结的生成逻辑或存储布局（4.3 是纯读）。

**排序**：`generatedAt` 降序 → 缺失/非法/`<=0` 用 mtime 兜底 → 仍相同按文件名降序稳定排序；返回值必须等于排序第一，验收须构造「mtime 与 generatedAt 相反」的夹具。

**契约**：必须含 `scope:"global"`、来源绝对路径、`generatedAt`（或 null + mtime 标注）、字节长度、正文全文；正文与磁盘**逐字节相等**（sha256 对照）。空态与读失败必须可区分（目录无候选 = 空态；文件存在但读/解码失败 = `unreadable`），不得伪装为空成功。

**教训**：任务书把「时段总结属于工作区」当作既定事实，实测是全局统揽。**判据写之前先验前提**，否则实现方只能停手或做偏。

## D4-2 · 2026-11-23 · 4.5 去重只接 `units`

**触发**：Codex 实测 `legacy` / `eventView` / `units` 三档都会重复投递同一段账本与检查点正文；三档都去重会改变默认 `eventView` 的字节输出。

**裁定**：采纳 A，仅 `units`。理由：D30B-14 把缺省定为 `eventView`，其价值是「缺省行为零变化 + 可原样回滚」；在兼容档去重会让默认行为漂移，须重新裁定 D30B-14 的字节等价约束，不在本批授权内。

**必须显式披露**：`eventView` 的重复写进回执「未解决」组与 CHANGELOG 草稿「仍未问题中 / 未验证」组，不许用「已修复」概括。

**保留判据**：账本入选且完整 ⇒ 保留账本原段位、省检查点同文；账本关闭/只投指针/未入选 ⇒ 保留检查点正文；差一字符两份都留；去重后那份必须仍在原段位。

**追加约束**：①去重键 = 规范化后逐字节相等指纹（CRLF→LF、去首尾空白），禁模糊匹配；②去重须在 `measureFrame` 之前或同步，避免预算虚高；③无同文场景的 `units` 三场景 digest 实现前后必须逐字节相同（先取实现前 digest）；④`pushPart` 口径按 31 命中 = 28 具名直调 + 1 通用转发 + 2 注释。

**教训（复现）**：我给的「31 处」是 grep 命中数，含注释；提问方分层为「具名直调 / 通用转发 / 注释」才有判断价值。验收判据要写**功能覆盖**。
