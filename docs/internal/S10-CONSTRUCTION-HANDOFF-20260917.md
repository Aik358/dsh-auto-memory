## 三、缺口 4⑤ 的纪律方案（用户的核心思路）

### 结论：**合法**，且比"造一条 LLM 通路"便宜一个量级

三条理由（已核实）：
1. **契约只禁"自动路径"**：§6 原文「需要 LLM 的一类（**必须手动触发，不进自动路径**）」。而「每轮收尾主代理写记忆」**不是自动路径** —— 是主代理在环的有意识判断，与人工触发同性质。
2. **工具通道现成**：`memory_note_pre(kind=plan)` 就是写白板的口子（`index.js:543` 的 `snapshotPlanTitle` 已告知模型"内容过时可用它重写"），且**过判据门 + 保护门**（`:1939`/`:2020`），丢卡会被拦。
3. **白板本就是"模型维护区"**：契约 §5 人机分区已规定模型写哪段。

### 但**必须先解决的前提**（实测）

**当前 `GUIDANCE` 对白板零覆盖** —— 逐字扫过：
```
白板 no   PLAN no   kind=plan no   handoff no   账本 no
```
`GUIDANCE`（`index.js:143`，**845 字符 ≈ 423 token**）是每轮注入的记忆纪律，**详列了各 memory_* 工具，唯独没提白板**。
⇒ **模型被明确要求"做记忆"，但从未被要求"维护白板"。这才是白板腐烂的真因 —— 不是模型偷懒，是纪律里没这条。**

### 所以要做的：「扩写 `GUIDANCE`」（用户说的"固化文档"）

**零新增管线** —— 它本来就每轮注入，加几十字符即可。

### 三条设计要点（**必须守住**）

**① 写成「条件触发」，不是「每轮都做」**
否则每轮改白板 → 噪声 + token 浪费。
措辞方向：「**当本轮产生与白板既有结论冲突的信息、或完成了白板上的目标时**，用 `memory_note_pre(kind=plan)` 更新」。

**② 必须写明「只报告、不自动删」**
契约 §6 尾注为硬纪律。否则模型会把"清理白板"理解成"删卡片" → 违反 §4 写入门（会被拒，但模型会反复试）。

**③ 白板关闭时不得有副作用**
`handoffEnabled=false` 时白板不读不写（`:3581`、`:3615` 已有解耦处理）。
纪律里须说明「白板未启用时跳过」，否则模型会去找不存在的 PLAN.md。

### 已纠正的数字误记

用户说的「默认 10000」**不是注入预算**：
- `SECTION_ORDER = 10000`（`index.js:137`）是**注入顺序** —— 末尾注入，让模型最后读到、遵循度高
- 真实注入预算是 `injectBudgetChars = 8000`（本机配置实测）
- **但用户直觉指对了位置**：那个"最后读到"的位置，正是放纪律最合适的地方
