## 4. A1-c 维护文档正式写入（11 PASS / 0 FAIL）

### 4.1 新接口

`memory_note` 新增 3 个参数（与既有 17 键并存，**旧键语义零变化**，现共 19 个属性）：
- `documentId`：只能是注入面/面板**实际给出**的身份，格式过 `validateDocumentId`；
- `expectedRevision`：维护文档 CAS；**与白板卡片的同名字段是两个不同字段**（描述里明写，避免混用）；
- `changeSet`：`[{regionId: title|content|eventIds, afterText}]`；缺省按 content 整段替换。

### 4.2 分流规则（关键）

```
kind=handoff 且给了 documentId
  ├─ ledgerDocEnabled !== true（现场读配置）⇒ 明确拒绝，不降级
  ├─ documentId 形状非法 ⇒ 拒绝
  ├─ 读不到该文档 ⇒ document-not-found（不静默新建）
  ├─ 缺 expectedRevision ⇒ 拒绝并回报当前 revision
  ├─ revision 不匹配 ⇒ document-version-conflict，零写入
  └─ 全部通过 ⇒ upsertDocument（CAS + WAL + changeset-base-match），回执「维护文档已更新 … (revision sha256:…)」
kind=handoff 且没给 documentId ⇒ 原样 writeHandoffLedger（旧账本，append-only）
kind=plan ⇒ 原样 writePlanSnapshot（未动）
```

### 4.3 实现要点

- 新增 `ledgerDocWriteSystemForPre(handoffDir)`：**可写**门面（`readOnly:false` + `EventStoreLedgerSink` + WAL），**不复用**只读缓存实例（只读实例 `readOnly:true` 且无 eventSink ⇒ `wal-not-configured`，首版即踩此坑并修正）。
- `changeSet` 的 `beforeText` **一律取当前文档真实文本**（不信任调用方传入），`changeset-base-match` 才成立；首版漏 `beforeText` 被 `changeset-invalid` 拦下并修正。
- `opId` 用 `r4op_` + `randomUUID().replace(/-/g,'')`（32 hex，满足 `OP_ID_RE`）。
- 回执区分「维护文档已更新」与「交接账本已写入」，避免模型分不清改了哪条路径。

### 4.4 变异验证（3 组，隔离副本，已还原）

### 14.1 缺口一：documentId 分支仍先写旧全文检查点（已修）

**原缺陷**：`memory_note` 的顺序是 Phase 1（`appendHandoffCheckpointPre` 写 `ledgerText` 全文）→ Phase 2a（R4 WAL 写文档）。⇒ 同一次写入被记**两套事件**；CAS / shape / 缺 revision 等**可预期拒绝**发生在 Phase 1 之后，事件已 +1。

**修法**：`lib/index.js` 的 `memory_note` handoff 分支**整体前移到 Phase 1 之前**；Phase 1 与 Phase 3（失败补偿）改为 `if (!docWrite) { … }`。
