## 组 1

旧版正式路由重现：9 MiB MEMORY.md/history.jsonl 未进入既有文件清单，默认 keep 覆盖；大 .from-pack 文件名未预留，rename 覆盖；同字节长度的大文件变化未使 previewToken 失效；注入真实读文件边界的 EACCES 被吞后视为新增；在重算计划/备份后创建的新文件被最终 rename 覆盖。故该组成立，不以提高 8 MiB 上限代替修复。

现在清单包含所有占用名称，小文件保留正文，大文件保留字节数和流式 SHA-256，目录/特殊文件保留占位。只有目标根目录确实 ENOENT 才视为空；其它枚举/读取失败明确拒绝 inspection/import。keep 保护所有既有名称，rename 同时预留目标清单与整包名称，overwrite 只允许常规文件且能报告大文件真实旧字节数。

previewToken 使用排序的完整清单，包含改名候选与大文件摘要。非空目标先做完整常规文件备份，备份名增加 UUID 防同秒互相覆盖。与来包相同的已知正文不再实际写入。新增/改名文件写完整同目录临时文件后 link 到目标，EEXIST 不覆盖并发新增；显式覆盖在合作锁内重新核对目标文件类型/摘要，再沿用原子写。PLAN 的原有新鲜 revision/conflict 分支保留。

边界：新增提交依赖文件系统硬链接支持；不支持时明确返回 write-failed，保留原目标，不降级为覆盖 rename。本环境验证 POSIX 文件系统，没有 Windows 实机文件系统验收。常规覆盖的摘要核对与 rename 之间仍可能被不合作外部编辑器改动；备份和失败列表保留，未声称任意外部写者都具事务隔离。多文件包仍为顺序提交，失败返回已写列表与备份，不声称整包原子性。符号链接/特殊文件仅保留名称，不声称 copyDir 会备份其链接对象；overwrite 此类目标明确拒绝。

## 组 4

旧版 POSIX→Windows 写入原始反斜杠，`D:\projects\app` 可变成非法转义，`D:\temp\new` 的 `\t`/`\n` 则可能解析成功而值已损坏。反向 Windows→POSIX 的初始用例通过，未将其误报为所有方向必失败。

JSON/JSONL 现在先验证格式，对每个原始字符串 token 解码，再运行原有单次字面量路径替换，只有变化的 token 才 JSON.stringify 编码。因此保留空白、行尾、未变化转义拼法和超安全整数范围的原始数字文本；不经整对象重序列化。普通文本路径替换保持原逻辑，同路径/rewriteBody=false 保持逐字节不变。双向迁移、tab/newline、JSONL CRLF、URI、未修改字符串和数字都有值级验收；不是仅检查 JSON.parse 不抛。格式损坏的 JSON/JSONL 在需重写时明确拒绝，而不是继续写损坏正文。
