# Issue 反馈（roadmap-aligned，2026-08-26）

感谢你详细的 issue——这正是我们 roadmap 里无人值守场景的核心诉求。以下是已落地/计划的对齐：

## 已实现（本次发布）

**1. 独立「无人值守模式」开关（默认关）**
设置 → 自动化 → 无人值守模式。开启后：
- 不再注入欢迎回来指令、行为指令、暂离/回归提示、日历提醒
- 只注入纯事实记忆（最近日志/反思/笔记摘要）
- 这解决了你观察到的「每轮回复以 Welcome back! 开头」——该指令完全剥离

**2. 工作区锁定（修复路径漂移）**
无人值守模式下，插件锁定当前工作区：即使子代理/工具改变了 cwd，也沿用已锁定路径，不再「context flips to unrelated path」。你的 ToolCallError 循环（edit requires reading first）正是由此消除。

**3. 自动检测（roadmap 承诺的 auto-detection entry）**
新增「夜间/非工作时间自动托管」开关（默认关）：本地时间处于非工作时间窗（默认 22:00-08:00，可配置）时自动进入无人值守模式；手动开关优先。自动托管任务运行时也会触发（钩子已预留）。

**4. 注入预算可调 + 已调低默认**
记忆快照注入预算（`injectBudgetChars`）默认从 2400 → 1600 字符，设置页可调。快照「变化才追加」由框架去重保证，不每轮膨胀。

## 路线图（后续发布）

- **新记忆插入机制**：从「整块注入」改为「可召回」——记忆进入上下文即使模型不主动调用；该机制自带开关（避免影响托管运行的注意力）。
- **独立开关持续扩展**：所有非核心功能（问候/日历/暂离/拟人化）将逐个拆成独立 toggle，而非一揽子。

## 说明
- 无人值守模式是**纯事实注入**：只保留对任务有用的记忆内容，剔除所有社交性/行为性指令。
- 与你的「托管模式」判断可联动：模型侧判断托管时，可驱动该开关（钩子已预留）。

如果你还有具体场景（如特定时间窗、托管任务触发条件），欢迎补充——我们会按此迭代。
