## 一、概念图的共性（先说结论：它不是"一个新页面"，是一套设计语言）

逐张比对后，概念图表达的是**同一套设计系统的 10 种应用**，共性有 7 条：

| # | 共性 | 说明 |
|---|---|---|
| 1 | **左侧固定侧栏** | 品牌区（logo + 名称 + 一句 slogan）+ 一级菜单（图标 + 中文名）+ 底部"本地优先"状态块 |
| 2 | **顶部工具条** | 居中的大搜索框（含快捷键提示 ⌘K）+ 右侧主题切换 + 用户信息区（头像 + 名字 + 一句话签名） |
| 3 | **页头带格言** | 每页右上角有一句斜体格言 + 署名「—— dsh-auto-memory」，这是**品牌资产**，应当模板化 |
| 4 | **白色卡片 + 细边框 + 柔和阴影** | 卡片圆角约 12–16px，边框极浅，阴影极淡（几乎是 1px 描边 + 微投影） |
| 5 | **统计卡横排** | 每页顶部 3–4 张统计卡：彩色圆角图标 + 标题 + 大号数字 + 增量徽标 |
| 6 | **左列表 + 右详情** | 记忆库、外部记忆、时间线、交接账本都是这个双栏母版，右侧详情可关闭 |
| 7 | **语义色系统** | 蓝（主/信息）、紫（团队）、绿（成功）、橙（警告）、红（危险）、灰（中性）——**全站只有这一套** |

> **实施判据**：只要把这 7 条做成组件与 token，10 个页面就是同一套零件的不同组合 ⇒ 这正是"可换肤"的前提。

## 四、从概念图到实现：样式层的引入路径（**这是最大的一处工程改动**）

### 4.1 现状障碍【实测】
- `lib/client.js` 有 **439 处内联 `style:{}`**，只有 **7 处 `className`**。
- 内联样式**优先于 CSS 类** ⇒ 直接加 CSS 皮肤会被内联样式压制。

### 4.2 三条可选路径

| 路径 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **A 追加式覆盖（推荐先行）** | 新增 `<style>` 段，选择器用 `[data-dam-*]` 属性（163 个稳定锚点现成），靠同特异性后者胜覆盖 | 零破坏既有守卫；但需为每个锚点写规则 | ✅ **先做**，可立即出皮肤 |
| B 逐步内联→类迁移 | 把 439 处内联逐块搬到 CSS 类 | 改动面大、易踩守卫锁 | ⏳ 分批，随功能改动顺带做 |
| C 全量重写前端 | —— | 与"不改本体"前提冲突 | ❌ 不做 |

### 4.3 路径 A 的硬约束（**必须遵守，否则会破锁**）

1. **只追加、不改写既有行** —— 既有 smoke 守卫大量使用 `includes(...)` 断源码文本。
2. 选择器**一律以 `[data-dam-` 开头**，避免误伤宿主自身的 `.dsw-*` 类。
3. 新增的 `<style>` 段必须**在既有样式段之后**注入（同特异性后者胜）。
4. 段落边界用**成对注释标记**（如 `/* dam-skin:begin */` … `/* dam-skin:end */`），便于失败时整段回退（fail-closed）。
