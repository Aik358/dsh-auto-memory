# 12 · 前端皮肤接口契约（企业自定义前端的落地规范）

> 本卷回答你的第三个要求：**「做皮肤的时候，顺便做前端的皮肤接口，让用户可以自己定义前端」**。
> 这是**客制化、每个企业不同定制化的关键**：同一套插件，客户 IT 能自己换皮、加自己的组件、接自己的门户。
> 配套：[`skin/skin-token-contract.md`](skin/skin-token-contract.md)（原型侧的令牌清单）、[`skin/index.html`](skin/index.html)（可运行演示）。

---

## 一、设计目标与三条原则

| 目标 | 说明 |
|---|---|
| **可换肤** | 换一套 token 即整体变样，**不改一行插件代码** |
| **可扩展** | 客户能挂自己的组件到既定插槽，**不 fork 插件** |
| **可降级** | 客户皮肤出错时必须 **fail-closed** 回落到默认皮肤，**绝不让插件不可用** |

原则：
1. **token 只增不改语义** —— 已发布的 token 含义永不变（要变就发新 token 并废弃旧的）。
2. **扩展点显式声明** —— 只在自己承诺的插槽上支持扩展，不承诺的地方不保证兼容。
3. **零构建** —— 客户不需要 npm / webpack；一个 JSON + 一个 CSS/JS 文件即可生效（与插件本身"零构建、手写模块加载器"的既有风格一致）。

## 二、皮肤包的物理形态

```
<皮肤包目录>/
├── theme.json         # 主题令牌（必需）
├── skin.css           # 追加样式（可选；只允许追加式覆盖）
├── skin.js            # 插槽组件（可选；由插槽契约决定是否允许）
├── assets/            # logo / 图标（可选；必须本地，不允许外链）
└── README.md          # 客户自述（版本、适配的插件版本）
```

**加载位置**（三选一，优先级从低到高）：

| 方式 | 位置 | 适用 |
|---|---|---|
| 内置主题 | 插件内置（默认 3 套） | 开箱即用 |
| 用户主题 | `~/.dsh/memory/skins/<name>/` | 个人换肤 |
| 团队主题 | 由团队服务端下发（S2），落到 `~/.dsh/memory/skins/team-<teamId>/` | **企业统一形象** |

**优先级**：团队主题 > 用户主题 > 内置主题；**同层内后者胜**（与 CSS 同规则）。
**冲突可见**：若用户主题覆盖了团队主题的关键 token，界面需**提示一行**（不禁止），让用户知道自己的选择。

## 三、`theme.json` 契约

### 3.1 结构

```json
{
  "schemaVersion": 1,
  "name": "acme-enterprise-blue",
  "displayName": "ACME 企业蓝",
  "author": "ACME IT",
  "compatiblePlugin": ">=3.1.0",
  "extends": "default",
  "tokens": {
    "color.brand": "#1E3A8A",
    "color.brandWeak": "#EEF2FF",
    "color.team": "#6D28D9",
    "radius.card": "16px",
    "font.family": "\"Source Han Serif\", \"Songti SC\", serif",
    "motion.durFast": "180ms"
  },
  "flags": {
    "reducedMotion": false,
    "highContrast": false,
    "fontScale": 1.0
  }
}
```

### 3.2 字段语义

| 字段 | 必需 | 约束 |
|---|---|---|
| `schemaVersion` | ✅ | 目前只有 `1`；未知版本 ⇒ **拒绝加载并回落默认** |
| `name` | ✅ | `^[a-z0-9-]{2,64}$`；同名后加载者胜 |
| `displayName` | ✅ | 显示在选择器中 |
| `compatiblePlugin` | ⚪ | semver range；不满足时**警告但仍加载**（皮肤通常向后兼容） |
| `extends` | ⚪ | 继承的内置主题名，默认 `default` |
| `tokens` | ✅ | 键必须来自**`4 的公开清单**；未知键 ⇒ 忽略并记一条警告（不 fail） |
| `flags` | ⚪ | 无障碍与缩放 |

### 3.3 校验与 fail-closed（**硬要求**）

1. `theme.json` 解析失败 ⇒ **整包回落到默认皮肤**，并在设置页显示一条可关闭的提示（含错误摘要）。
2. 单个 token 值非法（如颜色不是合法 CSS 颜色）⇒ **只忽略该 token**，其余照常生效，并记录警告。
3. `skin.css` 若包含 `@import` 或外链 `url(http...)` ⇒ **整段拒绝**（防数据外泄/白屏依赖）。
4. `skin.js` 抛错 ⇒ 捕获、卸载该插槽的自定义渲染、回落默认渲染，**不影响插件其余部分**。
5. 任何皮肤加载**不得**阻塞插件启动：加载超时（建议 2s）即回落。

## 五、插槽契约（企业自定义组件）

**插槽**＝插件承诺可以插入客户组件的稳定位置。共 **7 个**：

| # | 插槽 id | 位置 | 传入数据 | 是否能覆盖渲染 |
|---|---|---|---|---|
| 1 | `sidebar.brand` | 侧栏顶部品牌区 | `{brand, team, member}` | ✅ |
| 2 | `home.banner` | 首页横幅区 | `{todayStats, teamStats}` | ✅ |
| 3 | `card.memoryFooter` | 每条记忆卡的尾部 | `{memory, actor}` | ❌ 只能追加 |
| 4 | `detail.actionBar` | 详情面板动作条 | `{kind, payload, actions}` | ❌ 只能追加按钮 |
| 5 | `settings.extraSection` | 设置页末尾追加分区 | `{config, save}` | ❌ 只能追加 |
| 6 | `sync.statusBar` | 同步状态条 | `{state, queue, conflicts}` | ✅ |
| 7 | `conflict.actions` | 冲突裁决动作区 | `{conflict}` | ❌ 只能追加 |

**插槽实现形态**（零构建）：`skin.js` 导出一个对象：

```js
// 客户只需会写普通 JS，不需要打包工具
window.__DAM_SKIN__ = {
  slots: {
    'sidebar.brand'(ctx) {
      const el = document.createElement('div')
      el.textContent = ctx.brand.name + ' · ' + (ctx.team?.name ?? '未加入团队')
      return el            // 返回 DOM 节点
    },
    'detail.actionBar'(ctx) {
      return [ ctx.button('导出到门户', () => fetch('/portal/export', {method:'POST'})) ]
    },
  },
}
```

**契约约束**：
- 插槽回调**必须是同步返回节点/数组**（异步会破坏渲染时序；需要异步数据请在回调外预取）。
- 回调抛错 ⇒ 该插槽回落默认渲染 + 记警告，**其余插槽不受影响**。
- 回调**不得**直接改 `document` 全局（只能操作传入的 `ctx` 与返回的节点）。
- 不承诺插槽内的 DOM 结构稳定；**只承诺 ctx 的字段**。

## 六、三种接入方式（按客户能力分层）

| 方式 | 客户需要会 | 能力 | 适用 |
|---|---|---|---|
| **① 覆盖 CSS 变量** | CSS | 换色/圆角/字体/间距 | 大多数企业 |
| **② 加载 theme.json** | JSON | 换色 + 品牌资产 + 无障碍 | 有 IT 团队的企业 |
| **③ 挂载插槽组件** | JS | 追加/替换局部 UI，接自家门户 | 深度定制客户 |

**组合使用**：三层可叠加，优先级 ③ > ② > ①（③ 的组件内部仍可用 ② 的 token）。

## 八、版本兼容与生命周期

| 阶段 | 规则 |
|---|---|
| **新增 token** | 小版本内可增；旧皮肤不受影响（缺键走默认） |
| **废弃 token** | 先标记 deprecated（**保留至少 2 个小版本**，期间继续生效并打印警告），再移除 |
| **语义变更** | ❌ **禁止** —— 必须改为新 token 名 |
| **插槽新增** | 小版本内可增 |
| **插槽移除/改 ctx 字段** | **大版本**，并在 CHANGELOG 显著位置说明 |
| **schemaVersion 提升** | 大版本；旧 `schemaVersion` 皮肤拒绝加载并回落默认 |

## 九、后端 / 前端改动点（实施时）

### 后端（宿主侧）
| # | 改动 |
|---|---|
| 1 | 主题文件的读取与校验模块（`skin-loader`）：解析 theme.json、白名单校验 token、fail-closed |
| 2 | 团队主题下发（S2，随同步通道到本地 `skins/team-<teamId>/`） |
| 3 | 主题状态接口（当前生效主题、来源层、警告列表） |

### 前端
| # | 改动 |
|---|---|
| 1 | 启动时按优先级解析主题 → 生成 `--skin-*` 注入 `documentElement`（**注意：插件既有代码里 `documentElement` 仅 3 处使用，需要新增注入点**） |
| 2 | 新增 `/* dam-skin:begin */ … /* dam-skin:end */` 样式段，全部选择器以 `[data-dam-` 开头（**只追加不改写**，保护 179 个 smoke 守卫） |
| 3 | 7 个插槽的挂载点与默认渲染回退 |
| 4 | 设置页「外观」分区新增：主题选择器、导入主题包、当前主题来源、警告列表、无障碍选项 |
| 5 | 皮肤加载失败提示（可关闭、不阻塞） |

### ⚠️ 既有守卫风险（必须在实施时处理）
- **179 个 smoke 套件 / 45 个读 `lib/client.js`**（既有实测数据）⇒ 任何 UI 改动先做**撞锁测绘**。
- 设置页 9 分区的 key 与顺序**被硬锁** ⇒ 「外观」分区内的新增控件若改变既有分区结构，需**独立成批**并同步改守卫。
- 推荐手法（既有成功经验）：**追加式覆盖**，靠同特异性后者胜；不删除、不移动既有行。

## 十、验收清单（接口部分）

- [ ] 换 theme.json 后整体换色成功，**插件代码零改动**
- [ ] 非法 theme.json → 回落默认 + 提示，插件仍可用
- [ ] 非法单个 token → 仅忽略该项，其余生效
- [ ] skin.css 含外链 → 整段拒绝
- [ ] skin.js 抛错 → 该插槽回落，其余正常
- [ ] 7 个插槽均可挂载并正确回退
- [ ] 团队主题覆盖用户主题时有可见提示
- [ ] `prefers-reduced-motion` 与 highContrast 生效
- [ ] 加载超时（2s）回落
- [ ] 皮肤切换**即时回显**（符合既有 UI 偏好：写盘成功但界面无变化视为功能坏了）
