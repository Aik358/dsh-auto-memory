# 08 · 功能同步：日历与外部记忆（E 族）

> 覆盖 E1 日历提醒 / E2 外部记忆继承 / E3 迁移搬包（含「搬包并入团队共享」这一上轮已定方向）。

---

## E1 日历提醒

### 现状
`~/.dsh/memory/CALENDAR.md`；4 个工具 `calendar_add/list/done/remove`；路由 `calendar`；提醒来源含「对话承诺 / 截止时间 / 会议 / 重复提醒 / 复盘」五类。

### 多人同步
**必须双轨** —— 这是全插件少数「同一功能天然有两个所有权」的地方：

| 轨道 | 作用域 | 典型内容 | 同步 |
|---|---|---|---|
| **团队日历** | S2 | 项目会议、里程碑、交付截止、团队周会 | P1 字段级 + P5 墓碑 |
| **个人日程** | S1 | 我的复习计划、私人提醒、个人待办 | 跟随人跨设备，不进团队库 |

**关键设计**：条目必须**显式标注轨道**（在创建时就选），而不是事后猜。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 条目结构加 `scope: 'team'\|'personal'` + `actor` | 创建时必须指定，默认 personal（安全默认） |
| 2 | 两个物理文件 | `CALENDAR.md`（个人）与 `hub/team-calendar.md`（团队），物理分开 |
| 3 | 冲突 | 团队条目 P1；删除走墓碑（会议取消 ≠ 记录消失） |
| 4 | 提醒触发 | 提醒仍在**本机**触发（含他人创建的团队条目，需要拉取到本地） |

### 前端显示
- 日历视图**按来源分色**：团队条目一种色、个人条目另一种色（沿用既有五色语义再加一维）。
- 每条显示：创建人 + 「团队 / 仅我」徽标。
- 新建提醒时**第一步就选轨道**（默认"仅我"，需显式点"团队"）。
- 团队条目显示「3 人参加」这类聚合信息。

## E2 外部记忆继承

### 现状
`externalSources` 配置（13 子键）；路由 `external` / `external-import` / `external-remove` / `external-view`；工具 `memory_external`；来源含 WorkBuddy / CodeBuddy / Claude Code / Codex 等**本机其他 AI 工具**。

### 多人同步
- **纯 S0 本机态** —— 来源路径是**本机磁盘上的其他软件目录**（如 `C:\Users\<user>\.workbuddy\MEMORY.md`），换台机器路径就不存在。
- **唯一可上团队的**：被**导入后**的记忆条目本身（它们已变成普通记忆，按普通规则同步）。
- **必须显式告知用户**：「外部记忆源本身不参与团队同步」。

### 后端改动点
1. 导入动作产生的记忆条目加 `importedFrom: {app, path, at}` 溯源字段。
2. 源路径**不上报**到团队（含用户名，属隐私）。
3. 团队侧只看到「该条目由外部工具导入」，看不到原始路径。

### 前端显示
- 外部记忆页顶部加声明条：**「外部记忆源仅本机可见，不参与团队同步」**。
- 已导入条目在团队视图中显示「自外部工具导入」徽标，**不显示路径**。
- 「配置导入规则」入口标注「本机配置」。

## E3 迁移搬包（→ 并入团队共享）

### 现状
`lib/migrate-pack.js`：`buildPackPre` / `validatePackPre` / `planImportPre` / `mergeSummaryRecordPre` / `calendarMergePre` / `MIGRATE_PACK_FORMAT_PRE`；路由 `migrate-export` / `migrate-import` / `migrate-inspect`。

### 上轮已定方向（用户原话）
> 「目前的跨机迁移搬包应该挪入团队共享，也就是 teamwork 大工作里面。因为 teamwork 肯定是要上云的，这个共享应该和它上云是一套流程。」

### 多人同步 —— 搬包 = 同步的「手动模式」
**结论：搬包不应被废弃，而应被重新定位为同步的降级通道与初始化通道。**

| 用途 | 说明 |
|---|---|
| **初始化** | 新成员加入团队时，先搬一份基线包，再开始增量同步（避免首同步拉全量） |
| **降级通道** | 服务端不可达时的应急搬运（U 盘/内网/邮件） |
| **迁移** | 单人 → 团队、团队 A → 团队 B 的整体迁移 |
| **离线审阅** | 把包给客户/审计方看（含脱敏导出） |

**同步模式**：**P4 两阶段**（先写接收库 → 读回校验 → 再删源），与既有 `scoped.migrate()` 语义一致。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 包格式加**身份与作用域清单** | 包内区分 S1/S2；导入时按 scope 落位 |
| 2 | 冲突预检 | 导入前生成「新增 / 覆盖 / 跳过 / 冲突」四态报告 |
| 3 | 幂等 | 同一包重复导入不产生重复（内容寻址 id 的收益） |
| 4 | 与增量同步共用搬运原语 | `scoped.migrate()` 升格为通用搬运原语 |

### 前端显示
- 导入预览表：四态计数 + 冲突清单（逐条可点开）。
- 导出时选项：`包含私有数据（个人日志）` 默认**不勾**；`脱敏导出`（去路径/去用户名）。
- 显示包内摘要：`团队事实 42 · 技能 7 · 白板 3 · 日历 5（不含个人日志）`。

## 本族汇总

| 功能 | 同步模式 | 后端改动 | 前端显示 |
|---|---|---|---|
| E1 日历 | **团队 S2 / 个人 S1 双轨** | scope 字段 + 物理分文件 + 墓碑 | 分色 + 创建人 + 轨道选择 |
| E2 外部记忆 | **S0 本机** | 溯源字段 + 路径不外传 | 「不参与同步」声明 + 导入徽标 |
| E3 迁移搬包 | **P4 两阶段**（同步的手动模式） | 包带 scope 清单 + 四态预检 + 幂等 | 导入预览四态 + 脱敏导出 |

**本族待拍板**：
1. 团队日历是否需要**会议室/资源**这类企业级能力（会引入新的冲突形态）？
2. 搬包是否作为**销售交付物**（客户现场导入演示）？影响 13 卷交付章节。
