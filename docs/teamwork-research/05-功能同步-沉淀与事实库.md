# 05 · 功能同步：沉淀与事实库（B 族）

> 覆盖 B1 自动沉淀 / B2 事实库 / B3 证据链 / B4 剧集 / B5 重要性评分 / B6 分层注入。

---

## B1 自动沉淀

### 现状
每轮对话结束后由子代理把对话沉淀为结构化记忆；带冷却（30 分钟，夜间翻倍）与每日上限；产物写入工作区日志 + 事实库 + 用户级记忆。

### 多人同步
**核心问题**：沉淀是**高频自动写**，如果无脑进团队库，会把每个人的每一轮对话都灌进团队——团队库会瞬间被噪音淹没。

**解法：沉淀产物按作用域分流**

| 产物 | 作用域 | 理由 |
|---|---|---|
| 个人每日日志 | **S1 个人云** | 是个人工作痕迹，不是团队知识 |
| 个人反思 | **S1**，默认加密私有标记 | 更私密 |
| 抽取出的**事实候选** | **S2 待审区**（不是直接进团队事实库） | 经确认才成团队知识 |
| 技能候选 | S2 审批列表（见 06 卷） | 已有审批流 |

**关键设计：团队沉淀走「候选 → 采纳」两级**，而不是直写。这既解决噪音问题，也天然提供审计。

### 后端改动点
| # | 位置 | 改动 |
|---|---|---|
| 1 | 沉淀入口（`autoConsolidate` 路径） | 产物按 scope 分流：日志→S1，事实候选→S2 待审区 |
| 2 | 新增「团队待审区」存储 | 独立文件（如 `hub/team-inbox.json`），**不与个人待审混放** |
| 3 | 去重 | 入待审前用内容 hash 去重（含与团队已有事实比对） |
| 4 | 冷却与配额 | 团队待审区独立配额，避免单成员刷屏 |

### 前端显示
- 沉淀卡片增加**去向行**：`将写入：我的日志 · 团队待审区（待 2 人确认）`，且**可就地改去向**（改为"仅我"）。
- 概览「AI 已整理」横幅增加团队维度：「今天团队共沉淀 12 条，其中 3 条待你确认」。
- 新增「待审」入口（可放冲突中心或独立小页）。

### 验收
单人模式下沉淀行为**逐字节不变**；开启团队后，个人日志仍在 S1，团队待审区只增事实候选。

## B2 事实库（facts.json）

### 现状
`memory/hub/facts.json`；路由 `memory-hub`；有重要性、证据、元数据。

### 多人同步
- **S2 团队共享**，**逐条独立**（一条事实一个记录）。
- 冲突用 **P1 字段级 LWW**：标题/正文/标签各自带 `updatedAt`，**按字段**判新，而非整条判新。
- 同内容 hash 的**自动合并**（证据合并，不产生重复条目）。
- 删除走 **P5 墓碑**。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 记录结构扩展 | 加 `actor` / `updatedAt` / `origin` / `rev`（逻辑时钟） / `deletedAt` |
| 2 | **按字段合并** | 现有整条写路径需要拆成字段级 patch |
| 3 | 内容寻址去重 | 规范化正文 hash 作为稳定 id |
| 4 | 墓碑保留期 | 删除后保留 N 天（建议 30），期间可由管理员恢复 |
| 5 | 双向 Apply | 拉取变更 → 走**既有校验**（不绕过 Gate）写本地 |

### 前端显示
| 位置 | 显示 |
|---|---|
| 记忆库列表 | 每条右侧：作者头像 + 「团队」徽标 + 更新相对时间 |
| 事实详情 | 顶部：「由 张三 创建 · 李四 3 分钟前更新」+ 修订历史（可展开） |
| 筛选器 | 新增「按作者」「按来源（本地/团队）」 |
| 冲突标记 | 有未解冲突的事实显示橙色角标，点击进冲突中心 |
| 删除 | 已删除条目显示「已删除（可由管理员恢复）」而非消失 |

## B3 证据链（evidence/）

### 现状
`memory/evidence/`；支撑事实与技能晋升；「可信度可量化」是核心卖点之一。

### 多人同步
- **P2 只追加**、永不覆盖 —— 这是本族**最重要**的一条：证据天然是事实的"历史"，覆盖它就毁掉了可信度。
- **直接修复既有的 R3 风险**：晋升证据计数是逐机的、同步会互相覆盖 ⇒ 改成「证据追加日志 + 计数派生」。
- 证据原文（对话片段）**默认不上云**，只上摘要 + 指纹；原文留在产生它的机器（可配置）。

### 后端改动点
1. 证据写入改为**追加事件**，每条含 `actor/at/sessionRef/snippetHash`。
2. 计数**改为派生**（由证据条数算出），**不再落盘绝对值**。
3. 可选的"证据原文上云"开关（默认关，企业可按合规要求开）。

### 前端显示
- 证据列表：每条显示**来源人 + 时间 + 原话片段（若本机有原文）**。
- **跨人证据视觉可分**：不同人的证据用不同左边色条。
- 计数显示：「证据 7 条（张三 4 · 李四 3）」——**这是"可信度可量化"的团队版**，直接对应旧调研的差异化亮点 4。

## B4 剧集（episodes）

### 现状
`memory/hub/episodes.json`，`episodicMinSegments` / `episodicRetention`。

### 多人同步
- **以 S1 为主**（会话段落是个人轨迹）。
- 团队层面只需要「某项目发生过哪些关键会话」的**索引**，不需要全文。
- 建议：剧集**不进 S2**；如需团队视图，走"会话摘要"独立通道。

### 后端改动点
1. 剧集作用域固定为 S1。
2. 如需团队索引，另建轻量索引（会话标题 + 时间 + 参与者 + 摘要），独立文件。

### 前端显示
- 剧集区标注「仅我可见」。
- 若企业开启团队索引，显示「本项目共 42 次会话（含他人）」，但**不展示他人会话内容**。

## B5 重要性评分

### 现状
由证据聚合派生（`memory-importance.js`、`evidence-agg.js`）。

### 多人同步
- **纯 S3 派生**，永不搬运。
- 团队场景下评分输入变多（更多人的证据）⇒ 评分**必然变化**，这是**预期行为**，必须让用户看得到理由。

### 后端改动点
1. 评分函数显式标注「本机证据 / 团队证据」两个权重来源。
2. 提供评分变更的**解释输出**（为什么从 0.6 变 0.8）。

### 前端显示
- 事实卡显示评分 + `其中团队证据贡献 +2`。
- 悬停显示解释：`团队证据 5 条（张三 3 · 李四 2），本机证据 1 条`。

## B6 分层注入

### 现状
Tier0 常驻目录 + Tier1/2 下探；`injectBudgetChars` 等预算键；`tier0-*` 键族。快照装配（`memory-envelope.js` 等）。

### 多人同步
- **策略可同步，执行不可同步**：
  - 团队可下发「注入预算建议 / 哪些来源必注入」⇒ S2 策略（P1，管理员优先）。
  - 实际注入计算在**本机**执行（依赖个人上下文窗口与水位）。
- **冲突**：策略冲突走 P1；**设备级覆盖**允许存在并显式标注。

### 后端改动点
1. 注入策略读两层：团队默认 ← 本机覆盖；合并规则显式（列出谁覆盖了谁）。
2. 团队策略变更时，前端需能提示「团队更新了注入策略」。

### 前端显示
- 概览「注入」区显示：`策略来源：团队默认（含本机 2 处覆盖）`，可点开看差异。
- 团队改动时给一次性提示条，不自动改用户设置。

## 本族汇总

| 功能 | 同步模式 | 后端改动 | 前端显示 |
|---|---|---|---|
| B1 自动沉淀 | 分流：日志 S1 / 事实候选 S2 待审 | 分流 + 团队待审区 + 去重 | 去向行（可就地改）+ 待审入口 |
| B2 事实库 | S2 + P1 字段级 + P5 墓碑 | 记录加身份、字段级合并、内容寻址 | 作者/时间/修订历史/冲突角标 |
| B3 证据链 | **P2 只追加** + 计数派生 | 追加事件、计数派生、原文可选上云 | 跨人证据色条 + **证据贡献分解** |
| B4 剧集 | S1 为主 | 作用域固定 + 轻量团队索引 | 「仅我可见」标注 |
| B5 重要性 | S3 派生 | 双权重来源 + 解释输出 | 评分解释 |
| B6 分层注入 | 策略 S2、执行本机 | 两层策略合并 + 变更提示 | 策略来源 + 差异 |

**本族待拍板**：
1. 团队待审区需要几人确认才转正？（建议：项目库 1 人、通用库 2 人或管理员 1 人）
2. 证据原文是否允许上云？（默认否，合规客户可开）
