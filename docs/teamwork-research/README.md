### 问 2：能否按现在的桌面版/可登录形态重做调研？每个功能怎么做同步、前端显示什么？
**已重做，全量覆盖 38 项功能**（[02 卷测绘](02-现状测绘-功能清单与数据边界.md) → [03 卷总纲](03-同步总纲-每个功能的多人同步设计.md) → 04–09 六卷分族）。

核心结论六条：
1. **同步面只有 4 类数据**（本机私有 / 个人云 / 团队共享 / 派生重算），**派生数据永不搬运**。
2. **收口点只有 3 个**（路径出口 `memoryDir()`、注册出口 routes/tools、配置 IO）⇒ 不必重写 56 条路由。
3. **只有 4 处需要人工裁决**（用户规则整篇 / 项目笔记 / PLAN 白板 / 通用库技能审批），其余全可自动解 —— 这是可验收的冲突面上界。
4. **延迟预算**：用户可见事实 ≤5s，词法 ≤5s，**向量 ≤5min 异步**（"实时"的准确定义）。
5. **登录由宿主提供**（`ctx.authorization` 接缝 + `dsh-deepseek-account`），**插件只做成员映射**；旧调研的 OAuth 回调难题**自动消解**。
6. **必须先修两个身份级缺陷**：wsKey 按路径派生（跨机不汇合）、技能 id 非内容寻址（同步后重复）。

### 关于第 7–10 张的一次勘误（如实记录）

- 我在给皮肤子代理的任务简报里，**把这 4 张的路径标错了三个**（把 `e694ae13` 标成"外部记忆继承"、`047f0ea9` 标成"思维导图"、`dff7662f` 标成"日历提醒"），根因是按**用户消息里的文字顺序**去对应 sha 列表，而两者顺序并不一致。
- 子代理提出该巡检有疑点，但它给出的"更正后"标签**同样不对**（它把三者又换了一个排列）。
- **最终以我逐张开图的真实内容为准**（上表第 8/9/10 行），并据此复核原型：原型的 10 个页面与真实概念图**一一对应**，没有按错图去画。

**教训（已写入技能库）**：凡把附件路径写进任务简报，**必须先自己开图确认映射**，不能按消息文字顺序推断；子代理提出的"映射纠正"也要用同一手段复核，不能直接采信。
