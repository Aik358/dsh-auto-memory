# 04 · 功能同步：唤回与检索（A 族）

> 覆盖 A1 主动召回 / A2 影子检索 / A3 JS 语义引擎 / A4 Python 语义引擎 / A5 L0 索引 / A6 召回统计。
> 每个功能三问：**多人怎么同步 / 后端改哪 / 前端显示什么**。

---

## A1 主动召回

### 现状
每轮对话前把记忆上下文注入。数据源：`workspaces/<ws>/MEMORY.md`、`memory/index/`、用户级 `MEMORY.md`。
路由 `recall` / `smart-recall`；工具 `memory_recall`。

### 多人同步
- **召回行为本身是本机行为** —— 不应同步（每个人的上下文压力不同）。
- **被召回的内容**来自本地已同步的 S1/S2 库 ⇒ 同步在**内容层**完成，不需要「同步召回动作」。
- 新增需求：召回结果必须能回答**「这条是什么时候从团队拿到的」** ⇒ 本地为每条团队记录保留 `syncedAt`。

**同步模式**：无独立同步。**冲突**：无。

### 后端改动点
| # | 位置 | 改动 |
|---|---|---|
| 1 | 召回结果装配处 | 每条结果附加元信息 `{origin: 'local'\|'team', actor, syncedAt, scope}` |
| 2 | 结果缓存 | 团队来源的缓存条目带**版本号**，收到 CDC 变更时失效 |

### 前端显示
- 概览「召回」卡：每条结果右侧加**来源徽标**（🖥 本地 / 👥 团队）+ 相对时间（「团队库 · 3 秒前」）。
- 新鲜度滞后时（> 向量预算 5 分钟）显示「语义索引滞后，正在重算」的轻提示。
- 检索页加**分组**：「我的记忆 / 团队记忆」两个分组头。

### 验收
关掉团队开关后，召回结果与现状逐条一致（含顺序）。

## A2 影子检索

### 现状
旁路检索，不打断主对话；路由 `shadow-recent`；数据在 `memory/semantic/` 与遗留 `retrieval-pre`。

### 多人同步
- 影子命中**可以上报**作为团队质量信号（P2 追加），但**默认关闭**（隐私优先）。
- 上报内容**只含匿名指标**：命中与否、片段长度、时间；**不含原文**。

### 后端改动点
1. 新增可选上报通道（`team.audit.shadowReport` 开关，默认 false）。
2. 上报走 P2 追加，服务端聚合为「团队影子命中率」。

### 前端显示
- 「影子命中」区显示**两个口径**：本机命中率 / 团队平均命中率（仅在开启上报时显示团队口径）。
- 明确标注：「团队数据为匿名聚合，不含你的原文」。

## A3 JS 语义引擎（默认形态）

### 现状
`@huggingface/transformers` 可选依赖；模型资产本地缓存；路由 `semantic-status`/`semantic-emit`/`semantic-download`/`semantic-deep-detect`。
**铁律**：JS 端与 Python 端是**两项相对独立、可互相替换**的功能，**严禁联动**。

### 多人同步
- **模型资产不进团队库**（大文件、有许可问题、且各机可自行下载）。
- **向量与索引 = S3 派生**，永不搬运；团队成员各自本地编码。
- 团队可以下发**统一策略**：「本项目建议使用模型 X」（策略 P1，管理员优先），但**不得强制切换用户引擎**。

**关键指标**：团队内模型不一致 ⇒ 语义召回结果**不可比**。必须做成**可见的、可解释的**，而不是静默不一致。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 引擎身份上报 | 把 `engine-identity.js` 的指纹（模型名+版本+维度）上报为团队可见声明 |
| 2 | 向量元数据 | 每条向量带 `modelId` + `dims` + `embeddedAt` |
| 3 | 版本变更处理 | 检测到团队声明变更 ⇒ 标记**需重算**，不自动换模型 |

### 前端显示
- 设置页「团队」分区：显示**我的引擎** vs **团队建议引擎**；不一致时给黄色提示（不是错误色，避免用户误以为坏了）。
- 语义索引覆盖：`本机覆盖 82% · 团队均值 91%`。
- 滞后显式化：`语义索引滞后 4 分 12 秒（预算 5 分钟）`。

> **不做**：不显示"某人的引擎是 X"（隐私），只显示聚合。

## A4 Python 语义引擎（进阶形态）

### 现状
sidecar + venv，6 条 `python-setup/*` 路由（`detect`/`deps`/`venv`/`model`/`status`/`cancel`）。

### 多人同步
- **venv 与依赖纯本机 S0**：路径、Python 版本、依赖树都与本机强绑定，**搬运无意义且会坏**。
- 只同步**声明**：`本团队推荐引擎：JS / Python（可选）`。
- **严禁**因团队统一而自动切换用户引擎（铁律的团队版延伸）。

### 后端改动点
1. 引擎切换逻辑**不得**读取团队配置来自动切换（只读团队建议用于**提示**）。
2. 上报项仅：引擎类型、模型名、可用性布尔。

### 前端显示
- 安装向导卡显示「本团队推荐：JS（默认）/ Python（进阶）」的**建议标签**，不预选。
- 切换按钮旁注明：「这与团队设置无关，仅影响你自己的语义召回」。

## A5 L0 索引

### 现状
层级索引（Tier0 目录 + Tier1/2 下探），`index-sync.js`、`l0-index.js`、`l0-index-sync.js`；`memory/index/`。

### 多人同步
- **纯 S3 派生**：索引由本地内容构建，团队成员各自构建。
- 团队库内容变化 ⇒ 本地索引**增量重建**，不接收团队索引文件。

### 后端改动点
1. 索引构建的输入必须包含「团队库快照版本号」，避免用旧输入构建新索引。
2. 提供「索引新鲜度」指标（最后构建时间 + 覆盖的库版本）。

### 前端显示
- 统计页显示「索引新鲜度」：`索引已覆盖至团队版本 #1234（3 分钟前）`。

## A6 召回统计与反馈

### 现状
`recall-stats.json`、路由 `recall-stats`/`review-feedback`；召回审查页（今日召回、命中率、待审查、平均置信度）。

### 多人同步
**双轨**：
- **个人统计 S1**：跟随人跨设备，不进团队库（命中率是个人画像）。
- **团队聚合 S2**：走 **P2 追加计数**，服务端聚合。**绝不同步"命中率数字"本身**（那会互相覆盖）。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 反馈上报 | 每条反馈作为**追加事件**（含匿名 actor） |
| 2 | 聚合去重 | 同一 (sessionId, memoryId, actor) 幂等 |
| 3 | 团队聚合接口 | 返回团队命中率、成员参与度、趋势 |

### 前端显示
- 召回审查页顶部分**两个 tab**：「我的」/「团队」。
- 团队 tab：团队命中率、成员参与度热力、**我的贡献占比**。
- 每条审查记录显示「来源：本地/团队」；团队条目显示匿名作者（如「成员 #3」或显示名，由 `team.ui.showMemberBadges` 决定）。

### 隐私红线
- 团队统计**不得**暴露「某人召回了什么内容」，只暴露**聚合数字**。

## 本族汇总

| 功能 | 同步模式 | 后端改动 | 前端显示 |
|---|---|---|---|
| A1 主动召回 | 不同步行为，内容随库 | 结果加来源元信息 + 版本失效 | 来源徽标 + 新鲜度 |
| A2 影子检索 | 可选匿名上报（默认关） | 上报通道 + 聚合 | 双口径 + 匿名声明 |
| A3 JS 语义 | 资产不同步；索引 S3 | 引擎身份上报 + 向量元数据 | 我的 vs 团队建议引擎 |
| A4 Python 语义 | 纯本机；只同步声明 | 禁止自动切换 | 建议标签（不预选） |
| A5 L0 索引 | S3 派生 | 输入带库版本 | 索引新鲜度 |
| A6 召回统计 | 个人 S1 + 团队 P2 聚合 | 追加上报 + 幂等聚合 | 我的/团队双 tab |

**本族待拍板**：影子检索匿名上报是否默认开启？（建议：默认关，企业可在策略中开启）
