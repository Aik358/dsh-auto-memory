## 一、总体实施路线（6 个批次，按依赖排序）

### 批次 0 · 地基修复（**必须先做，否则后面全错**）

| # | 事项 | 为什么必须先做 | 产出 |
|---|---|---|---|
| 0.1 | **团队项目 ID** 取代路径派生的 wsKey | 不解决则两人项目库永远汇合不了（03 卷 8.3） | 映射模块 |
| 0.2 | **技能 id 改内容寻址** | 不解决则同步后必然重复条目 | id 生成器 + 兼容字段 |
| 0.3 | **证据计数改派生** | 不解决则晋升证据会互相覆盖 | 证据追加日志 |
| 0.4 | **配置拆两层**（团队策略 / 设备偏好） | 不解决则一人主题污染全团队 | 命名空间分离 |
| 0.5 | 同步黑名单落地（`*-pre`/`.bak-*`/心跳/投影缓存） | 不解决则历史垃圾上云 | 白+黑名单 |

**验收**：单人模式行为与现状**逐字节一致**（回归全绿），且上述 5 项有可复现的单测。

### 批次 1 · 身份与成员（依赖批次 0）

- 接入宿主 `ctx.authorization` + 账号状态；
- `team-identity.js` 成员映射；`actor` 注入所有写路径；
- 服务端：团队/成员/角色最小模型；
- 前端：设置页「团队」分区（第 10 分区，**追加不重排**）+ 顶部成员区。

**验收**：登录 → 看到自己 → 写一条记忆带上 `actor`；未登录时团队功能整体置灰且**不影响单人使用**。

### 批次 2 · 同步通道（依赖批次 1）

- `sync-outbox` / `sync-pull`；T1 秒级通道打通（文本类）；
- `sync-state` 路由 + 前端同步状态条；
- 灰度 G0（只读拉取）。

**验收**：α 机写一条事实，β 机 **≤5s** 看到；断网时本地可写、恢复后收敛。

### 批次 3 · 共享数据全量接入（依赖批次 2）

按 04–09 卷逐族接入：A（召回来源）→ B（事实/证据）→ F（规则/审查）→ D（交接/白板）→ C（技能/审批）→ E（日历/外部）。

**验收**：03 卷冲突矩阵中**除 4 处人工裁决外全部可自动解**，且每族有端到端用例。

### 批次 4 · 冲突中心与治理 UI（依赖批次 3）

- 冲突检测、4 类人工裁决队列、差异视图；
- 审批面板（技能）、规则分层 UI、审计导出。

**验收**：制造 4 类冲突各一次，全部能在 UI 中裁决并可追溯。

### 批次 5 · 皮肤与定制接口（**可与批次 2–4 并行**）

- 样式层引入（追加式覆盖）+ `--skin-*` token；
- theme.json 加载与校验、7 个插槽；
- 设置页「外观」分区 + 主题选择器；
- 2–3 套内置主题。

**验收**：换 theme.json 整体变样且**插件代码零改动**；非法主题 fail-closed。

### 批次 6 · 企业交付件（最后）

- 部署文档、运维手册、安全说明（含**明文披露**）、验收清单、培训材料。

## 二、部署形态（三种，按客户类型推荐）

| 形态 | 组成 | 适用 | 成本 |
|---|---|---|---|
| **A 全本地（局域网）** | 客户内网一台服务器跑权威服务端 + 对象存储；各成员插件指向内网地址 | 有内网、数据不出境 | 中（需内网运维） |
| **B 客户云自建（推荐）** | 权威服务端部署在客户云账号（阿里云为主，兼容腾讯/华为/AWS/GCP）；可挂载 RDS/OSS/向量库 | 中大型企业、合规要求高 | 高（客户承担云成本） |
| **C 我们托管 SaaS** | 我们运维服务端，客户只装插件 | 小团队/试用 | 低（但有数据托管顾虑） |

### 2.1 云产品映射（阿里云为主，沿用旧调研口径）

| 组件 | 阿里云 | 腾讯云 | 华为云 | AWS | GCP |
|---|---|---|---|---|---|
| 计算 | ECS | CVM | ECS | EC2 | GCE |
| 数据库 | RDS PostgreSQL | TencentDB | RDS | RDS | Cloud SQL |
| 对象存储 | OSS | COS | OBS | S3 | GCS |
| 向量（可选） | DashVector / ADB-PG | 向量数据库 | GaussDB(向量) | OpenSearch | Vertex AI VS |
| 密钥 | KMS | KMS | KMS | KMS | Cloud KMS |

### 2.2 最小部署规格（试点 20 人以内）

```
1 × 应用服务（2C4G）     权威 API + CDC + 审批
1 × PostgreSQL（2C4G）   权威存储 + 审计日志
1 × OSS bucket           证据原文 / 快照 / 迁移包
（可选）1 × 向量实例      仅当团队要用服务端语义检索
```

**重要**：**向量是可选的**（03 卷判据 1：能重算的永不搬运）—— 团队可以只用本地语义引擎，服务端不跑向量。

## 三、安全与合规（企业评审必答）

| 问题 | 我们的答案 |
|---|---|
| 数据存在哪？ | **默认全部本地**；只有被判定为 S2（团队共享）的数据才上云，且逐项可查（03 卷第二节） |
| 是否加密？ | **本地明文**（开源可审计），**企业可在存储层自持加密**；插件预留加解密接口。⚠️ **必须主动向甲方披露"当前明文"**（用户裁定 2） |
| 谁能看到我的私有记忆？ | 私有三层（本机/个人云/个人日志）**不进团队库**，服务端按 `teamId` 隔离，客户端过滤不参与 |
| 审计能做吗？ | 能做：召回审查 + 规则变更 + 审批 + 成员动作，均可导出 CSV（09 卷 F3） |
| 数据能删吗？ | 能：墓碑 + 保留期 + owner 级彻底删除；退出团队后可"本地化"保留个人数据 |
| 会外联吗？ | 只连**客户指定的**团队服务端；模型资产与外部记忆源均本地 |
| 能离线用吗？ | 能：本地优先，断网可读写，联网收敛（03 卷判据 4） |

## 四、报价口径（供商务参考，非最终定价）

三种计费轴（可组合）：

| 轴 | 说明 | 建议锚点 |
|---|---|---|
| **按席位** | 每成员每年 | 与"每人每天都在用"的价值对齐 |
| **按部署形态** | 一次性实施费（自建/内网） | 与运维复杂度对齐 |
| **定制开发** | 皮肤定制、私有集成、专有 IdP 对接 | 按人天 |

**差异化卖点（用于价值论证）**——沿用旧调研的"人无我有"并落到团队场景：

1. **记忆生命周期治理**：作废的记忆"返回但标记"，团队里**不会有人静默改掉别人的结论**。
2. **防记忆劫持**：无模型参与的记忆写入结构性不可能 —— 企业最怕"AI 记错了还到处传播"。
3. **失败与弯路是一等公民**：跨人接续继承的是**排除项** —— 新同事不会重走老坑。
4. **可信度可量化**：技能晋升要**跨人证据**，证据贡献可分解到人。
5. **冲突面控制**：物理分文件 + 四类冲突只有 4 处需人工裁决 —— 可解释、可验收。

## 七、风险与免责（交付时必须写明的话）

1. **本调研是实施方案，不是已实现功能** —— 所有代码级结论均标注【实测】，其余为【推断】，实施前需按批次验收。
2. **本轮未改动插件本体**，因此**没有引入任何新的回归风险**；所有改动点的风险评估基于静态分析。
3. **同步涉及数据出本地**，必须由客户在知情下开启；插件默认 `team.enabled=false`。
4. **明文存储**属既有裁定，交付时应书面确认。
5. **宿主版本依赖**：身份接缝基于 `@deepseek-ai/dsh@0.1.7-rc.2`；宿主升级需重新核对接缝契约。

## 八、收尾：这套东西做完之后是什么

```
今天：一个人的本地记忆插件（本地优先，隐私第一）
  ↓
Teamwork 企业版：
  · 同一个人的记忆跨设备跟随（个人云）
  · 团队共享事实 / 技能 / 交接 / 白板（受治理）
  · 每个企业的界面长相自己定（皮肤接口）
  · 一切可解释、可审计、可回退（治理与冲突中心）
```

**一句话**：把"AI 的记忆"从**个人工具**变成**企业资产**，同时不牺牲本地优先与可审计。
