# 09 · 功能同步：规则层与治理（F 族）

> 覆盖 F1 规则层 / F2 作废撤回 / F3 召回审查 / F4 存储管理 / F5 会话归档删除 / F6 降级账本。
> **这一族决定「记忆是可治理的」还是「记忆是一堆文件」** —— 企业客户最关心的就是这里。

---

## F1 规则层（用户级硬约束）

### 现状
- 真源：`~/.dsh/memory/MEMORY.md`
- 每轮**无条件注入**的「[规则]」段，是最贵也最硬的注入段
- 工具 `memory_rules`（list/add/update/remove，带 `expect` 内容锚定防误删）
- 路由 `rules` / `rules/apply`；`rules-edit.js` / `rules-layer.js`

### 多人同步
**这是治理的核心**：企业希望有**组织级规则**（如"所有交付物必须双语"），个人也有自己的规则。

**解法：规则分三层，物理分开**

| 层 | 来源 | 作用域 | 谁能改 |
|---|---|---|---|
| 个人规则 | 用户手写 | S1 | 本人 |
| 团队规则 | 团队约定 | S2 | 成员提议 + 管理员批准（或留痕） |
| 组织策略 | 企业下发 | S2（只读） | 仅管理员，成员**只能看不能改** |

**冲突**：跨层冲突**不自动解**，按优先级展示；**同层内**整篇写冲突 = 人工裁决。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 规则条目加 `layer` / `actor` / `enforced` | 分层与强制标记 |
| 2 | 注入时按层合并（个人 → 团队 → 组织，后者优先） | 注入段需显示来源层 |
| 3 | `memory_rules` 的 remove/update 增加**权限判定** | 组织策略层不可被成员删除 |
| 4 | 冲突检测 | 同层整篇写冲突 → 冲突中心 |
| 5 | 变更审计 | 规则变更走 P2 追加日志（谁在何时改了哪条） |

### 前端显示
- 规则列表**按层分组**，每条显示：来源层徽标 + 最后修改人 + 是否强制。
- 组织策略层显示锁图标 + 「由管理员设置」。
- 冲突时**禁止静默覆盖**：弹出差异视图，要求显式选择。
- 变更历史：每条规则可展开「谁改的、改了什么、何时」。

### 特别提醒（既有硬约束）
用户级 MEMORY.md 是**每轮无条件注入**的，**改动会直接影响所有人的提示词预算** ⇒ 团队规则层必须显示「该规则将占用团队每个人的 X token」这类成本提示。这是企业客户会问的问题。

## F2 作废 / 撤回（三态治理）

### 现状
`superseded` / `retracted` 状态行（`dsh-status`）；用户明确裁定「**返回但标记是正确的**」。

### 多人同步
- 状态是**事实**（P1 字段级），状态变更历史走 **P2 追加**。
- **并发状态变更**：后到者生效但**保留历史**（不丢"某人曾标过作废"这件事）。
- **团队版含义**：某人标作废后，**全团队都看到标记** —— 这正是"防记忆劫持"的团队延伸。

### 后端改动点
1. 状态行加 `by`（谁标的）与 `at`。
2. 状态变更写追加日志（可追溯"为什么作废"，附 `reason`）。
3. 拉取到状态变更时，本地条目标记但不删除内容。

### 前端显示
- 状态徽标：`current` / `⚠ 已作废` / `⚠ 已撤回`，悬停显示**谁在何时、为什么**。
- 作废条目仍返回（遵既有裁定），但**必须显式标注**并给出后继指向（`supersededBy`）。
- 团队视图里，他人的作废标记与自己的用同样样式（避免"我的作废更权威"的错觉）。

## F3 召回审查（审计能力）

### 现状
召回审查页：今日召回、命中率、待审查、平均置信度；明细表（主题 / 被召回记忆 / 分数 / 触发原因 / 来源 / 结果）+ 右侧详情（证据链、边界信息、反馈按钮）。

### 多人同步
**企业最看重的一页**：可解释、可审计。

- **个人审查记录 S1**；**团队审计聚合 S2**（P2 追加）。
- 审计内容：谁在何时召回了哪类记忆（**不暴露全文**）、命中与否、是否被采纳。
- **合规价值**：能回答"AI 为什么给了这个建议" —— 这是企业落地的硬门槛。

### 后端改动点
| # | 改动 | 说明 |
|---|---|---|
| 1 | 审查记录加 `actor` 与 `teamVisible` | 默认仅个人可见 |
| 2 | 团队聚合接口 | 命中率、成员参与度、趋势、异常（某类记忆总不命中） |
| 3 | 审计导出 | 支持导出为 CSV（合规存档） |

### 前端显示
- 审查页加 tab：「我的」/「团队」/「审计导出」。
- 团队 tab：成员参与度、团队命中率趋势、**团队记忆的"从未被召回"清单**（用于清理）。
- 每条详情增加「谁能看到这条审查记录」的标注。

## F4 存储管理

### 现状
扫描 / 修复 / 删除（下拉 + 输入 + 确认）；路由 `storage-manage` / `scan-dirty`。

### 多人同步
- **S0 本机运维动作**，不同步。
- **团队级新增**：团队配额视图（各成员占用）、团队库健康度（重复条目、孤儿证据、损坏 JSON）。

### 后端改动点
1. 团队侧新增配额与健康度接口（管理员可见）。
2. 本机删除动作**不得**删除团队共享数据（需权限判定）。

### 前端显示
- 存储页分两栏：「我的占用」/「团队占用（管理员可见）」。
- 团队健康度：重复条目数、孤儿证据数、待合并冲突数 + 一键导出报告。

## F5 会话归档 / 删除（F 线自持）

### 现状【实测】
本插件自持：`autoArchiveEnabled` / `autoArchiveDays=2` / `autoDeleteEnabled` / `autoDeleteDays=7` / `autoArchiveCheckMin`（下限 15）；`session-archive.js` / `subagent-gc.js`。

### 多人同步
- **纯 S0 本机态**：会话是**本机磁盘上的文件**，与团队无关。
- 团队层面唯一需要的是**策略**：企业可要求「所有会话保留 90 天」（合规），但这**改的是本机清理阈值**，且必须**用户可见**。

### 后端改动点
1. 团队策略可下发 `minRetentionDays`，但**只能延长不能缩短**（安全方向）。
2. 若团队策略生效，本机界面必须显示「保留期由组织策略设定」。

### 前端显示
- 设置页 F 线分区显示：`本机设置保留 7 天 · 组织要求 ≥ 90 天（以组织为准）`。
- 不允许把组织策略静默写入而不提示。

## F6 降级账本

### 现状
`memory/degrade/`；`degrade.js` / `degrade-pre.js`；配额探针与判定。

### 多人同步
- 本机降级原因（模型不可用、配额耗尽）**是运维信息**。
- 可选**聚合上报**（P2）让管理员知道"团队里多少人语义引擎不可用"。

### 后端改动点
1. 上报项仅：降级原因码、时间、引擎类型（**不含内容**）。
2. 管理员视图聚合。

### 前端显示
- 设置页调试中心显示本机降级原因。
- 管理员可见「团队 12 人中 3 人语义引擎未就绪」这类聚合。

## 本族汇总

| 功能 | 同步模式 | 后端改动 | 前端显示 |
|---|---|---|---|
| F1 规则层 | **三层（个人/团队/组织）** | 分层字段 + 权限 + 冲突 + 审计 | 分层分组 + 强制标记 + 成本提示 |
| F2 作废撤回 | P1 状态 + P2 历史 | 状态加人 + 追加日志 | 徽标 + 谁/为何 + 后继指向 |
| F3 召回审查 | 个人 S1 + 团队聚合 S2 | actor + 团队接口 + 导出 | 三 tab（我的/团队/导出） |
| F4 存储管理 | S0 + 团队配额视图 | 配额/健康度接口 + 权限 | 双栏 + 团队健康度 |
| F5 归档删除 | S0 + 团队策略（只延长） | minRetentionDays | 「以组织为准」提示 |
| F6 降级账本 | S0 + 可选聚合 | 原因码上报 | 本机原因 + 管理聚合 |

**本族待拍板**：
1. 组织策略层是否需要**强制下发不可覆盖**（合规客户通常要求 yes）？
2. 审计导出是否包含**提示词原文**（涉及隐私，建议默认不含）？
