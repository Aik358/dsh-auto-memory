| `--dsw-alias-button-primary-hover` | 悬停背景 |
| `--dsw-alias-button-primary-dimmed` | 禁用色调 |
| `--dsw-alias-label-primary-foreground` | 填充上的文字 |

**★ 明令禁止**：`--dsw-alias-brand-primary` 与 `--dsw-alias-brand-primary-invert` 是**强调色与前景令牌，不是按钮配对** —— 当前官方主题下两者**解析为同一主题中性值**，当 fill + text 用会渲染成**黑底黑字（亮色）/ 白底白字（暗色）**。**「Never consume them as a button fill.」**

**皮肤作者规则 4 条**：
1. 优先**按主题整套声明**（light 块 + `body[data-ds-dark-theme]` 块），颜色成对匹配。
2. **传统配对仍被尊重**（同时声明 `brand-primary` + `brand-primary-invert`）：加载器从 brand 派生 fill、朝 surface 派生 hover/dimmed、用 invert 作前景 —— **因为配对由作者保证**。
3. **部分声明只告警不失败**：加载器补齐缺失项；**既无 brand 又无按钮令牌的皮肤刻意保留 shell 自带的成套 CTA**。
4. 加载器**永不覆盖皮肤已定义的令牌**。

**完成矩阵（加载器 `css-safety/fallback.ts`）**：
| 皮肤声明 | 加载器补充 |
|---|---|
| `brand-primary` | `button-primary-fill: var(brand-primary)` |
| fill 可用（显式或派生） | `button-primary-hover` / `button-primary-dimmed`：朝 `--dsw-alias-bg-layer-1` 做 `color-mix` |
| `brand-primary` + `brand-primary-invert` | `label-primary-foreground: var(brand-primary-invert)` |
| **什么都没有** | **什么都不加** —— shell 自带 CTA 生效 |

**审计（`css-safety/token-audit.ts`）：仅告警，永不致命**。
- **完整性**：fill 由 `button-primary-fill` 或 `brand-primary` 满足；hover 由 `button-primary-hover` 或 fill 锚满足；前景由 `label-primary-foreground` 或传统 invert 对满足。
- **对比度**：每主题算 WCAG 2.x 前景 vs 填充比（皮肤值、一跳 `var()`、官方静态调色板 `--dsw-static-*`、shell 默认值兜底）。**低于 3:1 告警**。链路不可解析则跳过比值，不猜。
- **强制点**：catalog 构建（`dsh-skin list` 与皮肤中心诊断）/ `dsh-skin validate`·`install` / **内置皮肤 CI 门（出厂皮肤零契约告警）**。

**消费方规则（插件）**：实心主按钮**逐字使用该集**（BG = fill，label = foreground，hover = hover）。**不得**用 `brand-primary` 当按钮背景、**不得**引入每插件硬编码强调色、**不得**跨族配对令牌。

### 1.7 `performance-guidelines-v1.md` — 皮肤运行时性能契约（108 行）

**契约归属**：皮肤中心单方拥有（冲突仲裁不靠加载顺序）。版本 `performance-guidelines/v1`（2026-02）。
**定位**：「advice with teeth」—— 有代码评审钩子检查 + 人工评审案例研究（orca-link hooks / patches）。

| 规则 | 内容 | 判据/数值 |
|---|---|---|
| **R1** | DOM 观察必须**限定范围并短路** | 观察 `document.body` + `subtree:true` **仅在**每个回调能用 O(1) 回答「我的锚点真的变了吗」时才可接受；锚点用 `memo?.isConnected ? memo : locate()` 缓存；高换手区（终端、流式输入背景）用 `closest()` 快速排除后再扫描 |
| **R2** | 宿主字形指纹匹配必须**一次正则预扫** | 指纹表编成**单个 alternation regex**，用 `regex.test(html)` 当布尔门；**保留有序键表做决策**（「表中第一个出现的键」是优先级契约）；**绝不 clone 新 svg**；重新协调必须幂等（防叠第二层 art group） |
| **R3** | 帧循环与无限动画**隐藏时必须暂停** | 订阅 `visibilitychange`：隐藏=清 pending timeout；可见=**从当前序列索引重排**（**绝不重置动画状态**）；把隐藏态镜像到样式表可读的属性（如 `body[data-*tab-hidden]`）并设 `animation-play-state: paused`；**不要写没人消费的 CSS 自定义属性**；用合成属性（`transform` / `opacity`）做动画 |
| **R4** | `will-change` **不得停在全屏或空闲层** | `will-change: opacity, transform, filter` 会让 GPU 合成层**永久存活**；**只在持续动画元素上保留**；**绝不放**仅仅交叉淡入淡出的全视口固定背景；`backdrop-filter` 实时且昂贵 ⇒ **覆盖面积压到最小所需表面、避免动画它、在模糊面下滚动测试** |
| **R5** | 变更回调中**绝不交错布局读写** | `getBoundingClientRect()` / `offset*` 读会强制布局；变更风暴中读写交替 = **布局抖动** ⇒ **先批量读，再批量写**；把测量缓存到 binding 上，仅在引用元素变化时重算 |
| **R6** | 清理必须委派（既有契约，重申） | `apply()` 中创建的**每个** observer / listener（`visibilitychange`、`pointermove`、`click`、`focusin`…）/ timer / interval **必须经 `ctx.onCleanup` 注册并按逆序拆除**，**含新增的全局 body 属性** |

**验证门槛（可复算）**：用 DevTools Performance 面板在**会话加载**与**会话切换**期间前后测量（皮肤挂钩的最重 DOM 操作）。**长任务聚合 > 100ms** 或这两次操作期间主线程繁忙帧 ⇒ 违反上述规则。每个皮肤的性能追踪数字作为回归基线，**必须写进 PR 正文**。

## 三、L2 布局 schema 草案（JSON 形态）

### 3.0 设计前提（三条硬约束，来自 §1）

1. **不得自造平行 API**（`hooks-api.d.ts` 逐字） ⇒ 本草案**全部术语挂靠官方**：必填 `data-dsh-part`（官方枚举值）+ 我方 `data-dsh-plugin="auto-memory"`；我方私有槽位走 `data-dsh-part` 的**自定裸值**（官方纪律允许：每个枚举值必须有 owner —— **owner 就是我方**）。
2. **皮肤作者拿不到 hooks**（README 信任模型） ⇒ 「自由排版」**只能**由 CSS + DOM 属性实现，**本文案不含任何 JS 钩子**。
3. **`contributes.stylesheet` = L1 token + L2 语义样式**（官方 manifest 描述逐字） ⇒ 本 schema 属于官方已定义的 **L2 层**，不是新层。

### 3.1 层级模型（**3 层：region → slot → block**）

```
region (区域)       = 一块矩形承载面，有稳定的 data-dsh-part 锚点
  └ slot (插槽)     = 区域内一个可排序位置，有 data-dam-slot / data-dam-order
      └ block(块)   = 插槽内一个内容单元，有 data-dam-block + data-dam-kind
```

**皮肤作者的操作面（只有这 4 件事，全部是 CSS / HTML 属性）**：
| 能做 | 怎么做 |
|---|---|
| ① 改区域排版顺序 | `[data-dam-region]` 上覆写 `order`（或父容器 `display:flex/grid` + `--dam-region-order`） |
| ② 改区域尺寸 | 覆写 `--dam-region-w` / `--dam-region-h` / `--dam-region-min` |
| ③ 隐藏/显示区域或槽位 | `[data-dam-region="X"] { display:none }` / `[data-dam-slot="Y"] { display:none }` |
| ④ 改块外观/图片 | 覆写 `--dam-*` token + `[data-dam-block][data-dam-kind="Z"]` 背景图 |

**皮肤作者不能做（业务逻辑，永不由皮肤承担）**：改数据来源、改交互行为、改 API 路径、改渲染分支。

### 3.5 皮肤作者如何声明「把哪个 slot 排到哪」

**作者只写 CSS，不写 JSON、不写 JS。** 三种声明方式（按能力从弱到强）：

**方式 A —— 纯 CSS 重排（零成本，覆盖 90% 需求）**
```css
/* 把详情栏提到主区左侧，隐藏日历 */
html[data-dsh-skin="my-skin"] [data-dam-region="page"] {
  display: grid;
  grid-template-columns: 320px 1fr;
  grid-template-areas: "detail main" "detail main";
}
html[data-dsh-skin="my-skin"] [data-dam-slot="detail"] { grid-area: detail; }
html[data-dsh-skin="my-skin"] [data-dam-slot="calendar"] { display: none; }
```

**方式 B —— 顺序声明（用官方 `order`，不动布局算法）**
```css
html[data-dsh-skin="my-skin"] [data-dam-region="page"] { display: flex; flex-direction: column; }
html[data-dsh-skin="my-skin"] [data-dam-slot="summary"] { order: 1; }
html[data-dsh-skin="my-skin"] [data-dam-slot="chart"]   { order: 2; }
html[data-dsh-skin="my-skin"] [data-dam-slot="list"]    { order: 3; }
```

**方式 C —— 变更块内容类型（唯一需要我方配合的形态）**
```css
/* 作者声明：把 list 块换成时间轴外观 */
html[data-dsh-skin="my-skin"] [data-dam-block="list"] {
  --dam-block-style: timeline;   /* 我方消费此变量切换内部渲染分支的 CSS 面 */
}
```
⇒ **方式 C 需要我方在重写时预留 `--dam-block-style` 的消费点**（纯 CSS 消费，不新增 JS 分支）。**这是本草案唯一需要新增契约的地方，必须在拟合提问中拍板。**

### 问题 5 · 两个真缺陷（`--dam-fg` / `--dam-ease-linear`）与死代码（`--dam-ease-pop`）怎么处理？
