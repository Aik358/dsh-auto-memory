### 10.3 ★新风险（R11b 引入，必须由 R11c 处理）

**归档卡会与活跃卡混 kind 归并**：实测 348 组中 **4 组**「组内 kind 不纯」——

| 组 key | 混入的 kind |
|---|---|
| 汇报口径（用户裁定 · 只用这两行） | `plan` + `archive` |
| 已试方案与失败原因 | `ledger` + `archive` |
| 进度与下一步 | `ledger` + `archive` |
| 关键文件 | `ledger` + `archive` |

**根因**：`dedupeCardsPre` 的归并键目前只用 `section`，未含 `kind` ⇒ 归档卡被并进活跃组，其「版本归档」身份丢失（泳道由 `head.kind` 决定）。
**修法（R11c）**：归并键改为 **`kind + section`** 复合键 ⇒ 归档组独立成组、独立进「版本归档」泳道；活跃组行为**逐条不变**（实测 live 组内 kind 本就纯净）。需在 R11a 套件补 2 条判据（复合键分组正确 + 同 kind 行为不回归）。

### 10.4 R11c 判据（下一轮直接照用）

1. 默认路径：`includeArchive` 仍为 `false` ⇒ 读盘量不变（守用户拍板 C）。
2. 显式路径：传 `includeArchive:true` ⇒ 「版本归档」泳道 **> 0**（实测应为 97 组量级）。
3. 复合键：归档组与活跃组**不混**，`stats.byKind` 的 `archive` 计数 > 0。
4. 守恒：任一路径下 **Σcount === 卡片数**。
5. 负路径：畸形 opts / 不存在的 archive 目录 ⇒ 不抛、返回可渲染结果。
