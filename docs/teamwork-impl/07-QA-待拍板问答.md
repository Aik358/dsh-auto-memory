## ★ Q1（必答）团队服务端由谁部署？

**背景**：01 卷实测 —— 插件**不能接收服务端入站连接**（56 条路由全被回环守卫锁死）。⇒ 只能是「客户端推 + 客户端拉」，服务端必须是个**客户端能主动访问的 HTTP 端点**。

- [ ] **A ★ 局域网共享目录过渡** —— 暂不做服务端，先做「共享目录同步」（复用 `migrate-pack` 通道）。
      *优点：零服务端即可演示、风险最低；缺点：无实时性，适合 ≤5 人*
- [ ] **B 客户自建（交付 Docker 镜像）** —— 数据不出内网（企业最爱）、合规简单。
      *缺点：客户需运维能力、版本碎片化*
- [ ] **C 我们自建 SaaS** —— 客户零运维、升级统一。
      *缺点：我们承担数据合规责任，客户可能不接受数据出内网*

**我的建议**：**A 先行做演示 → B 作为正式交付形态 → C 作为可选托管**
**影响面**：决定 03 卷 `fetchJson` 的实现目标

**你的答案**：＿＿＿＿＿＿＿＿＿＿

## Q3 团队项目 ID 怎么生成？

**背景**：`wsKey` 按本机路径派生 ⇒ **跨机不汇合（身份级缺陷）**。需要与路径无关的团队项目 ID。

- [ ] **A ★ git remote 派生 + 管理员登记兜底** —— 从 `remote.origin.url` 规范化哈希；有 git 的团队零配置，无 git 则回退手填
- [ ] **B 纯管理员登记** —— 客户在团队设置里手填。最可控但需人工
- [ ] **C 服务端分配** —— 首次连接时服务端给 ID。需服务端，离线不可用

**需你一并确认的降级行为**：无 git 且未登记时，是否接受「**仅本机共享**」并在 UI 明确提示？
- [ ] **接受 + 明确提示**（我的实现；理由：静默失败更糟）
- [ ] 不接受，此时禁止进入团队模式

**你的答案**：＿＿＿＿＿＿＿＿＿＿
