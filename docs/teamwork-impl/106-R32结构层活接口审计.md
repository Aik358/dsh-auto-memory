## 二、★★关键判定修正：`chart-legend` 不是缺口，是**有意留白**

### 初次判断（**错的**）
首跑发现 `chart-legend` 是唯一「配置可写、DOM 零节点」项 ⇒ 一度判为「真缺口」并准备补挂。
### 检索既有裁定后推翻
`memory_recall` 命中 2026-09-26 的**既有裁定**（mem_639368b895e649ae）：
> `data-dam-graph-legend` / `data-dam-legend-dot` 属**死锚点**（CSS 有 display/flex/尺寸规则但 JS 零生产者），
> 按 schema 挂属性会**激活这些 CSS** 从而破坏零视觉变化，故 `chart-legend` slot **故意不注入**。
### 实测复核（本轮的独立取证）
| 属性 | 出现点 | 形态 |
|---|---|---|
| `data-dam-graph-legend` | **1 处**（L1887） | **CSS 规则**（非 JS 属性） |
| `data-dam-legend-dot` | **3 处**（L1888–L1890） | **CSS 规则**（非 JS 属性） |

⇒ 与既有裁定**逐字一致**：CSS 有规则、**JS 零生产者**。⇒ **遵循既有裁定，不自创第三解**。
### 处置（按裁定执行，不擅自改实现）
把它登记为**已知留白白名单**，与「真死接口」**显式区分**：
```js
const KNOWN_PENDING = { slots: ["chart-legend"] }   // 有据、非缺口
```
⇒ 审计工具**只在「真死接口 ≠ 0」时报 FAIL**，已知留白照常列出但不算失败。

## 三、★本轮新纪律（第 6 类教训）
**「发现差集」不等于「发现缺陷」——先检索既有裁定，再下判断。**
本轮若直接补挂 `chart-legend`，就会**违反一条已生效的纪律（62 卷 §二 零视觉变化）**，
且违反的正是**同一件事在上一轮已被裁定过**的那个点。
> 判据：任何「X 缺了 / X 没接通」的结论，落笔前必须先 `memory_recall` 查**是否已有裁定**；
> 已有裁定时**按裁定执行并把理由写进产出物**，而不是按直觉修。
