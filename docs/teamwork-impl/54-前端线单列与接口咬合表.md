## 3. ★并行策略（用户要求 (a)）

### 3.1 硬约束：什么不能并行

| 资源 | 并发性 | 依据 |
|---|---|---|
| `lib/client.js` | ❌ **单写者，绝对串行** | 8,250 行单文件；插入式改动会击穿 163 个 `data-dam-*` 锚点 |
| `lib/index.js` | ❌ 单写者（本线预计**零改动**，见 §4） | 66 条路由已就绪 |
| smoke 套件 | ⚠️ 可并行跑（`DEFAULT_JOBS=4`），但**改动本身**串行 | `tools/run-smoke.mjs` |

### 3.2 可以并行的三种工作（真实收益）

| # | 工作 | 为何能并行 | 产出 |
|---|---|---|---|
| **P1** | **L1 色值测绘与分组** | 纯只读：把 223 个色值按用途聚类、生成 token 映射表 | `token-map.json`（新文件，不碰 client.js） |
| **P2** | **L2 布局 JSON 草案** | 纯新增文件：定义 region/slot/block 结构与默认值 | `layout-default.json`（新文件） |
| **P3** | **L3 十条 team 路由的返回形状测绘** | 只读打真机接口，记录真实 payload | `team-payloads.json`（新文件） |
| **P4** | **S2 占位样式设计** | 独立 CSS 段，最后一次性追加 | `skin-placeholder.css`（新文件） |

**⇒ 并行的唯一形式 = 四个新文件先行产出，然后由 Lead 串行合并进 `client.js`。**

> 这不是「并行改 client.js」（不可能），而是「**并行准备素材，串行落地**」。
> 四个新文件彼此无依赖，可同时开工；合并期是瓶颈，无法压缩。

### 3.3 并行度建议

| 阶段 | 建议并行度 | 理由 |
|---|---|---|
| 准备期（P1–P4） | **2 个一级子代理**（用户规则上限） | P1+P2 一组（都属取值/布局层，语义近）；P3+P4 一组 |

## 4. ★★重启压缩方案（用户要求 (b)）

### 4.1 核心洞察：L1 不需要重启

| 层 | 是否需要重启才能验收 | 为什么 |
|---|---|---|
| **L1 取值层** | ❌ **不需要** | token 化是**值等价变换**：可用「展开 token 回原值 → 与原 CSS 逐字符比对」**离线证明**（判据：展开后字符串与改前 sha256 一致）。无需真机。 |
| **L2 布局层** | ✅ 需要 | 布局变化只有肉眼可见，必须真机 |
| **L3 团队层** | ✅ 需要 | 涉及 10 条路由真实数据，必须真机 |
| **S2 皮肤** | ✅ 需要（与 L2 同批） | 图是否显示只有真机可见 |

> **★关键**：L1 若坚持「视觉零变化」，它在数学上就不需要人眼验证。
> 把 L1 做完整 + 离线自证，**不占用任何重启名额**。

### 4.2 重启预算：3 次 → **1 次**

| 方案 | 重启次数 | 每次验什么 |
|---|---|---|
| ❌ 逐层验收 | 3–4 次 | L1 一次 / L2 一次 / L3 一次 / S2 一次 |
| ✅ **一次性批量验收** | **1 次** | L1+L2+L3+S2 全部合并完成后，一次重启验完 |

**代价与对策**：

| 风险 | 对策 |
|---|---|
| 一次改太多，出问题难定位 | **离线分层自证**：L1 用值等价证明；L2/L3/S2 用 `node --check` + 新增 smoke 套件 + 静态锚点计数守恒 |
| 若重启后发现问题，要再重启 | **预留 1 次机动名额**（总计 ≤2 次），但目标是 1 次通过 |
| 中间无法看效果 | 每层完成后出**静态预览**（把生成的 HTML/CSS 片段渲染成离线快照图，不经宿主） |

### 4.3 一次重启的验收清单（重启前必须全绿）

- [ ] `node --check lib/client.js` 通过
- [ ] L1 值等价证明通过（展开 token 后 sha256 == 改前）
- [ ] 163 个 `data-dam-*` 锚点计数**不变**
- [ ] 全量 smoke：**185 PASS / 0 FAIL**（不降级）
- [ ] 计数锁 `MEMORY_TABS()==2` 保持
- [ ] 10 条 team 路由字面量均在 `client.js` 中出现
- [ ] `teamEnabled=false` 负路径：静态断言该分支不触发任何 team 路由

**⇒ 重启后一次性验收**：真机打 10 条 team 路由 + 界面每屏对照概念图 + `teamEnabled` 开关正反两态。
