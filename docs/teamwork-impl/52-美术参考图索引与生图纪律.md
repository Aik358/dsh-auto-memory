## 五、★ 新坑：模型会「画」出假透明底（棋盘格）

**实测（2026-09-27 · 大号山主体那张）**：prompt 里写了 `透明背景 PNG alpha`，模型**没有生成真 alpha**，而是**画了一张棋盘格图案**冒充透明底。

| 证据 | 实测值 |
|---|---|
| 文件元数据 | `channels: 3`，**`hasAlpha: false`** |
| 四角像素 | `rgb(254,254,254) a=255` / `rgb(238,237,237) a=255` |
| 顶部横向扫描 | 254,254,237,238,254,254,238,240… **规律交替** |
| alpha>40 占比 | **100%**（全图不透明） |

**⇒ 判据：出图后必须查 `hasAlpha` 与 `alpha>0 占比`；若元数据 `channels:3` 或四角 alpha=255，即命中此坑。**

**修复（零成本，纯 sharp，无需重出）**：按下述判据抠图——

- 棋盘格 = **中性灰**（max-min < 10）**且亮**（>200）
- 山体 = **饱和度高的蓝色**（max-min 很大）

```js
if (max(r,g,b) - min(r,g,b) < 10 && max(r,g,b) > 200) alpha = 0;
```

**本次效果**：抠掉 1,217,674 px（77.4%），主体 bbox 1413×496 = **92.0% × 48.4%**（承诺 80%×55%，达标）。

## 六、2026-09-27 追加：自发光坑 + 每版出图数量 + 防重复

### 6.1 ★ 模型会「画」自发光，必须显式禁止

- **现象**：图标 sheet 四角 alpha=0（真透明），但**全图没有一个 alpha=255 的像素**；alpha 1–254 占 42–67%。模型给每个元素外围画了一圈半透明发光。
- **后果**：抠图后残留光晕与毛边（用户判定「边缘还是有点毛边，不好抠图」）。
- **修法（写进 prompt）**：禁止外发光/光晕/霓虹/柔光/投影；主体必须 **100% 不透明实色填充**；边缘锐利；背景 alpha=0、**主体 alpha=255，不要中间值**。
- **补救（已出图）**：alpha 重映射 LO=60 / HI=140 —— ≤60 置 0（消光晕）、≥140 置 255（保实体）、其间线性。三版实测 a=0 占比由 33–58% 升到 **69–73%**。

### 6.2 每版元素数量（按元素复杂度分档）

| 类型 | 网格 | 每版数量 | 画布 | 单格占比 |
|---|---|---|---|---|
| 图标 | 3 列 × 2 行 | **6 个** | 1536×1024 | 62% |
| 背景元素 | 2 列 × 2 行 | **4 个** | 1024×1024 | 74% |

单价：一版 5 分 ⇒ 6 个 **0.83 分/个**、4 个 **1.25 分/个**。

### 6.3 元素选题不限于自然景物

用户裁定：「不要局限于树山，欢迎页那种**书页**风格也可以，也可以发类似参考图让他生成其他内容。」
⇒ 纸张/书页类参考图走 a5df489b…（账本页）；自然类走 dd600fd2…（欢迎引导，最扁平）。

### 6.4 防重复：必须附「禁用清单」

实测 sheet02–04：**齿轮出现 5 次、放大镜 3 次、云 3 次**，18 个里有效不重复仅约 8–9 个。
⇒ prompt 必须显式列出本版**禁止出现的图形**（如云朵/铃铛/文件夹/齿轮牙齿/星星），否则模型会退化成画它最熟悉的通用图标。

| 每版 4 元素 | ✅ 2×2 / 1024² | **命中**，4 版均正确切出 4 个 |

### 7.2 ★新坑：底色是「浅色棋盘格」，阈值 >232 会漏掉一半

- **现象**：3 版 `ch=3` 白底图，泛洪抠图后深色底上仍见棋盘格残留（残留中性亮 27–34%）。
- **真因**：边缘环带实测是 **248/248/248 与 224/224/224 交替**（模型又画了棋盘格，这次是浅色的）。
  阈值 `mx>232` 只匹配 248 那半格，224 那半格被判为「非背景」⇒ 泛洪连通性被打断，无法绕行。
- **修法**：阈值降到 `mx>=205`，并把「**已透明像素**（a≤8）」作为**第二泛洪源**（真透明版可直接借道）。
- **统一判据**：源 = 已透明区 ∪ (通道差<16 且 mx≥205)；再按半径 3 的距离场对过渡带做 alpha 软化。
- **残留验收**：非透明像素中「中性亮（差<20 且 mx>200）」占比 **<0.4%** 视为干净。

### 8.4 可复用的教训（写进纪律）

1. **配色必须给实测 hex 值，不能给形容词**：「淡蓝」模型会理解成高饱和天蓝。
2. **背景必须描述「分层景深」**：只写「画树」会得到孤立剪影，不是背景。
3. **出图后必做量化验收**（平均亮度 / 绿色占比 / 饱和），肉眼判断会被「看起来还行」骗过。
