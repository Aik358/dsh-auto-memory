## 二、每轮固定流程（★四步不可省）

| 步 | 动作 | 落盘物 |
|---|---|---|
| **R1 立 plan** | 为大轮写 `plan-Rxx-<模块>.md`，列小轮清单 + 每小轮判据 | plan 文件 |
| **R2 开工前读卷** | 全量读该模块**全部**权威卷（read 全文，不用 grep 片段） | 登记进 65 卷读卷表 |
| **R3 分级实行** | 每小轮独立可验证，不通过不进下一小轮 | 每小轮证据 |
| **R4 完工后读卷 + 核验** | **再读一遍**权威卷，逐条核对「全量性与有效性」 | 验收卷 + 16 台账 |

**每轮必跑的复核（用户纪律②，一条不省）**：

1. `node --check lib/client.js`（+ 改 index.js 时一并）= exit 0
2. 全量回归 `node tools/run-smoke.mjs` ⇒ **FAIL 0 且 PASS 不降级**
3. 加载守卫（**真执行 factory**）`smoke-test-client-loadable.mjs`
4. `tools/verify-docs.mjs` **单独跑**（不在回归套件内）
5. 计数锁/守卫类常量改动 ⇒ **全仓检索所有出现点**
6. CR-10：真 import → 真构造 → 真调用 → 断言返回值 + **负路径** + 可复算物理量
7. 守卫**反向验证**（制造错误 ⇒ 守卫必须变红 ⇒ 字节级还原）
8. 留痕三件套：勾 58 卷表 · 更新 16 台账 · 写 65 卷留痕

## 五、并行与重启约束（决定执行顺序，不能随意重排）

**关键路径（串行，一个都不能并行）**：
`R1 → R2 → R3 → R4 → R5`（外观层，全改 client.js）→ `R6 → R7 → R8`（配置接线）→ `R9 → R10`（结构消费）→ `R16 → R17 → R18 → R19`（团队）→ `R20 → R23`（皮肤）→ `R24`

**可并行**：
- 看板层 R11–R15 主要改 `lib/wb-sidecar.js` + `lib/client.js` ⇒ 与外观层**争 client.js** ⇒ **不可并行**。
- **能并行的只有新文件**（新模块 + 新套件）与**纯调研**（读卷/测绘，≤2 个一级子代理）。

**重启预算（15 卷结论）**：改 `lib/*.js` 的轮次连排，用户手动重启 **≤2 次**：
- 第 1 次：R1–R10 完成后（外观层 + 配置接线 + 结构消费）
- 第 2 次：R11–R23 完成后（看板 + 团队 + 皮肤）
