**根因**：JS 的 `String.length` 是 **UTF-16 码元数**，不是字节数。改用 `Buffer.byteLength(s,'utf8')` 后与预期**逐字节一致**。

### 3.2 关于 `selfcheck.mjs` 的"输出为空"——**不是缺陷，是我的运行环境**

我跑 `node docs/teamwork-impl/demo/_gen/selfcheck.mjs` 得到：
- **退出码 = 0**（说明 12 条断言全部通过，否则脚本会 `process.exit(1)`）
- 但 **stdout 只有 `\r\n`（2 字节）**

**我最初的假说**："是 `process.exit()` 截断了管道输出"。**这个假说被我自己的对照实验推翻了**：

```
实验 A：脚本带 process.exit(0)        → stdout 2 字节
实验 B：完全相同的脚本，去掉 exit     → stdout 2 字节   ← 对照
```

**对照实验说明**：**去掉 `process.exit` 也一样只拿到 2 字节** ⇒ 不是脚本的问题，是**当前执行环境不转发子进程 stdout**。
⇒ **结论：脚本没问题，判据（退出码）有效；"看不到报告文字"是我这边的环境限制。**
⇒ 这也解释了为什么它的自述"12 PASS / 0 FAIL"我**无法直接从 stdout 验证** —— 但 **退出码 0 是可验证的等价证据**。

**这条写进来是为了留个方法论**：报告"某脚本输出为空"之前，**必须先做"去掉可疑因素"的对照实验**，否则会把环境问题当成脚本缺陷（我差点就这么报了）。
