## 0.3 团队化改造的总接口契约（所有模块共用的注入形状）

本仓所有"纯核心"模块都遵循同一形态：**模块自身零 IO，能力经 `opts` 注入**（见 `lib/fact-store.js:337` 的 `const io = opts.io || {...}`、`lib/procedure-store.js:190`、`lib/episodic-store.js` 同款）。
⇒ Teamwork 改造因此可以**统一从注入层切入**，而不必改写任一状态机。下面这段是**所有模块共享的团队暂存适配器契约**（本方案 70 份模块文档里的 `team.stage(...)` 全部指代它）。

```js
/**
 * 团队暂存适配器 —— Host 注入的实现，纯核心模块只调用 stage()，不做网络。
 *
 * 设计三条铁律（与仓库既有纪律同源）：
 *   1. **本地是权威**：stage 失败绝不影响本地写入（对照 hub-io.js:110 修复前
 *      "三条线全绿而磁盘没写上"的反面 —— 那次是失败被吞，这次是失败被允许且留痕）。
 *   2. **失败必须可见**：错误走 onError / degrade 台账，不静默
 *      （对照 degrade.js:65 的定性："fail-soft 本身是对的，缺陷在降级不可见"）。
 *   3. **载荷必须相对化**：绝不携带绝对路径（见 lib/dsh-home.js:86 的根口径）。
 *
 * @param {{groupId:string, actorId:string, onError?:Function, sink?:object}} cfg
 * @returns {{stage:(patch:object)=>{ok:boolean, error?:string}, stats:()=>object}}
 */
export function createTeamStagePre(cfg) {
  const c = cfg || {}
  const stats = { staged: 0, failed: 0, skipped: 0 }
  const pending = []
  return {
    stage(patch) {
      // 未入组 ⇒ 静默跳过（不是错误）：未开启团队版的用户路径必须逐字节不变
      if (!c.groupId) { stats.skipped++; return { ok: true, skipped: 'not-in-team' } }
      if (!patch || patch.v !== 1) { stats.skipped++; return { ok: true, skipped: 'unsupported-version' } }
      try {
        pending.push(patch)
        stats.staged++
        return { ok: true }
      } catch (e) {
        stats.failed++
        const msg = (e && e.message) ? String(e.message) : String(e)
        // 铁律 2：失败必须可见
        if (typeof c.onError === 'function') { try { c.onError('team-stage', msg) } catch (_) {} }
        return { ok: false, error: msg }
      }
    },
    stats: () => ({ ...stats, pending: pending.length }),
  }
}
```
