## 99.3 最重要的 5 个改造点

### ① `hub-io.js:110` —— 固定名 `.tmp`：**这是一个"条件性风险"，不是已发生的线上缺陷**

```js
const tmp = file + '.tmp'   // ← hub-io.js:110：tmp 名只由目标路径决定（已核准）
```

**★ 本轮独立复测（不改结论，只校准严重度）**：

| 检查项 | 结果 |
|---|---|
| 代码事实 | ✅ 已核准 —— 第 110 行确为 `const tmp = file + '.tmp'`，全文仅此一处 |
| 仓内先例 | ✅ 已核准 —— `config-io.js:50` 记录了**同一模式**在 issue #82 的修法与**实测病症**（并发保存时后到者 `rename` 找不到源 → **ENOENT**；对应守卫 `smoke-test-p3-batchb-guards.mjs` P3B-2d） |
| **是否已构成实时缺陷** | ⚠️ **取决于是否真的并发写同一 filePath**——单写者串行场景下**不会**触发 |

⇒ **准确表述应为**：这是**已被仓内先例证明是真缺陷的模式**，但在 hub-io 的**当前调用形态下是否触发，取决于实际并发度**，本轮**未做并发压测、不下"已发生"的断言**。
⇒ **团队化会显著提高触发概率**（本地写入 + 同步回写可能同时发生）——**这才是"必修"的真正理由：不是因为它现在坏了，而是因为团队模式会把它的触发概率从"低"推到"不可忽略"。**

**修法**（对齐 `config-io.js` 的既有处方，不要另创一套）：

```js
// lib/hub-io.js:108-113（改这一处即可）
let _tmpSeqPre = 0                       // 进程内自增序号（模块级）

function atomicWrite(file, name, data) {
  mk(dir, { recursive: true })
  // ★ 唯一段 = pid + 进程内自增序号（与 config-io.js:38 同一处方）
  const tmp = file + '.tmp-' + process.pid + '-' + (++_tmpSeqPre)
  try {
    wf(tmp, JSON.stringify(data), 'utf8')
    rn(tmp, file)
  } catch (e) {
    try { rn(tmp, file) } catch { /* 二次尝试 */ }   // 保留原语义
    throw e
  }
}
```

**边界（照抄 `config-io.js:49-51` 的纪律）**：tmp **必须落在同目录**（`rename` 需同文件系统）；失败路径须清理；进程崩溃会留下可识别的 `.tmp-<pid>-<n>`，**不自动扫描删除**（避免误删他人正在写的 tmp）。

**同类残留**：`recall-stats.js:123` 仍是固定名 —— 团队化前应一并处理（已核实）。

### ② `memory-writer.js:452` —— `_commit()` 是所有写入路径的**唯一汇聚点**

四个入口（`append` / `replace` / `replaceSingle` / `applyPlan`）最终都走 `_commit` ⇒ **一处接入即全路径覆盖**，不会出现"某个入口漏投递"的半修状态。
**必须遵守的顺序**：先落盘、后投递（对照 `hub-io` 修复前"三条线全绿而磁盘没写上"的反面教训）。

### ③ `procedure-store.js:378` —— 被守卫锁死、**不可改函数体**

`promote()` 与 `evaluatePromotion()` 的门限顺序被 `smoke-test-r2-promotion.mjs` 用**字面正则锁签名 + 源码切片比对**。⇒ 团队化只能**新增**（如 `applyTeamEvidencePre`），绝不能重构这两个函数。
这正是 `procedure-store.js:505 hiddenStructuralCodesPre` 展示的模式：**给"被守卫锁死不能改"的核心函数做只读增补**，而不是重构它。

### ④ `engine-identity.js:34` —— 跨端复用向量的**唯一硬门**

七类字段（模型与权重摘要 / tokenizer / 精度 / 维度 / 池化 / 归一化 / 输入处理版本）缺一即会串用。
文件头记录了失败案例：**e5（384 维）与 bge-m3（1024 维）混进同一次排序 = T2-9 判失败**。
⇒ 团队化的"共享向量省算力"必须过此门；**身份必须随载荷显式携带**，绝不能由接收方猜。详见 `engine-identity.md` / `l0-index.md`。

### ⑤ 三条**反复出现**的纪律（不是单个模块的问题）

| 纪律 | 首次踩坑 | 团队化风险 |
|---|---|---|
| **身份/指纹/digest 不得掺入团队身份** | `memory-anchor.js`（id 稳定）、`wb-sidecar.js:11-14`（BUG-10 同一条目两个 id） | 两端算出不同 id ⇒ 团队索引无法归并 |
| **同一语义不得多处实现** | `ledger-criteria.js:16-18` 明确"勿重复造轮，统一转发保持单一真源" | 团队端另写一套 ⇒ 出现"有的路径能解析、有的恒判失败"的半修状态 |
| **失败必须可见** | `hub-io.js`（#110）、`degrade.js:33`（R2：四条臂各自静默降级） | 团队同步静默失效 ⇒ 用户只觉"记忆好像没同步过来" |

## 99.4 实施顺序建议（按依赖与风险排序）

| 阶段 | 目标 | 涉及模块 | 前置条件 |
|---|---|---|---|
| **P0 · 缺陷止血** | 修 `hub-io.js:110` 固定 tmp 名；确认 `recall-stats.js:123` 同类问题 | hub-io、recall-stats | 无（可立即做） |
| **P1 · 契约握手** | 给所有 S2 契约加**版本断言**（fail closed） | engine-identity、wb-contract、ledger-criteria、memory-mutation、state-commit、index-sync、m7-wire | P0 |
| **P2 · 写入链路** | `memory-writer._commit`（L452）单点投递 + `applyRemotePatchPre` 防回流 | memory-writer、memory-anchor、fact-store、procedure-store、episodic-store | P1（契约先定） |
| **P3 · 证据与重要性** | 跨端证据合并 + actor 复合去重键（三处统一） | context-bridge、evidence-store、evidence-agg、memory-importance、procedure-store、procedure-observation | P2 |
| **P4 · 注入与预算** | team 桶独立预算 + 分段配额 + 来源标 | memory-envelope、tier-layer-inject、tier0-catalog、rules-layer、activation-inbox | P3 |
| **P5 · 索引与向量** | 团队索引同步（复用 index-sync / m7-index-sync-host）+ 向量复用门 | index-sync、m7-index-sync-host、l0-index、l0-index-sync、engine-switch | P1（身份门） |
| **P6 · 白板与治理** | 白板/账本共享 + 团队规则真源 + 团队验收门禁 | wb-contract、wb-sidecar、handoff-anchor、rules-edit、acceptance、storage-manage | P2 |
| **P7 · 观测与诊断** | 团队臂进 degrade 台账 + 各就绪度上报 | degrade、recall-fusion、rerank-host、semantic-js、semantic-decide | P5、P6 |

**顺序理由（三条硬依赖）**：
1. **契约先于数据**：P1 的版本握手是 P2–P6 的前提 —— 否则两端对同一份数据给出不同判定，同步会产生**静默分叉**。
2. **写入链路先于其它**：`memory-writer._commit` 是唯一汇聚点，先接通它，后续所有模块的"投递"才有统一出口。
3. **身份门先于向量共享**：P5 的向量复用若不过 `engine-identity` 门，会直接复现 T2-9 的维度混用失败。

## 99.5 贯穿全部模块的团队化铁律（从 70 份文档中提炼）

| # | 铁律 | 来源（反复出现） |
|---|---|---|
| 1 | **本地是权威，同步是尽力而为**；同步失败绝不回滚本地 | fact-store、memory-writer、context-host |
| 2 | **远程补丁必须防回流**（否则 A→B→A 无限回环） | memory-writer 片段 3 |
| 3 | **身份派生量绝不掺入 actorId/groupId/时间戳** | memory-anchor、wb-sidecar、evidence-agg、procedure-observation、index-sync |
| 4 | **版本/枚举不一致时 fail closed**（不猜、不"尽力而为"） | wb-contract、ledger-criteria、memory-mutation、state-commit |
| 5 | **新增一律"独立开关 + 缺省关闭"**（单一开关不得顺带改变其他行为） | 全部 70 份；用户硬性规则 |
| 6 | **团队预算是独立的、不得挤占本机** | memory-envelope、tier-layer-inject、tier0-catalog、activation-inbox、shadow-host |
| 7 | **失败必须进可查询台账**（degrade 的 arm='team'） | degrade 及其 10 个消费点 |
| 8 | **JS 端与 Python 端是两套可互换实现，严禁联动** | semantic-js、semantic-decide、context-sink-python、python-setup、shadow-host、wb-sidecar |
