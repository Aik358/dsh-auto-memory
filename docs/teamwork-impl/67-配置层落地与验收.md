## 五、★施工中抓到并修掉的两个真缺陷（诚实记录）

### 缺陷 1：`node --check` 假绿 —— 多写一个 `}` 导致顶层 `return`
- **现象**：`node --check lib/layout-config.js` **exit 0**（全绿）；但真 import 抛 `SyntaxError: Illegal return statement`。
- **根因**：`node --check` 按 **CommonJS** 解析，**顶层 `return` 合法**；本模块是 ESM（含 `export`），ESM 顶层 `return` 非法。多写的那个 `}` 提前闭合了函数体 ⇒ 后续 `return` 落到模块顶层。
- **判据（可复用）**：**`node --check` 不足以证明 ESM 模块可加载** —— 凡 `.js` 含 `export`，**必须真 `import` 一次**。与本项目既有硬规则「静态守卫不足以证明能加载」同源。
- **修复**：删多余 `}`（9,889 → 9,884 B），真 import 通过。

### 缺陷 2：非法布尔值被静默写成 `false`
- **现象**：`hidden: "yes"`（字符串）被写成 `hidden: false`，而非「忽略该项」。
- **为什么是缺陷**：违反判据③纪律「未知/非法项 ⇒ 忽略 + 告警」。静默写 `false` 会让客户误以为写错也生效。
- **修复**：`hidden` 仅接受真布尔（`=== true` / `=== false`），其余 **忽略 + 一条告警**；测试断言同步拆分（原断言把「非法布尔」与「hidden 数组覆盖」写在**同一输入**里，自相冲突 —— 那是**我的测试写错**，不是实现错）。
