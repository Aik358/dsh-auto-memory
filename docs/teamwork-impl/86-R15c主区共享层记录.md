## 六、★本轮自身缺陷（**3 个，全在生成器阶段拦截，未落盘**）

| # | 缺陷 | 根因 → 修法 |
|---|---|---|
| 1 | 生成器语法错 3 连（`Unexpected token`）| 我在 `A(...)` 行里**逐层手写嵌套引号**（`"  \"...\""`）⇒ 转义地狱。**修法：把所有源码文本（锚 / 旧调用 / 新调用）搬进片段文件**，生成器内**零嵌套引号** —— 即 R6 已定型的片段纪律，本轮我在 R15c 初版又违反了它 |
| 2 | 兜底修复时把 `A("...")` 插到了**生成器自身代码层**（`ReferenceError: A is not defined`）| 用「按行插入」时未区分「生成器源码」与「被生成的字符串」两层 ⇒ 改为按行号精确替换且**立即打印上下文复核** |
| 3 | ★判据⑤「净增行数」期望 **111**，实测 **116** | ★**第 7 次「凭直觉写期望值」**：我只算了「片段插入行数」，**漏算「调用点替换本身」的 +5 行**（1 行 → 6 行）⇒ 改为 `EXP_TOTAL = EXP_INS + EXP_CALL`（两者都由片段自算）|

**⇒ 第 7 次同类教训的升级**：期望值不仅要「由片段自身派生」，还**必须覆盖全部改动来源**（新增 + 替换 + 删除）。**多处改动时，期望 = Σ 各处 delta，逐处自算后再相加**，不得只算其中一处。
