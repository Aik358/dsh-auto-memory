## 一、修复方向（按优先级，全部为前端线）

### R1 · 整页承载面【A 级】
- v4 看板（`KanbanBoardRail` 一族：rail + `DamRailToolbar` + `DamStatBar` + `DamTimelineList`/`KanbanBoard` + `DamFoldBar`）必须获得**整页/全宽承载**，**禁止**再塞进 `Card` 卡片（凡命中 client.js:1896 `max-height:220px` 的容器一律不得承载看板）。
- 具体落点建议（二选一或并行）：
  - **白板页**：皮肤=「看板工作流 v4」时，整页替换为看板视图（rail 左 + main 右，1585×992 版式的流式实现）；皮肤=「经典」时维持现状。
  - **底部「白板看板」页签**（宽表面）：皮肤激活时渲染 v4 时间轴形态，替换现在的「时间矩阵」表格（或矩阵作为 v4 里的「列表视图」档收编，三视图切换按钮本来就是它的位）。
- **不重写数据层**：`wb-sidecar.js` / `/kanban-board` 接口 / 取参逻辑照用。

### R2 · 皮肤注册与切换【A 级】
- 在**既有皮肤机制**（skin-center / 设置页皮肤档位）注册两档：
  - ①「经典」（现状 UI，**默认**，老用户零感知 —— G-A1/G-A3 红线）；
  - ②「看板工作流 v4」（新看板整页）。
- 切换粒度：至少**白板/看板区域**随皮肤切换；不要求全应用换肤。
- 落盘沿用既有配置机制（配置键/boardMode 同区或 skin-center-active 同源），**客户改一行能切回**；不新增路由、不新增依赖（package.json 保持空 `{}`）。

## 四、★修正（用户 2026-09-27 晚追加）：切换语义 = 「或」替换，不是「且」并存

> 用户原话要点：「旧 UI 和新 UI 是 **or** 的关系。你选了新 UI，旧 UI 就应该被**替换**，全屏的东西就会变成新 UI。」

### R40 复验中间态实测（20260927-27/28 截图）

- ✅ 220px 一刀切已解除：rail 8 项 + 「工作流时间轴」main 已抬升为页面流内整宽区块（`data-dam-flow` 直接子元素生效）。
- ❌ **但切换语义仍是「并存」**：boardMode=graph 时，白板页从上到下依次渲染 开关卡 → 自动接续 → 上下文水位 → **rail + v4 看板** → （下方仍是）PLAN.md / 历史版本 / 账本时间线 / 一键接续 —— 新旧两代 UI 同页堆叠。

### 修正后的验收语义（R1/R2 据此改判）

| 档位 | 白板页/看板承载面必须渲染 | 必须不渲染 |
|---|---|---|
| **新 UI**（graph/v4） | **只有** v4 看板整页：rail(220px 左栏) + main（工具栏/统计卡/时间轴/折叠条），占满承载面全部高度 | 开关卡、自动接续、水位卡、PLAN.md、历史版本、账本时间线、一键接续等**全部旧内容卡** |
| **旧 UI**（legacy/经典，默认） | 现状（与修复前逐字节一致） | 不得出现 rail / 时间轴 / 统计卡任何 v4 组件 |

- **切回入口必须保留**：新 UI 档下旧内容卡被替换掉，但切换开关必须在**设置页**可达（实施方自报设置页已有 boardMode 按钮 —— 复验时实点验证「新 UI ⇒ 设置 ⇒ 切回旧 UI ⇒ 白板页恢复旧貌」全链）。
- 底部「白板看板」宽页签同理：新 UI 档=整页 v4 形态；旧 UI 档=现状时间矩阵。
- 判定人复验项新增两条：① 新 UI 档下白板页**不含任何旧卡**（截图）；② 设置页切回全链实点（截图两态）。

### R2 裁定（对实施方「做到一半」的答复）

**接受复用 boardMode，不强制新增独立配置键**（理由：零新键=零计数锁连坐，且 boardMode 本就是「新旧两档」语义；对客户而言这就是新旧 UI 开关）。但必须补两点：
1. 在设置页该开关旁**把文案改名为「界面版本」或「白板皮肤」**（经典 / 看板工作流 v4），让「皮肤/可切换」语义对客户可见——纯文案改动，不动计数锁；
2. graph 档下按上表执行**替换**语义（这是本次修正的实质）。
