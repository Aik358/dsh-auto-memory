## 三、12 条改法要点（按改动量排序，逐条给代码位置）

### ★3.1 【最高优先】memory_procedure 的技能 id 必须内容寻址

**问题（身份级缺陷，不同步也会踩）**：技能 id 当前是 **title + 时间戳哈希**。两个人写同名技能 ⇒ **不同 id ⇒ 同步后变两条重复**。

**改法**（`lib/procedure-store.js`）：把 id 生成改为**内容寻址**，并保留旧 id 作别名（向后兼容）：

```js
// ===== 改 lib/procedure-store.js 的 id 生成点 =====
import { createHash } from 'node:crypto'

/**
 * 内容寻址 id：同内容 ⇒ 同 id ⇒ 天然去重、天然跨机一致。
 * 归一化必须**跨机稳定**：只用 title + steps（**不含时间戳/路径/机器名**）。
 * 旧 id 保留为 alias，避免既有条目失联。
 */
export function procedureIdOf(entry) {
  const norm = [
    String(entry.title || '').trim(),
    (Array.isArray(entry.steps) ? entry.steps : []).map((s) => String(s).trim()).join('\n'),
  ].join('\u0000')
  return 'proc_' + createHash('sha1').update(norm, 'utf8').digest('hex').slice(0, 16)
}

// 写入时：新条目用内容寻址 id；既有条目补 alias（幂等，只补一次）
export function ensureContentAddressed(store) {
  for (const e of store.list()) {
    if (e.id && e.id.startsWith('proc_')) continue
    const nid = procedureIdOf(e)
    if (nid === e.id) continue
    e.alias = e.alias || e.id      // ★ 旧 id 存为别名
    e.id = nid
  }
  return store
}
```

**回归**：既有条目 id 会变 ⇒ **必须**同时保留 `alias` 并在查找时双路匹配（`byId(id) || byAlias(id)`），否则前端书签/引用会断。

### ★3.2 【最高优先】团队项目 ID 替代路径派生的 wsKey

（完整实现见 03 卷 `2.5 `team-project-map.js`）

**问题**：`wsKey` 由本机绝对路径派生（实测形如 `--D--dsh-auto-memory--`）。两台机器盘符不同 ⇒ **项目库永不汇合**。

**改法**：`engine.resolvePaths` 里，**读取**时优先用团队项目 ID 映射；**写入**时双写（本机 wsKey 目录 + 团队项目目录软链或副本），保证旧路径仍可用。


### 3.4 config 分层：团队策略 vs 设备偏好

```js
// ===== 新增：lib/config-scope.js =====
/** 设备偏好白名单：这些键**永不进团队策略层**（防"改主题污染全团队"）。 */
export const DEVICE_ONLY_KEYS = Object.freeze([
  'theme', 'skin', 'locale', 'language', 'fontScale', 'density',
  'notifications', 'soundEnabled', 'panelWidth', 'lastTab', 'tourDone',
  'updateAuto', 'telemetry', 'proxyUrl', 'customCss',
])

/** 团队策略键前缀（可被管理员下发覆盖）。 */
export const TEAM_POLICY_PREFIX = 'team.'

export function scopeOfKey(k) {
  const key = String(k || '')
  if (DEVICE_ONLY_KEYS.some((d) => key === d || key.startsWith(d + '.'))) return 'device'
  if (key.startsWith(TEAM_POLICY_PREFIX)) return 'team'
  return 'device'                     // ★ 默认 device（保守：不确定就不外传）
}

/** 合并：设备层覆盖团队层（**用户的界面偏好永远归本人**）。 */
export function mergeConfig(teamPolicy, deviceConfig) {
  return { ...(teamPolicy || {}), ...(deviceConfig || {}) }
}
```

**★ 默认保守原则**：`scopeOfKey` 对**未知键一律返回 `device`**。这样即使将来加了新配置键，也不会因为"忘了归类"而被误同步到全团队。
