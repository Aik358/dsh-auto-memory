## 二、★本轮处理的两处「既有守卫 vs 契约」冲突（按第 10 条纪律：口径取自权威）

### ① L3 套件 §10.7「L3 段内 `apiGet(API.state)` 恰 1 处」

- 结果：L3 套件 **ALL GREEN**（`apiGet(API.state)` 仍恰 1 处）。

### ② r15 套件 D1 白名单「真值全在白名单」
- 新增 token `--dam-team-actor-hue` 触发 D1 红。
- **裁定**：该 token 是 **fe02 §5.3 逐字要求**（性质与既有白名单项 `--dam-radius` 同类：团队层专用、由 JS 运行时写行内变量）⇒ **扩充白名单 2→3 条**，并**同步更新注释说明**（避免「半修」）。

### ③ L3 套件 §9.2「追加段硬编码色 = 0」
- 初次把 `hsl(var(--dam-team-actor-hue) 62% 52%)` 计为硬编码色 ⇒ 红。
- **裁定**：颜色函数**参数内含 `var()` 属「动态色」**（色相来自变量、由皮肤 token 决定），只有**纯字面量**才算硬编码 ⇒ 守卫改判据为「正则捕获完整调用后过滤含 `var(` 者」，并**同步更新文案**。
