### 0.2 复现方式

本清单的每一张表都由 3 个只读脚本产出（脚本落在 `docs/teamwork-impl/frontend/_gen/`，与本文档同目录，可复跑）：

1. `measure.json` —— 全局计数：锚点、CSS 变量、i18n 键、路由常量与调用点、组件行段。
2. `anchors.json` —— 163 个 `data-dam-*` 锚点的逐项归属（角色 / 首个行号 / 全部命中行号 / 所在组件）。
3. 组件行段表 —— 用「模块作用域（缩进 4 空格）的 `function Name(` 或 `var Name =`」切分出的 200 个行段，用于把每个锚点/调用点归到所属函数。

### 0.3 术语与判据

- **注册面**：`ctx.slots.inject(slot)` + `slots.register({name,id,order,label})` 的全部落点。
- **页签**：`MEMORY_TABS()` 返回的 13 项（id + 标题键），以及 `MemoryTabBody(tab, nonce)` 的分派函数。
- **锚点角色**判据（脚本自动判定，不靠肉眼）：
  - **控件** = 锚点所在 `h('tag', ...)` 的 tag ∈ {button, input, select, textarea, a}；
  - **容器** = 其他元素 tag（div/span/nav/section/header/svg/g/…）；
  - **CSS 选择器** = 该锚点仅出现在 CSS 字符串里（零 JS 使用）；
  - **JS 选择器** = 该锚点在 JS 里被 `querySelector / closest / getElementById` 读取。
- **路由调用点**：`apiGet(API.x)` / `apiPost(API.x)` / `fetch('……')` 三种写法的行级命中；`API` 常量表在第 **1588–1645** 行，前缀 `ROUTE_PREFIX = '/api/dsh-auto-memory'` 定于第 **1584** 行。

### 5.2 「中英对照方式」——两套并存，必须都遵守

1. **字典键法（主通道，632 处）**：所有跨语言通用文案（页签名、字段名、按钮、提示）走 `t(key)`。新增团队版文案**必须**同时补 `zh` 与 `en` 两段，否则英文界面回落中文。
2. **就地三元法（408 处）**：`locale === 'zh' ? '中文' : 'English'` 直接写在 JSX 里，**不进字典**。适用于一次性/场景化文案（如 `'收起浮层' : 'Hide card'`，5928 行）。此法**零 i18n 表改动**（源码注释第 6759 行明确把它当作优点）。
   > 团队版新增界面若走这条路，**不需要改 i18n 字典**，但也就不会被 `t()` 的键名回退保护——漏一处就是空白文案。
3. **函数值键**：字典值可以是函数（`hubScopeCounts(g, w)` 602 行、`hubWhyDiversity(d, need)` 621 行等），用于带参文案；实测 zh 段内含多个 `function` 值项。

**团队版前端三条硬约束**

1. **只加不改（追加式覆盖）**：新界面挂进既有 `registerSurfaces()`（8166）；新分区追加进 `sectionLabels`（7405）；新文案同时追加进 `I18N.zh` 与 `I18N.en`；新锚点统一用 `data-dam-team-*` 前缀。既有 163 锚点 / 23 变量 / 13 页签 / 9 分区**一字不动** ⇒ 字符串锚定守卫零破坏。
2. **三条唯一通道不许绕**：写配置 → `saveConfigPatch`（1670）；发请求 → `apiGet`/`apiPost`（1652/1658）；读配置 → `configOf`（1695）。
3. **状态只走 `controller`**：要跨「左下角浮层 / 记忆会话页」同步的团队版状态，必须挂到模块级 `controller`（145–199）+ `emit()`（134）+ `useTick`（2287）；不得自建第二套状态源（否则会重演「两处切页不同步」）。
