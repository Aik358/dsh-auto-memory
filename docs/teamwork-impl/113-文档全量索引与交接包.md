## §4 ★判据层级：事实 > 代码 > 程序（读这一段再动手）

> **这是本项目最重要的一条裁定，来自用户 2026-09-27 原话**：
> 「**我不太相信你这些配套的断言插件（也就是程序）。你这些断言可能只是你认为的正确，并不是实际上的正确。还是要面向事实，面向代码是否有这样的实现、这样的实现是否正常，以及前端是否以这样的实现为主。**」

**⇒ 判据可信度四级（从高到低，高者可推翻低者）**：

| 级 | 名称 | 是什么 | 可否作为结论 |
|---|---|---|---|
| **L1** | **事实** | 界面上真实发生的事：截图、点击、真机 HTTP 响应、落盘文件字节 | ✅ **唯一可直接成结论的层级** |
| **L2** | **代码** | 源码里**真的存在这样的实现**，且**这个实现本身正常**（读得通、逻辑自洽、边界处理合理） | ✅ 可作强证据（须附文件 + 行号 + 代码原文） |
| **L3** | **消费** | **前端 / 宿主确实以这个实现为主**（不是「写了但没人用」的孤儿代码） | ✅ **必查** —— 本项目重灾区 |
| **L4** | **程序** | 我方自己的断言脚本、验收器、套件 | ⚠️ **只能作线索，不能作结论** |

### 4.1 为什么 L4 必须降级 —— 本项目自己的实证（全部真实发生过）

| # | 发生过的假绿 / 假红 | 教训 |
|---:|---|---|
| 1 | **套件全绿 ≠ 功能通过**：R33 之前，看板层四项**只有源码字符串守卫**，套件一直绿，但功能从未被真执行验证 | 断言对象是「源码里有没有某字符串」= 恒真守卫 |
| 2 | **verify-facts.mjs 自带 exit 0**，且其第 4/5 项用**过期正则**（`slot:` / `id:'overview'`），与现行 `data-dam-*` 体系**不是同一套** | 报出的「实测 = 0」可能是**探测器老旧**，不是事实 |
| 3 | **node --check 假绿**：函数体多写一个 `}` 提前闭合 ⇒ 顶层 `return`；CommonJS 下**合法** ⇒ exit 0 全绿，只有真 import 才炸 | 语法检查 ≠ 能加载 |
| 4 | **静态守卫不足以证明「能加载」**（2026-09-27 真实发生插件加载失败） | 必须跑**真执行 factory** 的运行时守卫 |
| 5 | **负路径恒绿**：用注释包住被检定义 ⇒ 解析器仍匹配注释内文本 ⇒ 负路径失守，**等于没测** | 负路径必须**真删**定义 + 断言锚串恰命中 1 次 |
| 6 | **探针签名错导致 3 次假红**：函数名不存在 / 少传第 3 参 / 参数错位 | 报红前先读 `export function` 签名 |
| 7 | **凭直觉写死期望值**（累计 8 次）：中文排序、天数偏移、上限口径全猜错 | 期望值必须**由被测数据或源码派生** |
| 8 | **排除清单过宽** ⇒ 覆盖率 84.3% → 71.9% ⇒ 判据静默退化为恒真守卫 | 排除清单必须配**覆盖度下限** |

### 4.2 L4 的正确用法（不是禁用，是降级）

| 用法 | 允许？ |
|---|---|
| 用程序**定位**问题（哪里可能有坑） | ✅ 允许 |
| 用程序**生成**候选证据（待复核） | ✅ 允许，但须标注「未复核」 |
| 用程序**直接下结论** | ❌ **禁止** |
| 用「套件全绿」代替「现象发生」 | ❌ **禁止**（00 卷明确反例） |

**⇒ 对外部 Agent 的硬要求**：任何「通过」的结论，**必须追溯到 L1（截图 / 点击 / 真机响应 / 落盘字节）或 L2+L3（代码存在 + 代码正常 + 前端确实在用）**。
**若只有 L4，请写「有程序证据但未取得事实证据」—— 这不是「通过」。**

### 4.3 「代码是否真有实现 / 实现是否正常 / 前端是否以此为主」—— 三问清单

对每个功能点逐条问：

| # | 问 | 怎么答 | 本项目真实反例 |
|---:|---|---|---|
| 1 | **真的存在这样的实现吗？** | 给**文件 + 行号 + 代码原文** | 声称已接线，实际只写了函数、**零调用点** |
| 2 | **这个实现本身正常吗？** | 读通逻辑；看边界（空值 / 异常 / 并发）；看是 fail-safe 还是**静默失效** | 8 个 `--dam-*` token **有消费、无定义、无 fallback** ⇒ 整条声明被丢弃，**屏幕上看不出样式**，而所有静态守卫全绿 |
| 3 | **前端是否以这个实现为主？** | 找**消费方**（调用点 / 渲染分支 / 取值路径）；「写了但没人读」= 不算数 | 三层锚点 `data-dam-region/slot/block` 挂满 1,871 次，但**当时零消费方** ⇒ 铭牌不是接口 |

> **★第三问是本项目重灾区**（46 卷 B1、26 卷、32 卷都栽在这里）。**「存在」与「生效」之间隔着一条消费链** —— 必须把链走完。

### 7.2 截图验收怎么算通过（**判据必须写成「对齐 49 卷 §四」而不是「看起来差不多」**）

| # | 要看的现象 | 判据 |
|---:|---|---|
| 1 | **时间轴卡片** | 四行结构齐全（身份行 / 标题 / 摘要 / 元信息）；卡片等高；右端两个 28×28 按钮 |

| 7 | **欢迎向导 hero** | 首屏有主视觉图（不是灰块、不留白塌陷） |

| 9 | **四套主题** | light / dark / contrast / warm **逐套点一遍关键交互**（不是只看） |

### 7.3 截图纪律（★不做这一步，截图等于白截）

1. **每张截图必须带上下文**：窗口标题 / URL / 时间 / 当前主题 / 当前页签；
2. **必须做「负路径」**：至少一张**故意切到错误页签或未重启状态**的图，用来说明「这个界面确实会跟着状态变」——否则无法排除「截图恰好拍到了缓存页」；
3. **必须复核三重判据**：截图前先记 PID / mtime / 端口；**若没重启过，那拍到的还是旧字节**，该截图**不能用于验收 R25 之后的任何前端改动**；
4. **对照 49 卷 §四 逐项编号**回复，不要写「看起来不错」；
5. 存证路径建议：`docs/teamwork-impl/_shots/<日期>-<项号>.png`（**判定人新建目录**，我方未预置）。
