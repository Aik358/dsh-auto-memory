### 2.5 三条纪律（写进代码注释）

1. **红线段言**：`teamEnabled !== true` ⇒ `canDo` **短路放行**，不读 role、不读配置、不记日志
2. **fail-closed on unknown action**：未知动作**拒绝**（不然任何门都可被拼错的动作名绕过）
3. **fail-open on gate error**：权限门自身抛错 ⇒ **放行**（本模块铁律：绝不因身份模块阻断本机功能）

## 六、2026-10-07 本机业务入口补齐（SEC-02 / #258）

上文 17 项验证的是身份模块能力矩阵，并非各业务入口的端到端权限验收。此次将同一 `canDo` 策略接入团队配置保存、记忆/日历/白板写入原语，以及每条出站队列的发送前准入。

- 配置保存按事务中读取的 **旧 durable 配置** 判定 `edit-team-config`，然后才应用 patch。viewer 不能借同一 patch 改角色、清成员或关闭团队门；普通个人设置仍可编辑。
- `/config` 的现有 `DEFAULT_CONFIG` 字段白名单保持不变。`teamMemberId` / `teamMemberRole` 未在该 HTTP 白名单内；直接保存原语和 HTTP 支持字段分别测试，不将被忽略的 HTTP 角色字段描述为成功改写。
- 同一登记成员变更角色后立即观察最新值；sender 每条复核 `write-own-memory`。拒绝时抛出，真实 outbox 保留条目且不误计 sent，恢复 editor 后可重试。
- 个人模式、未登记身份、默认 administrator 及未知角色回落的既有用户裁定保留。

这是用户在本机登记的业务策略，不是团队服务器身份认证。本机文件所有者仍可自行修改配置；未验证服务器接受或拒绝该用户请求。验证命令为 `node tests/smoke/smoke-test-issue258-team-policy.mjs`：使用真实保存/磁盘/handler/outbox，HTTP 出口为进程内计数器，无真实网络。跨进程原语授权应在统一配置事务外门内用 fresh durable 配置复核，而非仅信实例缓存。
