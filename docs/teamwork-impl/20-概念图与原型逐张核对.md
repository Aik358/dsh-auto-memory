## 3. ★结论

### 3.1 README 那句话：**不成立**

> README §2.5 原句：「最终以我逐张开图的真实内容为准（上表第 8/9/10 行），并据此复核原型：原型的 10 个页面与真实概念图**一一对应**，没有按错图去画。」

**判定：不成立。** 不是「图像映射错了」，而是**「据此复核原型」这一动作没有可验证的证据链**，且环境证据指向相反方向。三条独立证据：

| # | 证据 | 说明 |
|---|---|---|
| **E1** | **时间顺序排除法** | `11-前端皮肤规格-客户概念图.md` mtime **20:11:04** → `skin/index.html` **20:17:07** → `README.md` **20:21:41**。规格卷**先于**原型、原型**先于** README 勘误段。规格卷内**通篇没有任何 sha/路径**（我已检索确认），它只是按「屏 1 … 屏 10」编号的转述。⇒ 子代理拿到的是**文字简报/规格卷**，不是图；README 的勘误是在**事后**追加的自述。 |
| **E2** | **无独立佐证** | 全仓检索 10 个 sha 前缀，**只命中 `README.md` §2.5 与 `_gen/TASK-C.md` 两处**（后者是本次任务的题面，抄自 README）。既没有子代理的映射记录、也没有交接账本记录拿过正确路径。⇒ 全仓**只有 README 一处**声称「原型与概念图一一对应且经过逐张核对」——**孤证**。 |
| **E3** | **preview 残缺** | 一个真的「逐张开图核对过 10 张」的产出，其 5 张渲染截图里**正缺 05/06/07**，且 05/06/07 恰好就是勘误涉及排序错位的区间（见 §4）。⇒ 至少这 3 张在**产线证据层面**没有对图比对的过程留痕。 |

### 3.2 但**比对结果本身是好的**（必须分清）

如果把问题拆成两问，答案是分离的：

| 子问题 | 结论 | 依据 |
|---|---|---|

### 3.3 为什么仍判「不成立」而不是「成立」——高熵数值的同源歧义

这是本次核对最硬的一条发现：

1. 原型里存在大量**高熵细节**与概念图逐字相同，例如：`342 / 128 / 56 / 8`、`76%`、`83% / 12 / 3 / 0.76`、`0.92`、`128/42/36/28/22`、`8/5/12`、`152/98/76/64`、`6/2/14/3`、引语「项目的每一步，都是认知的积累。」。这类细节**无法靠巧合复现**，初看极像「照着图画的」铁证。
2. 但检索显示：**同样的数值在 `11-前端皮肤规格-客户概念图.md` 里几乎逐一存在**（实测命中：`342` 见 vol11:34、`83%` 见 vol11:67、`76%` 见 vol11:56、`152` 见 vol11:95 ……），而该规格卷的 mtime（20:11）**早于**原型（20:17）。
3. ⇒ 「原型照图画的」与「原型照规格卷/文字简报抄的」这两种假设，**在当前证据下产生完全相同的结果**。

> **判定依据**：README 那句主张的是「**据此（开图）复核** ⇒ 没有按错图去画」，即主张一条**因果链**。而当子代理拿到的实际输入（文字编号简报/规格卷）与概念图在可见细节上**不可区分**时，这条因果链**无法被证实**——同时它也无法被证伪。**可证实的只有结果表面的对齐，不是「按图核对过」这一过程**。

⇒ 结论措辞（可放心引用）：

**「不成立」**——README §2.5「原型的 10 个页面与真实概念图一一对应，没有按错图去画」这句话中：
- 「**10 个页面与 10 张概念图在布局与细节上高度对齐**」＝**实测为真**（§2 十页全 `对得上`）；
- 「**且这是经过逐张开图复核得到的**」＝**无证据支持**，且时间顺序与 preview 残缺两项环境证据指向相反。**该句作为「已复核」的结论不成立**，应降级为**「结果未发现按错图，但复核过程无迹可查」**。

**推断（显式标注为推断）**：文件名形如 `<序号>-<主题名>-<页面>.png`，序号与主题都是一套**枚举**：
- 已落地的 4 个主题 = `default` / `enterprise-blue` / `dark-pro` / `a11y-contrast`（我已在 index.html 中实测这 4 个 `data-skin` 值）⇒ **01–04 恰好是「按 4 套主题各出一张」**；
- 序号 05–07 按同一枚举应当对应**另外 3 个页面**，08 则单独对应 `mindmap`；
- 全仓**不存在**任何 05/06/07 的皮肤截图（`**/0[567]-*.png` 只命中 `artifacts/_r3v2-shots/` 与 `artifacts/_v3-shots/` 下**与本皮肤原型无关**的旧截图）。

⇒ **最可能的解释（推断）**：这组截图是**一次未完成的批量截图任务**——作者先按主题拍了 01–04，中途跳号，最后只补拍了 08（mindmap）；05/06/07 **从未生成**，而不是生成后被删除。

**支持「从未生成」而非「被删除」的硬证据**：`git status --porcelain` 对 `skin/` **无任何输出**、`git log` 只有 1 个提交 `a88f2d6` ⇒ 工作树与提交一致，**不存在可追溯的删除痕迹**；mtime 呈连续 2 秒步进的拍图节奏，04→08 之间 8 秒空档符合「跳过不拍」而非「拍完删掉」。

**与勘误的关联（推断，须标注）**：05/06/07 所覆盖的**序号区间**与勘误出错的 4 张（7/8/9/10）在**排序敏感区**上重叠。若当时按「消息文字顺序」而非「sha 顺序」拍图，很容易拍错对象、进而干脆跳过——但这只是推断，**我没有直接证据**。
