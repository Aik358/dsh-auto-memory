给插件**追加一套独立的新 UI 皮肤层**，让「记忆窗格」在经典/新款之间整体切换；**新 UI 严格对齐 10 张参考图**，且**经典档与今天逐字节一致**。

## §2 · 硬约束（违反即失败，不接受「差不多」）

### C1 · 本体零改动【最高优先级】

- 11 卷 §四 §5 验收项原文：「**插件本体零改动（SHA256 基线比对通过）**」。
- **允许新增**：新文件（皮肤包 / 皮肤 CSS / 皮肤 JS / 工具 / 测试）。
- **禁止**：为「新款」而改 `lib/client.js` 的既有行、改 `lib/index.js`、改既有 224 个守卫套件。
- **例外（唯一）**：设置页那个开关按钮（§4.3）与**回退 R41 的替换语义**（§4.4）——这两处必须动 `lib/client.js`，属**修复性回退**，不是新功能。

### C2 · 只追加、不改写

- 新增 `<style>` 段必须**在既有样式段之后**注入（同特异性后者胜）。
- 选择器**一律以 `[data-dam-` 开头**（既有 163 个稳定锚点现成），避免误伤宿主 `.dsw-*`。
- 段落边界用**成对注释标记**：`/* dam-skin:begin */` … `/* dam-skin:end */`，便于整段回退（fail-closed）。

### C3 · 零构建

- 12 卷原则三：「客户不需要 npm / webpack；一个 JSON + 一个 CSS/JS 文件即可生效」。
- **禁止**新增 `package.json` 依赖（保持 `{}`）、禁止引入构建步骤。

### C4 · token 命名

- 皮肤 token 前缀 **`--skin-*`**（与插件既有 `--dam-*` 分离：`--dam-` 管布局尺度，`--skin-` 管外观）。
- 值**照抄 11 卷 §3.1–3.4**，不得自创色值/圆角/时长。

### C5 · fail-closed

- 12 卷原则三：「客户皮肤出错时必须 **fail-closed 回落到默认皮肤**，绝不让插件不可用」。
- 皮肤加载失败 ⇒ 静默回落经典档，**不得白屏、不得抛错到页面**。

## §4 · 实施步骤（严格按序，每步有验收）

### 步骤 1 · 建皮肤包骨架

按 12 卷 §二形态建目录（**新增文件，不动本体**）：

```
skins/classic/theme.json      # 默认档（内容可为空覆写，仅声明）
skins/v4/theme.json           # 新款档（11 卷 §3 token 全套）
skins/v4/skin.css             # 新款追加样式（只追加式覆盖）
skins/v4/skin.js              # 新款插槽组件（10 屏结构；可拆多文件）
skins/v4/assets/              # 本地素材（禁止外链）
skins/v4/README.md            # 版本 / 适配插件版本
```

**验收**：`theme.json` 可被 `JSON.parse`；`skin.css` 内所有 `var(--skin-*)` 引用都在 `theme.json` 有定义（11 卷 §五第 4 条「无硬编码遗漏」）。

### 步骤 2 · 实现 10 屏

- 每屏结构**照抄 11 卷 §二对应屏**，视觉对齐参考图。
- 数据**只用既有接口**，不新建路由（宿主 67 路由不动）。
- 单屏做完即比对参考图，**一屏一验**，不要 10 屏一起做。

**验收（每屏）**：与参考图同屏对比——布局骨架 / 组件构成 / **高熵数值**（如 342、128、56、8、88、92%/85%/78%）逐项对齐（20 卷 §2 用的就是这个判据）。

### 步骤 3 · 注册两档并接通切换

- 在**既有皮肤机制**里注册 `classic`（默认）/ `v4` 两档。
- 12 卷 §二优先级：团队主题 > 用户主题 > 内置主题。
- **切换粒度 = 整个记忆窗格**（不是白板一块）。

**验收**：切换后整窗格换样；切回经典 ⇒ 与今天逐字节一致。

### 步骤 4 · 设置页入口（§2 C1 的允许例外之一）

- 位置：设置页（参考图「设置」屏，或既有设置页对应分组）。
- 文案：**「外观与皮肤」→「皮肤中心」**，两档命名 **「经典皮肤」/「客户要的新款皮肤」**（用户原话）。
- **即时回显**（用户硬性偏好：开关点了标签立刻翻面，不得写盘成功但界面无变化）。

### 步骤 5 · 回退 R41 的「替换语义」（§2 C1 的允许例外之二）

**背景**：R41 在 `lib/client.js` 里给 `PlanTab` 加了 graph 档短路，使旧内容卡全部不渲染。**这是错的**（用户原话：「旧 UI 表保持的肯定就是现在的样子，减去那个搞错的白板的东西」）。

**要做**：把该短路**撤销**，让经典档恢复本来的样子。具体位置：搜索 `data-dam-surface-v4` 与 `boardModeLocal === 'graph' && kbData`。

**验收**：经典档下白板页与 R40 之前一致；新模式由皮肤层承担，不再由 `boardMode` 短路承担。
