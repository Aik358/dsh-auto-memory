> 生成 2026-09-26 ｜ 起因：用户问「客户买了存储空间我又没买，我怎么测试？」并提出「T2 做成测试路线」。
> 本文先纠正**三处混淆**（不纠正会把力气花在错地方），再给出**四层测试方案**。
> 本卷**修正 [25 卷](25-架构裁定与双通道落位.md) §2 补充一与补充三**（T2 的定位与安全等级）。

## 0. 先纠正三处混淆（★这三条比方案本身重要）

### 混淆一：把「测试要用的存储」和「产品要卖的存储」当成同一个东西

你的原话是「客户买了这个服务端的存储空间，那我又没买，那我该怎么测试呢」。

> **真实情况：测试根本不需要买任何存储。** 因为：
> ① **S3 兼容的服务器可以完全跑在自己电脑上**（MinIO 就是干这个的，免费、单文件、一条命令）；
> ② **本机实测结果**：这台机器上 **Docker / podman / MinIO 全都没装**（只有 Node v24.18.0 与 Python 3.14.6）；
> ③ 但这**不构成阻塞** —— 见 §1，有一条**零下载**的测试路线。

**判据**：测试环境 ≠ 生产环境是**常态**，不是例外。任何一个卖 SaaS/自托管软件的公司，开发机上都跑本地假存储。

### 混淆二：把「T2（自建服务端）」当成「测试路线」

你说「这个 T2 就做成测试路线嘛……安全就不用考虑那么严」。**这条不能这么做，理由有三**：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **T2 与测试没有关系** | 测 S3 通道要在 S3 上测；测 HTTP 通道要在 HTTP 上测。**T2 是第二条产品线，不是测试工具** |
| 2 | **T2 已经是「涉密客户用的那一条」** | 涉密场景下「以为走内网、实际走公网」是**安全事故级**。把它的安全等级降为「随便写写」等于给涉密客户埋雷 |
| 3 | ★**你现在要测的根本不是 T2** | 主线是 **B11a/b/c（S3 通道）**。T2（B11e）**已裁定延后**。给一个延后的东西写测试，是给未来还债 |

> ⇒ **正确做法**：测试路线**是 S3 通道**，不是 T2。T2 的安全红线（[25 卷](25-架构裁定与双通道落位.md) §2 补充三）**保持原样、不得放松**。

### 混淆三：把「测试方法」当成「必须装软件」

你说的「随便写写，测试通过就行了」——**方向对，但对象错**：

- ✗ 错的对象：以为要**装 MinIO / 装 Docker** 才能测；
- ✅ 对的对象：**本仓已有现成的测试手法**（181 个 smoke 套件 + `tools/run-smoke.mjs`），而且这套手法**不需要任何外部服务**。

**本仓既有惯例**（实测）：`tests/smoke/*.mjs` 就是「纯源码逻辑 + 内置 node」的测试，不依赖网络、不依赖服务端。
> ⇒ 新增的同步测试**应当沿用这个惯例**：写 `smoke-test-team-*.mjs`，用**注入的假 fetch / 内存对象存储**跑，进 181 套件一起门禁。

## 1. 四层测试方案（从便宜到贵，L1/L2 现在就能做）

| 层 | 名字 | 要装什么 | 能证明什么 | 成本 |
|---|---|---|---|---|
| **L1** | **假存储**（内存对象存储） | **什么都不用装** | 同步语义正确性：排队/重试/冲突/合并/日历/注入 | 极低 |
| **L2** | **假 HTTP 服务**（Node 自带 `http` 起一个 20 行服务器，实现 `api/team/sync/push`） | **什么都不用装** | 现有 `team-auth` + `team-sync` 这条 HTTP 链路**能真的跑通** | 极低 |
| **L3** | **真 MinIO**（本机下载单文件 exe） | 下载一个 exe | S3 签名（V4）真的对、PUT/GET/LIST 真的通 | 低 |
| **L4** | **真云**（客户给凭据后） | 客户提供 | 那把钥匙真的能开那把锁（**这才是 E2 真机证据**） | 中（等客户） |

### L1 / L2 是**现在就能做**的，而且足够推进施工

**L1 的关键设计（也是 [25 卷](25-架构裁定与双通道落位.md) §2 补充二要求的接缝）**：

```
  transport 接缝（put/get/list）
        ├── S3Backend      （B11b 要写）
        ├── MemoryBackend  （L1 测试用：一个 Map）      ← 几十行，零依赖
        └── HttpBackend    （B11e，延后）
```

> ★**MemoryBackend 不只是「测试用」** —— 它同时是**接缝一致性测试的基准**：
> [25 卷](25-架构裁定与双通道落位.md) 要求「同一组操作跑两个后端，断言产出相同」。有了 MemoryBackend，这条断言**从第一天就可执行**。

**L2 的价值（常被忽略）**：
> 你可能觉得「HTTP 服务端路线都延后了，测它干嘛」。但事实上 **`team-auth` 与 `team-sync` 的代码已经写好了、而且是当前唯一能跑的发送路径**（`PUSH_PATH = api/team/sync/push`）。
> 用 20 行 Node http 服务器把它跑通，是**用最低成本验证既有代码没坏**，而不是为 T2 投资。

## 2. L3 的现实情况（本机实测）

| 探测项 | 实测结果 |
|---|---|
| Docker | **未安装** |
| podman | **未安装** |
| MinIO 可执行文件 | **未安装** |
| Node | ✅ v24.18.0 |
| Python | ✅ 3.14.6 |
| MinIO 官方下载站 | ⚠️ `dl.min.io` 返回 **HTTP 410 Gone**（该路径已下线，需换官方新入口） |

**⇒ L3 需要一次「下载一个 exe」的动作，且下载地址要重新确认**（410 说明旧路径失效）。这**不是阻塞**，因为 L1/L2 已经能推进到 B11c 结束；L3 只在「要证明 S3 签名真的对」时才需要。

**L3 的替代路径（若不想装任何东西）**：
1. **用 Node 写一个「假 S3」**：本仓零第三方依赖，但 S3 签名验证要自己实现（约 100 行），成本中等；
2. **等客户的真实凭据**（L4）——但那时才发现签名错，返工贵；
3. **推荐**：先做 L1/L2 推进主线，**L3 作为一个独立小批次**在 B11b 完成后专门做一次。

## 3. 裁定（CR-9）：测试路线 = S3 通道，不走 T2

| # | 裁定 |
|---|---|
| R1 | **测试路线不是 T2**，而是 **S3 通道（T0/T1）**；T2 保持「涉密内网产品线 + 延后 + 安全红线不放松」 |
| R2 | 测试**分层**：L1 假存储（零安装）→ L2 假 HTTP（零安装）→ L3 真 MinIO（装一个 exe）→ L4 真云（等客户） |
| R3 | L1/L2 **进本仓既有 smoke 体系**（`tests/smoke/` + `tools/run-smoke.mjs`），**不引入任何外部服务依赖** |
| R4 | **MemoryBackend 必须实现**，它既是 L1 测试件，**又是一致性测试的基准后端** |
| R5 | **不使用 Docker**（本机未装）；L3 用 MinIO 单文件绿色版（免安装） |
