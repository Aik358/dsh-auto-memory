# 89 · R17 外观层残余归零（真·裸 hex = 0 / 真·裸 rgba = 0）

> 依据：goal 目标书「外观层：**裸 hex 归零** + **裸 rgba 归零**」；R16 建立的唯一度量实现 `tools/lib/appearance-scan.mjs`。

## 一、★R16 为什么没清干净（根因实测）

| # | 根因 | 证据 |
|---|---|---|
| ① | ★**R16 生成器自带一套扫描，未复用共享模块**（违反 R16 刚立的**第 9 条纪律**）| R16 只处理 21 种字面量；残留 **14 处 / 11 种** hex（`#4d6bfe` `#c2603f` `#8a7fbf` `#4f7cff` `#3aa675` `#e0a53a` `#d66666` `#c061c0` `#8a8f98` `#e08a8a` `#e8eaed`）与 **61 处 rgba** 未纳入 |
| ② | **两类「已 token 驱动」的写法被误计** | (a) `rgba(var(--tile-rgb),.52)` ⇒ 掩码 `var()` 后残留 `rgba(,.52)`（首参为空）；(b) `'rgba(' + col.r + …` ⇒ 运行时拼接（JS 表达式）|

## 二、本轮两条修正

1. **度量补丁（共享模块）**：新增 `isDynamicRgba()` —— 首参为空的 `rgba(,` 与以引号开头的 `rgba('` 一律**排除**（它们是**已 token 化**的写法，不是裸值）。⇒ 真·裸 rgba 由 81 修正为 **61**。
2. **生成器改为真 import 共享模块**（`scanAppearanceDetail`），并按**行号精确替换**。

## 三、★两条安全纪律（R16 教训的直接延续）

1. **先包裹引用、后插 token 定义** —— 否则定义行被裹成 `--dam-x: var(--dam-x, #v)` (**自引用循环**，CSS 循环 var 失效 ⇒ 视觉变化)。
2. ★**按行精确替换，绝不全局 replace-all** —— 同一字面量可能同时存在于「R16 已建的 token 定义行」与「裸用点」；全局替换会把定义行也裹进 `var()`（新出现的风险）。本轮生成器加断言：**目标行若是定义行则直接抛错**。
