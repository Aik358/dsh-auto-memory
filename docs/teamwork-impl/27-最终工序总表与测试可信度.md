## 0. ★用户的一句担心，被实测证实（CR-10）

用户原话：「我最怕的就是本机测试不了，只能用这个断言来测定，但断言肯定是有逻辑漏洞的。」

### 实测结果（2026-09-26，逐文件静态分析 181 个套件）

| 类别 | 判据 | 数量 |
|---|---|---|
| **A 纯源码断言** | 只 `readFileSync` 读源码 + 正则匹配；**无** `import`/`require`/`spawn`/`new Function`/`writeFileSync`，**且从不调用被测函数** | **56 / 181（31%）** |
| B 纯真执行 | 真跑代码，无源码匹配 | 11 |
| C 混合 | 既读源码也真执行 | 74 |

> ★**结论：你的担心成立。181 套件里 56 套（31%）是「读源码找字符串」，它们能证明「代码里写了这行」，
> 但**不能证明「这行运行起来是对的」**。

### 裁定（CR-10）：新代码一律「真执行」，且必须给可观测物理量

| # | 裁定 |
|---|---|
| R1 | **B11 新增的每个模块，验收必须是「真执行」**：`await import()` 真模块 → `create*()` 真构造 → 真调用 → 断言返回值 |
| R2 | **禁止用「源码里有这行字符串」作为功能验收**（那只能作为**守卫**，不能作为**功能证据**） |
| R3 | **必须给物理量**：字节数 / sha / PASS 数 / 真跑耗时 —— 让「通过」可复算，不可口头 |
| R4 | 断言里**必须有负路径**（该失败时必须失败），否则守卫恒真（本仓已有先例：B2「四情形全 {ok:false}」就是恒真守卫） |
| R5 | 56 个 A 类套件**本次不动**（它们是既有守卫，改动风险大于收益），但**新增的一律不得是 A 类** |

## 5. 回归提速（2026-09-26 实测，用户要求）

**根因**：`tools/run-smoke.mjs` 的 `DEFAULT_JOBS = 4`（2026-09-20 用户已裁定「默认并行」），但本项目历次交付一律显式传 `--jobs=1`，把并行退回串行。

| 并发度 | 墙钟 | PASS/FAIL | 相对提速 |
|---|---|---|---|
| `--jobs=1`（此前每批都用） | 201.4s | 183 / 0 | 1.0× |
| `--jobs=8` | 34.9s | 183 / 0 | **5.8×** |
| `--jobs=16` | 30.4s | 183 / 0 | **6.6×** |

**结论**：`--jobs=8` 已接近下界（最慢单套件 `smoke-test-autocont-host.mjs` 30.4s 即理论下限）；再提高并发只增内存占用、收益 <15%。**默认命令改为 `--jobs=8`**。

★**纪律**：`--jobs=<N>` 是**验证前的加速手段**，不得因此跳过任何套件。并行不改变套件集合、不改变断言内容 ⇒ 「并行 183 PASS」与「串行 183 PASS」等价（本轮已双向实测确认）。

**推荐命令**：

```
# ① 全量回归（默认并行，约 31–35s）
node tools/run-smoke.mjs --jobs=8 --timeout=90000 \
  --exclude=-live- --exclude=m79-feature-v2-pre \
  --exclude=m710-fv2-emit-pre --exclude=c4-fresh-install-pre

# ② 文档计数锁（★不在①里，必须单独跑）
node tools/verify-docs.mjs

# ③ 语法检查
node --check lib/index.js
```
