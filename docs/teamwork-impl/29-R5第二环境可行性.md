### 2.1 G-B3 —— 同一文档在 Windows 与 Linux 算出同一条目 id

**判据原文**：同一 `PLAN.md` 文本，两平台解析出的条目 **id 集合完全相同**；取证必须**实际换过路径分隔符**。
**反例**：❌ 只在 Windows 上跑；❌ 只比 id **数量**而不是 **id 集合**。

**可行性**：✅ **本机可触达**（只欠一次 push 触发 CI）。

#### ★ 关键源码证据（这条是 7 条里唯一「设计上已解决」的）

条目 id 派生函数 `wbEntryIdPre`（`lib/wb-sidecar.js:78-83`）：

```js
export function wbEntryIdPre(workspaceKey, relPath, title) {
  const h = createHash('sha256')
    .update(String(workspaceKey || '') + '\0' + normalizeRelPathPre(relPath) + '\0' + normalizeTitlePre(title))
    .digest('hex')
  return 'mem_' + h.slice(0, 32)
}
```

`normalizeRelPathPre` 的定义（`lib/wb-sidecar.js:57-59`）**就是为这条目标写的**：

```js
export function normalizeRelPathPre(relPath) {
  return String(relPath || '').replace(/\\/g, '/')
}
```

其上方注释（**L53-56 原文，逐字**）：

> relPath 规范化: 一律正斜杠。write 侧传 `path.relative(...)` 在 Windows 得反斜杠,
> rebuild 侧拼 `'handoff/'+f` 得正斜杠 ⇒ 不统一就会同一条目两个 id。

**⇒ 结论（有源码为证）**：Windows 的 `path.relative()` 产出反斜杠，**先被 `normalizeRelPathPre` 归一为正斜杠，再进 sha256**。
**因此「实际换过路径分隔符」这件事发生在函数内部** —— 两平台喂入不同分隔符，**哈希输入相同**。

#### 可立即执行方案（三步）

**① Windows 侧就地自证（先证明规范化生效，不依赖外部环境）**

```powershell
console.log(JSON.stringify(ids, null, 2))
console.log('all equal:', new Set(ids).size === 1)
"
```

判定：`all equal: true` 即证明规范化生效。
**★ 注意**：这**只证明「规范化函数对」**，**不满足** G-B3 的「两平台各跑一次」要求（反例第 1 条明确禁止「只在 Windows 上跑」）。**它是前置自检，不是取证本身。**

### 2.3 G-C3 —— A 机写 → B 机读，不暴露任何本机端口

**判据原文**：两台机器经对象存储收敛；**本机不监听任何新端口**，防火墙无新增入站规则。
**反例（★与本任务其他条目冲突的关键一条）**：❌ **只在同一台机器上开两个进程假装两台机（共享了文件系统，测不出真实链路）**。

**可行性**：⚠️ **需用户提供** —— ❌ 本机双进程方案被反例**逐字排除**。

**★ 为什么不能用 §2.4 那套复用**：G-C3 的反例**点名禁止**「同一台机器开两个进程假装两台机」；而 G-D1/D4/E2 允许双实例。
**这两类目标的取证方式必须分开，不得用同一套结果去结两条案。**

**本机现状（实测）**：

- `~/.ssh/config` **不存在** ⇒ 无命名主机别名。
- `known_hosts` **2 条** ⇒ 历史连过 2 个远端（**推断，未实测**其凭据/可用性；条目存在不等于可用）。
- 无第二台机器接入的任何证据。

```powershell
# 【基线】A 机（本机）取证前：记录监听端口集合
$a_before = Get-NetTCPConnection -State Listen |
  Select-Object -ExpandProperty LocalPort | Sort-Object -Unique

"baseline 端口数: " + $a_before.Count          # 本次实测：68 个唯一端口

  Select-Object Name,DisplayName | Out-File "$env:TEMP\a-fw-before.txt"

Compare-Object $a_before $a_after      # ★ 必须为空
```

**判据（三条同时成立才算过）**：

1. **B 机确实读到 A 机写入的内容**（对向验证，非「能连上」）；
2. `Compare-Object` **差集为空**（无新增监听端口）。
   ⚠️ **注意**：基线里**已经含 `19387`（DSH 宿主自身）**，差集法天然容忍它存在、只要求**不新增** —— **这正是正确的判据写法**（不要把它当违规）。

**阻塞点**：**缺第二台真实机器**（及可用的对象存储凭据）。
**用户需提供**：第二台能访问同一对象存储的机器。**前提**：两端均**只做出站**请求即可 —— 按 ADR-001，**56 条路由被回环守卫锁死是安全特性**，C3 正是要证明「不需要开端口也能同步」。

**结论**：⚠️ **必须用户提供第二台机器**；❌ 本机双进程方案被反例明令排除。

### 2.4 G-D1 —— 交换输入顺序 ⇒ 合并结果逐字节相同（收敛性）

**判据原文**：`merge(A,B)` 与 `merge(B,A)` 输出**逐字节相同**；需对**每一个原语（P1–P6）**都做双向合并。
**反例（★最重要）**：❌ 只测单向（本项目两个真 bug —— `compareClock` 双空返回 `-1`、排序键不足 —— **只有双向测试能发现**）；❌ 比「字段值相等」而非**序列化后逐字节相等**；❌ 用「合并三次看是否稳定」（分叉情形下**看起来也稳定**）。

**可行性**：✅ **本机可触达**。

**★ 为什么本机够用**：判据要求「**两个真实实例**」，**没有「两台机器」的要求**（对比 G-C3 明确禁止同机双进程）。
⇒ **两个独立进程 + 两套独立存储**即构成「两个真实实例」；本机 **MinIO 双实例（§1.7）+ node 双进程** 完全满足。

```powershell
# 实例准备同 §2.2 的 ①（9000 / 9010 各一套 data 目录）
node --input-type=module -e "
import { mergePre } from './lib/<同步原语模块>.js'   // ← 实际导出名以 04 卷为准
const A = [ /* 输入集 A */ ]
const B = [ /* 输入集 B */ ]
const sab = JSON.stringify(mergePre(A, B))
const sba = JSON.stringify(mergePre(B, A))
console.log('byte-equal:', sab === sba)
console.log('len:', sab.length, sba.length)
"
```

**★ 判据纪律（照反例逐条对齐）**：

- 必须**双向**跑（`merge(A,B)` 与 `merge(B,A)`）；
- 必须比 **`JSON.stringify` 后的字符串（逐字节）**，**不得**只比字段值；
- **不得**用「合并三次稳定」代替 —— 分叉时它**看起来也稳定**；
- 应对 **P1–P6 每一个原语**都做双向比对（冻结书原文：「对**每一个**原语（P1–P6）都做双向合并，比对字节」）。

**阻塞点**：**无环境阻塞**。
⚠️ 唯一前置：实际跑需确认 04 卷给出的原语模块**真实导出名**（**本报告未核实**，标为待确认项）。

**结论**：✅ **本机可触达**。

### 2.5 G-D4 —— 两端条目数最终相等（无重复、无丢失）

**判据原文**：两端 **id 集合集合相等**（**不是数量相等**）；需 **A→B、B→A 同步，两轮后**比对 id 集合与各自内容哈希。
**反例**：❌ 只比数量（重复 + 丢失恰好抵消时数量相同）；❌ **只同步一次就断言收敛**（需**多轮**才能暴露「每轮都产生新差异」）。

**可行性**：✅ **本机可触达**（材料同 G-D1）。

```powershell
# 双实例起好后：① A→B、② B→A、③ 再 A→B……两端各至少 2 轮
node --input-type=module -e "
const a = new Set(/* A 端 id 列表 */)
const b = new Set(/* B 端 id 列表 */)
const onlyA = [...a].filter(x => !b.has(x))
const onlyB = [...b].filter(x => !a.has(x))
console.log('A-only:', onlyA.length, 'B-only:', onlyB.length,
            'set-equal:', onlyA.length === 0 && onlyB.length === 0)
"
```

**★ 判据纪律**：**集合相等**（双向差集均为空）**且**各自内容哈希一致；**必须多轮**。

**阻塞点**：**无环境阻塞**（同 G-D1 的前置待确认项）。

**结论**：✅ **本机可触达**。

### 2.6 G-E2 —— 两人改不同条目 ⇒ 自动合并，零人工

**判据原文**：A 改条目 1、B 改条目 2 → 同步后**两端都有两条改动**，且**不产生冲突记录**（观察**冲突中心为空**）。
**反例**：❌ 两端内容看着都对，但**冲突中心里躺着一条无人处理的冲突**；❌ **只在单机上模拟两个修改（共享内存掩盖了真实的时钟/设备差异）**。

**可行性**：✅ **本机可触达**（条件：两个实例必须是**独立进程 + 独立存储 + 独立时钟**，不得共享内存）。

**★ 分寸说明**：G-E2 反例第 2 条只禁止「**单机**模拟」。本机做的是**两个独立进程 + 两套独立存储 + 独立时钟**，**不是**单进程内模拟 ⇒ **满足 G-E2 的字面要求**；但**不满足 G-C3**（C3 的反例才禁止同机双进程）。**两者不得混用。**

```powershell
# 用两个独立 node 进程并发（不是同一进程里先后调用）
Start-Job -ScriptBlock { node "$using:PWD\tools\<同步入口>.mjs" push --entry=1 } -Name instA
Start-Job -ScriptBlock { node "$using:PWD\tools\<同步入口>.mjs" push --entry=2 } -Name instB
Wait-Job instA, instB | Receive-Job
# 收敛后：① 两端都含两条改动（集合比对，同 G-D4）  ② 冲突记录数 == 0
```

**判据（两条同时成立才算过）**：

1. 两端**都**有两条改动；
2. **冲突中心为空**（**不是**「两端内容一致就行」——反例第 1 条专门防这个）。

**阻塞点**：**无环境阻塞**（同上前置待确认项）。

**结论**：✅ **本机可触达**。

### 2.7 G-F6 —— 装 python / 不装 python，行为一致

**判据原文**：两种环境下**所有同步相关行为逐字节相同**。
**反例**：❌ 「没 Python 时能跑」≠「行为一致」（可能**悄悄降级**）；❌ 代码里 `if (!pythonAvailable)` 影响同步行为即**违反铁律**。
**静态断言要求**：`derivedIndexEnabled` 一类开关，**函数体内不得出现 `pythonEngine`**。

**可行性**：⚠️ **需用户提供**（「不装 python」那一半缺干净环境）。

#### ★ 实测发现（与任务简报的前提有出入）

简报写「装 python / 不装 python 两种环境」；**实测本机 `python` 存在且多版本**（§1.6）。
**但更关键的是**：本插件与 python 的关系**不是「装了就用」**、**也不是「探测是否安装」**——

| `lib/` 中 python 相关文件 | 命中数 | 注释原文摘录 |
|---|---:|---|
| `lib/context-sink-python.js` | 4 | `M7-0/M7-1 PythonContextSinkPre(docs/PYTHON-SIDECAR-CONTRACT.md §5.2,§8.2,§13.1)` |
| `lib/activation-host.js` | 1 | `M7-1 三重门(PYTHON-SIDECAR-CONTRACT §13.1):默认 fake 时恒不走 python 分支` |
| `lib/context-host.js` | 1 | `M7-1 三重门(…§13.1):**默认 false/null 时恒为假 → 永远走 null sink**` |
| `lib/index-sync.js` | 1 | `M7-1 Authorized index_sync 构造与执行` |
| `lib/m7-wire.js` | 1 | `M7-0 Wire Protocol 纯核心` |
| `lib/m7-index-sync-host.js` | 1 | `M7-8 Host Index Sync Orchestrator` |
| `lib/python-sidecar-client.js` | 1 | `M7-0 JS SidecarClient` |

**⇒ 实测含义**：`lib/` 里**没有「检测 python 是否安装」的逻辑** —— python 走的是 **「M7-1 三重门」显式开关**，且**默认 false/null 时恒走 null sink**（`lib/context-host.js:133` 注释逐字）。
⇒ **「装/不装 python」在插件侧不是自动探测，而是配置开关。** 这**反而让 G-F6 更容易取证**。

```powershell

$env:PYTHON_ENGINE=''      # 或配置项置空/false（键名以 PYTHON-SIDECAR-CONTRACT §13.1 为准）
node tools/<同步入口>.mjs <完整场景> ; $h1 = <产物哈希>

# 环境二：python 开关开启（显式）
$env:PYTHON_ENGINE='1'
node tools/<同步入口>.mjs <完整场景> ; $h2 = <产物哈希>

"逐字节相同: " + ($h1 -eq $h2)
```

**两条取证路径**：

- **路径甲（本机，推荐先做）**：**开关开/关**两种配置各跑完整场景，比对**产物哈希**。
  依据：**python 是否生效由三重门决定，而非由解释器是否存在决定**。
- **路径乙（严格）**：**真正装/不装 python** 的两个环境。⇒ **本机做不到「不装」**（已装 5 个解释器，且**禁止卸载软件**）。

**⇒ 路径乙的可行载体：CI 的 `ubuntu-latest`**。`tests.yml` 里**没有任何 setup-python 步骤**（实测 L40-46 只有 `actions/checkout` + `actions/setup-node`）：

```yaml
          node-version: ${{ matrix.node-version }}
```

**【推断，未实测】**：`ubuntu-latest` 镜像**预装** python3（GitHub 官方 runner 镜像通常含 python），因此**它也不是「无 python」环境**。
⇒ 要把「无 python」做实，必须**改 `.github/workflows/tests.yml`** 显式遮蔽 python —— **该文件不在本任务可改范围**。

**阻塞点**：

1. 本机**无法**做出「无 python」环境（已装 + 禁止卸载）；
2. 走 CI 需**修改既有 workflow**（本任务只读，不可改）；

**结论**：⚠️ **路径甲（开关开/关 + 产物哈希）本机即可执行**；**路径乙（真装/真不装）需用户提供干净环境或授权改 CI**。
