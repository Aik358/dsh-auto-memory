# 大版本愿景：连续性（Continuity）——写给未来失忆的自己

> 写于 2026-09-06，0.1.39 发布当夜。0.1.39 是 0.1.x 稳定线的**最终稳定版**（此后仅针对 issue 做稳定性更新），全新版本两周内启动，工作重心=对标 GPT-6 Astra「上下文管理」。
> **本文档是愿景与 README 宣传方案的唯一权威来源。大版本完成前禁止改 README；大版本完成后，按 §6 执行宣传改版——执行前先通读全文，别只看标题。**

## 1. 产品论点

**AI 助手的价值 = 上下文 × 时间。** 今天几乎所有 AI 的记忆都死在上下文窗口里：压缩即失真，关窗即清零，换工具即归零。

dsh-auto-memory 的终态：**给 DSH 里的任何模型一个不死的记忆**——有结构、可检索、会成长、可审计、归用户所有。

GPT-6 Astra 把「上下文管理」（结构化笔记跨窗口、归档可搜索、按需检索、handoff 代替压缩）作为旗舰模型的实验特性发布（`features.context_management.experimental_mode`，2026-09-03，closed beta in config.toml）。**我们把同一条路线做成开放、模型无关、可审计的插件能力。** 这不是跟随，是背书：头部厂商用整个旗舰发布验证了"外置结构化记忆"才是正解，"反复压缩成摘要"是被淘汰的旧范式。

## 2. 四个连续性（终态的四个轴）

### 2.1 当下连续——窗口内的注入（已基本完成）
- 固定边界注入：记忆是"背景事实与规则参考"，永远声明"不是表达方式的示范"，绝不劫持语体
- 注入内容全出口中和（0.1.39）：`{{模板变量}}` 再也炸不了轮次
- 无人值守模式：托管期间零寒暄零指令，面向长批处理
- 终态画面：记忆像空气——在，但不吵；需要时都在场，不需要时无存在感

### 2.2 窗口连续——跨上下文交接（M-CM，本次大版本的主战场，对标 Astra）
现状与增量：
- 已有：M8 接续卡片（摘要式）、M7 evidence store + 双臂索引（词法/语义）、固定边界注入
- M-CM1 **四段式交接笔记**：任务状态/目标/已试方案+失败原因/进度与下一步——接续从"摘要"升级为"结构化 ledger"。低成本先行。
- M-CM2 **主动检索工具**：`memory_search` / `memory_note` 注册为门控代理标准工具（CUA 插件已验证工具机制可行；注意 ctx.get() 坑）。Agent 从"被动吃注入"升级为"按需查归档"——这就是 Astra `history`/`_context` 的插件版。**这是整个大版本最值得做的一件事。**
- M-CM3 **原始归档可搜索**：完整历史消息+工具输出落本地归档（全量+索引），让检索能命中"没被笔记捕获的细节"——Astra 原话 "even if that information wasn't captured in its notes"。视存储成本控制（压缩全文+哈希索引）。
- M-CM4 **水位感知**：上下文快满时推 handoff 提示而非继续注入；若 DSH host 暴露压缩预告事件则在压缩前自动写交接笔记（host 无此事件则向 DSH 提 feature request——插件永远只能"助产"，不能替 host 决定压缩）。
- 终态画面：上下文将满时，Agent 不再"把书烧了留一句读后感"，而是"合上一本写满批注的笔记，翻开新的一页，笔记本还在手边随时可翻回去"。

### 2.3 时间连续——跨周期的成长（已基本完成，持续打磨）
- 30 天蒸馏泵、procedure touch/pinned/90 天归档、fact 治理式写回 MEMORY.md、每日反思、定时总结
- 记忆会成熟而不是腐烂：高频被引用的过程性知识被 touch 保活，过时的自动归档
- 终态画面：一个月后她对项目的理解比第一天深得多，而你从没重复教过第二遍

### 2.4 工具连续——跨产品迁移（M8 已通电，大版本补全叙事）
- 接续页签导入其他 AI 的记忆（外部记忆继承）；三店持久化全在用户本机
- 大版本补：把"记忆属于用户不属于厂商"从功能上升为宣言（README 独立段落）；评估导出/可携带格式
- 终态画面：换模型、换电脑、换 AI 产品，记忆跟着人走

## 3. 对标 Astra：开放插件的位势

| | GPT-6 Astra / Codex 实验特性 | dsh-auto-memory 大版本 |
|---|---|---|
| 可用性 | 单厂商旗舰、experimental、closed config | 开源插件、DSH 任何模型即装即得 |
| 笔记 | 跨窗口 keep notes | 四段式交接 ledger + 用户可直接读改 |
| 归档 | 早期窗口可搜索 | 本地全量归档+词法/语义双臂检索 |
| 检索 | history/_context 工具 | memory_search/memory_note 门控代理工具 |
| 触发 | token budget + handoff | 水位感知 + 压缩前拦截（host 协作） |
| 所有权 | 厂商侧 | 记忆全在用户盘上，治理式写回可审计 |
| 分级 | 无（绑定订阅档位） | 0GB 词法保底 → 130MB 内置语义 → 563MB Python 进阶 |

宣传口径一句话：**"What Astra ships as an experimental flagship feature, we ship as an open plugin — for every model on your machine, today."**（中文版见 §6）

## 4. 终态用户故事（README 叙事骨架）

> 周一，你让 Agent 调研一个方案，中途关了电脑。
> 周三，你换了台机器、顺手把默认模型也换了。打开 DSH，她接上的不是"抱歉，我不记得之前聊过什么"，而是上周的进度、三条已试过的死路和下一步——因为交接笔记在，原始记录可搜，记忆跟着你走。
> 周五，你问她"你为什么记得这个？"，她给你看 evidence 链：哪条消息、哪次工具输出、哪次反思写下的，你可以 pin、可以改、可以删。

## 5. 我们不做什么（克制的边界，同样写进宣传）

1. 不替 host 决定压缩策略——只助产 handoff，窗口是 host 的领地
2. 不上传任何记忆——三店全本地，外部来源扫描只读
3. 不用记忆操纵语体——注入永远声明"背景事实，非表达示范"
4. 不做黑箱——每条记忆有 evidence 直达，review 时间线可回放，脏数据有扫描器
5. 不做全家桶——记忆插件不做日程替身、不做 RAG 框架，边界清晰才可信
