   「禁止对 lib/client.js / skins/iter5/* 做三方合并或整块替换式重构」
   （2026-10-01 用户明确警告，起因是社区 merge 造成大面积污染、修了一整天）。
3. **顺序依赖**：#469（测试脚手架）是其余四条的安全网，**必须最先**。安全网没立起来就动
   结构性重构，等于在没有保险的情况下拆承重墙。
4. **收益不在当下**：这五条的收益是「后续改动的边际成本」，不是「用户可见的缺陷」。
   v4 主线动工时一并做，摊薄成本。

## 已修 · **issue482 家族两个套件**每天 00:00–07:30 必红（2026-11-03 修复 + 变异验证）

**实测（2026-11-03 01:05–01:16 本地，HEAD `b989a5f9` + datadir 深化）**：

- `smoke-test-issue482-dayview-past-date.mjs` → 单跑 **FAIL 21 / FAIL 8**；
- `smoke-test-issue482-483-log-binding.mjs` → 单跑 **EXIT=1**，失败项
  `✗ A4 负路径：直接用 now ⇒ memDateOfPre 判为今天 ≠ 昨天（原缺陷复现）`。
- **两者同一根因**（下详）。

**根因（实测数值，非推测）**：两个套件都用**真实时钟**算日期，而「记忆日」与「日历日」口径不同：

```
本地时间                         = Tue Nov 03 2026 01:05
TODAY     = memDateOfPre(NOW,450) = 2026-11-02   ← 记忆日（日界 450min ⇒ 凌晨归前一天）
YESTERDAY = 日历减一天             = 2026-11-02   ← 日历日
★ TODAY === YESTERDAY ⇒ true
```

⇒ 当本地时刻落在 `[00:00, 07:30)`（boundary 450 分钟以内）时两者指向同一天：
- dayview 套件的 A/C/D/F 四段判据自相矛盾（"昨天那份应为空"与"今天那份不应被污染"同时断言在一个日期上）⇒ 21 条 FAIL；
- log-binding 套件的 A4 要求 `memDateOfPre(now) ≠ 昨天` ⇒ 直接失败。

**危害**：这两个套件**每天合计 7.5 小时是红的**。红灯成为常态会掩盖真缺陷 ——
任何一次真回归红都可能被当成"哦，又是那个时钟套件"。

**修法（建议，二选一）**：
1. **隔离时钟**（推荐）：把 `NOW` 改为可注入的固定时间戳（如落在日界中段的 `Date.UTC(2026,10,2,12,0)`），判据不再随时钟漂移；
2. 或把 `YESTERDAY` 也改用记忆日口径（`memDateOfPre(NOW - 86400000, B)`），并在 `TODAY === YESTERDAY` 时显式 SKIP 而非判红。

**归因已隔离**：`git stash push -- lib/datadir.js` 去掉本批改动后单跑**仍 FAIL 21 / FAIL 8**
⇒ 与本批无关；`git stash pop` 后 `datadir.js` sha256 前缀恢复 `ec0a377eb9cf4dff`（未丢失）。

**已修（2026-11-03，用户裁定「时钟套件本身就收掉」）**：把两个套件的时钟源改为**固定本地 12:00**
（`new Date(2026, 2, 15, 12, 0, 0, 0).getTime()`），并在每处加**时钟隔离守卫**：

- `dayview`：新增 `A0 ★时钟隔离守卫`，断言 TODAY / YESTERDAY / TOMORROW **三者互不相同** ——
  若有人改回真实时钟且恰逢日界窗口，**这一条先红**并打印三个值，比 A/C/D/F 四段各红一遍更易判读；
- `log-binding`：把 A4 升级为 `★时钟隔离守卫`，标签直说触发条件（"改回真实时钟且落在本地 00:00–07:30 ⇒ 此条先红"）。

**变异验证（证明判据没被"修松"）**：把副本时钟改回 `Date.now()` ⇒ 在边界期内
`A0` 先红（实测输出 `TODAY=2026-11-02 YESTERDAY=2026-11-02`）、`A4` 红，两个套件 `EXIT=1`；
还原固定时钟 ⇒ 两者 `EXIT=0`。改动**只碰测试、不碰产品代码**。
