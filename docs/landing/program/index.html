Pilot Credits Program

插件维护方发起 · 额度由 DSHAPI 倾情赞助

引航者计划

以推理额度，敬奉躬行者 —— 一条被校验的 issue、一个被提炼的合并 PR、一段长青的模块守护，皆可即时兑现为充沛的模型端点动力。

本计划额度悉数源自 DSHAPI（api.dshapi.icu）。它长期为本项目的开发调试、回归测试及语义引擎选型提供端点支持。须明晓者：此乃 API 推理额度，而非物理算力 —— 尊驾所获者，系调用模型端点之配额，供运行评测、合成数据、蒸馏实验及前后端深度调试之用，非可自由调度的硬件资源。

此乃插件维护方发起的社区同仁计划，额度由 DSHAPI 独家赞助。它非官方机构资助，亦无任何商业背书 —— 纯粹是维护者将赞助方的馈赠，精准倾注于真正动手实践的开发者。

探索疆界

额度何以助君拨迷寻路

八篇公开报告已冻结了一批具象的科学问题。它们静候领航 —— 每一个课题，只需「换一个端点、换一批语料、调整一组参数」，便能推演复现、直言反驳，或向未知更推进一步。

01

检索选型

现状
3 模型 × 5 分块 × 6 通道 交叉网格对比；BGE-M3 真实层 R@5 = 0.925。
额度所能为
更换推理端点、重载新语料重跑网格，以验证此数，抑或证明其局限。
02

分块策略

现状
最优粒度于合成层与真实层之间发生反转，规律不可外推。
额度所能为
于两层补设更丰盈之语料，看清反转之轨迹与内在机理。
03

检索通道

现状
加权融合赋予真实层 MRR +11.9% 增益，且未引入额外依赖；然权重标定空间尚待开垦。
额度所能为
跨端点扫描融合权重与通道贡献，绘制精密的标定曲面。
04

重排

现状
重排品质获 +13% MRR 提升，惟 CPU 延迟超预算 52–66 倍。
额度所能为
探索更轻量之重排器与部分重排策略，确证收益与代价之真正交界。
05

激活策略（回声陷阱）

现状
单阈值精确率为 0；双通道决策链 precision 0.818 / recall 0.237。
额度所能为
召回率尚待破局 —— 借由带标注之对照实验提升召回，且绝不妥协精确率。
06

注入成本与前缀缓存

现状
完整版 18,291 字符 = 预算之 228.6%；同站缓存命中率落差达 2.96 倍。
额度所能为
切换端点并量化缓存行为，验证特定裁剪能否换取更高之命中率。
07

架构治理

现状
18,525 行巨型文件已解耦拆分为 110 个模块及 158 条依赖边。
额度所能为
引入模型交叉审阅模块边界，校验拆分方案能否经受独立通读之考验。
08

关系型记忆议程

现状
四类记忆对象 × 五个决策阶段，六个可证伪假说仍缺乏实证数据。
额度所能为
将假说构建为小型对照实验：固定候选、随机化表达、模型打分结合人工复核。

上述结论皆呈示于技术报告索引页 —— 评测、语料与数据全盘公之于众。社区可复现、可反驳，亦可补全未竟之实验。额度存在的意义，是让「万事俱备，只欠端点」不再成为搁浅探索的借口。

立项本怀

因本计划切实可被深度构建

绝非虚饰的「欢迎献策」，而是能改写代码、能跑通实验、能留下可核验印痕的笃实参与。

前端单文件、零构建、全开源

记忆面板与设置页凝练于单文件之中，无需复杂依赖，免去构建繁琐，改动即时生效。何处可改、为何而改、改后如何校验，皆有公开的落点地图可循。

后端语义模型参数昭然可见

Embedding 检索通道、分块粒度、激活门槛及注入预算，诸多参数皆明摆于表，评测口径严格复现。社区同仁得以展开严谨的对照实验，而非仅凭凭空感受谈天。

两相契合，瓶颈赫然显现：构想已就、落点已明、参数可调、报告公开，所匮缺者，唯有跑通下一个实验所需之模型端点。本计划即为补齐此一拼图 —— 将赞助方之 API 额度，亲手呈递给躬行实践之人。

阶梯额度

凭据为标，不凭私交

三阶划分唯看「凭据之硬度，历时之长久」：issue 系单次洞察，合并 PR 系一次交付，长期维护系一道轨迹。一切凭据，皆以公开可查之链接为准。

阶梯补充说明

三阶之间绝无尊卑高下。尊驾完全可能在同月内兼具 issue 与合并 PR；核验时将按当时可出示之最硬凭据取阶。具体额度配额与可用模型，以核验通过后随 API Key 附发之接入指南为准。

申领路径

私信维护者，三行即足

无需繁文缛节，不必撰写长篇大论。将凭据凝练为链接，将用途归纳为一句话，余者皆交由公开核验。

01

私信维护者

使用提交 issue / PR 的同一 GitHub 账号直接私信维护者，注明拟申领之阶梯。

02

撰写三行

正文只需三行，长篇大论绝不增加优先级：

  • ·GitHub 用户名
  • ·issue 或 PR 链接
  • ·用途一句话 + 计划使用之模型名称
03

查验

对照公开链接核验归属与状态：issue 是否获确认/复现，PR 是否已合并，改动是否已采纳。

04

颁发

查验通过即下发专属 API Key 及接入说明，明确写明额度周期、可用模型与到期时间。

何以只需三行

凭据本身自具说服力 —— issue 具状态，PR 具合并记录，review 具留痕。将三行写得清晰纯粹，胜过万字自我推介。

用途与边界

额度系跑通实验之燃料

其本质为 API 推理额度，故能赋能之事极其具象；亦正因如此，下述红线须昭告于前。

正当用途

01

模型选型与评测

将同一批检索与激活任务置于不同端点运行，对比特定语料下之表现差异。

02

合成数据与蒸馏实验

构建测试语料、运行小规模蒸馏对比，验证参数改动之实际成效。

03

插件前后端调试与优调

真实会话回归测试、注入预算调参、前端交互联调 —— 须频繁调用模型方能定位之难题。

疑虑澄清

先将四项核心关切陈述于前

Q1能否将额度用于商业项目？

断不可用于对外商业服务。插件本体遵循 BSD-3-Clause 协议开源，个人自用、学术研究及内部测试皆不受额度牵制；然将额度嵌入收费服务链路，绝不在本额度覆盖之列。

Q2额度能否私相转授他人？

决不可。额度强绑定至申领账号及申领时报备之用途，严禁转售、共享或二次分发。易人使用即视同滥用。

Q3复核周期如何厘定？

严格遵循阶梯走：启航档按周、远航档按月、领航档按季。复核时仅查验该周期内是否有可核验之产出；无产出则降档或停用，有产出则凭凭据顺延至下一周期。

Q4此举是否变相设立付费墙？

绝无可能。插件代码永远开源免费，无任何功能因额度而设锁 —— 纵不发额度，插件亦完整无损。额度仅赠予愿意并肩躬行者，系对「已然动手」者的补贴，而非「解锁功能」之门票。
