Make continuation and archive state durable (#207)

This draft is limited to #207's continuation counter, continued-source latch and archive ledger persistence. It starts independently at upstream main 131ca794b9f0d07f78b19bf6feee3312939854ed and does not import PR #206/#208/#209 or change their branches. Refs #207; it does not claim to close the full issue. greetCount remains owned by #199/#206, and the unsupported generic WASM/CDN claim is excluded.

A real MemoryEngine with last=12 and refused writes returned 13 twice, marked an unpersisted source as successfully continued, lost early sources after 205 records and restart, and swallowed archive ledger write errors. The patch commits counter reservations atomically under a cross-process lock and refuses unreserved fallback numbers. Reservations never roll back: packaging failures may leave gaps but cannot reuse a number. Cold migration skips ordinary files, scans all selected JSONL session versions, and rejects inaccessible, invalid UTF-8 or incomplete compressed evidence. SQLite history requires an explicitly reviewed high-water seed via the packaged maintenance command. Parent directory aliases share the lock; leaf state-file symlinks are refused without changing either target or link.

Source latches now use permanent bounded records keyed by the normalized source ID's SHA-256. Existing array/object JSON is read without alteration; new records are not truncated to the most recent 200 or cached in an unbounded Set. Total storage grows with source identities; previously pruned identities cannot be reconstructed. All shared-directory writers must upgrade; old versions do not understand the new shards.

The host durably reserves a source before external side effects and saves its successor before delivery. Only one new host can reserve a source. Successful delivery is followed by a durable done record; ambiguous delivery or a completion commit failure retains pending and returns an explicit error and successor ID. Failure before creation releases its own token; once creation returns an ID, pending remains even when successor persistence fails; unknown delivery does not automatically retry. Restart-safe GET status and the packaged lib/continuation-maintenance.js command expose pending/completed records. Explicit verified complete or non-delivered release checks the current token and successor snapshot, and refuses an active delivery. Raw successor IDs are preserved; old normalized IDs require operator verification. Pending never expires by age/PID death. No remote exactly-once protocol is claimed, and the legacy material route cannot control old clients independently creating sessions outside the plugin.

Archive writes reread and merge actual deltas/deletions under a cross-process lock. Atomic failure preserves old bytes, returns a false health report and diagnostic, and stops deletion for that run. Unknown archive ages remain protected; failed new timestamp persistence is not repaired by inventing an age. This serializes state updates, not an external registry operation as a distributed transaction.

Validation uses twelve real state regressions, formal apply/HTTP routes and host manual/automatic continuation, and real child processes covering directory aliases, leaf-file alias refusal, restart and dead-owner recovery. The final stale-token test replaces the original token, checks the exact persisted-reservation error and verifies unchanged state bytes. No real model, QQ, notification or user service is called. The packaged maintenance entry was also run from an isolated installed layout; run it from the installed package root or use its absolute script path.
