### 17:30 · P1 根因定位（白板检查点数全为 0）

**根因（两模块契约断层 · 第 2 次同类）**：

```js
// lib/ev4-adapter.js:208  adaptEventPre()
const cps = arrPre(ev.checkpoints).map(...)   // ← 只认 ev.checkpoints
```

但 `event-store.list()` **刻意不返回 `checkpoints`**（7 个基础字段不带 checkpoints，正文走 `/event-detail`），
只返回 **`checkpointCount: number`**。

⇒ `arrPre(undefined)` = `[]` ⇒ `cps.length = 0` ⇒ 白板显示「0 个检查点」。

**证据链**：
| 位置 | 值 |
|---|---|
| 磁盘 event-store.json | **311 个检查点**（项目白板 156 / v4 底层改造 114 / v3.3.x 22 / …） |
| `/event-list` 返回 | `checkpointCount` 字段存在且正确 |
| 白板 UI 显示 | 每个事件「**0 个检查点**」 |
| `ev4-adapter.js:208` | 只读 `ev.checkpoints`，**从不读 `checkpointCount`** |

**这是同一个缺陷家族第 2 次**：
- 第 1 次：「1970 时间」= adapter 按 `cps[0].ms` / `createdAt` 算，而 list 投影两者都不给（已修）
- 第 2 次（本次）：检查点数 = adapter 按 `ev.checkpoints` 算，而 list 投影只给 `checkpointCount`

**共同点**：**adapter 假设的字段 ≠ list 投影实际返回的字段**，两段各自测、没人测接缝。

### 17:50 · P8 修复（泳道/工作流视图恒 0 事件）

// lib/event-store.js
function projectEventForListPre(e, withPercept, withTime, withKind) {
  ...

### 🔴 新发现缺陷 P9：泳道时间轴从 `1/1 00:00` 起

**实测**：泳道视图的横轴刻度显示 `1/1 00:00` / `1/1 02:00` / `1/1 04:00`，不是真实日期。

**根因**：
```js
function timeScale(items) {
  var min = Infinity, max = -Infinity;
  for (...) for (...) { var ms = items[i].checkpoints[j].ms; ... }  // ← 只读 checkpoints[].ms
  if (!isFinite(min)) { min = 0; max = 1; }   // ← 列表态占位检查点无 ms ⇒ 回落 0/1 ⇒ 1/1 00:00
}
```

这是「1970」缺陷家族的**残留分支**：之前修了 `eventSpanOfPre`（左栏）和 adapter 的 `pickMsPre`（事件时间），但 `timeScale`（泳道横轴）没修。

**修法**：`timeScale` 在 `checkpoints[].ms` 全缺时，退到 `items[].startMs / endMs`（业务时间），绝不伪造 0。
```js
if (!isFinite(min)) {
  for (var k = 0; k < items.length; k++) {
    var s0 = Number(items[k].startMs), e0 = Number(items[k].endMs);
    if (isFinite(s0) && s0 > 0 && s0 < min) min = s0;
    if (isFinite(e0) && e0 > 0 && e0 > max) max = e0;

  }
}
```

## 8. P9 的真正根因（第二轮修复 · 19:00）

### 为什么第一版修法无效

我第一版把无时间的 `ms` 设成 **NaN**，以为「不伪造就是对的」。但产物**要经过 JSON 序列化**才到前端：

```js
JSON.stringify({ ms: NaN })  // => '{"ms":null}'   ← 变 null，不是 NaN、也不是丢键！
null < Infinity             // => true          ← null 被 ToNumber 成 0
// ⇒ min = null；isFinite(null) === true ⇒ 我加的兜底 if(!isFinite(min)) 永不触发
```

**实测坐实的证据**：轴刻度 `1/1 08:00 / 09:30 / 11:00 / 12:30 / 14:00` ——
间隔正好 1.5h × 4 = 6h，正是 `max = min + 6*3600000`（时间跨度不足 6h 时的默认兜底宽度），起点 = `null` → 1970。

### 修法

```js
// ❌ 旧：if (!isFinite(ms)) ms = NaN      // JSON 里变 null，污染 min
// ✅ 新：if (!isFinite(ms)) ms = undefined  // JSON 直接丢键 ⇒ 前端 undefined < min 恒 false
```

**验证（跨 JSON 往返，不是内存对象）**：
| 项 | 结果 |
|---|---|
| 往返后 `cps[0].ms` | `undefined`，`'ms' in cp === false` ✅ |
| 裸循环 `min` | `Infinity`（未被污染）✅ |
| `!isFinite(min)` | `true` ⇒ 兜底正常触发 ✅ |

### ★新增守卫：`smoke-test-v4-json-roundtrip.mjs`（11 PASS / 0 FAIL）

**这是本轮最重要的固化**。它守的不是某个字段，而是**一整类错误**：

> **测的是内存对象，跑的是序列化之后的对象。**
> 即「测试与运行之间隔着一层序列化边界，而测试没跨过它」。

| 用例 | 断言 |
|---|---|
| JR-0a | `JSON.stringify(NaN)` 确实产出 `null`（元事实） |
| JR-0b | `null` 参与 `<` 比较会把 min 污染成 `null` |
| JR-0c | `isFinite(null) === true` ⇒ 兜底守卫会失守 |
| JR-0d | `JSON.stringify(undefined)` 直接丢键（正确空值） |
| JR-1a | 真时间经往返后仍是原数字 |
| **JR-1c** | **占位检查点的 ms 不得为 null** |
| **JR-1e/f** | **聚合后 min 必须有限且 >1e12（不得回 1970）** |
| JR-1g | 负路径：故意设 NaN 时确实出现 null |

**变异验证（证明它有鉴别力）**：
| 版本 | 结果 |
|---|---|
| `ms = undefined`（修复版） | **11 PASS / 0 FAIL** |
| `ms = NaN`（变异回缺陷版） | **9 PASS / 2 FAIL**（JR-1c + JR-1f，`got=null`） |
