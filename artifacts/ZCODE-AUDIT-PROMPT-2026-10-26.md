## 核心方法论：这个项目自己总结的「绿但假的」9 类谱系

**这是你审计时最锋利的武器。** 项目内部反复踩过这些坑，你要拿它们当检查清单去查**当前代码是否还有同类问题**：

| # | 形态 | 含义 |
|---|---|---|
| 1 | `ok:true` 未写盘 | 返回成功但磁盘没变 |
| 2 | 源码字符串断言 | 断言「源码含某字符串」——恒真，不构成功能证据 |
| 3 | **假状态桩** | 测试手工塞了产品代码**永远不会产出**的字段 ⇒ 断言全绿但功能是死的 |
| 4 | 探针未命中 | 插桩点根本没被调用，却当成有效观测 |
| 5 | 两段式只测后段 | 只测渲染函数，不测「refresh → render」完整链路 |
| 6 | 单向核对 | 只验「A 等于 B」，不验「B 也等于 A」 |
| 7 | 未真渲染 | 静态检查 DOM 结构，没真跑浏览器 |
| 8 | `uncaughtException` 吞成 exit 0 | 进程明明崩了，退出码却是 0 |
| 9 | 复刻环境缺真实初始条件 | 复刻页一开始就有尺寸，掩盖了真实环境的 0 尺寸死循环 |

**另一条元教训**：「同一语义在多个函数里各写一份判据」⇒ 改动只改了一部分 = **半修**。症状看起来像新 bug，实为同一根因未改完。项目里这个坑复现了 **6~7 次**（`this.state` vs `stateFor(agent)` 家族）。
