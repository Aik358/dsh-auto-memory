## §1 · 问候环节实测（回答担忧 1）

### 1.1 它现在到底做什么

| 项 | 实测 |
|---|---|
| 段名 | `welcome-title`（`[欢迎回来]`）+ `welcome-body` |
| 触发条件 | 距上次活动 > `awayMinutes`（默认 60 分钟）且非无人值守模式 |
| 文案 | 「用户离开已超过 1 小时…先用一句简短温暖的话欢迎用户回来，然后提示自动记忆窗口将打开」 |
| **读什么记忆** | **不读任何记忆** —— 纯静态文案 |
| 属于哪一区 | 区 III 通道区（≤300 字符，可整段丢弃） |

### 1.2 ★结论：问候环节**确实需要改**

| 问题 | 现状 | 应改为 |
|---|---|---|
| 内容 | 静态「欢迎回来」+ 提示打开窗口 | **读事件摘要**：上次离开时正在做什么（活跃事件头）+ 这段时间有什么进展 |
| 情感性 | 无（只有一句泛化的温暖话） | **有依据的关心**：「上次你说的 X 有进展了」「你提到的 Y 还没做」 |
| 数据源 | 无 | **事件头 summary + 未完成 commitments + userPercept(kind=unfinished-goal)** |
| 与 memory_note 关系 | 无 | 应能引用白板当前状态与最近账本 |

**设计要点**（用户原话「面向长期人际交流的情感性」）：

```
问候 = 事件摘要（在做什么） + 未完成承诺 + 时间感知（离开多久）
       ↑ 这才是「有记忆的问候」，而不是「模板寒暄」
```

**注入位置约束**：问候在区 III（通道区 ≤300），要塞事件摘要必须先做**预算重排**（挪一部分到区 II）。

### 2.2 ★注入层：四个字段**全部 0 消费**（这是真缺口）

| 字段 | 注入侧消费 | 状态 |
|---|---|---|
| `userPercept` | **0** | ❌ **只存不用** |
| `agentTrace` | **0** | ❌ 只存不用 |
| `sharedGround` | **0** | ❌ 只存不用 |
| `commitments` | **0**（且 index.js 里 0 处，连工具参数都没暴露） | ❌ **连存都存不进** |

**根因**：`renderT2Pre`（`lib/event-render.js`）只渲染 `name/status/sections/checkpoints/outcome`，**完全没有读四个 percept 字段**。

### 2.3 文档原定的设计（SPEC-v2 §2.1，用户参与制定）

| 类别 | 字段 | 例子 |
|---|---|---|
| **用户记忆** | `userPercept` | 用户不吃某食物；项目约束 |
| **Agent 自传记忆** | `agentTrace` | Agent 上次建议方案 B，后来被证伪 |
| **共同/关系记忆** | `sharedGround` | 一起完成某项目；用户纠正某项长期误解 |
| **关系约定** | `commitments` | Agent 承诺下次先验证再建议；用户不希望主动提某话题 |

**原文裁定**（SPEC-v2 L389）：
> | 8 | **userPercept 本期只存不用** | 2026-10-23 | 用户「至少先记录上，以后一定会用」 |

⇒ **「只存不用」是当时有意为之**，但用户现在明确说下一步面向「长期人际交流的情感性」⇒ **本期必须开始用**。

## §3 · MemoryMe（用户画像）实测

### 3.1 用户原话（SPEC-v2 第 14 行）

> 「我在想要是注入事件信息一定要在尾部…**用户画像记忆和项目规约还是可以单独的**」

### 3.2 实测：**没有「用户画像」这个独立容器**

| 项 | 实测 |
|---|---|
| `memoryMe` / `MemoryMe` / `userProfile` | **0 处** |
| `用户画像` | 1 处（仅注释） |
| 现有替代 | `memory_user` 写 `~/.dsh/memory/MEMORY.md`（跨项目规则），**不是画像** |
| `userPercept` | 事件级、**只存不用** |

### 3.3 ★结论：用户画像缺一个**独立的注入位**

用户说的是「画像记忆和项目规约**还是可以单独的**」⇒ 两者应是**并列的独立段**：

| 段 | 内容 | 现状 |
|---|---|---|
| 项目规约 | `MEMORY.md`（规约卡） | ✅ 有（Q4 裁定保留） |
| **用户画像** | 这是**谁**：偏好 / 沟通风格 / 情感倾向 / 雷区 | ❌ **无独立段** |

**建议**：新增注入段 `user-portrait`，数据源 = 聚合事件里的 `userPercept`（跨事件）+ `memory_user` 中的偏好类条目。
