```
event = {
  id: 'evt_<8hex>',
  name,                          // 一句话标题（手绘 1「Task XX」）
  summary,                       // 一段话总览（L0）
  outcome,                       // 成果
  skillRef,                      // 是否固化成 skill（手绘 1「有可能固化成 skill」）
  userPercept: [],               // ★手绘 1 的「用户观察」→ 线二落点
  sections: { goal, doing, deadend, next },   // 你的四段
  checkpoints: [                 // 时间轴（手绘 1 中「打开」后的竖轴）
    { at, kind, text, sourceRef }  // sourceRef 指向原账本文件 + 行区间
  ],
  constraints: ['rule:<id>', 'spec:<id>'],    // ★只引用，不复制
  status: 'active' | 'closed',

```

### D2 · 未归档事件窗格（存量兼容）

**为什么必须有**：现存 **575 篇顶层账本 + 258 篇 archive = 833 篇**，全部无事件归属（`eventId` 实测 0/515）。升级用户一定会遇到这个问题。

**六步流程**：
1. **检测存量** — 扫 `handoff/` + `handoff/archive/`，凡无 `eventId` 者入列
2. **窗格展示** — 分页列出：文件 / 时间 / 目标首行 / 字节
3. **点「审理」** — 按批（默认 40 篇）启动子代理
4. **生成草案** — 聚类 + 抽四段 + 起事件名，产出草案 JSON（不写盘）
5. **人在环确认** — 窗格预览草案，逐条接受 / 改名 / 合并 / 丢弃
6. **写入 + 回写** — 写 event 存储；原账本只加 `eventId` 引用

**成本估算（实测口径）**：
- 833 篇 ÷ 40 = **21 批**
- 每批输入 46,120 字 ≈ **27,129 token**；输出约 3,000 token
- 合计 **约 570k 输入 / 63k 输出 token**
- 单篇平均：输入 678 token · 输出 75 token

**四条硬约束**：
| # | 约束 | 判据 |
|---|---|---|
| 1 | 原件只读 | 不改账本正文，只在文件尾部追加 eventId 注释行；前后 sha256 全量比对，任一不一致即中止 |
| 2 | 可回滚 | 事件存储与账本引用分离：删事件只删索引，账本回到「未归档」；提供「撤销本批」 |
| 3 | 可审计 | 每批写 `event-curation-log.jsonl`：批号 / 输入文件清单 / 输入 sha256 / 子代理输出原文 / 人工决定 / 时间 |
| 4 | 不阻塞 | 后台任务；窗格显示「第 N/M 批」；中途关页面不影响，重进可续 |
