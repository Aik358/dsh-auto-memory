## 二、三个根因（先说这个，后面所有失败项都挂在这里）

### 根因 ①：`lib/client.js:7712` 把缺失时间硬归零，击穿了适配层的兜底

```
lib/client.js（v6-B5 映射层 ev4ProtoCheckpointPre）
  var ms = Number(cp.ms)
  if (!isFinite(ms)) ms = Number(cp.at)
  if (!isFinite(ms)) ms = 0        ← ★这一行
  cp.ms = ms
```

**因果链（已用真实数据离线复刻，逐一吻合）**：

1. 列表态走 `/event-list`，该接口**刻意不返回 checkpoints**，只给 `checkpointCount`。
2. `ev4-adapter.js` 按 count 生成**占位检查点 `{}`**，`ms` 算不出来 → 按 2026-10-27 的修法设为 `undefined`。
3. `undefined` 经 JSON 序列化**丢键** → 前端读到 `undefined` → `ms = 0`（就是上面那一行）。
4. 于是 `timeScale()` 里 `min = 0` 且 `isFinite(0) === true` → 适配层特意加的「退到 startMs/endMs」兜底**永不触发**。
5. 轴变成 `1970-01-01 08:00` 起，因为 `max-min < 6h` 又强制拉成 6 小时宽 → 刻度 `1/1 08:00 / 09:30 / 11:00 / 12:30 / 14:00`。

**实测截图与复刻结果逐刻度一致**（截图 54、实算 4 等分完全相同）。

> 注：`lib/ev4-prototype-blocks.js` 里 `timeScale` 的注释写着「绝不伪造 0」，适配层 `adaptCheckpointPre` 也写了三处修复注释——**三处闸门只改了两处，第三处（client.js 映射层）把前两处的意图整个抵消了**。

### 根因 ②：占位检查点只有数量、没有正文，右栏检查点整体空壳

同一个占位机制的连带结果：

| 字段 | 实际值 | 后果 |
|---|---|---|
| `cp.at` | `""` | D8 时间列空白 |
| `cp.rel` | `""` | 检查点来源列空白 |
| `cp.panels` | `[]` | 展开后无任何面板（I8/I9/D5） |
| `cp.sha256` | `""` | D11「sha256 前缀 」为空 |

运行时 `renderPanels()` 遍历 `cp.panels`，`countsOf()` 也遍历 `cp.panels` —— 空数组 ⇒ 展开后 `innerHTML` 为空，但**箭头仍会从 ▶ 翻成 ▼**（因为展开逻辑只切换 CSS class，与有没有内容无关）。这就是「点了有反应但什么都不显示」的观感来源。

### 根因 ③：`已完成 / 进行中 / 未判定` 三态筛选在运行时里根本不存在

在 63,157 字节的运行时里检索：「已完成 / 进行中 / 未判定」**只出现在 `statusLabel()` 这一个状态文案函数里**，没有任何 `statusFilter` / `filterByStatus` / `data-filter` 实现，也没有对应 click 绑定。

⇒ 点击三个 chip **不会有任何反应**，这是**功能未实现**（原型的写法如此，产品没搬过来），不是坏了。

## 五、疑似根因（可直接施工）

### 修复 1（一行，解决 K4 / M6 / D8 的时间部分）

`lib/client.js:7712`
```
- if (!isFinite(ms)) ms = 0
+ // 绝不伪造 0：缺时间就保持 undefined（JSON 序列化丢键），交给 timeScale 的 startMs 兜底
+ if (!isFinite(ms)) ms = undefined
```

同文件 `ev4ProtoCheckpointPre` 的 `cp.ms = ms` 需同步改成允许 `undefined`。改完后 `timeScale` 里那段「退到事件自身 startMs/endMs」的兜底就会真正生效，轴会落在真实日期区间。

### 修复 2（治本，解决 ②③ 全部 8 项）

列表态用 `/event-detail` 补齐真检查点，而不是用占位对象顶数：

- 现状：`adaptEventPre` 按 `checkpointCount` 造 `{}` 占位 → 数量对了，内容全空。
- 建议：命中选中事件时把 `detailEv.checkpoints` 合并进 payload 再重建 iframe（`ev4Sig` 里加入 detail 版本号），或让适配层对占位检查点输出明确的「未加载」态而不是空对象，让 UI 语义诚实。

### 修复 3（功能补齐）

三态筛选需要在运行时补 `statusFilter` 状态 + 三个 chip 的 click 绑定 + `applyFilterVisibility` 里叠加状态谓词。当前运行时只有文本搜索谓词。

## 九、验证方法说明（可复现）

1. **GUI 层**：computer-use 真实点击，每步截图落盘。
2. **契约层**：直接 `curl` 宿主 loopback 路由 `http://127.0.0.1:19387/api/dsh-auto-memory/event-list?all=1`，确认真实返回含 `members / kind / startMs / endMs`（证明后端三条 `with*` 开关都已生效）。
3. **数据层**：读磁盘 `~/.dsh/memory/workspaces/--D--dsh-auto-memory--/handoff/event-store.json`，确认 10 事件 / 311 检查点、`cp[0].at = 1792915966614` 真实存在、四段 `goal/state/dead/next` 齐全。
4. **链路复刻**：用真实接口返回跑 `adaptStoreToPrototypePayload`，再叠加 `client.js` 的 v6-B5 映射层，最后 JSON roundtrip —— 输出与 UI 现象逐刻度吻合。

**这套方法的价值**：GUI 只能看到「1/1 08:00」，链路上四个环节（数据/后端/适配层/映射层）究竟谁坏的，只有逐层复刻才能定位到具体那一行。
