## 1. 弹窗文案（`UpgradePopup`，打开白板看板时触发）

### 1.1 标题

**现在**：`检测到旧版记忆格式`

**建议改为**：

```
记忆架构升级 · 你的旧记忆需要整理一下
```

> 理由：原句像「报错」。改成「升级」语气，且明确「旧记忆还在，只是需要整理」，不是「你的东西坏了」。

### 1.2 正文（三段式）

```
【为什么升级】
旧版把记忆存成「流水账」——按时间一条条堆着。新版改成以「事件」为单位：
一件事一个容器，跨天也能接着做，能记住来龙去脉、以及你和我在某件事上的共识。
这是为了让记忆真正能用起来，而不只是能搜到。

【会发生什么】
点下面的按钮，会派一个子代理在你的机器上整理，大约 10 分钟。
它只整理格式，不删任何东西。

【你的旧记忆不会丢】
所有原始记忆都会先备份，再整理。整理完还能回退。
整理期间你可以正常用，不影响当前对话。
```

### 1.3 按钮

| 位置 | 现在 | 建议 |
|---|---|---|
| 左 | `稍后（3 天内不再提示）` | **保持不变**（已有降频机制） |
| 中 | `关闭` | **保持不变** |
| 右（主） | `立即派子代理整理` | `开始整理（约 10 分钟）` |

> 理由：把「10 分钟」放按钮上，比藏在正文里更让人敢点。

### 1.4 整理中 / 失败的文案

| 状态 | 现在 | 建议 |
|---|---|---|
| running | `正在整理记忆…` | `正在整理记忆 · 大约 10 分钟，可以先干别的` |
| failed | `整理失败` | `整理没成功 · 原始记忆未受影响，可以重试` |

## 3. 发版说明（CHANGELOG / 公告用）

```markdown
## [3.4.0] — 2026-11 · 记忆单元从「流水账」升级为「事件」

> **一句话**：这是一次**底层记忆架构**升级。旧版按时间堆流水账，新版以「事件」为单位组织——
> 一件事一个容器（跨天可续），并挂载「你的偏好 / 我的动作 / 双方共识 / 约定」四类情境。

### 这次为什么要升级

旧结构有三个限制：
1. **记不住来龙去脉**——按时间切片，同一件事跨天就断成好几条；
2. **记不住人**——用户画像与共同经历无处挂载；
3. **注入不可控**——流水账越长越挤占上下文，最后只能粗暴截断。

### 升级后有什么不一样

| 维度 | 旧（流水账） | 新（事件） |
|---|---|---|
| 组织单位 | 时间切片 | 一件事一个容器 |
| 跨天 | 断开 | 可续（中断再捡起） |
| 情境 | 无 | 四类 percept 挂在事件上 |
| 白板 | 手写正文 | 事件的投影视图 |
| 注入 | 全量堆叠 | 按事件优先级分层 |

### 对老用户意味着什么（重要）

**① 你的记忆不会丢。**
整理只做格式转换，**原始记忆会先完整备份**，整理后仍可回退。

**② 不整理也能用。**
插件已做好**向后兼容**：旧格式记忆可以正常读写，不会报错、不会打不开。
只是白板仍读旧格式，显示会不全（白板段已临时截流以省注入）。

**③ 整理是可选、可拒绝、可延后的。**
我们不会自动改你的记忆。检测到旧格式时：
- **打开白板看板**会弹一个提示窗，说明情况并给两个按钮（开始整理 / 稍后）；
- **对话结束后**我也会提一句，你也可以直接说「整理旧记忆」；
- 点「稍后」后 **3 天内不再打扰**。

**④ 整理要多久？**
派一个子代理在你本机跑，**大约 10 分钟**。整理期间不影响你正常对话。

### 后续

这次更新将在 **7 天左右**上传。
预计 **11 月底**还会更新**检索模型**，继续探索人机长期交互的**主动式记忆**的边界。
```
