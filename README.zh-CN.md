# dsh-auto-memory：最小记忆核心

只保留六项能力：**自动提取、统一整理、短摘要注入、按需搜索、纠正与删除、原文追溯**。

## 工作方式

1. 主会话一轮结束时，保存脱敏后的对话文字事件及会话、轮次信息。
2. 工作区空闲 60 秒后，直接调用宿主已配置的模型，提取值得长期保留的信息，合并已有自动记忆。每次读取最多 24,000 字符原文和 16,000 字符候选记忆；剩余内容在后续空闲时间继续处理。
3. 组装提示词时注入短摘要，默认上限 3,000 字符。模型通过工具按需搜索、读取详细记忆和原文。
4. 用户纠正优先。修改和删除检查版本，手动确认的记忆不能被自动整理覆盖。

数据集中存储，范围只有“当前项目”和“用户偏好”。所有写入采用进程锁和原子替换。自动提取没有工具权限，不创建子代理。

## 安装和使用

需要 Node.js 22.19+，以及提供 `llm`、`tools`、`systemPrompt`、`webServer` 和 `conversation.view` 的 DSH 宿主。接口按公开 DSH 提交 `687f282e8625c6b8d11ff58211a90524be2e4317` 核对。

检出此分支后执行：

```sh
npm test
npm pack
```

通过 DSH 的插件安装流程安装生成的 `a9i5k4-dsh-auto-memory-4.0.0-alpha.1.tgz`，替换旧版本后重启。插件名称和 bundle patch 保持兼容。

会话顶部的“记忆”页提供搜索、新增、纠正、删除、原文查看，以及“整理待处理原文”。页面跟随当前会话工作区。完成一次模型请求后，自动提取复用该工作区的模型配置。

## 数据与旧版本迁移

数据默认位于 `$DSH_HOME/memory-core`，未设置时为 `~/.dsh/memory-core`：

- `memory.json`：统一记忆、适用范围、来源索引、处理进度和删除记录。
- `sources/src_*.json`：脱敏原文，保留会话及轮次标识，可分页读取。

首次打开工作区时，导入旧版用户及项目 `MEMORY.md`、日期日志和 `archive` 中的日期日志。支持旧版集中目录及项目 `.dsh-memory`。旧配置仅用于定位目录，旧文件保留原样。导入记录持久化，同一文件只处理一次；导入内容也需经过提取才成为正式记忆。

删除后，条目退出摘要与记忆检索，相关旧来源退出原文搜索和自动提取。原文文件继续保留，可凭来源 ID 为共享该来源的其他记忆提供追溯。删除记忆不会清除 DSH 自己的会话历史；用户之后明确表达的新事实可形成新证据。

用户偏好跨项目共享；完整项目会话原文只能在原工作区读取。常见密钥、令牌和密码格式会脱敏，无法保证识别所有敏感文本。备份或迁移时复制整个数据目录。

## 配置

可在 DSH profile 中现有插件条目的 `config` 配置：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `autoExtract` | `true` | 空闲时自动提取 |
| `idleMs` | `60000` | 空闲等待时间，毫秒 |
| `requestTimeoutMs` | `120000` | 单次模型请求超时，毫秒 |
| `summaryChars` | `3000` | 注入摘要字符上限 |
| `directory` | 上述默认目录 | 自定义记忆库绝对路径 |
| `provider` / `model` | 当前工作区模型 | 可选独立提取模型 |

关闭自动提取后仍保存原文，可搜索和手动修改。新一轮对话开始会中止后台提取；模型失败不会推进处理进度，页面显示错误。可手动重试，或在下一轮对话后自动重试。重启后保留待处理原文，打开工作区并获取模型配置后继续。

## 保留的工具

| 工具 | 作用 |
| --- | --- |
| `memory_search` | 关键词搜索，可同时搜索原文 |
| `memory_read` | 完整记忆、版本和来源 ID |
| `memory_source` | 分页读取脱敏原文 |
| `memory_write` | 新增或纠正；纠正需当前版本 |
| `memory_delete` | 检查版本后删除 |

检索采用英文词和中文双字匹配，无向量服务和额外模型依赖。UI 使用一个本机同源 HTTP 接口。
